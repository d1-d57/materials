# GEJTY — реестр гейтов конвейера (данные для трекера)

> **Когда читать:** строишь трекер-скрипт (заход ③) или каталог (заход ④); нужен полный список дверей фабрики и способ проверить каждую по диску. · **Что это:** структурная таблица — КАЖДЫЙ гейт как запись `id · стадия/граница · что проверяет · признак-на-диске · тип · возврат-разрешён`, которую скрипт-трекер проверяет автоматически (или помечает браузерным для ручного прогона). НЕ алгоритм-проза (та — `ALGORITM.md`) и НЕ реализация трекера (та — заход ③, вне этого файла). · **Куда дальше:** драйвер, который эти гейты вызывает — `ALGORITM.md`; формат Фазы II — `FORMAT-ISTOCHNIKA.md`.

## Как читать эту таблицу
- **тип** — `жёсткий-стоп-вперёд` (блокирует переход на следующий шаг, пока не зелёный) · `автор-чекпоинт` (требует вкуса/взгляда владельца, механически не решается) · `дисциплина-хук=WARN` (предупреждает по ходу работы ДО гейта-границы, не блокирует). Гейт может нести оба типа сразу (авто-часть + чекпоинт-часть) — тогда указаны через `+`.
- Пометка **[браузерный]** — трекер (заход ③) не проверяет автоматически в CI/скрипте без браузера; выносит отдельным пунктом «прогнать локально у владельца» (Playwright/`render.py`/`audit.py`).
- **возврат-разрешён** — да/нет по смыслу «гейты не рельсы» (`ALGORITM.md §Модель исполнения`): да означает, что провал этого гейта — штатный повод для волны назад по конвейеру, а не тупик.

### G13 · иллюстрация-ответ не раньше своей сцены (границы 8→9, 9→10)
- **что проверяет:** если рисунок отвечает на заданный на слайде вопрос, он появляется **вместе с ответом**, а не с началом слайда. Иначе картинка спойлерит и убивает отгадывание залом. На живом прогоне нарушали четыре рисунка.
- **признак-на-диске:** для каждого `data-ill` в `slides/<id>.html`, у которого задан `data-scene="N"`, — в `content/<id>.md` существует маркер `{@N}` или `{blur@N` с тем же N (илл. привязана к существующей сцене, не «сцена 0 по умолчанию»); обратно — если раздел содержит `{blur@` (то есть на слайде есть спрятанный ответ), а `data-ill` того же слайда не несёт `data-scene`, → FAIL (рисунок показан раньше ответа).
- **тип:** жёсткий-стоп-вперёд (привязка — авто) + автор-чекпоинт (является ли рисунок ответом — вкус)
- **возврат-разрешён:** да (спойлер → назад в арку 8, разметка сцен)

### G14 · `data-scenes` согласован с числом сцен в тексте (внутри арки 8)
- **что проверяет:** атрибут `data-scenes="N"` слайда равен фактическому числу сцен в его тексте. Разошлись — блюр не раскрывается, кликер уходит на следующий слайд (урок 7 арки 27.07).
- **признак-на-диске:** для каждого `<id>`: `N` из `data-scenes="N"` в `slides/<id>.html` == `max` по всем маркерам `{@k}`, `{blur@k`, `{fill@k` в `content/<id>.md`. **Правильная починка — не сверка, а генерация:** `data-scenes` должен вычисляться сборкой из текста, а не выписываться руками (см. H6).
- **тип:** жёсткий-стоп-вперёд (авто, без браузера)

### H6 · величина выписана руками в двух местах (общее правило)
- **стадия:** любая, continuous. Особенно арки 7/8/10.

- **возврат-разрешён:** н/п
