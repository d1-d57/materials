## 3. ЗАДАЧА
По раскадровке (см. «Вход» в `## 0`) для каждого слайда из списка расставь в `content/<id>.md` шорткаты Р2 (полная таблица — `SLIDE-FORMAT.md`, синтаксис/семантика — `DOK.md`):
- `{@N}` в начале абзаца — абзац появляется целиком на сцене N;
- `{@N-M}` — виден со сцены N до сцены M; `{@-M}` — виден до сцены M;
- `{@N|текст}` инлайн — кусок ВНУТРИ абзаца появляется на сцене N (не весь абзац);
- `{fill@N|бланк|ответ}` — шторка бланк→ответ на сцене N (генератор сам собирает пару `<span class="fill">`, ровно два варианта текста);
- `{blur@N|значение}` — блюр-шторка, раскрывается на сцене N (генератор сам собирает `<span class="blur-reveal" data-reveal="N">`).

Для сложных вложенных случаев (блюр ВНУТРИ одного из двух состояний `.fill`, как в живом примере `PRIMERY.md` §1) фигурных скобок Р2 не хватает — используй escape hatch (сырой HTML прямо в `content/<id>.md`, см. `SLIDE-FORMAT.md`): пиши `<span class="fill">…</span>`/`<span class="blur-reveal" data-reveal="N">…</span>` руками, ВОСПРОИЗВОДЯ те же классы/атрибуты, что дал бы генератор, — не изобретай свои имена.

**Правило «связка вне блюра»** (разбор — `PRIMERY.md` §1): математический/логический символ-связка (`≈`, `=`, «то есть» и т.п.) перед пропуском/блюром — ВСЕГДА снаружи `{fill@}`/`{blur@}` (`≈ {blur@3|...}`, НИКОГДА `{blur@3|≈ ...}`): связка внутри шторки ломает наложение `grid-area:1/1`, потому что второй (ещё не раскрытый) вариант её не содержит.

**КРИТЕРИЙ ГОТОВНОСТИ** (условие, способное провалиться — проверяй буквально, не «на глаз»):
- ни одной сцены без визуального изменения (дед-клик) — на каждый номер сцены K (от 2 до максимума раскадровки этого слайда) существует хотя бы один `{@K}`/`{fill@K|...}`/`{blur@K|...}` в тексте этого слайда (аналог `--scene-diff`; прецедент провала — Kepler, схлопнувшиеся 3 сцены в 1, — не повторить молча);
- геометрия заморожена: ты НЕ добавил и не подвинул ни одного элемента ни в `content/<id>.md` (кроме самих шорткатов и текста, который они оборачивают), ни тем более в `slides/<id>.html` (см. `## 2`) — сцены отличаются ТОЛЬКО добавленными пикселями через `opacity`+`visibility`;
- связка (`≈`, `=`) во ВСЕХ случаях СНАРУЖИ `{fill@}`/`{blur@}` (см. правило выше) — ни одного вхождения вида `{blur@N|≈ …}`/`{fill@N|≈ …|…}`;
- ровно один активный child `.fill` на сцену — на каждый `{fill@N|a|b}` (или ручной `<span class="fill">`) ровно ДВА варианта текста, не три и не один; если внутри `.fill` нужен ЕЩЁ и блюр (см. `PRIMERY.md` §1), это по-прежнему ровно два child верхнего уровня — блюр живёт ВНУТРИ одного из них, не добавляет третий;
- блюр несёт `data-reveal`, НЕ `data-scene-from` — так генератор всегда собирает `{blur@}` сам; если на живом деке блюр «дёргается» вместо плавного раскрытия, в первую очередь проверь, не поставлен ли по ошибке `data-scene-from` вместо `data-reveal` на этом элементе (механизмы независимы по конструкции ровно потому, что не пересекаются на этом атрибуте — см. `DOK.md` «Механика reveal»);
- если хоть один слайд из списка использует `{blur@}` ИЛИ совмещает текст+картинку одной сцены — в деке физически присутствует нужный CSS (`overlay.css` или его аналог) с `.blur-reveal{filter:…}` и `transition-delay:0s!important` (см. `## 2`, разбор — `PRIMERY.md` §4); отсутствие — явный пункт `## ВОПРОСЫ`/`## ОТЧЁТ`, не тихий пропуск;
- линтер `build_deck.py` (см. ниже) зелёный, и число сцен в `data-scenes` (см. «Важно про `data-scenes`» в `## 2`) на каждом слайде из списка сверено вручную со значением в `slides/<id>.html` и совпадает с раскадровкой — не появляется на выходе само.

Раскадровка невозможно закрыть без данных, которых нет (не сказано, что появляется на сцене K; номер сцены в раскадровке не совпадает с тем, что физически можно показать на слайде) → НЕ придумывай отсутствующее: стоп на этом слайде, вопрос в `## ВОПРОСЫ`, переходи к следующему. Это честная граница («стоп до цели»), не провал захода — но заяви её громко в `## ОТЧЁТ`.
