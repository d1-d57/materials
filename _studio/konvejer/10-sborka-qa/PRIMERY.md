## 1. Манифест `brief.md` — реальная схема с разбором

Полный фронтматтер `buffon/src/brief.md` (строки 1–33):
```yaml
---
id: buffon
title: "Игла Бюффона"
canvas: 1440x810
provenance: materials/buffon/index.html
provenance_sha256: c0c9b846fd040eb1755d66de10fd5609e51cc050cd2ddc59848b99f767d13d19
milestone: 1 (дословный распил; текст слайдов пока HTML, markdown — M2)
accent_tag: span
slide_order:
  - sl-title
  - sl-vizitka
  - sl-buffon
  - sl-sim
  - sl-convergence
  - sl-coin
  - sl-interval
  - sl-divider1
  - sl-plan

  - sl-prob
  - sl-polygons
  - sl-circle

  - sl-divider2
  - sl-grid
  - sl-coords
  - sl-condition

  - sl-thanks
---
```

**Разбор поля за полем** (значение — по `_studio/konvejer/FORMAT-ISTOCHNIKA.md` §«Манифест
`brief.md` — схема», строки 28–44):
- `id` / `title` / `canvas` — имя дека, название, фиксированный холст канона (`1440x810` — не
  меняется между лекциями).
- `provenance` — путь к монолиту, из которого распилен дек (регрессия); у **greenfield**-дека —
  пусто/`"greenfield"`.
- `provenance_sha256` — хэш оригинала; **если поле пусто/отсутствует — render-identity гейт
  (слой 2 шага 10) неприменим**, работает только линтер+аудит+глаз. У buffon это
  `c0c9b846fd040eb1755d66de10fd5609e51cc050cd2ddc59848b99f767d13d19` (реальный регрессионный
  дек — гейт применим).
- `milestone` — свободная заметка о стадии распила (не машинно проверяется линтером; у buffon —
  «1 (дословный распил...)», у dandelin — «2 (текст 12/19 слайдов вынесен в content/*.md...)» —
  формат заметки не унифицирован между лекциями, это нормально, поле для человека).
- `accent_tag: b | span` — HTML-тег для `**жирный**` из markdown (`build_deck.py` подставляет
  его в `render_inline_md(..., acc_tag)`, по умолчанию `"b"`). **Живой нюанс**: buffon объявляет
  `accent_tag: span` явно; `dandelin/src/brief.md` (строки 1–28) вообще НЕ несёт поле
  `accent_tag` в фронтматтере — используется дефолт `"b"` функции `render_md`/`render_inline_md`
  в `_generator/build_deck.py` без явного объявления в манифесте. Т.е. схема FORMAT-ISTOCHNIKA
  документирует поле как «core», но на практике оно опционально там, где дефолт устраивает —
  писать в `brief.md` новой лекции ЯВНО, только если тег не `b`.
- `slide_order` — единственный источник истины порядка показа; должен ТОЧНО покрывать
  `content/`+`slides/` без сирот/дублей (линтер-гейт слоя 1, см. §3 ниже). У buffon — 23 id
  плоским списком, без вложенности.

## 2. CLI `build_deck.py` / `--lint` / `render.py --compare` — команды и ожидаемый вид PASS

Команды дословно из `_generator/README.md` (строки 12–14):
```bash
python3 _generator/build_deck.py dandelin/src            # линтер-гейт + сборка → dandelin/src/dist/index.html
python3 _generator/build_deck.py dandelin/src --lint     # только линтер
python3 _generator/build_deck.py dandelin/src --no-banner # без баннера (для byte-exact сверки с оригиналом)
```
и сверка глазами (README.md строка 52):
```bash
python3 _generator/render.py --compare dandelin/index.html dandelin/src/dist/index.html _render
```
(нужен `pip install playwright pillow && playwright install chrome` — README.md строка 54; та же
установка отдельно продублирована в `render.py` строка 14: «Установка на своей машине: pip
install playwright && playwright install chrome»).

**Формат ожидаемого PASS-вывода** — дословные форматные строки из живого кода (`main()` в
`_generator/build_deck.py`, строки 333–357), с РЕАЛЬНЫМИ числами для dandelin — посчитанными по
прозе его же `brief.md` (это НЕ захваченный лог фактического прогона: сам `build_deck.py`
playwright не требует и мог бы быть прогнан здесь, но проверка велась чтением, не исполнением):
```
── ЛИНТЕР ──
  ⚠ illustrations/cone-cut не используется (нет data-ill="cone-cut")
  ⚠ исходный id "tpl-mirror" встречается 2× в оригинале — второе вхождение недостижимо через getElementById (сохранено дословно)
  … (ещё 9 неиспользуемых illustrations + 1 дублирующийся tpl-id — см. ниже)
  ✓ структурные проверки пройдены (12 мягк. предупрежд.)
  слайдов:19  шаблонов(иллюстраций):20  глав(3D):10  драйверов:10  sims:0  вес:NNNNКБ
── СБОРКА ──
  ✓ dandelin/src/dist/index.html (NNNN КБ)
```
Строка статистики — реальный формат `stats_line()` (build_deck.py строки 309–314): «слайдов:%d
шаблонов(иллюстраций):%d глав(3D):%d драйверов:%d sims:%d вес:%dКБ». Числа **слайдов/
иллюстраций/глав/драйверов/sims** для dandelin взяты дословно из прозы `dandelin/src/brief.md`
(19 секций — строки 43–45; 20 шаблонов — строка 47; 10 3D-глав — строка 65; `drivers/01.js…10.js`
— строка 74; sims — 0, у dandelin нет `sims/`, `FORMAT-ISTOCHNIKA.md`: «dandelin = 3D-тяжёлый…
без sims/math»); вес (`NNNN`) сознательно не подставлен точным числом — известен только порядок
величины (`_generator/DESIGN.md` §1: «колоды materials/\* — самодостаточные монолиты **2.5–3
МБ**»), точный КБ — по факту прогона на машине с playwright.

**Мягкие предупреждения для dandelin — тоже РЕАЛЬНОЕ число, не 0.** `dandelin/src/brief.md`
документирует (имена — строки 49–56, счёт неиспользуемых — строки 58–63, дубли id глав —
строки 66–72): **10** неиспользуемых `illustrations/*` (4 SVG:
`cone-title`, `axial-section`, `tangent-ray`, `montage` + 6 растровых плейсхолдеров: `cone-cut`,
`conics-trio`, `string`, `spheres`, `river`, `lithotripsy-bowl`) + **2** дублирующихся id
3D-главы (`tpl-mirror`, `tpl-tangent`, каждый по 2 файла) = **12** ожидаемых строк `⚠` при
реальном прогоне линтера на dandelin — это МЯГКИЕ предупреждения (exit остаётся 0), задокумен-
тированный инвариант оригинального монолита, не дефект пересборки. Формат строк — дословно из
`build_deck.py` строки 294–295 (`'illustrations/%s не используется (нет data-ill="%s")'`) и
301–303 (`'исходный id "tpl-%s" встречается %d× в оригинале — второе вхождение недостижимо
через getElementById (сохранено дословно)'`).

При FAIL вместо `── СБОРКА ──` печатается (build_deck.py строки 336–340):
```
  ✗ <текст первой структурной ошибки>
  ✗ <текст второй…>
ЛИНТЕР ПРОВАЛЕН: 2 структурн. ошибк(а/и). Сборка прервана.
```
и процесс возвращает exit 1 (`dist/` не пишется).

**Реальное подтверждённое PASS** (не гипотетика, а факт из живых манифестов/README):
- dandelin: пересборка **byte-exact** с оригиналом после нормализации (снятие HTML-комментариев
  + схлопывание пробелов) — `_generator/README.md` строки 44–47: «обе нормали = 3 004 501
  симв.; все 21 шаблон иллюстраций, 10 3D-глав, 5 шрифтов, 15 растров на месте, список потерь
  ПУСТ»; sha `69812415…` (`dandelin/src/brief.md` строка 6).
- buffon: пересборка **байт-в-байт** совпадает с оригиналом при `--no-banner` — `cmp` exit 0,
  sha256 совпадает (`buffon/src/brief.md` строки 38–39).

Формат вывода `render.py --compare` — дословные строки из `_generator/render.py` (строки 74–75,
80–81):
```
  слайд 07: изменённых пикселей = 0  ✓ идентичен
  слайд 12: изменённых пикселей = 348  ⟵ смотри кадр
...
ИТОГ: различаются слайды [12] — открой _render/12_orig.png vs 12_rebuilt.png
```
или при чистой сверке: `ИТОГ: все слайды попиксельно идентичны ✓`.

## 3. Линтер §9 (`_generator/DESIGN.md`, строки 96–105) — список проверок дословно

```
1. 0 нерезолвленных {{...}} в выходе.
2. Каждый data-ill="NAME" имеет файл (illustrations/NAME.* или chapters/ tpl) — иначе битая ссылка.
3. Каждый var(--x) в illustrations/*.svg/grids.css/overlay.css определён в tokens.css
   (неопределённая переменная в SVG → чёрная заливка — известный инвариант канона).
4. 0 внешних asset-URL (src/href на шрифты/js/картинки/css). Ссылки <a href> в контенте — разрешены.
5. Порядок слайдов из brief.md покрывает все content/+slides/; нет сирот/дублей id.
6. (мягко) неиспользуемые illustrations/* → warn.
```
Печатать самопроверку-статистику: слайдов, шаблонов, `class="katex"`, `blur-reveal`, вес КБ
(DESIGN.md строка 105 — в реализации `stats_line()` печатает чуть иной набор чисел, см. §2 выше:
слайдов/иллюстраций/глав/драйверов/sims/КБ, без отдельного счётчика `class="katex"`/
`blur-reveal"` — расхождение спецификации DESIGN.md и текущей реализации `build_deck.py`, не
баг гейта, но стоит знать при чтении вывода).

**Нюанс, сверенный по коду, не по DESIGN.md-тексту:** сам `build_deck.py` (`lint()`, строки
243–305) реализует ещё одну FAIL-проверку, не выписанную отдельным пунктом в тексте DESIGN.md
§9 — **1b**: каждая формула `$tex$` из `content/*.md` обязана резолвиться в
`math/katex.json`, иначе в выходе остаётся `⟦MISSING-MATH:<tex>⟧`, что тоже валит гейт («формула
$%s$ не в math/katex.json (пересобери harvest_katex.py)»). Плюс мягкое предупреждение про
дублирующийся id 3D-главы (build_deck.py строки 296–303), тоже не в списке DESIGN.md буквально.
Список DESIGN.md §9 — контракт верхнего уровня; фактических проверок в коде на 2 больше.

## 4. «Правка в жизни» — пример из `_studio/konvejer/FORMAT-ISTOCHNIKA.md` (строки 59–63)

```
- «убери слово X на слайде N» → правишь content/<id>.md, пересборка меняет одну строку.
- «абзац появляется на 3-й сцене» → {@3} перед абзацем в content/<id>.md.
- «подпись лишняя на рисунке» → правишь illustrations/<NAME>.svg, текст слайда не трогается.
- Пересборка: python3 _generator/build_deck.py <лекция>/src — секунды, копейки токенов.
```
Это и есть операционный смысл всего гейта шага 10: правка — одна строка в одном файле слоя, гейт
(слои 1–5 из `ZAHOD.md` этого шага) — дешёвая машинная проверка, что эта одна строка не сломала
остальные 18–23 слайда, а не построчная пересборка всей колоды вручную.
