# ФОРМАТ ИСТОЧНИКА — как хранится дек (канонический выход фабрики)

> **Когда читать:** любой шаг, который ПИШЕТ в источник (6/7/8/9) или СОБИРАЕТ его (10); проектируешь выход фабрики. · **Что это:** контракт папки `<лекция>/src/` — что где лежит, как называется, почему так, как редактируется. **Фабрика ОБЯЗАНА выдавать ровно этот формат** — иначе теряется дешёвая правка. · **Куда дальше:** генератор — `../../_generator/{DESIGN.md,SLIDE-FORMAT.md,build_deck.py}`; живые образцы — `../../dandelin/src/`, `../../buffon/src/`.

## Принцип (Р1)
Дек хранится НЕ как монолит 2.5–3 МБ, а как **папка-источник** слоями. Генератор `build_deck.py` собирает её в один самодостаточный `dist/index.html` (0 внешних URL). Смысл разбивки — **дешёвая правка**: текст правится в markdown (не в HTML), одна иллюстрация — в своём файле (не читая остальные), палитра/шрифты — в одном месте, вёрстка — отдельный слой. Правка гейтится нормализованной render-identity сверкой с оригиналом. Это и есть «нужный формат», о котором думали при пересборке dandelin/buffon.

## Дерево `src/` — ядро (всегда) + опц. модули-расширения
```
<лекция>/src/
  brief.md          ЯДРО — манифест дека (схема ниже): id, порядок слайдов, provenance, accent_tag
  shablon.html      ЯДРО — 4-блочный каркас канона с плейсхолдерами {{...}}; НЕСЁТ базовый + грид CSS в <style>
  tokens.css        ЯДРО — один :root{…}: ПОЛНАЯ палитра + типо-токены — ЕДИНЫЙ источник стиля
  fonts/faces.css   ЯДРО — 5 @font-face (Forum · Glacial Indifference ×2 · Noto Sans ×2), base64 woff2, дословно
  engine.js         ЯДРО — блок [4] движок, ДОСЛОВНО (не править; патчи уже вшиты при распиле)
  content/<id>.md   ЯДРО — ТЕКСТ слайда (markdown-диалект Р2) — поверхность быстрых правок
  slides/<id>.html  ЯДРО — layout-фрагмент: <section class="slide" data-scenes="N"> с зонами, слотом {{MD:<id>}}, пустыми data-ill боксами
  illustrations/<NAME>.(svg|html)  ЯДРО — по файлу на иллюстрацию (см. конвенции)
  dist/index.html   ВЫХОД — собранный самодостаточный дек (руками не править — баннер «СГЕНЕРИРОВАНО»)
  ── опц. модули (заводятся ТОЛЬКО если нужны) ──
  overlay.css       опц. — второй <style>: акцент-патчи, blur-reveal CSS, KaTeX-стили, точечные #id override. Есть у buffon, НЕТ у dandelin
  math/katex.json   опц. — статический кэш {tex→html} (Р7). Есть у buffon (есть формулы), НЕТ у dandelin (математики нет)
  sims/lab.core.js + sims/ext/*.js   опц. — фреймворк симуляций (canvas). Есть у buffon, НЕТ у dandelin
  chapters/<NAME>.html + drivers/NN.js + lib/three.min.js   опц. — 3D-главы для iframe. Есть у dandelin, НЕТ у buffon
```
Два эталона показывают ортогональные наборы модулей: **dandelin** = 3D-тяжёлый (chapters/drivers/lib, без sims/math), **buffon** = sim+math-тяжёлый (sims/math/overlay, без 3D). Ядро у обоих идентично; `tokens.css` палитрой+типо-токенами идентичен (подтверждает Р8 primitive-слой).

## Манифест `brief.md` — схема
YAML-фронтматтер + прозовое тело (документирует provenance и особенности распила):
```yaml
---
id: <slug>                     # имя дека
title: "<Название>"
canvas: 1440x810               # фиксированный холст канона
provenance: <откуда распилено> # для регрессии; у greenfield-дека — пусто/"greenfield"
provenance_sha256: <hash>      # у greenfield нет — render-identity гейт не применим, только линтер+глаз
milestone: <заметка о стадии>
accent_tag: b | span           # тег для **acc**: b = dandelin, span = buffon (в tokens задан класс .acc)
slide_order:                   # ПОРЯДОК показа — единственный источник истины порядка
  - <id1>
  - <id2>
---
```
`slide_order` обязан ТОЧНО покрывать `content/`+`slides/` — без сирот и дублей (линтер-гейт). `data-skip` на секции = слайд в DOM, но исключён из показа (`.slide:not([data-skip])`).

## Конвенции имён (связывают слои — соблюдать дословно)
- **Слайд:** `id` в `slide_order` ↔ `slides/<id>.html` (`<section id="<id>">`) ↔ `content/<id>.md` ↔ слот `{{MD:<id>}}` внутри слайда. Правка текста → трогаешь только `content/<id>.md`.
- **Иллюстрация:** `data-ill="<NAME>"` в слайде ↔ `illustrations/<NAME>.svg` (вектор) или `<NAME>.html` (растр `<img data:base64>` / плейсхолдер `<div class="ph">`). Генератор эмитит `<template id="ill-<NAME>">` только для используемых `data-ill` (неиспользуемый файл → warn).
- **3D-глава:** `data-iframe="tpl-<NAME>"` ↔ `chapters/<NAME>.html` (полный документ для iframe) + `drivers/NN.js` (анимация сцены, на её месте в главе плейсхолдер `{{DRIVER:NN}}`). Нужен `lib/three.min.js`.
- **Симуляция:** `<canvas data-sim="<KIND>">` ↔ kind в `sims/lab.core.js` или `sims/ext/<KIND>.js`.
- **Формула:** `$tex$` в тексте ↔ запись в `math/katex.json` (печёт `harvest_katex.py`, Р7).

## Плейсхолдеры `shablon.html` (порядок = 4 блока канона)
`{{TITLE}} {{GEN_BANNER}} {{FONTS}} {{TOKENS}} {{OVERLAY}}` · `{{SLIDES}} {{ASSETS}} {{SIMS}} {{ENGINE}}`. 0 нерезолвленных `{{...}}` в выходе = гейт. Базовый + грид CSS **НЕ отдельные файлы**, а живут в `<style>` шаблона (см. расхождение ниже).

## ⚠ Расхождение с `_generator/DESIGN.md §4` — решить
DESIGN.md §4 перечисляет `base.css` и `grids.css` как отдельные файлы источника. **В реальности оба дека их НЕ используют:** базовый CSS канона и пер-слайдовые грид-раскладки лежат дословно в `<style>` внутри `shablon.html` (подтверждено briefs обоих деков, «что НЕ вынесено»). То есть живой формат = грид+база в `shablon`, а `base.css`/`grids.css` — аспирационный контракт, не задействован. **Для greenfield-дека надо решить:** (а) оставить как в эталонах — грид bespoke в `shablon` (рекомендация арки 7, дешевле для распила-регрессии, но каждый новый дек копирует канон-CSS); (б) вынести общий базовый CSS в `base.css` (одна правка на все деки — кандидат вместе с blur-reveal, см. `08-sceny/DOK.md`, вопрос уровня конвейера про `base.css`). Пока не решено — по умолчанию (а).

## Правки в жизни (почему формат такой)
- «убери слово X на слайде N» → правишь `content/<id>.md`, пересборка меняет одну строку.
- «абзац появляется на 3-й сцене» → `{@3}` перед абзацем в `content/<id>.md`.
- «подпись лишняя на рисунке» → правишь `illustrations/<NAME>.svg`, текст слайда не трогается.
- Пересборка: `python3 _generator/build_deck.py <лекция>/src` — секунды, копейки токенов.

## Обязательство фабрики (стык с шагами)
Каждый шаг Фазы II пишет в СВОЙ слой этого формата, не трогая чужие: арка 6 → `content/<id>.md`; арка 7 → `slides/<id>.html` + грид в `shablon`; арка 8 → шорткаты сцен в `content/<id>.md`; арка 9 → `illustrations/*` / `chapters/*`+`drivers/*`. Арка 10 собирает `build_deck.py`-ом и гейтит. **Greenfield-нюанс:** у нового дека нет `provenance_sha256` → render-identity гейт (Р1) неприменим на первой сборке; его заменяют линтер + аудит + глаз (арка 10). render-identity включается со ВТОРОЙ сборки (правка уже собранного дека).
