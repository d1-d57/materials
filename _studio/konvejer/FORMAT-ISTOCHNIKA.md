## Принцип (Р1)
Дек хранится НЕ как монолит 2.5–3 МБ, а как **папка-источник** слоями. Генератор `build_deck.py` собирает её в один самодостаточный `dist/index.html` (0 внешних URL). Смысл разбивки — **дешёвая правка**: текст правится в markdown (не в HTML), одна иллюстрация — в своём файле (не читая остальные), палитра/шрифты — в одном месте, вёрстка — отдельный слой. Правка гейтится нормализованной render-identity сверкой с оригиналом. Это и есть «нужный формат», о котором думали при пересборке dandelin/buffon.

## Дерево `src/` — ядро (всегда) + опц. модули-расширения
```
<лекция>/src/
  brief.md          ЯДРО — манифест дека (схема ниже): id, порядок слайдов, provenance, accent_tag
  shablon.html      ЯДРО — 4-блочный каркас канона с плейсхолдерами {{...}}; НЕСЁТ базовый + грид CSS в <style>
  tokens.css        ЯДРО — один :root{…}: ПОЛНАЯ палитра + типо-токены — ЕДИНЫЙ источник стиля
  fonts/faces.css   ЯДРО — 5 @font-face (Forum · Glacial Indifference ×2 · Noto Sans ×2), base64 woff2, дословно
  engine.js         ЯДРО — блок [4] движок, ДОСЛОВНО (не править; патчи уже вшиты при распиле)
  content/<id>.md   ЯДРО — ТЕКСТ слайда (markdown-диалект Р2). ⚠ ПОРОЖДАЕМЫЙ слой (см. ниже): авторская правка текста живёт в ленте Фазы I, сюда она приезжает
  slides/<id>.html  ЯДРО — layout-фрагмент: <section class="slide" data-scenes="N"> с зонами, слотом {{MD:<id>}}, пустыми data-ill боксами
  illustrations/<NAME>.(svg|html)  ЯДРО — по файлу на иллюстрацию (см. конвенции)
  dist/index.html   ВЫХОД — собранный самодостаточный дек (руками не править — баннер «СГЕНЕРИРОВАНО»)
  ── опц. модули (заводятся ТОЛЬКО если нужны) ──
  overlay.css       опц. — второй <style>: акцент-патчи, blur-reveal CSS, KaTeX-стили, точечные #id override. Есть у buffon, НЕТ у dandelin
  math/katex.json   опц. — статический кэш {tex→html} (Р7). Есть у buffon (есть формулы), НЕТ у dandelin (математики нет)
  sims/lab.core.js + sims/ext/*.js   опц. — фреймворк симуляций (canvas). Есть у buffon, НЕТ у dandelin
  chapters/<NAME>.html + drivers/NN.js + lib/three.min.js   опц. — 3D-главы для iframe. Есть у dandelin, НЕТ у buffon
```
Два эталона показывают ортогональные наборы модулей: **dandelin** = 3D-тяжёлый (chapters/drivers/lib, без sims/math), **buffon** = sim+math-тяжёлый (sims/math/overlay, без 3D). Ядро у обоих идентично; `tokens.css` палитрой+типо-токенами идентичен (подтверждает Р8 primitive-слой).

## Откуда берётся текст: лента Фазы I, а не `src/content/` (решено 27.07.2026)
Шаг 6 переехал в Фазу I и стал **предвёрсточным документом**: тексты ВСЕХ слайдов лежат лентой и читаются сверху вниз одним видом. По отдельным файлам содержание не судится — пролистав пятнадцать файлов, не увидишь, что нарратив провисает между слайдами.
```
<лекция>/raskadrovka/teksty/<блок>.md   ИСТОЧНИК шага 6 — фронтматтер tab/status/poryadok/registr (как у котлов);
                                        раздел `^## ` = слайд, порядок совпадает с раскадровкой;
                                        боковая пометка `> поле:mn **Раскладка.**` у каждого слайда;
                                        <figure>+<figcaption> здесь разрешены — в дек не идут
<лекция>/raskadrovka/teksty/view.html   ВИД — собирается build_doc.py, 0 токенов на пересборку;
                                        это то, что владелец читает целиком и по чему судит
```
**`src/content/<id>.md` — порождаемый слой Фазы II, не место авторской правки.** Из принятой владельцем ленты его механически порождают: раздел `^## ` → файл по своему `id` из `slide_order`, `<figure>`/`<figcaption>` и `поле:mn` снимаются, шорткаты `{@N}`/`{fill@}`/`{blur@}`/`**acc**`/`$tex$` сохраняются как есть (заход — `06-tekst/ZAHOD.md`). Правка текста, начатая в `src/content/`, а не в ленте, будет затёрта следующим порождением и не попадёт в вид, по которому дек принимали.

Гейт на это — **G7** «предвёрсточный документ принят» (`GEJTY.md`); в трекере `sostoyanie.py` он судит именно ленту. Дек, у которого папки `raskadrovka/teksty/` нет вовсе, — не нарушитель: он шёл по схеме до 27.07.2026, и G7 у него `N/A`.

## Манифест `brief.md` — схема
YAML-фронтматтер + прозовое тело (документирует provenance и особенности распила):
```yaml
---
id: <slug>                     # имя дека
title: "<Название>"
canvas: 1440x810               # фиксированный холст канона
provenance: <откуда распилено> # для регрессии; у greenfield-дека — пусто/"greenfield"
provenance_sha256: <hash>      # у greenfield нет — render-identity гейт не применим, только линтер+глаз
milestone: <заметка о стадии>
accent_tag: b | span           # тег для **acc**: b = dandelin, span = buffon (в tokens задан класс .acc)
register: устный | читаемый    # регистр деки — наследуется ВСЕМИ слайдами, на слайде не решается (G5)
word_budget_per_slide: <целое> # бюджет слов на слайд, из регистра: устные ~30-35, читаемые ~45-57 (G5, G7)
# ── служебные слайды: НЕ верстаются, а объявляются полями (раздел ниже) ──
cover_ill: <name>              # опц. — одна иллюстрация обложки (↔ illustrations/<name>.*)
cover_sub: <строка>            # опц. — подзаголовок обложки
cover_date: <строка>           # опц. — дата события
cover_place: <строка>          # опц. — место события
final_ill: <name>              # опц. — одна иллюстрация финала
vizitka: net                   # опц. — ЕДИНСТВЕННЫЙ способ убрать визитку; без поля она есть всегда
slide_order:                   # ПОРЯДОК показа — единственный источник истины порядка
  - <id1>                      # ТОЛЬКО содержательные слайды: обложку, визитку и финал
  - <id2>                      # генератор вставляет сам (см. ниже)
---
```
`slide_order` обязан ТОЧНО покрывать `content/`+`slides/` — без сирот и дублей (линтер-гейт). `data-skip` на секции = слайд в DOM, но исключён из показа (`.slide:not([data-skip])`).

## Три служебных слайда ПОРОЖДАЮТСЯ, а не верстаются (решено 28.07.2026)
Обложка (`sl-title`), визитка «Про меня» (`sl-vizitka`) и финал «Спасибо за внимание» (`sl-thanks`) — **не слой вёрстки**. Рукописных `slides/<id>.html` и `content/<id>.md` для них не существует: генератор строит их из полей выше и канона `../../_generator/skeleton/sluzhebnye/` (`oblozhka.html` · `vizitka.html` · `vizitka.md` · `final.html` · `style.css` + активы визитки, фото и QR). Правка биографии, фото или QR — одна правка в каноне на ВСЕ деки; правка обложки конкретного дека — правка поля в его `brief.md`.

**Нет поля — нет элемента.** Значений по умолчанию нет ни одного, ничего не выводится из `id`/`title`: не объявлен `cover_sub` — подзаголовка на обложке физически нет. Это и есть механика, которой заменена дисциплина «не дописывай на обложку лишнего»: место, куда дописывают, отсутствует.

**Включается плейсхолдером `{{SLIDES}}`** в `shablon.html` — вместо рукописного списка `{{SLIDE:<id>}}`. Поток слайдов = обложка + визитка + `slide_order` + финал, и порядок перестаёт дублироваться в двух местах (хук H6). Второй плейсхолдер, `{{SLUZHEBNYE_CSS}}` в `<style>`, приносит канон-CSS этих слайдов — пер-слайдового грида для них в деке тоже нет. Деки, собранные до перехода (`buffon`, `dandelin`, `fibonacci`), плейсхолдеров не несут и собираются как прежде, байт-в-байт. Если у дека на порождении всё же лежит рукописный служебный слайд — приоритет у него (дек не ломается), а гейт **G12** красит это как долг.

## Конвенции имён (связывают слои — соблюдать дословно)
- **Слайд:** `id` в `slide_order` ↔ `slides/<id>.html` (`<section id="<id>">`) ↔ `content/<id>.md` ↔ слот `{{MD:<id>}}` внутри слайда ↔ раздел `^## ` в ленте `raskadrovka/teksty/`. Правка **вёрстки** трогает только `slides/<id>.html`; правка **текста** идёт в ленту, а `content/<id>.md` пере-порождается.
- **Иллюстрация:** `data-ill="<NAME>"` в слайде ↔ `illustrations/<NAME>.svg` (вектор) или `<NAME>.html` (растр `<img data:base64>` / плейсхолдер `<div class="ph">`). Генератор эмитит `<template id="ill-<NAME>">` только для используемых `data-ill` (неиспользуемый файл → warn).
- **3D-глава:** `data-iframe="tpl-<NAME>"` ↔ `chapters/<NAME>.html` (полный документ для iframe) + `drivers/NN.js` (анимация сцены, на её месте в главе плейсхолдер `{{DRIVER:NN}}`). Нужен `lib/three.min.js`.
- **Симуляция:** `<canvas data-sim="<KIND>">` ↔ kind в `sims/lab.core.js` или `sims/ext/<KIND>.js`.
- **Формула:** `$tex$` в тексте ↔ запись в `math/katex.json` (печёт `harvest_katex.py`, Р7).

## Плейсхолдеры `shablon.html` (порядок = 4 блока канона)
`{{TITLE}} {{GEN_BANNER}} {{FONTS}} {{TOKENS}} {{OVERLAY}}` · `{{SLIDES}} {{ASSETS}} {{SIMS}} {{ENGINE}}`. 0 нерезолвленных `{{...}}` в выходе = гейт. Базовый + грид CSS **НЕ отдельные файлы**, а живут в `<style>` шаблона (см. расхождение ниже).
Живые имена в `build_deck.py` — `{{FONTS_CSS}} {{TOKENS_CSS}} {{BASE_CSS}} {{SLUZHEBNYE_CSS}} {{OVERLAY_CSS}}` · `{{SLIDES}}` **или** пофайловые `{{SLIDE:<id>}}` · `{{ILL:<name>}} {{SIM:<kind>}} {{ENGINE_JS}}`.
⚠ **Плейсхолдер нельзя называть в комментарии** — ни в `shablon.html`, ни внутри вшиваемого файла. Подстановка идёт до неподвижной точки и комментарий не отличает: упоминание `{{SLUZHEBNYE_CSS}}` в шапке самого `sluzhebnye/style.css` воспроизводило себя каждым проходом и валило линтер «нерезрешённый плейсхолдер» (28.07.2026). Пиши имя без двойных скобок.

## Правки в жизни (почему формат такой)
- «убери слово X на слайде N» → правишь **раздел ленты**, пере-порождаешь `content/<id>.md`, пересборка меняет одну строку. Правка прямо в `content/` разъедет дек с видом, по которому его принимали.
- «абзац появляется на 3-й сцене» → `{@3}` перед абзацем: в ленте, если абзац виден владельцу при приёмке; в `content/<id>.md`, если сцена — уже решение Фазы II (арка 8).
- «подпись лишняя на рисунке» → правишь `illustrations/<NAME>.svg`, текст слайда не трогается.
- Пересборка: `python3 _generator/build_deck.py <лекция>/src` — секунды, копейки токенов.

## Обязательство фабрики (стык с шагами)
Каждый шаг Фазы II пишет в СВОЙ слой этого формата, не трогая чужие.
