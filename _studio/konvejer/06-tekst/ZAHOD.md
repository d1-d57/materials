## 1. ДИСЦИПЛИНА (Карпатов)
- **Предпосылка, которая может быть ложной**: раскадровка передаёт регистр+бюджет слов деки ЯВНО. DOK
  прямо помечает это открытым вопросом (арка 5→6 контракт не устоялся). Если раскадровка регистр/бюджет
  не называет — не додумывай молча: зафиксируй допущение в `## ВОПРОСЫ`, возьми консервативный дефолт
  (медиана корпуса ≈45 слов/3 предложения на слайде с иллюстрацией, `text-only` — до ~650 знаков/3
  абзацев, см. DOK), и назови это решение вслух в `## ОТЧЁТ`.
- **Минимум без спекуляций**: ни одного нового факта/числа сверх дистилляции и гибрид-источника;
  формулы — ТОЛЬКО транскрипция уже выверенного `$tex$`, никогда передоказательство, упрощение или
  юникод-приближение.
- **Хирургия**: трогаешь только `content/<id>.md`. Ничего в `slides/`, `illustrations/`, `chapters/`,
  `drivers/`, `sims/`, `engine.js`, `tokens.css`, `fonts/`, `shablon.html`, `overlay.css`,
  `math/katex.json`.
- **Явный запрет (унаследован от DOK «Граница: стиль источника vs слайда»)**: НЕ копировать абзацы
  гибрид-источника на слайд дословно, даже если смысл идентичен, — источник журнальнее и мягче слайда;
  текст слайда всегда переписывается заново через голос корпуса (см. PRIMERY.md).
- **Критерий, который может провалиться**: см. `## 3 → КРИТЕРИЙ ГОТОВНОСТИ` — каждый пункт
  сформулирован так, что честный ответ может быть «нет».
- **Оспорить ложную предпосылку**: если раскадровка на деле подсовывает готовую ПРОЗУ вместо «дистилляции
  смысла» — не переноси её как есть, сожми и перепиши; если иллюстрация уже несёт подпись — не дублируй
  её текстом слайда.
- Сохранять по умолчанию: не переставляй `slide_order`, не переименовывай `id` без крайней необходимости
  (переименование — забота арки 7, не этого захода).
- Субагенты (если сам заводишь параллельные под-проходы по группам слайдов): ≤5 одновременно, рейт-лимит
  = отступить и доложить, не слепой ретрай.

## 2. ГРАНИЦЫ
- НЕ трогать: `slides/*.html`, `illustrations/*`, `chapters/*`, `drivers/*`, `sims/*`, `engine.js`,
  `tokens.css`, `fonts/*`, `shablon.html`, `overlay.css`, `math/katex.json`, `dist/*` (руками). Только
  `content/<id>.md`. `brief.md` — читаешь (slide_order/accent_tag), не пишешь (если структура слайдов
  меняется — сигнал наверх, в раскадровку, не самовольная правка brief).
- `dist/*` можно ПЕРЕСОБРАТЬ генератором (`python3 _generator/build_deck.py <src-путь>`) как визуальную
  проверку своей же работы (см. `## 4`) — это не «трогать руками», это штатный способ проверить рендер.
- Термины: новый/спорный термин — НЕ решай сам, помечай списком для внешнего скилла
  `math-russian-terminology`, вызывать батчем по всей деке (рекомендация DOK, дешевле, чем по слайду).
- Регистр и бюджет слов — НЕ выбираются на слайде, только наследуются от раскадровки/деки целиком.
- `**acc**` — пиши markdown-разметку (0–1 на слайд, экономно), НЕ пиши `<b class="acc">`/`<span
  class="acc">` руками — конкретный тег (`b` или `span`) подставляет генератор из `accent_tag` в
  `brief.md`. Типографское выделение (не смысловой акцент — имя, цифра, ярлык внутри списка) — это
  отдельный случай, escape hatch (`<b>` вручную), не `**acc**` (см. PRIMERY.md, пример vizitka).
- Заголовки — обычным регистром («Введение в графы»), капс — CSS-трансформ сборки, не твоя работа.
- `russian-editor` для стиля слайда НЕ применять (только гигиена опечаток/«ё», не перекрывает голос
  корпуса); `kt-channel-editor` не применять вовсе (другой медиум).

## 3. ЗАДАЧА
На каждый слайд `<id>` (из `slide_order` или из раскадровки): прочитать вход (archetype + дистилляция +
сцены + илл. + унаследованные регистр/бюджет), свернуть дистилляцию в тезис-кандидат на `**acc**`,
выбрать текстовый паттерн по таблице DOK, написать `content/<id>.md` по 8-шаговому алгоритму DOK
(§«Алгоритм: раскадровка → md»), схлопнув reveal-дубли в `{@N}` / `{fill@N|…|…}` / `{blur@N|…}` (см.
PRIMERY.md, пример Б), формулы — `$tex$` из гибрид-источника (см. PRIMERY.md, пример В).

**КРИТЕРИЙ ГОТОВНОСТИ** (проверяемый, способен провалиться — прогнать по каждому файлу, не одной общей
галочкой на весь дек):
1. Каждый `id` из `slide_order`/раскадровки имеет `content/<id>.md` ИЛИ явно помечен в отчёте как
   структурный (без прозы) — с обоснованием архетипом.
2. Гейт «плакатный баланс» DOK (8 пунктов) пройден по КАЖДОМУ файлу отдельно. Не прошёл хоть один пункт
   → шаг назад к выбору паттерна (DOK, шаги 3–4 алгоритма), НЕ точечная правка отдельного слова — это
   петля, а не разовая проверка.
3. 0 финальных точек в конце текстового блока (точки МЕЖДУ предложениями внутри блока — норма).
4. 0 живых reveal-дублей: там, где раскадровка описывает несколько почти одинаковых сцен-слайдов
   подряд, в `content/` они схлопнуты в ОДНУ md-запись со сценами — не воспроизведены как отдельные
   почти одинаковые файлы.
5. Формулы — только `$tex$` (настоящий LaTeX), 0 юникод-приближений (`×`, `÷`, `≤`, `≥`, `π`, `Σ`, `→`
   как голые текстовые символы вместо `\times`, `\leq`, `\pi`, `\sum` и т.п. внутри `$…$`).
6. `**acc**` — 0 или 1 на слайд, не декоративный (на тезис-вывод или вопрос-заголовок целиком).
7. Нет самовольных html-тегов кроме точечного escape hatch (сырой `<b>`/`<br>`/`<span>` только там, где
   формат сам не справляется — см. PRIMERY.md, пример А про `sl-polygons.md`).
8. Нет подписей-описаний иллюстрации («на картинке показано…») ни в одном файле.
9. Список спорных/новых терминов вынесен отдельно в отчёт для батч-вызова `math-russian-terminology` —
   не решён произвольно на месте.
10. Слайды, не влезающие в бюджет после ЧЕСТНОГО сжатия, НЕ уминались шрифтом/потоком — вместо этого в
    отчёте явный сигнал «разделить слайд `<id>`» (решение возвращается в раскадровку арки 5, не решается
    здесь).

## 4. ВЕРИФИКАТОР
Схлопывание reveal-дублей и перенос формул — лоссовые операции (сжатие/синтез входа раскадровки), поэтому
ПЕРЕД отчётом прогони отдельный свежий проход — холодным взглядом (как будто не ты писал текст) или
отдельным субагентом, если доступен инструмент параллельных заходов:
- **Технический слой** (дёшево, механически): пересобрать `python3 _generator/build_deck.py <src-путь>`
  — 0 ошибок генератора/линтера по `content/`, все `{@N}`/`{fill@}`/`{blur@}` резолвятся, 0 нерезолвленных
  `{{...}}`. Это дешёвый гейт ДО смысловой сверки.
- **Смысловой слой**: по каждому `content/<id>.md` — механическая сверка пп. 3, 5, 6, 7 критерия
  (финальная точка, юникод-математика, число `**acc**`, посторонние теги — регексом или глазами) +
  смысловая сверка п. 2 (гейт «плакатный баланс» целиком) и п. 4 (не потерялась ли сцена при
  схлопывании — сверить с исходным списком сцен раскадровки, что каждая сцена входа отражена шорткатом,
  ни одна не выброшена молча).
Результат — по каждому файлу «прошёл / не прошёл + почему», не общий вердикт на весь дек.
