# АЛГОРИТМ ФАЗЫ II — управляющая линия «источник → готовый дек»

> **Когда читать:** гонишь Фазу II (механика: шаги 6→10) на конкретной лекции, или проверяешь, что фабрика склеена в один чёткий алгоритм. · **Что это:** driver-линия конвейера — как Cowork ведёт Claude Code шаг-в-шаг, с гейтами, развилками и точками взаимодействия с владельцем. Детали шага — в его пакете `NN-<имя>/DOK.md`; запуск — `NN-<имя>/ZAHOD.md`. · **Куда дальше:** карта шагов — `00-KONVEJER.md`; формат выхода — `FORMAT-ISTOCHNIKA.md`; дизайн фабрики — `../docs/spravka/ARHITEKTURA-FABRIKI.md`.

Фаза II — АВТОМАТ: индивидуальность автора уже заперта в Фазе I (гибрид-источник + раскадровка). Здесь линия детерминирована — «почти как на Python»: конкретные шаги, жёсткое чтение, ясные развилки, каждый шаг в своём чате Claude Code.

## Модель исполнения (driver)
- **Состояние живёт на диске** (KONSTITUCIYA §8): `<лекция>/src/` (растёт по слоям) + накопленный контекст лекции (гибрид-источник арки 4, раскадровка арки 5). Между шагами контекст НЕ держится в памяти — каждый шаг стартует с пустого контекста и читает названное.
- **Один шаг = один чат Claude Code.** Из Cowork показываешь ему `konvejer/NN-<имя>/ZAHOD.md`; он читает свой `DOK.md` + `FORMAT-ISTOCHNIKA.md` + `PRIMERY.md` + накопленный контекст, делает шаг, пишет в СВОЙ слой `src/`, отдаёт отчёт.
- **Cowork судит по гейту** (не построчно), двигает дальше или возвращает на точечную дочистку. Развилку, требующую вкуса, поднимает владельцу.

```
# драйвер Фазы II (псевдокод)
state = <лекция>/src/                      # + гибрид-источник, раскадровка как контекст
assert precondition_phase2(state)          # вход Фазы II готов (см. ниже); иначе → Фаза I
for step in [6, 7, 8, 9, 10]:              # 9 может идти параллельно 8 (см. DAG)
    assert precondition(step, state)       # нужные слои на месте; иначе стоп → предыдущий шаг
    chat = open_claude_code()              # свежий пустой контекст
    feed(chat, f"konvejer/{step}/ZAHOD.md")
    run(step)                              # пишет в свой слой src/, не трогает чужие
    for fork in forks(step):               # напр. SPLIT слайда, 3D-vs-SVG, регистр
        if fork.needs_taste: ask_owner(fork)   # точка взаимодействия
        else: decide_by_criterion(fork)        # по правилу из DOK
    if not gate(step).passed:              # критерий-который-может-провалиться из ZAHOD
        fix_in_place() or back_to(step or upstream)   # ПЕТЛЯ, не вперёд
    snapshot(state)                        # точка отката (git), сверка после
# выход: шаг 10 собрал dist/index.html + прошёл 5 слоёв гейта
```

## Вход Фазы II (стык с Фазой I — precondition)
Фаза II стартует, когда раскадровка (арка 5) оставила в `<лекция>/src/`:
- **канон-скелет** (замороженный канон): `shablon.html` · `engine.js` · `tokens.css` · `fonts/` — скопирован из скелета (см. «Стыки», ниже);
- **`brief.md`**: `id`, `title`, `canvas 1440x810`, `accent_tag`, `slide_order`, **регистр + бюджет слов деки** (устный/читаемый — критично для шага 6);
- **`slides/<id>.html`** — рамочные каркасы (архетип, зоны, пустые `data-ill`) — из раскадровки (кликабельное HTML-демо, `FAZA-1-BLUEPRINT`);
- **`illustrations/<name>`** — плейсхолдеры `<div class="ph">` с описанием + числом сцен;
- накопленный контекст: **гибрид-источник** (арка 4) — откуда шаг 6 берёт `$tex$` и смысл, шаг 9 — 🖼-описания.

Гейт входа: `slide_order` покрывает `slides/`; на каждый прозаический слайд есть каркас; регистр+бюджет заданы. Нет — вернуться в Фазу I (раскадровка не закрыта).

## Линия шагов (DAG: 6 → 7 → 8, 9 ∥ 8, → 10)
Для каждого шага: **вход · действие(→DOK) · выход(слой формата) · гейт · развилки/чекпоинты**. Полный контракт — в `NN/DOK.md`.

**6 · Текст** (`06-tekst/`). Вход: раскадровка (архетип+смысл+сцены+илл.) + регистр/бюджет + гибрид-источник. Действие: плакатный текст со шорткатами Р2. Выход: `content/<id>.md`. Гейт: «плакатный баланс» (8 пунктов). Развилки: не влезает после честного сжатия → **сигнал SPLIT наверх, в раскадровку** (чекпоинт владельцу); регистр/бюджет не переданы → **чекпоинт**. Внешнее: термины → `math-russian-terminology`.

**7 · Вёрстка** (`07-verstka/`). Вход: `content/<id>.md` (шаг 6) + описания илл. + архетип. Действие: грид канона, зоны, `data-scenes="N"`, слот `{{MD:<id>}}`, пустые `data-ill`. Выход: `slides/<id>.html` + пер-слайд грид в `shablon.html`. Гейт: 0 overflow, `--t-body` не уменьшен, палитра из `:root`, глаз. Развилки: переполнение → порядок починки → не влезло → **SPLIT слайда** (`<id>b`; трогает `slide_order` → чекпоинт). Грид bespoke (не общие классы).

**8 · Сцены** (`08-sceny/`). Вход: `slides/<id>.html` с финальной геометрией + `content/<id>.md`. Действие: шорткаты `{@N}`/`{fill@N}`/`{blur@N}` в `content/<id>.md`; **сверить/поправить `data-scenes` в `slides/<id>.html`** (генератор его НЕ считает — слой арки 7). Выход: разметка сцен. Гейт: нет дед-кликов, связка вне блюра, геометрия заморожена. Развилки: нет `overlay.css`/blur-CSS на новом деке → **стоп+вопрос** (или из `base.css`, если решено).

**9 · Иллюстрации** (`09-illustracii/`, ∥ 8). Вход: плейсхолдеры + 🖼-описания + число сцен от шага 8. Действие: заменить плейсхолдер, сохранив stem/id. Выход: `illustrations/*` (SVG/растр) или `chapters/*`+`drivers/*` (3D). Гейт: `var(--x)` определён (иначе чёрная заливка), SVG не переполняет, per-file id-prefix. **Развилка (4 ветки):** статичная схема→SVG · плоский интерактив→lab.js · 3D-объект→`threejs` (standalone-first) · готовый растр→код/`images.md`. **3D дорог → чекпоинт перед постройкой.** Внешнее: 3D→`threejs`, код.

**10 · Сборка + QA** (`10-sborka-qa/`). Вход: заполненная `src/`. Действие: `build_deck.py <src>` + аудит. Выход: `dist/index.html` самодостаточный. Гейт (5 слоёв дёшево→дорого): линтер → render-identity (**только для правки; greenfield — N/A**) → аудит → scene-diff → глаз. FAIL → назад на виновный шаг. Стоп-до-цели: render-identity неприменим к первому greenfield-деку — замена = линтер+аудит+глаз.

## Развилки и чекпоинты — «что не продолбать» (сводка)
- **Владельцу (вкус):** SPLIT слайда (6/7 — меняет число/порядок слайдов); постройка 3D (9 — дорого); отсутствие регистра/бюджета (6); отсутствие blur-CSS на новом деке (8).
- **Автономно по правилу (из DOK):** выбор архетипного паттерна текста (6); порядок починки переполнения (7); ветка иллюстрации по критерию «убрать глубину — понятно?» (9); порядок 5 слоёв гейта (10).
- **Жёсткие «не продолбать»:** `--t-body` не уменьшать (7); связка вне блюра (8); `var(--x)` определён/токенами, не hex (9); `data-scenes` сверить руками — автоподсчёта нет (8); render-identity только для правки, не greenfield (10).
