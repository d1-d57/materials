# RUKOVODSTVO-zahodami — как вести исполнителя (заход + приёмка)

> **КОГДА читать:** когда готовишь заход исполнителю (субагент через Agent tool или Claude Code). · **ЧТО дописывать сюда:** только методологию захода. · **КУДА дальше:** `ARKA.md §5`.

## Единственный принцип
**Состояние живёт на диске (доки проекта + файл-заход), не в памяти сессии.** Исполнитель стартует с ПУСТЫМ контекстом. Отсюда: заход **самодостаточен** (вход, что прочитать, что сделать, как отчитаться — внутри текста), **один заход = одна задача**, durable — сразу в дома.

## Заход — дай всё, иначе соберёт не то
- Несёт ВСЁ: рабочая папка, что прочитать ПОИМЁННО, что сделать, границы, как отчитаться. Явно: «читай только названное, проект не изучай».
- Существующие конвенции и имена — **авансом** → переиспользует, не изобретает своё.
- **Дизайн-канон — авансом (HTML-заход).** Дай исполнителю дизайн-систему деки: `tokens.css` (палитра), правило акцента (канон: Bold + ОДИН охряный `.acc`, не свой цвет), словарь вёрстки/архетипов (`../../konvejer/07-verstka/DOK.md`), сцен-контракт — ИЛИ явный указатель на канон (`konvejer/07,08,09`, `RESHENIYA Р23/Р24`). Не дал — исполнитель переизобретёт свой стиль. *Прецедент #14: канон не отдан явно → розовые акценты вместо охры, монотонная вёрстка.* Для формат-чувствительного дека — ОДИН короткий контракт формата авансом (не «прочитай 01–10» россыпью), и НЕ делай таст/вёрстку ХВОСТОМ длинного автономного прогона: формат заслуживает свежего окна (прецедент #14 — дек собран последним, в измотанном контексте, формат уехал).
- **Канон разметки — авансом и для DOC-захода, не только для HTML.** Исполнителю, который пишет текст под `build_doc.py`, дай ПОИМЁННО `STANDART-oformlenia.md` (типы блоков, конвенция слитного блока, списки) и `STANDART-teksta.md`. Не дал — он пишет «по общему markdown», а движок понимает не общий markdown. *Прецедент `vidy-obzor`: конвенция слитного блока в каноне БЫЛА — и была нарушена, потому что заход её не назвал: тела девяти типизированных блоков, включая формулы из определений, вывалились из врезок. Оба машинных гейта при этом зелёные (слепая зона объявлена — `STANDART-oformlenia §7½`), увидел владелец глазами по скриншоту. Стоило: полный круг правок плюс чтение исходника движка.*
- **Текст — готовым, не импровизацией сборщика.** Плакатный текст пишет текст-стадия (арка 6 / Cowork в голосе корпуса `content-studio/assets/corpus/texts-corpus.md`); HTML-исполнитель ставит его ДОСЛОВНО, своей прозы не пишет. Формальные формулировки (задача/определение) — из первоисточника дословно. *Прецедент #14: сборщик писал текст сам → не в авторском голосе.*
- Есть ошибка/лог — вкладывай RAW и «почини», НЕ пересказ (пересказ теряет деталь).
- **🔴 КРИТЕРИЙ ГОТОВНОСТИ — ГЕЙТ. Гейт, который не может провалиться, — не гейт. Три клаузы, все обязательны:**
  1. **Называет АРТЕФАКТ, КОТОРЫЙ ПОКРАСНЕЕТ.** «Проверь внимательно», «дыры названы аккуратно», «я закончу» — пожелание. «N файлов на местах, битых ссылок 0», «`--gates` печатает ❌», «каждая ✅ несёт id поставщика + номер лекции, арифметика — скриптом» — гейт.
  2. **Отрицательный вердикт несёт ОХВАТ В СЕБЕ**, не в примечании. «Дыр не найдено» и «дыр не найдено **на 2 лекциях из 9**» выглядят одинаково и читаются как первое. Требуй строку «проверено X из Y» внутри самого вердикта.
  3. **Чекер честно печатает, чего он НЕ проверяет** (образец — `../../../_generator/tools/check_kartoteka.py`). Зелёный чекер с необъявленной слепой зоной опаснее красного: ему верят.
  *Цена клауз 1–2 — контраст на ОДНОЙ арке, ОДНА модель (Opus), два исхода. Ход 7, критерий «каждая 🔴 ДЫРА называет место в курсе»: дыр не нашли — критерий не сработал ВООБЩЕ, а вердикт «дыр нет» на деле означал «проверено 2 лекции из 9» и читался как «все девять». Ходы 8 и 12, критерий «каждая ✅ несёт id поставщика + номер лекции, арифметика — скриптом»: нашлись 2 настоящие дыры, гейты закрылись 9/9 впервые за двое суток. **Разница не в исполнителе — в том, что второй критерий проверяет МАШИНА.** Цена клаузы 3: тупой греп родов поймал дыру, которую три умных прохода не увидели, — но сам был слеп в разметке (5 понятий курса без рода `понятие`; на Л1 прокси видит 1 карточку из 14), а `seed` в роде `пример` не печатался нигде — из-за чего файл ГОД врал «кандидатов нет» при трёх живых.*
- **Визуальный гейт — host-side, не в песочнице (прецедент #15).** Машинные гейты (линтер, `verify_models`) ловят структуру и математику, но НЕ вид/интерактив. Браузера в песочнице Cowork нет (CDN Chromium заблокирован) → визуал правится вслепую и помечается; `_generator/render.py` (PNG кадров) + `_generator/audit.py` (overflow/палитра/floor/fit — НАПИСАН, нужен браузер) гоняет host (владелец / host-заход, там Chrome). *Прецедент #15: зелёные машинные гейты ≠ визуально готово; без визуального гейта фаза ревью-петли доминирует по стоимости (~5 кругов доводки Фибоначчи). Интерактив/визуал прозой недоспецифицируем → якорь на рендер/референс-слайд ДО тиража.*
- **Флаг «стоп до цели».** Если заход по замыслу останавливается ДО ожидаемого владельцем результата — скажи это громко и заранее одной фразой («получишь X, но НЕ Y; Y запускается так-то»).
- **Заход проверяет ГИПОТЕЗУ САМОГО аналитика → впиши «не подыгрывай» (прецедент teorkat, 2026-07-16).** Две ловушки, и заход опасен с обеих сторон — назови ОБЕ явно, иначе получишь уверенный отчёт ни о чём.
  - **Аналитик — заинтересованное лицо.** Ему приятно, если гипотеза подтвердится, и услужливый исполнитель её подтвердит. Формулировка в заход: «**опровержение — полноценный успех**, оно спасает от постройки на песке; "источник не отвечает" — законный исход, если сказано, чего именно не хватает; **брак — только выдуманный вердикт**».
  - **Форма источника ≠ существо предмета.** Учебник показывает СВОЙ вход и молчит про остальные — не потому, что других нет, а потому что у него уже всё на столе. *Прецедент: CCC определяется через сопряжения (Маклейн §4.6) И через evaluation map без единого функтора (Ловер, Awodey) — один предмет, два входа. Заход, читающий параграф внутри главы «Сопряжения», обязан различать «автор ГОВОРИТ адъюнктно» и «определение их ТРЕБУЕТ».* Вопрос ставить как «**что предмету НУЖНО**», а не «как делает автор», и ловушку назвать в заходе поимённо, с требованием отчитаться: поддался или нет.
  - *Почему:* исполнитель с пустым контекстом не знает, что вердикт кому-то выгоден, и не видит, что структура книги — это выбор автора, а не свойство математики. Обе ошибки дают отчёт, который читается как находка.
- **🔴 ГЕЙТ ВХОДА — прогони СВОЙ вход по четырём вопросам ПЕРЕД выдачей захода.** Общий дефект: аналитик проверяет, что ссылка СУЩЕСТВУЕТ, но не что лежащее по ней ТОЖДЕСТВЕННО задаче.
  1. **Издание/версия актуальны?** 2. **id/имя указывает на ТО САМОЕ?** 3. **ЗОНА содержит файл, в котором лежит ответ?** — самый дорогой вопрос. 4. **Предпосылка жива?** — сверь по ЖИВОМУ файлу, включая свою; трогает заход только что закрытое — пометь «уже закрыто: проверить зелёным, не открывать заново».
  *Цена: пять дефектных входов за двое суток; все пять заход спас САМ (потому и жив — см. `../KONSTITUCIYA.md §11` о пустом контексте). Smith 2-е издание вместо 3-го — а заход МЕРИЛ порядок глав, который во 2-м «significantly rearranged» · неверный arXiv-id (дан «Ologs» вместо нужной работы) · имя файла врало («…for-the-sciences.pdf» при содержимом «for Scientists») · **зона без `kartoteka/**` при задаче «найди молчаливые опоры» отсекла ровно тот файл, где они живут — §2.3 выполнен на 2 лекциях из 9** · ложный поставщик (назван узел Л9 вместо Л3 — при том что ловушку «поставщик есть, но ПОЗЖЕ» аналитик сам вписал в тот же заход, на той же странице) · стале-предпосылка: заход сказал «TERMINY — открыт спор о владении», хотя шапка файла уже говорила «решено, файл аналитика»; исполнитель честно отступил по ложной предпосылке, и долг терминов завис ВТОРОЙ заход подряд из-за аналитика.*
- Лоссовый/двигающий заход → встрой верификатор (ниже).

## Зона изменений и git — коммить ТОЛЬКО своё

> 🔴 **Вся git-механика переехала в единственный дом — `GIT-disciplina.md`.** Здесь остаётся только то, что относится к УСТРОЙСТВУ захода; локи, форма коммита, `--no-optional-locks`, worktree, «кто коммитит» — там, и правятся ТОЛЬКО там. *Почему переехало: до 21.07 git-правила жили в шести местах и противоречили друг другу (напр. «НИКОГДА `add` → `commit`» против рабочего инструмента, который делает именно это).*

- **КОНТРАКТ ЗОНЫ — ОБЯЗАН быть в КАЖДОМ заходе Claude Code (требование владельца 2026-07-11). Без него заход НЕполон — не запускать.** Вписывает его COWORK генератором, не руками: `python3 ../../../_generator/tools/bootstrap_zahod.py <арка> <тема> --branch <ветка> --zone "<пути>" [--worktree <имя>]` создаёт `kod_<тема>.md` из `../../zhurnal/_TEMPLATE-zahod.md` с уже вшитым контрактом (`--branch`/`--zone` обязательны). **`--worktree` — если заход идёт ПАРАЛЛЕЛЬНО другому** (`GIT-disciplina.md §4`): генератор заводит рабочую папку и вписывает `cd` вместо `git checkout`. Cowork дозаполняет только `<...>`. Блок «место · зона · коммит · запрет»:
  - **МЕСТО** — worktree-папка (параллельный заход) ИЛИ ветка в основной папке (одиночный). Развилку решает генератор, в заход уходит ОДИН вариант — исполнитель с пустым контекстом гадать не должен. Ветку он НЕ переключает сам: назвали неверно → СПРОСИ.
  - **ЗОНА** — явный перечень путей, которые МОЖНО менять (обычно ОДНА папка проекта + свой дневник). Всё вне — **READ-ONLY**: не править, не двигать, не удалять, не рефакторить «заодно».
  - **КОММИТ** — свою зону, форма и «кто коммитит» — `GIT-disciplina.md §3`. Субагенты НЕ коммитят: только ведущий заход, только свою зону.
  - **ЗАПРЕТ** — ничего за пределами зоны, даже если «мешает». Нашёл проблему вне зоны → в отчёт, не трогай.
- **Аналитик — ТОЖЕ параллельный писатель, и его зона тоже должна быть названа.** Правишь доки, пока идёт чужой прогон, — объяви свою зону прямо в тексте захода («файлы X, Y правлю я — не трогай»). *Цена одолжена у инцидента 2026-07-11: параллельный прогон расщепил работу по двум коммитам.*
- **Разделение по зонам:** общую документацию правит Cowork; HTML/код — только код-заход в своей папке; никто не лезет в чужую зону.
- **Приёмка «работа доехала в git» — гейт 0, `git_zona.py check --zone <зона>` первым ходом** (`§Приёмка` ниже; полностью — `GIT-disciplina.md §2`).
## Субагенты — аккуратный режим
Вложенные — можно ОСМЫСЛЕННО и по плану, не случайный рой. Fan-out ≤~5 параллельно (крупную пачку — в очередь). Рейт-лимит = отступить и доложить, НЕ слепой ретрай. Назвать ЯВНО: сколько субагентов и на что. Дешёвое/механическое/параллельное — дешёвым моделям; тяжёлое суждение — сильной. Метрика — стоимость за успешный РЕЗУЛЬТАТ, не за токен.

**🔴 Время ожидания меряй `date`, а НЕ суммой своих `sleep`.** Статуса живого субагента исполнитель не видит, читать его лог запрещено (переполнит контекст) — остаётся косвенное измерение, и оно систематически завышает: номинальная сумма `sleep` набегает вдвое быстрее стенных часов. Отсюда два правила: **отступать от живого субагента только по ВНЕШНЕМУ признаку** (рейт-лимит, ошибка, явный отказ), а не по ощущению «долго»; **отступил и написал запасную версию — при возврате субагента ОБЯЗАН сверить и переписать**, а не оставить первую редакцию. *Цена: поисковый субагент работал 26 минут; исполнитель насчитал по `sleep` 43 минуты при 24 реальных, счёл его зависшим и отступил ЗА 7 МИНУТ ДО ФИНАЛА. Беглый запасной поиск дал §C с вердиктом «устоявшегося названия не нашёл» — вердикт ОШИБОЧНЫЙ (имена есть: Implicit Species Theorem; canonical fixed point локально сжимающего функтора). Полный результат пришёл через несколько минут, §C переписан целиком: ~15 минут и один лишний прогон поиска. Спасло только то, что исполнитель сверил, а не оставил.*

## Модель в заход (первой строкой) и запуск
**Дефолт — Sonnet.** Opus — только когда рассуждение рождается В ХОДЕ исполнения (не то, что Cowork уже расписал заходом).

| Тип захода | Модель |
|---|---|
| Исполнительный, полностью расписанный (якорные замены, вставки, renumber, рендер/сборка, линтер) | **Sonnet** — механика; abort+верификатор ловят сбой |
| Исследовательский/неоднозначный («разберись и почини» без готовых якорей) | **Opus** — план рождается по ходу, меньше ретраев |
| Смешанный | план на Opus, механику на Sonnet (`opusplan`) |

Чем детальнее заход (точные якоря, критерий, границы), тем увереннее Sonnet — хороший заход удешевляет модель. Бюджет душит не 5-часовое окно, а **недельные капы** (проект из многих прогонов) → тиринг моделей + не разводить рой субагентов.

🔴 **Стартовое сообщение НЕ пишется по памяти — его ПЕЧАТАЕТ `bootstrap_zahod.py`.** Скрипт уже знает модель (`--model`), ветку и абсолютный путь, поэтому выдаёт готовый блок сразу после генерации захода: Cowork копирует, а не сочиняет. **Заход считается сданным владельцу только вместе с этим блоком.**

*Почему так, а не «правилом»: формулировка ниже жила в каноне с самого начала — и 21.07 аналитик дважды подряд собрал стартовое сообщение без строки «Модель», просто не открыв этот параграф. Правило было записано и не сработало; поймал владелец. `KONSTITUCIYA §11`: правило, которому нечему покраснеть, — надежда. Здесь вместо гейта убрано место для ошибки — как со счётчиками, где число заменили командой.*

**Стандартный текст запуска (владелец → Claude Code; ПОЛНЫЙ путь + модель первой строкой):**
```
Модель: <Sonnet | Opus> — <одна фраза почему>.
Claude Code, твой заход — файл <ПОЛНЫЙ_АБСОЛЮТНЫЙ_ПУТЬ>/kod_<тема>.md. Прочитай ТОЛЬКО его и то, что он называет; остальной проект не изучай. <Точка отката: git-коммит / zip-бэкап сразу.> План/вопросы/отчёт пиши в этот же файл внизу (## ПЛАН / ## ВОПРОСЫ / ## ОТЧЁТ). Ничего сверх задачи не трогай.
```

## Термины — глоссарий держит АНАЛИТИК, исполнитель сдаёт хенд-оффом (решение владельца 2026-07-17)

**Правило (у проекта с глоссарием — напр. `<курс>/spravochnik/TERMINY-russkie.md`):**
1. **Термин ищем, только если его НЕТ в глоссарии.** Глоссарий выше веба; веб — только для отсутствующего. **Нашёл — сразу дописал строку.** *Почему:* иначе один и тот же термин ищется по десятому разу, и каждый раз заново.
2. **Пишет в глоссарий тот, кто им занимается.** По умолчанию это **аналитик**: глоссарий — гейт финального текста, его держит тот, кто текст выдаёт.
3. **Исполнителю Code в глоссарий НЕ писать; из зоны захода TERMINY исключать ЯВНО.** *Почему:* (а) гонки записи — 17.07 исполнитель обнаружил в файле несохранённую live-правку аналитика и правильно отступил; (б) исполнитель не должен вылезать в документацию.
4. **Взамен — перенос термина есть ШАГ ПРИЁМКИ, тут же.** Термины — частный случай хенд-офф-долга; правило и его цена — в §Приёмка шаг 2, здесь не повторяются.
5. **Гейт терминов начинать с грепа полнотекстового источника проекта, а не с веба** — дешевле и авторитетнее. ⚠ Но `grep = 0` **не доказывает отсутствия** (см. врезку ниже).

## ⛔ ГРЕП ПО КОРПУСУ ДОКАЗЫВАЕТ ПРИСУТСТВИЕ, НО НЕ ДОКАЗЫВАЕТ ОТСУТСТВИЕ (2026-07-17)

**`grep = 0` в PDF-корпусе не значит ничего.** Текстовый слой ломает искомое тремя способами — все три пойманы на живых файлах:

| Поломка | Пример |
|---|---|
| **OCR греческих букв** | «π(X)» читается как «7г(Х)» (рус. Маклейн) — три захода грепали мимо |
| **Разрядка** | имя студента у Ловера набрано `d a n i l o` — греп по `Danilo` = 0 |
| **Перенос строки** | у Awodey «A natural\nnumbers object» — греп по фразе на странице = 0 |

**Цена уже заплачена:** дайджест волны 1 записал «у Ловера NNO нет» на основании `грep("natural numbers object") = 0`. **Ложь** — предмет есть, в Part III, до всяких УС, и это самый дешёвый вход из четырёх источников. Заход, посланный искать NNO, ходил мимо якоря №1 проекта.

**⇒ В КАЖДЫЙ заход:** отрицательный вывод «в источнике этого нет» обязан опираться на **чтение оглавления/раздела глазами**, а не на греп. Греп — разведка «где смотреть», не доказательство.

## Приёмка отчёта — ЖЁСТКИЙ РИТУАЛ (каждый раз, когда пришёл отчёт от исполнителя)
Неважно, как оформлен отчёт и какими словами владелец сказал «пришёл отчёт / прими». ВСЕГДА, по порядку — пять шагов:
0. **🔴 ГЕЙТ «РАБОТА ДОЕХАЛА В GIT» — ПЕРВЫМ, ДО ЧТЕНИЯ ОТЧЁТА.** Гоняет Cowork САМ, одной командой, на живых файлах:
   ```
   python3 _generator/tools/git_zona.py check --zone <зона захода>
   ```
   Красный (exit 1) → **отчёт не принимается**, что бы в нём ни было написано. Исполнитель обязан либо закоммитить свою зону, либо назвать ВНЕШНЮЮ причину отдельной строкой отчёта («коммита нет, причина такая-то, нужно ваше действие»). Молчаливое «сделано» при грязной зоне — брак.
   *Почему гейт стоит ДО отчёта, а не среди прочих: «файл написан» и «файл в git» — разные состояния, и второе не проверял никто. За одну сессию арки `mat-kostyak` работа не доехала ТРИЖДЫ; в Ф2 исполнитель закоммитил, в Ф2.1 забыл — и это всплыло только на приёмке. Гейт в `ARKA §6` (хэндофф чат→чат) срабатывал СЛИШКОМ ПОЗДНО: между заходом и хэндоффом успевало пройти несколько заходов.*
   ⚠ **Никаких голых `git status` из Cowork.** Обычный `git status` переписывает индекс и берёт `.git/index.lock` — тем самым роняет ручной коммит владельца. Все git-вызовы `git_zona.py` идут с `--no-optional-locks`; свои разовые — тоже. *Цена: три сорванных коммита за одну сессию, причём ронял их ровно тот гейт, который проверял, что работа доехала.*
1. **Гейты (все обязательны).** Критерий выполнен · **хэш коммита в отчёте есть и он существует** (`git --no-optional-locks show --stat <хэш>`) · числа сходятся · границы соблюдены · **SPEKA соблюдена** (охват полон, формат-отклонения выдержаны — для курс-проекта) · решения обоснованы · вопросы исполнителя разобраны · верификатор/регрессия зелёные · **время + токены** · **нет тихого недобора** (стоп до цели заявлен громко). Объективные гейты (линтер/верификаторы/зона коммитов) Cowork перегоняет САМ на живых файлах, не на слово. Отчёт может долетать МИД-ФЛАЙТ (на диске — только точка отката) → перечитай живое состояние (git/диск) перед вердиктом. Токены среда могла не отдать — раскрытая деталь, не нарушение. Санити дешёвый (`tree`/`grep`), не построчно. Дисциплинированное НЕ-действие — ХОРОШО. Вердикт: **принять** ИЛИ **вернуть на точечную дочистку**. Вопрос без ответа → в начало следующего захода.
2. **🔴 Запись — и ЗАКРЫТИЕ ХЕНД-ОФФ-ДОЛГА ТУТ ЖЕ, не «потом».** Вся новая информация (решения, находки, отклонения, вопросы, помарки) → в документы СРАЗУ (дневник арки; при закрытии — durable по домам). «Осталось только в чате — потеряно.»
   **Хенд-офф-долг — общий закон, а не частность терминов.** Контракт зоны запрещает исполнителю писать в чужой дом ⇒ он сдаёт находку хенд-оффом ⇒ **перенести обязан аналитик, ТЕМ ЖЕ ходом. Отложил = потерял.** Четыре дома, четыре одинаковых провала за сутки:

   | Дом | Что сдаётся | Цена |
   |---|---|---|
   | глоссарий (`<курс>/spravochnik/TERMINY-russkie.md`) | термины из разведки | два захода подряд копили, аналитик не переносил. ⭐ Когда перенёс — глоссарий **поймал ДВЕ кальки на пути в письмо заказчику** («эквалайзер» вместо «уравнитель», «комма-категория» вместо «категория запятой») |
   | владелец | вопросы исполнителя | 8 накопилось в `kod_*.md` — **0 дошло, 6 протухло**. Владелец файлы-заходы не читает **ПО УСТРОЙСТВУ** |
   | `istochniki/MANIFEST` · `SPISOK-skachat` | найденные источники | 8 книг лежали невлитыми |
   | канон фабрики | уроки о самой фабрике | **17 секций «→ фабрика» за сутки, дошла ОДНА** (§Хук ниже) |

   ⇒ Прежняя формулировка «иначе термин потерян» **СЛАБЕЕ правды**: не потерян — **уехал наружу в виде кальки**. Перенос термина — **гейт исходящего текста, а не учёт**.
   **Проверка шага (может провалиться):** в отчёте есть слово «термин» → в глоссарии появилась строка? есть вопрос владельцу → он ЗАДАН владельцу, а не оставлен лежать в файле-заходе? найден источник → он в `MANIFEST`? Нет — шаг не закрыт.
3. **Пересказ человеческим языком.** Владельцу, простыми словами, максимально понятно: что сделано, что обнаружено, что осталось. НЕ прятать в термины, НЕ пропускать — это частая ошибка.
4. **Рефлексия (короткая, ВСЕГДА).** После реакции владельца Cowork САМ спрашивает: «что здесь было не так и что можно поправить — в заходе / процессе / фабрике?». Не ждать, пока попросят.
5. **Хук «→ фабрика» — ОДНА строка в `UROKI-FABRIKE.md` арки: факт + ЦЕНА. НЕ правка канона** (§Хук ниже: править канон посреди приёмки дорого — потому этого и не делали).

## Хук «→ фабрика» — почему трёх хуков было мало и что вместо них

**Факт, из которого это правило выросло: у фабрики было ТРИ хука «→ фабрика» (после отчёта · хэндофф · закрытие арки). За трое суток они сработали ~1 раз из ~12 возможных — написано 17 секций «→ фабрика», до канона дошла ОДНА.** Проверяется в две команды: `grep -rn "<формулировка урока>" _studio/docs/` (0 файлов) и `git log --since=<начало арки> -- _studio/docs/` (один коммит за трое суток, и не про уроки).

**Три хука доставили меньше, чем один.** Каждый был диффузией ответственности («поймает следующий»), и каждый требовал ДОРОГОГО действия — консолидирующей правки канона — в момент, когда занят другим. Дорогое пожелание не исполняется никогда. «Сделать хуки жёстче» — это то же правило-пожелание в четвёртый раз (`../KONSTITUCIYA.md §11`), поэтому механизм разнесён ПО ЦЕНЕ:

| Когда | Что ДЕЛАЕТСЯ | Цена действия |
|---|---|---|
| **исполнитель, по ходу захода** | секция `## УРОКИ ФАБРИКЕ` в СВОЁМ `kod_<тема>.md` (вшита `bootstrap_zahod.py`): факт + `ЦЕНА:`. **Пишет сам — переносить аналитику не надо** | 0 |
| **после каждого отчёта/хода** (бывш. хук A) | ОДНА строка в `UROKI-FABRIKE.md` арки: **факт + ЦЕНА** (что сломалось и сколько стоило). Не формулировка закона и не правка канона | ~минута |
| **конец сессии** (бывш. хук B) | **ничего отдельного — хук УДАЛЁН.** Он дублировал A и создавал иллюзию второго шанса | 0 |
| **закрытие арки** (бывш. хук C) | **ОТДЕЛЬНАЯ сессия с ПУСТЫМ контекстом:** читает только `UROKI-FABRIKE.md` + канон, выносит вердикт по КАЖДОМУ уроку, правит канон **КОНСОЛИДИРУЯ** (удалить/слить/переписать — можно; терять накопленное и плодить свалку — нет) | сессия |

**Почему вердикт выносит не тот, кто урок записал.** Автор уроков — **лицо заинтересованное**: ему приятно, если его формулировка станет законом, и красивый заголовок от него подозрителен by design. Из механизмов, которые за арку реально ловили аналитика, самый надёжный — **вынос задачи исполнителю с пустым контекстом** (поймал дважды подряд). Поэтому в файл пишется ФАКТ и ЦЕНА, а ЗАКОН формулирует свежая сессия. **Отбраковать слабый урок — результат сессии, а не её провал:** девять законов, вписанных плохо, хуже трёх, вписанных точно, — канон читают ВСЕ будущие проекты, и плохое правило тиражируется.

**Почему исполнитель пишет САМ, а не сдаёт хенд-оффом.** Прежняя цепочка «исполнитель → `## ОТЧЁТ` → аналитик переносит» — это хенд-офф-долг, тот самый, что дал 0/8 по вопросам и 1/17 по урокам. Звено убрано: `kod_<тема>.md` **уже в зоне исполнителя** (проверено по живым заходам, а не по прозе канона), так что писать туда он вправе без расширения зоны и без гонок с параллельными заходами. И пишет тот, у кого ПУСТОЙ контекст, — единственный, кто за арку ловил аналитика дважды подряд. Закрывающая сессия собирает оба источника:
```
grep -A4 '^### ' <арка>/UROKI-FABRIKE.md                    # уроки аналитика
grep -A4 -h '^### ' <арка>/kod_*.md | ...                   # уроки исполнителей (секция ## УРОКИ ФАБРИКЕ)
grep -c '^### ' vs '^ВЕРДИКТ: ' <арка>/UROKI-FABRIKE.md      # разошлось ⇒ арка НЕ закрыта (ARKA §7)
```

**Гейт с зубами — в pre-commit, а не в уговоре:** `python3 ../../../_generator/tools/check_uroki.py` красит ❌ на урок без `ЦЕНА:` в арке, которую трогает коммит. Ставится один раз: `git config core.hooksPath .githooks`. Проверяет только тронутые арки и молчит, когда чисто, — иначе его отключат, и это будет конец затеи. Урок с `ВЕРДИКТ:` не пересматривает: его уже отсудила закрывающая сессия.
*Обойти — `git commit --no-verify`. Это не дыра: закон (`../KONSTITUCIYA.md §11`) запрещает нарушать МОЛЧА, а не нарушать. `--no-verify` придётся напечатать руками.*
*Чего гейт НЕ проверяет (клауза 3): что цена настоящая, что урок вообще записан (молчание не отличить от «уроков не было») и что он доехал до канона. Считает строки, не правду.*

Цель владельца прежняя: замечания уходят не только в историю ПРОЕКТА, но и правят саму ФАБРИКУ — курсы тестируют фабрику, каждый прогон её улучшает.

## Верификатор (для потерь/перемещений)
Лоссовая операция (синтез/сжатие/архивация/удаление) или правка путей → встрой ОТДЕЛЬНЫЙ свежий субагент-верификатор как ГЕЙТ: «исходный смысл → новый дом» полно (список потерь ПУСТ); каждая ссылка резолвится (битых 0, программно). **Ключ — ДРУГОЙ субагент и ДРУГОЙ метод** (читает оригиналы из бэкапа/`git show`, проверяет программно): у автора правок слепые пятна.

## Тип захода и «один риск за раз»
- **Мутирующий** (двигает/правит): откат по блокам (git/zip), сверка после каждого.
- **Аналитический** (только измеряет): данные не трогать; артефакт + предложения; решение — владельцу.
- **Организационный** (порядок папки/доков): содержание/архитектуру не менять.
Тяжёлое режь по риску: read-only АУДИТ → МУТАЦИЯ по плану → read-only СВЕРКА. Перемещение файлов — отдельным заходом с верификатором.

## Скелет захода
**Не пиши с нуля — сгенерируй:** `python3 ../../../_generator/tools/bootstrap_zahod.py <арка> <тема> --branch <ветка> --zone "<пути>"` → `kod_<тема>.md` с вшитым контрактом зоны (шаблон `../../zhurnal/_TEMPLATE-zahod.md`). Ниже — форма (что дозаполняет Cowork в `<...>`):
```
# Канал исполнителя — <КОРОТКОЕ ИМЯ> (один заход до конца)
> Твой единственный файл-заход. Читай ТОЛЬКО его и названные якоря; проект не изучай.
> План/вопросы/отчёт — в секции внизу. Метрика — КАЧЕСТВО. Часы — норма.

КОНТЕКСТ. <проект в 1–2 фразы>. Прошлый этап: <состояние>. ЦЕЛЬ: <что закрыть>.
Приёмка — по ОТЧЁТУ, без построчной сверки. <Если стоп до цели: получишь X, но НЕ Y.>
## 0. ПЕРВЫЙ ХОД. Рабочая папка <путь>; точка отката: git-коммит СВОЕЙ ЗОНЫ (`git add <пути>`, НЕ `-A`) ИЛИ zip;
   прочитать ТОЛЬКО <названные файлы> — для курс-проекта `<курс>/SPEKA.md` ПЕРВОЙ (охват/формат/роутер — истина проекта); ПЛАН — в ## ПЛАН перед действиями.
## 1. ДИСЦИПЛИНА (Карпатов). Предпосылки/развилки назвать; минимум без спекуляций; хирургия
   (строка → к заданию); критерий, который может провалиться. Якорные замены — abort при ≠1.
   Сохранять по умолчанию. Оспорить ложную предпосылку — **включая КРИТЕРИЙ ГОТОВНОСТИ, в `## ПЛАН`, ДО работы**
   (*заход `molchalivye-opory`: мой критерий в буквальном чтении объявлял дырой 12 строк из 37 — назвал до работы,
   применил поправку, в отчёте пригласил возразить. Обратная цена — ход 7: плохой критерий, который никто не
   оспорил, дал «дыр нет» на 2 лекциях из 9*). Субагенты: ≤5, рейт-лимит=отступить+доложить.
## 2. ВЕТКА + ЗОНА + ГРАНИЦЫ. <ВЕТКА: `git checkout <ветка>` первым ходом; не назвали — спроси, чужую не трогай/не переключай>. <ЗОНА: пути, которые МОЖНО менять — обычно своя папка + свой дневник; всё вне — read-only: не править/двигать/удалять>. git: коммить ТОЛЬКО зону (`git add <явные пути>`), НИКОГДА `-A`/`commit -am`; авто-коммит — тоже по явным путям; субагенты не коммитят.
## 3. ЗАДАЧА. <конкретно>. КРИТЕРИЙ ГОТОВНОСТИ: <условие, которое (1) называет артефакт, который ПОКРАСНЕЕТ,
   (2) требует «проверено X из Y» внутри отрицательного вердикта — три клаузы гейта см. §Заход>.
## 4. ВЕРИФИКАТОР (если двигаем/теряем). Свежий субагент, ДРУГОЙ метод, сверка с бэкапом, программно.
## 5. ОТЧЁТ → секция ## ОТЧЁТ внизу: что сделал+ЗАЧЕМ / как проверил / что НЕ трогал / вопросы /
   результат верификатора / **время прогона + токены**.

## ПЛАН — (заполняет исполнитель)
## ВОПРОСЫ — (заполняет исполнитель)
## ОТЧЁТ — (заполняет исполнитель)
```

## Когда НЕ усердствовать
Тривиальный заход (одна правка строки, опечатка) — без церемоний, не спрашивай трактовку «почини опечатку». Эвристика: усердие там, где цена ошибки — переделка; быстро там, где откат дёшев.
