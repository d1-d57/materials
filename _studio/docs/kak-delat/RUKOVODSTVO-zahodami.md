# RUKOVODSTVO-zahodami — как вести исполнителя (заход + приёмка)

> **КОГДА читать:** когда готовишь заход исполнителю (субагент через Agent tool или Claude Code). · **ЧТО дописывать сюда:** только методологию захода. · **КУДА дальше:** `ARKA.md §5`.

## Единственный принцип
**Состояние живёт на диске (доки проекта + файл-заход), не в памяти сессии.** Исполнитель стартует с ПУСТЫМ контекстом. Отсюда: заход **самодостаточен** (вход, что прочитать, что сделать, как отчитаться — внутри текста), **один заход = одна задача**, durable — сразу в дома.

## Заход — дай всё, иначе соберёт не то
- Несёт ВСЁ: рабочая папка, что прочитать ПОИМЁННО, что сделать, границы, как отчитаться. Явно: «читай только названное, проект не изучай».
- Существующие конвенции и имена — **авансом** → переиспользует, не изобретает своё.
- **Дизайн-канон — авансом (HTML-заход).** Дай исполнителю дизайн-систему деки: `tokens.css` (палитра), правило акцента (канон: Bold + ОДИН охряный `.acc`, не свой цвет), словарь вёрстки/архетипов (`../../konvejer/07-verstka/DOK.md`), сцен-контракт — ИЛИ явный указатель на канон (`konvejer/07,08,09`, `RESHENIYA Р23/Р24`). Не дал — исполнитель переизобретёт свой стиль. *Прецедент #14: канон не отдан явно → розовые акценты вместо охры, монотонная вёрстка.* Для формат-чувствительного дека — ОДИН короткий контракт формата авансом (не «прочитай 01–10» россыпью), и НЕ делай таст/вёрстку ХВОСТОМ длинного автономного прогона: формат заслуживает свежего окна (прецедент #14 — дек собран последним, в измотанном контексте, формат уехал).
- **Канон разметки — авансом и для DOC-захода, не только для HTML.** Исполнителю, который пишет текст под `build_doc.py`, дай ПОИМЁННО `STANDART-oformlenia.md` (типы блоков, конвенция слитного блока, списки) и `STANDART-teksta.md`. Не дал — он пишет «по общему markdown», а движок понимает не общий markdown. *Прецедент `vidy-obzor`: конвенция слитного блока в каноне БЫЛА — и была нарушена, потому что заход её не назвал: тела девяти типизированных блоков, включая формулы из определений, вывалились из врезок. Оба машинных гейта при этом зелёные (слепая зона объявлена — `STANDART-oformlenia §7½`), увидел владелец глазами по скриншоту. Стоило: полный круг правок плюс чтение исходника движка.*
- **Текст — готовым, не импровизацией сборщика.** Плакатный текст пишет текст-стадия (арка 6 / Cowork в голосе корпуса `content-studio/assets/corpus/texts-corpus.md`); HTML-исполнитель ставит его ДОСЛОВНО, своей прозы не пишет. Формальные формулировки (задача/определение) — из первоисточника дословно. *Прецедент #14: сборщик писал текст сам → не в авторском голосе.*
- Есть ошибка/лог — вкладывай RAW и «почини», НЕ пересказ (пересказ теряет деталь).
- **🔴 КРИТЕРИЙ ГОТОВНОСТИ — ГЕЙТ. Гейт, который не может провалиться, — не гейт. Три клаузы, все обязательны:**
  1. **Называет АРТЕФАКТ, КОТОРЫЙ ПОКРАСНЕЕТ.** «Проверь внимательно», «дыры названы аккуратно», «я закончу» — пожелание. «N файлов на местах, битых ссылок 0», «`--gates` печатает ❌», «каждая ✅ несёт id поставщика + номер лекции, арифметика — скриптом» — гейт.
  2. **Отрицательный вердикт несёт ОХВАТ В СЕБЕ**, не в примечании. «Дыр не найдено» и «дыр не найдено **на 2 лекциях из 9**» выглядят одинаково и читаются как первое. Требуй строку «проверено X из Y» внутри самого вердикта. **И Y — ЧИСЛО, посчитанное по источнику ДО работы, а не описание его синтаксиса.** «Строки таблиц банка», «позиции с якорем» — это ФОРМА источника, а форму он держит не везде: часть позиций лежит прозой, абзацами, хвостовыми кластерами, и охват, заданный синтаксисом, теряет их МОЛЧА. Пиши: «в файле N позиций, команда такая-то; охват сверяется с N» — тогда расхождение видно на входе, а не после сдачи. *Цена: критерий «id и якоря строк банка» дал бы 330 позиций из 379 — охват был бы объявлен СПЛОШНЫМ при дыре в 13 %, и дыра пришлась бы на спорное и реабилитированное, самое хрупкое место корпуса. Ловушка не сработала: спасло то, что исполнитель открыл конец файла глазами.*
  3. **НЕ утверждай в критерии факт о состоянии диска без команды, которая его считает — и ЧИСЛО в критерии пиши командой, а не значением.** `KONSTITUCIYA §10` — не только про числа в прозе, он и про критерии, **и в критериях он нарушается систематически, потому что там число выглядит как часть формулировки задачи, а не как замер** (формулировка исполнителя `kod_sjatie`, 2026-07-29). Пиши «иллюстраций: `ls src/illustrations | wc -l`, сирот 0», а не «иллюстраций 51». *Цена 29.07: четыре числа критерия («51 иллюстрация», «8 портретов», «13 красных слайдов», «33→30 разделов») устарели за два хода между написанием захода и его запуском — живые были 40/7/15/29. Раздел «🔴 ОБНОВЛЕНО ПЕРЕД ЗАПУСКОМ» отменял §2, а критерий ниже остался старым и формально главнее; исполнитель написал прямо: «критерий „иллюстраций 51“ я мог бы попытаться ИСПОЛНИТЬ — то есть искать 11 пропавших картинок вместо подгонки, за час до эфира». Тот же класс в трёх инструментах разом: `== 33` в гейте ленты красил ❌ ровно за выполнение задания, а `AKTY = [9,7,8,8]` в сборщике роняли сборку насмерть — дек не собирался ВООБЩЕ.* «На лекции X гейт зелёный» и «`sostoyanie.py X` печатает гейт с названной причиной» стоят по-разному: первое — предсказание аналитика, и если оно ложно, исполнитель обязан ослаблять проверку, пока эталон не позеленеет, — то есть сдать гейт, который по построению не увидит долг на том самом деке, ради которого писался. *Цена 28.07: критерий требовал «на Паскале G7 зелёный» и объявлял красный доказательством неверного кода. На диске лента несла 14 разделов против 22 в `slide_order` — настоящий долг, видимый в `git log`. Спасло только то, что исполнитель пересчитал разделы до первой строки кода и подал возражение в `## ПЛАН`; приняв критерий на веру, он сдал бы слепой гейт с честным отчётом.*
  4. **Чекер честно печатает, чего он НЕ проверяет** (образец — `../../../_generator/tools/check_kartoteka.py`). Зелёный чекер с необъявленной слепой зоной опаснее красного: ему верят.
  4½. **🔴 ЧЕКЕР ПЕЧАТАЕТ ОХВАТ ВМЕСТЕ С ВЕРДИКТОМ — иначе «зелёный» и «промахнулся мимо входа» неразличимы.** Клауза 4 закрывает слепую зону, которую чекер про себя ЗНАЕТ. Здесь — та, о которой не знает: он не нашёл, что проверять, и молча вернул успех. **Любой чекер обязан печатать «проверено X из Y», где Y считается ДО работы и по источнику; `X = 0` при непустом источнике — красный, а не зелёный.** *Цена 16.07: `targets_from()` вернул пустой список, чекер отдал тишину и `rc=0`, исполнитель записал «верификатор уроков зелёный». Реально проверено 0 уроков из 14. «Ещё бы одна ночь зелёного молчания — и урок №13 остался бы починенным на бумаге». Класс — первый по объёму во всём корпусе (154 записи ЦЕНА) и до 31.07 не имел в каноне ни одной строки: греп по «промахн», «0 из 0» давал ноль.*
  4⅗. **🔴 ГЕЙТ, КОТОРЫЙ НЕЛЬЗЯ ПОЧИНИТЬ, ЧИНЯТ СОДЕРЖАНИЕМ — И ЗАКАЗ ВЛАДЕЛЬЦА ТИХО ЛОМАЕТСЯ.** Третий вид сломанного гейта, помимо «краснеет на здоровом» и «молчит по промаху»: гейт красен законно, но лежит ВНЕ зоны исполнителя. Тогда единственный доступный ремонт — переписать материал под гейт, и это происходит молча, потому что формально всё зелено. **Гейт вне зоны — это развилка для отчёта, а не повод править содержание.** *Цена 01.08: линтер «порция текста на клик» считает блоки по атрибуту на самом `<li>`, а формат кладёт сцену пункта инлайном — три пункта, приходящие кликом, гейт видит на первой сцене и роняет три слайда разом. `_generator/` вне зоны. Первый круг: исполнитель отказался от списков и переписал три слайда абзацами — то есть **тихо отказал владельцу в том, чего тот не просил менять**. Второй круг: владелец потребовал булеты прямым текстом, поимённо в пяти местах, и пришлось заводить обходной носитель. Итог — в колоде ДВА разных механизма списка, и следующий исполнитель обязан знать, какой когда. Настоящее лечение — одна строка в самом гейте.*

  4¾. **🔴 ИНСТРУМЕНТ МОГ НЕ ЗАПУСТИТЬСЯ, А ВЫВОД — ОСТАТЬСЯ ОТ ПРОШЛОГО ПРОГОНА.** Артефакт с прошлого хода выглядит как свежий результат. Читаешь файл, который сам же велел создать, — сверь его ВРЕМЯ, а не только содержимое. *Цена 16.07: в песочнице не писался `/tmp`, редирект упал, скрипт не запускался ВООБЩЕ — а `tail` напечатал содержимое, лежавшее там с ночи, и вывод несуществующего прогона был прочитан как свой. Тот же класс 31.07 в другой одежде: цепочка `porodit && sverstat && build_deck` оборвалась на штатном ненулевом коде середины, сборка не пошла, владелец открыл вчерашний файл и заключил, что правка не сработала — круг ушёл на диагностику поломки, которой не было.*
  5. **🔴 ГРЕП-КРИТЕРИЙ ПРОГОНЯЕТСЯ НА ЖИВОМ ФАЙЛЕ ДО ВЫДАЧИ ЗАХОДА, и его текущее значение пишется в заход.** Формулировать греп-гейт «на глаз» нельзя: за одну арку он оказался негодным ШЕСТЬЮ разными способами, и каждый выглядел защитимым.
     - **Несёт ПУТЬ, а не «в ленте».** Критерий «„группоид“ = 0 вхождений» при живых 5, из которых три — сама доказываемая теорема: буквальное выполнение снесло бы ядро раздела за час до лекции, и все гейты остались бы зелёными (текст короче, переполнений нет).
     - **Грепает ИСТОЧНИК, не порождённое.** Критерий по `src/content/` выполним правкой выхода и обнуляется первой же сборкой. Порождённое проверяется СБОРКОЙ: два числа (в источнике и в выходе), совпадение — доказательство.
     - **Слово из критерия в файлах ЕСТЬ.** Греп по слову, которого нет ни в одном файле, даёт 0 и до работы, и после — «отчёт бессодержательный, а не ложный, и приёмка этого не отличит».
     - **Слово из критерия задание не велит НАПЕЧАТАТЬ.** «Слов „изоморфизм“ — ноль» при пункте «напечатать „$V$ и $V^*$ изоморфны“»: субагент, получивший критерий дословно, снёс бы весь сюжет.
     - **Коридор односторонний, если потолки односторонние; и новый гейт прогоняется по живому ЭТАЛОНУ прежде, чем по работе.** Двусторонний коридор «45–57 слов» дал **9 ложных ❌ из 14 разделов на эталонной ленте, по которой сам же калиброван**. Красное на эталоне = ложный гейт, а не больной эталон (`../pochemu-i-videnie/RESHENIYA.md Р33`, распространено с критериев отбора на гейты). Цена невыполнения названа в `../../konvejer/GEJTY.md` заранее: гейт, краснеющий на здоровом деке, обходят `--no-verify`, и пропадает вся защита.
     - **Критерии проверяются на совместимость арифметикой — между собой.** Два критерия одного захода бывают взаимно невыполнимы, и это видно счётом ДО первой правки: «медиана 55 слов требует −53 % объёма, а лишние 15 п.п. взять неоткуда, кроме формулировок, которые запрещает критерий 4 того же захода».
  6. **ОДИН заход = ОДИН критерий готовности.** Справочный материал в заходе не содержит ни критериев, ни обязательных действий — иначе он не справочный. *Цена: заход нёс вторую задачу под заголовком «СПРАВОЧНО (не задача этого захода)» с ВТОРЫМ критерием на 7 пунктов; два его пункта исполнять было надо, то есть заголовок врал, и отличить в нём живое от мёртвого может только тот, кто уже прочёл весь заход — при лекции через три часа.*
  7. **Шкала или классификация сдаётся ВМЕСТЕ С РАСПРЕДЕЛЕНИЕМ.** Ноль в клетке — либо мёртвая клетка, либо непокрытый случай; разбирать надо оба. Клетка, которая генерирует систематический спор в одном и том же месте, — тоже дефект шкалы, а не разметки. *Цена: значение `НЕ НА СЛАЙДЕ` не встретилось ни разу на 106 блоках, и вместе с ним оказалось мёртвым правило, гейту которого нечем было покраснеть; нашёл не исполнитель, а верификатор, потому что считал РАСПРЕДЕЛЕНИЕ, а не проверял метки по одной. Обратная клетка стоила слайда на 11 минут расчёта при 516 знаках текста — самого дорогого и самого пустого в деке.* Механизм дешёвый: печать `Counter` вместо абзаца увещевания.
  *Цена клауз 1–2 — контраст на ОДНОЙ арке, ОДНА модель (Opus), два исхода. Ход 7, критерий «каждая 🔴 ДЫРА называет место в курсе»: дыр не нашли — критерий не сработал ВООБЩЕ, а вердикт «дыр нет» на деле означал «проверено 2 лекции из 9» и читался как «все девять». Ходы 8 и 12, критерий «каждая ✅ несёт id поставщика + номер лекции, арифметика — скриптом»: нашлись 2 настоящие дыры, гейты закрылись 9/9 впервые за двое суток. **Разница не в исполнителе — в том, что второй критерий проверяет МАШИНА.** Цена клаузы 3: тупой греп родов поймал дыру, которую три умных прохода не увидели, — но сам был слеп в разметке (5 понятий курса без рода `понятие`; на Л1 прокси видит 1 карточку из 14), а `seed` в роде `пример` не печатался нигде — из-за чего файл ГОД врал «кандидатов нет» при трёх живых.*
- **Визуальный гейт — host-side, не в песочнице (прецедент #15).** Машинные гейты (линтер, `verify_models`) ловят структуру и математику, но НЕ вид/интерактив. Браузера в песочнице Cowork нет (CDN Chromium заблокирован) → визуал правится вслепую и помечается; `_generator/render.py` (PNG кадров) + `_generator/audit.py` (overflow/палитра/floor/fit — НАПИСАН, нужен браузер) гоняет host (владелец / host-заход, там Chrome). *Прецедент #15: зелёные машинные гейты ≠ визуально готово; без визуального гейта фаза ревью-петли доминирует по стоимости (~5 кругов доводки Фибоначчи). Интерактив/визуал прозой недоспецифицируем → якорь на рендер/референс-слайд ДО тиража.*
- **🔴 ПОИСКОВЫЙ заход — не производственный, и приёмы у них разные.** В производственном заходе числовая планка («не менее N источников / задач») полезна; в поисковом она вредит с ДВУХ сторон — снизу подталкивает натянуть список до числа, сверху даёт право остановиться, когда число набрано, а сколько существует хорошего, заранее неизвестно. Вместо планки — «**назови охват числом**». Вторая половина того же перекоса: наводка владельца в поисковом заходе — ОДНА позиция пула, а не приоритетный раздел с подвопросами и требованием верифицировать; поиск меряется многообразием находок, глубина по одной — следующая задача, и она удваивает верификацию (исполнитель проверяет, потом проверяет приёмка). *Цена: обе планки сняты владельцем, заход переписан; тем же днём развёрнутый в приоритетный раздел единственный сюжет переписан назад — «ты опять уходишь в частности, которые любишь верифицировать… Не нужно». Оба раза поймал владелец, не гейт; оба — перенос приёма из ЧУЖОГО класса задач.*
- **Флаг «стоп до цели».** Если заход по замыслу останавливается ДО ожидаемого владельцем результата — скажи это громко и заранее одной фразой («получишь X, но НЕ Y; Y запускается так-то»).
- **🔴 АДРЕС ПРАВКИ — ЗАГОЛОВОК, номер только справочно.** Заголовок живёт, номер умирает при первом же снятии или перестановке. *Цена 29.07: из 20 пунктов диктовки один заход сделал 7, из 8 пунктов следующий — 4, и причину назвал сам: «три пункта не сделаны не по времени, а потому что **ЦЕЛЬ НЕ АДРЕСУЕТСЯ**». Между диктовкой и исполнением заходы снимали слайды, добавляли визитку и меняли местами два — всё после точки вставки сдвинулось. Восстановить исходную нумерацию постфактум **не удалось**: сверка сохранённой владельцем копии с диктовкой дала расхождение на единицу, и владелец не смог подтвердить, откуда оно. Пришлось строить таблицу «номер → заголовок» вручную по смыслу каждой правки.* **Доказано на живом материале в той же арке:** заход, перешедший на адресацию заголовками, сошёлся **20 из 20** и получил в сверке «НЕ НАЙДЕН АДРЕС — 0», то есть класс отказа исчез полностью. Два лишних слова при диктовке против трети невыполненных пунктов на приёмке.
- **🔴 СПИСОК ПРАВОК СОРТИРУЕТСЯ ПО «ЗАМЕТНОСТЬ × ДЕШЕВИЗНА», а не по тяжести дефекта.** Правка на десять секунд идёт первой ВСЕГДА: она не конкурирует за время, зато конкурирует за доверие. *Цена: приоритет был выстроен по важности (сначала дефекты сцен, ломающие слайд на экране), и это логично; но снятие одной фразы стоило десять секунд, стояло в хвосте — и владелец наткнулся на неё первым взглядом за минуты до эфира и решил, что «ничего не внеслось», хотя к тому моменту было закрыто семь пунктов из двадцати, включая тяжёлые. Потребовался ещё один заход ради двух правок на минуту работы.*
- **🔴 ПРЕТЕНЗИЯ ВЛАДЕЛЬЦА ЗАПИСЫВАЕТСЯ ВМЕСТЕ С ЕЁ ОТМЕНОЙ И ОГРАНИЧИТЕЛЕМ.** Третье обязательное поле у записанной правки — «что при этом НЕ делать»; если владелец сам себя отменил или смягчил, отмена стоит РЯДОМ, а не вместо. Механизм проверки: сводка правок вычитывается вторым проходом ОТ КОНЦА акта к началу — отмена всегда идёт ПОСЛЕ претензии и при линейном чтении теряется. *Цена: сводка перечисляет прямые последствия своей же первой редакции — буквальное исполнение **сняло бы с картинки цифры, которые владелец велел оставить**, перерисовало бы картинку не тем примером и удалило бы два примера, которые владелец не отменял. Плюс собственная ошибка адресации: смягчение по одному слайду приписано соседнему.*
- **🔴 УСЛОВИЕ АВТОЗАПУСКА ЦЕПОЧКИ ЗАХОДОВ НЕ ЗАВИСИТ ОТ ФОРМУЛИРОВКИ ИСПОЛНИТЕЛЯ.** Сторож ждёт МАШИННОГО факта — коммита, трогающего зону (`git log` по путям); если греп, то терпимый (`^\*\*КОММИТ.*\`[0-9a-f]{7,}\``). *Цена 29.07: сторож ждал точную строку `**КОММИТ:** \`<хэш>\``; заход её написал, сторож отработал — но потом исполнитель сделал второй коммит и переписал строку в расширенную форму. Ложный диагноз стоил минут; настоящая цена в том, чего не случилось: **напиши исполнитель расширенную форму сразу, лента не запустилась бы вовсе, и ночь была бы потеряна целиком** — а обнаружилось бы это утром, за несколько часов до лекции. Форма строки нигде не была зафиксирована как контракт, и двое из трёх заходов подряд её расширили.*
- **Заход проверяет ГИПОТЕЗУ САМОГО аналитика → впиши «не подыгрывай» (прецедент teorkat, 2026-07-16).** Две ловушки, и заход опасен с обеих сторон — назови ОБЕ явно, иначе получишь уверенный отчёт ни о чём.
  - **Аналитик — заинтересованное лицо.** Ему приятно, если гипотеза подтвердится, и услужливый исполнитель её подтвердит. Формулировка в заход: «**опровержение — полноценный успех**, оно спасает от постройки на песке; "источник не отвечает" — законный исход, если сказано, чего именно не хватает; **брак — только выдуманный вердикт**».
  - **Форма источника ≠ существо предмета.** Учебник показывает СВОЙ вход и молчит про остальные — не потому, что других нет, а потому что у него уже всё на столе. *Прецедент: CCC определяется через сопряжения (Маклейн §4.6) И через evaluation map без единого функтора (Ловер, Awodey) — один предмет, два входа. Заход, читающий параграф внутри главы «Сопряжения», обязан различать «автор ГОВОРИТ адъюнктно» и «определение их ТРЕБУЕТ».* Вопрос ставить как «**что предмету НУЖНО**», а не «как делает автор», и ловушку назвать в заходе поимённо, с требованием отчитаться: поддался или нет.
  - *Почему:* исполнитель с пустым контекстом не знает, что вердикт кому-то выгоден, и не видит, что структура книги — это выбор автора, а не свойство математики. Обе ошибки дают отчёт, который читается как находка.
- **🔴 ГЕЙТ ВХОДА — прогони СВОЙ вход по СЕМИ вопросам ПЕРЕД выдачей захода.** Общий дефект: аналитик проверяет, что ссылка СУЩЕСТВУЕТ, но не что лежащее по ней ТОЖДЕСТВЕННО задаче. **Асимметрия, которая делает гейт обязательным, а не рекомендуемым: у составителя каждая проверка — одна команда `grep`; у исполнителя запрет смотреть по сторонам, то есть поймать ошибку входа он не может ПО ПОСТРОЕНИЮ.**
  1. **Издание/версия актуальны?** 2. **id/имя указывает на ТО САМОЕ?** 3. **ЗОНА содержит файл, в котором лежит ответ?** — самый дорогой вопрос. 4. **Предпосылка жива?** — сверь по ЖИВОМУ файлу, включая свою; трогает заход только что закрытое — пометь «уже закрыто: проверить зелёным, не открывать заново». 5. **Разметка предыдущего захода ПЕРЕВОДИТСЯ в твою?** Заход, велящий «забрать готовым» выход прошлого захода, обязан нести таблицу «старая ось → новая» — с честной строкой **«не переводится»** там, где не переводится. Без неё «забери как есть» звучит исполнимо, не являясь, и ставит исполнителя между двумя обязательными указаниями без названного приоритета.
  6. **🔴 КАЖДЫЙ АДРЕС, названный заходом, ПРОВЕРЕН ГРЕПОМ — и каталог, названный заходом, ПОРОЖДАЕТСЯ ЖИВЫМ КОДОМ (`ls`).** Заход на ДОНАБОР обязан называть место, где лежит уже набранное, иначе критерий-счётчик подтвердит выполнение при дублях. **Метка «проверено» ставится ТОЛЬКО вместе с командой, которой проверено** — без команды это слово запрещено: оно снимает проверку с того, кто единственный мог бы её сделать. *Цена 28–30.07, четыре неверных адреса за арку: долг назван «утверждение 130, вкладка 10» при живом адресе в вкладке 11, которую заход открывать ЗАПРЕТИЛ — «исполнитель, выполнивший инструкцию буквально, написал бы формулировку с нуля и не увидел бы трёх вещей, включая вторую половину того же сюжета; ошибка поймана одним грепом, составитель мог сделать тот же греп при сборке» · «материал в `01-liniya-A.md`» при нуле вхождений искомого слова · «ищи по слову „раскрас“ в районе строк 120–135» — там другой предмет · заход велел переиспользовать модель, формат которой несовместим с предписанным им же движком: 2,9 ГБ и 12 минут, которых заход обещал избежать · «`/usr/bin/ffmpeg` — проверено» при отсутствующем файле: скрипт, написанный по заходу дословно, упал бы на первом же акте вечером, когда чинить некогда.*
  7. **ЗАДАЧА УЖЕ СДЕЛАНА? — грепом, при сборке захода.** Самый дешёвый вопрос входа и самый частый: сработал бы **пять раз за трое суток**. *Цена: заход поставил три задачи, уже выполненные названной им же базой; исполнитель прочитал `A-krasivaya.md` целиком (31 КБ, самый большой файл ленты) ради вывода «трогать нечего» — перед лекцией это тот же ресурс, что работа. При этом заход НАЗЫВАЛ базу коммитом точно, и «„греп по „Вербиц“ = 0“ стояло в критерии готовности как ЦЕЛЬ, хотя было ФАКТОМ на входе». Остальные четыре: перестановка, уже сделанная в живом файле; «не упоминать X» при нуле вхождений X; «урезать до 32 слайдов» при живых 32 — заход, исполненный буквально по своей ЦЕЛИ, закрывался нулевой работой с честным отчётом при слайдах в три экрана; «переписать в формате соседнего слайда» — уже переписан.*
  *Цена вопроса 5: старая разметка шла по четырём лупам, новый заход ввёл шесть меток по минимуму языка; три лупа переводятся однозначно, четвёртый — нет (его гейт накрывает разом три метки). Оси менял аналитик законно, по правке владельца, но переводимость не проверил. ~30 позиций пересужены вместо забранных готовыми (порядка получаса) плюс риск тихого расхождения с предыдущим заходом — заход спас исполнитель, назвав поломку в `## ПЛАН` ДО работы, как уже бывало пять раз.*
  *Цена: пять дефектных входов за двое суток; все пять заход спас САМ (потому и жив — см. `../KONSTITUCIYA.md §11` о пустом контексте). Smith 2-е издание вместо 3-го — а заход МЕРИЛ порядок глав, который во 2-м «significantly rearranged» · неверный arXiv-id (дан «Ologs» вместо нужной работы) · имя файла врало («…for-the-sciences.pdf» при содержимом «for Scientists») · **зона без `kartoteka/**` при задаче «найди молчаливые опоры» отсекла ровно тот файл, где они живут — §2.3 выполнен на 2 лекциях из 9** · ложный поставщик (назван узел Л9 вместо Л3 — при том что ловушку «поставщик есть, но ПОЗЖЕ» аналитик сам вписал в тот же заход, на той же странице) · стале-предпосылка: заход сказал «TERMINY — открыт спор о владении», хотя шапка файла уже говорила «решено, файл аналитика»; исполнитель честно отступил по ложной предпосылке, и долг терминов завис ВТОРОЙ заход подряд из-за аналитика.*

## Зона изменений и git — коммить ТОЛЬКО своё

> 🔴 **Вся git-механика переехала в единственный дом — `GIT-disciplina.md`.** Здесь остаётся только то, что относится к УСТРОЙСТВУ захода; локи, форма коммита, `--no-optional-locks`, worktree, «кто коммитит» — там, и правятся ТОЛЬКО там. *Почему переехало: до 21.07 git-правила жили в шести местах и противоречили друг другу (напр. «НИКОГДА `add` → `commit`» против рабочего инструмента, который делает именно это).*

- **КОНТРАКТ ЗОНЫ — ОБЯЗАН быть в КАЖДОМ заходе Claude Code (требование владельца 2026-07-11). Без него заход НЕполон — не запускать.** Вписывает его COWORK генератором, не руками: `python3 ../../../_generator/tools/bootstrap_zahod.py <арка> <тема> --branch <ветка> --zone "<пути>" [--worktree <имя>]` создаёт `kod_<тема>.md` из `../../zhurnal/_TEMPLATE-zahod.md` с уже вшитым контрактом (`--branch`/`--zone` обязательны). **`--worktree` — если заход идёт ПАРАЛЛЕЛЬНО другому** (`GIT-disciplina.md §4`): генератор заводит рабочую папку и вписывает `cd` вместо `git checkout`. Cowork дозаполняет только `<...>`. Блок «место · зона · коммит · запрет»:
  - **МЕСТО** — worktree-папка (параллельный заход) ИЛИ ветка в основной папке (одиночный). Развилку решает генератор, в заход уходит ОДИН вариант — исполнитель с пустым контекстом гадать не должен. Ветку он НЕ переключает сам: назвали неверно → СПРОСИ.
  - **ЗОНА** — явный перечень путей, которые МОЖНО менять (обычно ОДНА папка проекта + свой дневник). Всё вне — **READ-ONLY**: не править, не двигать, не удалять, не рефакторить «заодно».
    🔴 **Зона собирается из путей, которые ЗАДАЧА НАЗЫВАЕТ, а не из папки, где заход начался.** Задача, требующая создать файл вне объявленной зоны, ставит исполнителя между двумя обязательными указаниями, и последствие хуже самого нарушения: *«коммит захода шире объявленной зоны, и `git_zona.py check --zone` по объявленной зоне этот файл не увидит — приёмка гейтом его не проверит. Сама подстраховка „check --zone первым ходом“ на таком заходе слепа»* (`kod_perekomponovka3`, 29.07). **Зона из нескольких корней — законная**, и инструмент обязан её принимать; пока `--zone` берёт один префикс, исполнители обходят это двумя коммитами и первый оказывается шире зоны.
    🔴 **ПОРОЖДАЕМЫЕ каталоги названы в зоне отдельной строкой, с запретом править напрямую.** Исполнитель с пустым контекстом видит в `src/` обычные файлы под git, папка называется «источник» — и теряет всё на первом же шаге конвейера, который сам же заход велел запустить. *Цена 29.07, самая дорогая в арке по последствию: `porodit.py` снёс содержательные правки в 7 файлах `content/`, затем `sverstat.py` снёс раскладку в 9 файлах `slides/`, `shablon.html` и — дороже всего — перестановку слайдов в `slide_order`, то есть приоритеты 2 и 3 ТЗ целиком. Всё делалось заново в ленте; ушло ~20 минут при бюджете ~20 минут до лекции — **прямая причина того, что единственный пункт с пометкой «железно обязательно» и шесть пунктов правок остались несделанными**.* Строка стоит в `../../zhurnal/_TEMPLATE-zahod.md`, а не только здесь: до исполнителя доезжают шаблон и гейт коммита (`../KONSTITUCIYA.md §11`).
  - **КОММИТ** — свою зону, форма и «кто коммитит» — `GIT-disciplina.md §3`. Субагенты НЕ коммитят: только ведущий заход, только свою зону.
  - **ЗАПРЕТ** — ничего за пределами зоны, даже если «мешает». Нашёл проблему вне зоны → в отчёт, не трогай.
- **🔴 ЗАВЁЛ НОВЫЙ `.md` — РЕГИСТРИРУЕШЬ ЕГО САМ, ТЕМ ЖЕ ХОДОМ, ОДНОЙ КОМАНДОЙ:** `python3 ../../../_generator/tools/register_doc.py <путь> "<описание>"` (из корня репо). `_studio/docs/` по-прежнему READ-ONLY **для правки руками** — дверь ровно одна, и это она; правило одинаково для аналитика, владельца и исполнителя (`ISTOCHNIK-PRAVDY.md §4`). Красный хук на своём новом `.md` — повод позвать дверь, не повод для `--no-verify`. То же стоит в `../../zhurnal/_TEMPLATE-zahod.md` — и стоит там ПОТОМУ, что до исполнителя доезжает шаблон, а не канон (`../KONSTITUCIYA.md` п. 11). *Цена прежней редакции («регистрирует аналитик, не исполнитель»), отменённой 2026-07-30: пять документов ушли в приёмку сиротами 26.07 (по `../KONSTITUCIYA.md` п. 9 документ-сирота = не существует), коллизия повторилась дословно через два дня, а до появления двери — два обязательных указания («зарегистрируй» и «`docs/` только на чтение») выполнить разом было физически нельзя, и это дало 27 обходов `--no-verify` из 28 (48 % всей боли с коммитами по `_INFRA-git/INCIDENTY.md`).*
  🔴 **ЧЕСТНАЯ ГРАНИЦА ГЕЙТА — правило шире того, что проверяет хук, и обязано это про себя говорить.** Проверено по живым файлам 29.07: активный `.githooks/pre-commit` требует регистрации только для `.md` внутри `_studio/`, а `../KARTA.md §6` **не содержит ни одного файла из папки проекта** (совпадения по грепу дают только `_SHTAB-*`). Значит либо §6 — не дом проектных документов, либо дом тот, но проектные файлы в него не попадали никогда; развилка владельца, стоит в `../sostoyanie/OTKRYTYE-ZADACHI.md`. *Цена молчания об этой границе: коллизия записана 26.07 с ценой в пять сирот и вписана в шаблон — и всё равно сработала в ШЕСТИ файлах арки `2026-07-28_konspekt-l1`, потому что она структурная, а не забывчивость; плюс три чужих `.md` вошли в git точкой отката чужого захода, и гейт регистрации на них не сработал вовсе.* Зелёный хук при таком правиле читается как «всё зарегистрировано» — и это чтение неверно.
- **Аналитик — ТОЖЕ параллельный писатель, и его зона тоже должна быть названа.** Правишь доки, пока идёт чужой прогон, — объяви свою зону прямо в тексте захода («файлы X, Y правлю я — не трогай»). *Цена одолжена у инцидента 2026-07-11: параллельный прогон расщепил работу по двум коммитам.*
- **Разделение по зонам:** общую документацию правит Cowork; HTML/код — только код-заход в своей папке; никто не лезет в чужую зону.
- **Приёмка «работа доехала в git» — гейт 0, `git_zona.py check --zone <зона>` первым ходом** (`§Приёмка` ниже; полностью — `GIT-disciplina.md §2`).
## Субагенты — аккуратный режим
Вложенные — можно ОСМЫСЛЕННО и по плану, не случайный рой. Fan-out ≤~5 параллельно (крупную пачку — в очередь). Рейт-лимит = отступить и доложить, НЕ слепой ретрай. Назвать ЯВНО: сколько субагентов и на что. Дешёвое/механическое/параллельное — дешёвым моделям; тяжёлое суждение — сильной. Метрика — стоимость за успешный РЕЗУЛЬТАТ, не за токен.

🔴 **Число, названное субагенту как ПОТОЛОК, работает как ЦЕЛЬ.** Давай ему ЦЕЛЬ (замер эталона) и отдельно потолок как аварийную границу; одно число в задании читается как цель, каким бы словом его ни назвали. *Цена 29.07: исполнитель назвал субагентам «потолок 75 слов» при цели 50; первую редакцию своего блока он переписал целиком (75 → 59), по остальным четырём блокам перепрогона не делал — «субагенты остановились на потолке 75, который я им сам и назвал, и приняли его за цель». Итоговая медиана ленты 70 слов против 51,5 у эталона, на 36 % выше, и понизить её потом можно было только новыми дроблениями слайдов или снятием формулировок.*

🔴 **ОТВЕТ СУБАГЕНТА МОГ БЫТЬ УСЕЧЁН, И ЭТО НЕОТЛИЧИМО ОТ ЧЕСТНОГО «МАЛО НАШЛОСЬ».** Требуй финальной строкой самоотчёт: «выдано N позиций из M найденных». Нет строки — считай ответ неполным, а не полным. *Цена: обрезанная выдача принимается как исчерпывающая, и охват объявляется сплошным при дыре, размер которой никто не измерил.*

🔴 **УМИРАЮЩИЙ СУБАГЕНТ НЕ ОТДАЁТ НИЧЕГО — значит добыча пишется на диск ПО ХОДУ, а не в финальном ответе.** *Цена 18.07: из четырёх умерших по таймауту выемщиков ни один не сохранил ничего; ~40 минут работы выброшены безвозвратно. Приём копеечный и обязан стоять в промпте выемщика по умолчанию.*

🔴 **Мандат чтения ВЕРИФИКАТОРА шире мандата исполнителя — по построению.** Верификатор ищет то, чего исполнитель не мог знать; запрет на чтение делает его слепым ровно там, где он полезен. *Цена, дважды за арку: рамку лекции (`SPEKA.md:74`) нашёл верификатор, НАРУШИВ мандат, — исполнитель, соблюдавший правило «рамку из файлов не выводить», её не нашёл, и полтора часа перебора остались незамеченными до круга переделки конспекта и отчёта. Второй раз субагент открыл запрещённый файл и **именно поэтому нашёл ложную предпосылку в задании исполнителя**.* Развилка двух правил канона разрешена так: **исполнитель рамку не выводит и называет дефект захода; верификатор её ищет и обязан.**

**🔴 Время ожидания меряй `date`, а НЕ суммой своих `sleep`.** Статуса живого субагента исполнитель не видит, читать его лог запрещено (переполнит контекст) — остаётся косвенное измерение, и оно систематически завышает: номинальная сумма `sleep` набегает вдвое быстрее стенных часов. Отсюда два правила: **отступать от живого субагента только по ВНЕШНЕМУ признаку** (рейт-лимит, ошибка, явный отказ), а не по ощущению «долго»; **отступил и написал запасную версию — при возврате субагента ОБЯЗАН сверить и переписать**, а не оставить первую редакцию. *Цена: поисковый субагент работал 26 минут; исполнитель насчитал по `sleep` 43 минуты при 24 реальных, счёл его зависшим и отступил ЗА 7 МИНУТ ДО ФИНАЛА. Беглый запасной поиск дал §C с вердиктом «устоявшегося названия не нашёл» — вердикт ОШИБОЧНЫЙ (имена есть: Implicit Species Theorem; canonical fixed point локально сжимающего функтора). Полный результат пришёл через несколько минут, §C переписан целиком: ~15 минут и один лишний прогон поиска. Спасло только то, что исполнитель сверил, а не оставил.*

## Модель в заход (первой строкой) и запуск
**Дефолт — Sonnet.** Opus — только когда рассуждение рождается В ХОДЕ исполнения (не то, что Cowork уже расписал заходом).

| Тип захода | Модель |
|---|---|
| Исполнительный, полностью расписанный (якорные замены, вставки, renumber, рендер/сборка, линтер) | **Sonnet** — механика; abort+верификатор ловят сбой |
| Исследовательский/неоднозначный («разберись и почини» без готовых якорей) | **Opus** — план рождается по ходу, меньше ретраев |
| Смешанный | план на Opus, механику на Sonnet (`opusplan`) |

Чем детальнее заход (точные якоря, критерий, границы), тем увереннее Sonnet — хороший заход удешевляет модель. Бюджет душит не 5-часовое окно, а **недельные капы** (проект из многих прогонов) → тиринг моделей + не разводить рой субагентов.

Первый честный замер: **5 заходов на Sonnet, 2 на Opus, приёмка не вернула на переделку ни одного.**

🔴 **Единственная найденная слабость Sonnet — и она про ГРАНИЦУ, а не про качество.** Диагноз останавливался на уровень раньше: «фикстура зовёт отсутствующий `check_ves.py`» — при том, что файл в репозитории есть, а сломан стенд, который его не копирует. Формально верно, по сути мимо; стоило круга. Отсюда граница:

| Заход, чей ПРОДУКТ — диагноз (а не починка) | **Opus**, либо в заход вписывается явный шаг «проверь существование названного файла командой и покажи вывод» |

Оба Opus-захода этой сессии — те, где план рождался по ходу (три merge подряд; переезд живой публикации). Правило таблицы подтвердилось буквально.

**Контекст 2026:** Sonnet 5 (30.06.2026) — дефолтная модель в Claude Code, окно 1M токенов, заметно сильнее в агентности и многошаговых задачах, чем поколение, под которое писалась таблица. То есть дефолт «Sonnet» сегодня обоснован сильнее, чем когда его записали. Оговорка по цене: у Sonnet 5 новый токенайзер, он кодирует тот же текст в ~1.0–1.35× больше токенов — сравнивать стоимость по числу токенов между поколениями нельзя, только по деньгам за успешный результат.

🔴 **Стартовое сообщение НЕ пишется по памяти — его ПЕЧАТАЕТ `bootstrap_zahod.py`.** Скрипт уже знает модель (`--model`), ветку и абсолютный путь, поэтому выдаёт готовый блок сразу после генерации захода: Cowork копирует, а не сочиняет. **Заход считается сданным владельцу только вместе с этим блоком.**

*Почему так, а не «правилом»: формулировка ниже жила в каноне с самого начала — и 21.07 аналитик дважды подряд собрал стартовое сообщение без строки «Модель», просто не открыв этот параграф. Правило было записано и не сработало; поймал владелец. `KONSTITUCIYA §11`: правило, которому нечему покраснеть, — надежда. Здесь вместо гейта убрано место для ошибки — как со счётчиками, где число заменили командой.*

🔴 **ПРОМПТ АГЕНТА И КОМАНДА ТЕРМИНАЛА — РАЗНЫЕ ВЕЩИ, И ПОДАВАТЬ ИХ ОДИНАКОВЫМ БЛОКОМ НЕЛЬЗЯ.** Владельцу уходит ТОЛЬКО исполняемая строка `cd … && claude -p …`, внутри которой промпт лежит закавыченным. Текст промпта отдельным блоком кода выглядит как команда и будет вставлен в оболочку. *Цена 31.07: владелец вставил промпт в zsh, получил четыре `command not found` («Модель:», «Твой», «Прочитай», «проект»), Claude Code не запускался вовсе — и на диагностику этого ушёл круг, потому что снаружи «агент вернулся молча» и «агент не стартовал» выглядят одинаково. Это третий за две сессии случай, когда команда владельцу оказалась нерабочей; два предыдущих — потому что писалась по памяти, а не сверялась с `--help`.*

### Два канала запуска — печатает генератор (`--kanal terminal|app`, дефолт `terminal`)

**A. ТЕРМИНАЛ (основной канал).** Владелец копирует ОДНУ строку в системную строку Терминала (ту же, где он коммитит, — НЕ внутрь открытой сессии Claude) и больше ничего не печатает и не переключает:
```
cd <АБСОЛЮТНЫЙ_ПУТЬ_К_РЕПО> && claude -p --verbose --model <sonnet|opus> --dangerously-skip-permissions "Твой заход — файл <ПОЛНЫЙ_АБСОЛЮТНЫЙ_ПУТЬ>/kod_<тема>.md. Прочитай ТОЛЬКО его и то, что он называет; остальной проект не изучай. План/вопросы/отчёт пиши в этот же файл внизу (## ПЛАН / ## ВОПРОСЫ / ## ОТЧЁТ). Ничего сверх задачи не трогай." 2>&1 | tee /tmp/zahod-<тема>.log
```
🔴 **`--verbose` обязателен в паре с `-p`.** Голый `-p` молчит от старта до итога: живой прогон, зависший прогон и оборванный интернет выглядят на экране ОДИНАКОВО — пустой строкой с курсором. Владелец при этом не может ни ждать осмысленно, ни прервать вовремя. `--verbose` печатает ход работы, и молчание снова начинает что-то значить. *Цена: первый же прогон канала 28.07 владелец счёл несработавшим и написал «по-моему, ничего не сработало» — заход в этот момент работал нормально.*
🔴 **`-p` — не украшение, а суть канала: заход РАЗОВЫЙ, диалога нет.** Без `-p` открывается сессия-чат, которая после работы ждёт следующего сообщения и не закрывается сама — владельцу приходится её гасить, а канал по замыслу «отправил и забыл». С `-p` агент отрабатывает и выходит в терминал сам. Вопросы исполнителя от этого не теряются: они и так уходят не в чат, а в секцию `## ВОПРОСЫ` файла-захода — там их берёт приёмка.
**`tee` в лог обязателен именно потому, что никто не смотрит.** Упал прогон — в файле-заходе не будет ни отчёта, ни следа; лог — единственное место, где видно, на чём он умер.
🔴 **Здесь МОДЕЛЬ — флаг, а не фраза, и это главное приобретение канала.** В варианте B строка «Модель: Sonnet» — пожелание владельцу переключить модель руками в интерфейсе: место для ошибки есть, и оно уже стреляло (см. курсив ниже). Флаг `--model` печатать нечего и забыть нечего — тот же приём «убрано место для ошибки», что со счётчиками и с самим стартовым блоком. Ветку/worktree в командную строку НЕ выносим: исполнитель берёт её первым ходом из §0 захода, иначе у одного решения два дома.

**B. ПРИЛОЖЕНИЕ (Claude Code в десктопе)** — когда работаем не из терминала:
```
Модель: <Sonnet | Opus> — <одна фраза почему>.
Claude Code, твой заход — файл <ПОЛНЫЙ_АБСОЛЮТНЫЙ_ПУТЬ>/kod_<тема>.md. Прочитай ТОЛЬКО его и то, что он называет; остальной проект не изучай. <Точка отката: git-коммит / zip-бэкап сразу.> План/вопросы/отчёт пиши в этот же файл внизу (## ПЛАН / ## ВОПРОСЫ / ## ОТЧЁТ). Ничего сверх задачи не трогай.
```

🔴 **КАНАЛ — ПАРАМЕТР СРЕДЫ ВЛАДЕЛЬЦА, А НЕ ВЫБОР АНАЛИТИКА.** У `bootstrap_zahod.py` есть флаг `--kanal terminal|app` ровно для этого, и дефолт `terminal` молча выбирает за владельца. Спрашивать, чем он работает сейчас, — часть сборки захода. *Цена 03.08: аналитик дважды подряд напечатал терминальную строку владельцу, работавшему в приложении; обе инструкции были нерабочими, и он сказал прямо: «мы сейчас Claude Code не через терминал используем, а через встроенную систему».*

🔴 **ФАЙЛ-ЗАХОД ЖИВЁТ В ОДНОМ ЭКЗЕМПЛЯРЕ — В ОСНОВНОЙ ПАПКЕ, ПО ТОМУ АБСОЛЮТНОМУ ПУТИ, ЧТО НАЗВАН В СТАРТОВОЙ СТРОКЕ.** Туда исполнитель пишет `## ПЛАН`, `## ВОПРОСЫ`, `## ОТЧЁТ` и `## УРОКИ ФАБРИКЕ`. Worktree заводится **только под код**; файл-заход в его зону коммита НЕ входит и коммитит его аналитик при приёмке.

*Почему именно так, а не наоборот.* 03.08 канон полсуток простоял в обратной редакции — «пиши в worktree, приёмка перенесёт `adopt`». Она логична (у отчёта один дом, он едет вместе с кодом) и на практике негодна: **worktree недоступен ни владельцу в чате, ни аналитику в песочнице**, поэтому приёмка трижды подряд открыла файл в основной папке, увидела пустые секции и объявила, что отчёта нет. Первый раз это стоило круга с переспросом исполнителя; дальше владелец каждый раз перекладывал файлы руками и сказал прямо: *«давай сделаем, чтобы больше такого не было — чтобы мне не приходилось что-то перекладывать вручную»*.

🔴 **Правило, из которого это следует и которое шире отчётов: канал доставки выбирается по тому, у кого есть ДОСТУП, а не по тому, где логичнее лежать.** Артефакт в месте, куда читатель не дотягивается, не существует — ровно как документ-сирота.

🔴 **`--dangerously-skip-permissions` (bypassPermissions) — решение владельца 28.07. Чем платим — назвать честно, потому что гейта у этого нет.** Порча файлов не страшна: зона очерчена, репо под git, откат дёшев. Страшно другое: заход, который читает ВНЕШНЕЕ — PDF источника, веб-страницу, чужой репозиторий, — выполнит инструкцию, лежащую в этом тексте, не спросив владельца, потому что спрашивать больше некого. Компенсация не в разрешениях, а в отчёте: §5 шаблона захода требует отдельным списком назвать КАЖДОЕ необратимое действие, и это **единственное** место, где владелец о них узнаёт. Считать это гейтом нельзя — это объявленная слепая зона (`KONSTITUCIYA §11`: нарушать нельзя МОЛЧА, а не нельзя вообще).

*Почему каналов два, а не один: 28.07 лимиты подписки на приложение кончились посреди работы над лекцией, и канал «терминал + API-ключ» стал основным за час. Переключение стоило бы дёшево, если бы стартовый блок печатался — а он в тот момент печатался только в форме A.*

## Термины — глоссарий держит АНАЛИТИК, исполнитель сдаёт хенд-оффом (решение владельца 2026-07-17)

**Правило (у проекта с глоссарием — напр. `<курс>/spravochnik/TERMINY-russkie.md`):**
1. **Термин ищем, только если его НЕТ в глоссарии.** Глоссарий выше веба; веб — только для отсутствующего. **Нашёл — сразу дописал строку.** *Почему:* иначе один и тот же термин ищется по десятому разу, и каждый раз заново.
2. **Пишет в глоссарий тот, кто им занимается.** По умолчанию это **аналитик**: глоссарий — гейт финального текста, его держит тот, кто текст выдаёт.
3. **Исполнителю Code в глоссарий НЕ писать; из зоны захода TERMINY исключать ЯВНО.** *Почему:* (а) гонки записи — 17.07 исполнитель обнаружил в файле несохранённую live-правку аналитика и правильно отступил; (б) исполнитель не должен вылезать в документацию.
4. **Взамен — перенос термина есть ШАГ ПРИЁМКИ, тут же.** Термины — частный случай хенд-офф-долга; правило и его цена — в §Приёмка шаг 2, здесь не повторяются.
5. **Гейт терминов начинать с грепа полнотекстового источника проекта, а не с веба** — дешевле и авторитетнее. ⚠ Но `grep = 0` **не доказывает отсутствия** (см. врезку ниже).

## ⛔ ГРЕП ПО КОРПУСУ ДОКАЗЫВАЕТ ПРИСУТСТВИЕ, НО НЕ ДОКАЗЫВАЕТ ОТСУТСТВИЕ (2026-07-17)

**`grep = 0` в PDF-корпусе не значит ничего.** Текстовый слой ломает искомое тремя способами — все три пойманы на живых файлах:

| Поломка | Пример |
|---|---|
| **OCR греческих букв** | «π(X)» читается как «7г(Х)» (рус. Маклейн) — три захода грепали мимо |
| **Разрядка** | имя студента у Ловера набрано `d a n i l o` — греп по `Danilo` = 0 |
| **Перенос строки** | у Awodey «A natural\nnumbers object» — греп по фразе на странице = 0 |

**Цена уже заплачена:** дайджест волны 1 записал «у Ловера NNO нет» на основании `грep("natural numbers object") = 0`. **Ложь** — предмет есть, в Part III, до всяких УС, и это самый дешёвый вход из четырёх источников. Заход, посланный искать NNO, ходил мимо якоря №1 проекта.

## Приёмка отчёта — ЖЁСТКИЙ РИТУАЛ (каждый раз, когда пришёл отчёт от исполнителя)

### 🔴 ПЕРВАЯ СТРОКА ПРИЁМКИ — ПЕРЕНЕСТИ КОД К СЕБЕ

**Отчёт переносить не надо:** файл-заход существует в одном экземпляре, в основной папке (§Два канала запуска), и приёмка читает его сразу. Переносится только **код**, который заход коммитил в свою рабочую папку, — **пофайлово**:

```
python3 _generator/tools/git_zona.py adopt --branch zahod/<тема> --zone <путь-файла> --yes
```

⚠ **Пофайлово, а не одной командой по всей зоне.** `adopt` заменяет рабочую копию версией ветки; широкая зона рядом с чужой незакоммиченной работой стирает её МОЛЧА. *Цена 03.08: в `_generator/tools` лежала незакоммиченная правка владельца из параллельного чата (второй судимый корень `obzory/` в двери регистрации); `adopt --zone _generator/tools` уничтожил бы её без следа.*

*Почему шаг вообще понадобился: 03.08 приёмка трижды подряд открыла файл-заход в основной папке, увидела пустые секции и решила, что отчёта нет. Отчёт был — в worktree. Первый раз это стоило круга с переспросом исполнителя.*

### 🔴 ВТОРАЯ СТРОКА — КОМАНДА, А НЕ ЧТЕНИЕ

```
python3 _generator/tools/priyomka.py <путь к kod_*.md>
```

Она прогоняет **семь машинных гейтов** (зона доехала в git · хэш коммита существует · строка `АРТЕФАКТ` не плейсхолдер · артефакт не старше источника · `## ОТЧЁТ` и `## ПЛАН` непусты · уроки исполнителя несут `ЦЕНА:` · упоминания урока в дневнике имеют пару в доме уроков), `exit 1` на любом красном, и отдельным блоком **печатает для рук** то, что машина проверить не может: вопросы исполнителя целиком, его уроки, числовые утверждения об артефакте и чек-лист оставшихся шагов.

**Шаги ниже — не инструкция к исполнению по памяти, а объяснение, ЗАЧЕМ каждый гейт существует и что делать с печатью.** Читать их подряд на каждой приёмке не нужно; нужно прогнать команду и разобрать то, что она вывела.

*Почему первая строка появилась только 03.08, хотя ритуал описан давно: из шести шагов носитель был ровно у одного — шага 0. Остальные пять держались на внимательности аналитика, и владелец проговаривал их голосом на КАЖДОМ отчёте — дословно: «обязательно всё консолидировать, обязательно всё разнести по домам, обязательно сразу после приёмки отчёта». Правило, которое приходится произносить вслух на каждом применении, механизмом не является (`../KONSTITUCIYA.md §11`). Цена измерена этим же разделом: 0 из 8 вопросов исполнителей дошло до владельца, 1 из 17 уроков — до канона.*

⚠ **Чего команда НЕ проверяет — названо поимённо, а не забыто.** Верификатор охвата (свежий субагент, только канон + код) нашёл одиннадцать пробелов; восемь оставлены сознательно, потому что это суждения аналитика — выполнен ли критерий по существу, обоснованы ли решения, соблюдена ли SPEKA. Механизировать их значит имитировать проверку. Три остались долгом: соблюдение границ зоны, эвристика «тихого недобора», наличие охвата у положительного вердикта.

Неважно, как оформлен отчёт и какими словами владелец сказал «пришёл отчёт / прими». ВСЕГДА, по порядку — пять шагов:
0. **🔴 ГЕЙТ «РАБОТА ДОЕХАЛА В GIT» — ПЕРВЫМ, ДО ЧТЕНИЯ ОТЧЁТА.** Гоняет Cowork САМ, одной командой, на живых файлах:
   ```
   python3 _generator/tools/git_zona.py check --zone <зона захода>
   ```
   Красный (exit 1) → **отчёт не принимается**, что бы в нём ни было написано. Исполнитель обязан либо закоммитить свою зону, либо назвать ВНЕШНЮЮ причину отдельной строкой отчёта («коммита нет, причина такая-то, нужно ваше действие»). Молчаливое «сделано» при грязной зоне — брак.
   *Почему гейт стоит ДО отчёта, а не среди прочих: «файл написан» и «файл в git» — разные состояния, и второе не проверял никто. За одну сессию арки `mat-kostyak` работа не доехала ТРИЖДЫ; в Ф2 исполнитель закоммитил, в Ф2.1 забыл — и это всплыло только на приёмке. Гейт в `ARKA §6` (хэндофф чат→чат) срабатывал СЛИШКОМ ПОЗДНО: между заходом и хэндоффом успевало пройти несколько заходов.*
   ⚠ **Никаких голых `git status` из Cowork.** Обычный `git status` переписывает индекс и берёт `.git/index.lock` — тем самым роняет ручной коммит владельца. Все git-вызовы `git_zona.py` идут с `--no-optional-locks`; свои разовые — тоже. *Цена: три сорванных коммита за одну сессию, причём ронял их ровно тот гейт, который проверял, что работа доехала.*
1. **Гейты (все обязательны).** Критерий выполнен · **хэш коммита в отчёте есть и он существует** (`git --no-optional-locks show --stat <хэш>`) · **числа отчёта ВОСПРОИЗВЕДЕНЫ командой на живом артефакте, а не «сходятся»** (см. врезку ниже) · границы соблюдены · **SPEKA соблюдена** (охват полон, формат-отклонения выдержаны — для курс-проекта) · решения обоснованы · вопросы исполнителя разобраны · верификатор/регрессия зелёные · **время + токены** · **нет тихого недобора** (стоп до цели заявлен громко). Объективные гейты (линтер/верификаторы/зона коммитов) Cowork перегоняет САМ на живых файлах, не на слово. Отчёт может долетать МИД-ФЛАЙТ (на диске — только точка отката) → перечитай живое состояние (git/диск) перед вердиктом. Токены среда могла не отдать — раскрытая деталь, не нарушение. Санити дешёвый (`tree`/`grep`), не построчно. Дисциплинированное НЕ-действие — ХОРОШО. Вердикт: **принять** ИЛИ **вернуть на точечную дочистку**. Вопрос без ответа → в начало следующего захода.
   🔴 **Всякое числовое утверждение отчёта об АРТЕФАКТЕ приёмка перегоняет по артефакту САМА.** Не «числа сходятся» (это про арифметику внутри отчёта), а «число отчёта воспроизведено командой на живом файле». *Цена 29.07: отчёт ленты заявил «106 блоков **с адресами**» — греп по номерам блоков в самой ленте ПУСТ, трассировки «слайд → блок» в артефакте нет вовсе. Приёмка приняла заявление, не проверив; долг всплыл только при закрытии арки. Тот же субагент нашёл, что в ленту напечатано отнесённое конспектом к устному: 16 строк доказательств, фразы из служебных полей, одна из четырёх секций «Слайда нет» и сочинённая обложка.*
   🔴 **Охват называется и у ПОЛОЖИТЕЛЬНОГО вердикта тоже.** Клауза 2 гейта требует охват у отрицательного («дыр не найдено, проверено X из Y»); у положительного он нужен ровно так же. *Цена: «список из четырёх классификационных результатов проверен» означало проверку ОДНОГО; он оказался ложным, а три остальных «никем не сверены и стоят на слайде» — долг передан дальше по арке и всплыл двумя заходами позже. «Это ровно тот жанр, где ошибка прячется.»* Образец честной формы, взятый из живого отчёта: «просмотрено 14 кадров из 56; **42 кадра не видел никто**».
1½. **🔴 АРТЕФАКТ — ВЫВЕСТИ ВЛАДЕЛЬЦУ КАРТОЧКОЙ, В ТОМ ЖЕ СООБЩЕНИИ, ЧТО И ВЕРДИКТ.** Заход собрал файл, который смотрят глазами (колода, документ, PDF, картинки) → приёмка не закрыта, пока Cowork не сделал ДВА хода: (а) проверил, что файл **не старше** своего источника, (б) отдал его владельцу `present_files` плюс абсолютным путём строкой. Отчёт без строки `**АРТЕФАКТ:**` возвращается исполнителю — на коммите это же ловит `check_uroki.py`.
   🔴 **Путь артефакта — ОТ КОРНЯ РЕПОЗИТОРИЯ, а не абсолютный путь рабочей папки захода.** *Цена 03.08: отчёт назвал артефакт как `materials-wt/priyomka-mehanizm/_generator/tools/priyomka.py`; после переноса зоны в основную папку worktree исчез, и гейт Г3 покраснел на живом, полностью исправном файле. Абсолютный путь во временной папке протухает при первом же переносе — то есть ровно тогда, когда отчёт начинают читать.*
   ⚠ **Свежесть проверяется, а не предполагается:** `ls -la` по артефакту и по источнику. Артефакт старше источника = сборка молча не запускалась, и владелец откроет прошлое состояние.
   *Цена 31.07, одна сессия: собраны колода слайдов, вид ленты и три документа — **ни одного пути не было названо**, и владелец сказал прямо: «я всё время не могу найти твои новые файлы». Дороже: `sverstat.py` штатно возвращает ненулевой код, цепочка `porodit && sverstat && build_deck` оборвалась ПЕРЕД сборкой, владелец открыл вчерашнюю колоду и заключил, что правка не сработала — круг диагностики поломки, которой не было. Оба провала лечит один и тот же ход: назвать путь и сверить время.*
2. **🔴 Запись — и ЗАКРЫТИЕ ХЕНД-ОФФ-ДОЛГА ТУТ ЖЕ, не «потом».** Вся новая информация (решения, находки, отклонения, вопросы, помарки) → в документы СРАЗУ (дневник арки; при закрытии — durable по домам). «Осталось только в чате — потеряно.»
   **Хенд-офф-долг — общий закон, а не частность терминов.** Контракт зоны запрещает исполнителю писать в чужой дом ⇒ он сдаёт находку хенд-оффом ⇒ **перенести обязан аналитик, ТЕМ ЖЕ ходом. Отложил = потерял.** Четыре дома, четыре одинаковых провала за сутки:

   | Дом | Что сдаётся | Цена |
   |---|---|---|
   | глоссарий (`<курс>/spravochnik/TERMINY-russkie.md`) | термины из разведки | два захода подряд копили, аналитик не переносил. ⭐ Когда перенёс — глоссарий **поймал ДВЕ кальки на пути в письмо заказчику** («эквалайзер» вместо «уравнитель», «комма-категория» вместо «категория запятой») |
   | владелец | вопросы исполнителя | 8 накопилось в `kod_*.md` — **0 дошло, 6 протухло**. Владелец файлы-заходы не читает **ПО УСТРОЙСТВУ** |
   | `istochniki/MANIFEST` · `SPISOK-skachat` | найденные источники | 8 книг лежали невлитыми |
   | канон фабрики | уроки о самой фабрике | **17 секций «→ фабрика» за сутки, дошла ОДНА** (§Хук ниже) |
   | **следующий заход** | **выход предыдущего захода как ВХОД** | **результат ночного ресёрча лежал в досье и до дека не дошёл. Владелец на репетиции: *«У нас был ночной заход на поиск. Он куда-то пропал, по-моему. По крайней мере, не вижу результатов»*. Потерян был не результат, а СВЯЗЬ с ним; плюс 8 адресов «это уже было написано / я это устно сказал», и один слайд недосчитался половины содержания** |

   ⇒ **Пятый дом — самый дорогой, и правило у него то же: результат захода без АДРЕСА в целевом артефакте не существует.** Проверка — грепом по артефакту, а не чтением отчёта (см. врезку в шаге 1).

   ⇒ Прежняя формулировка «иначе термин потерян» **СЛАБЕЕ правды**: не потерян — **уехал наружу в виде кальки**. Перенос термина — **гейт исходящего текста, а не учёт**.
   **Проверка шага (может провалиться):** в отчёте есть слово «термин» → в глоссарии появилась строка? есть вопрос владельцу → он ЗАДАН владельцу, а не оставлен лежать в файле-заходе? найден источник → он в `MANIFEST`? Нет — шаг не закрыт.
2½. **🔴 ЗАКРЫТЬ ВЕТКУ ЗАХОДА — ТЕМ ЖЕ ХОДОМ, ЧТО И ПРИЁМКА.** Заход отработал ⇒ его ветка больше ничего не держит, её содержимое уже перенесено шагом 0. Держать её — значит копить. **Перенос и удаление — РАЗНЫЕ действия, и путать их нельзя:** перенос обязателен сразу, удаление можно откладывать; параллельная работа мешает только второму.
   ```
   python3 _generator/tools/git_zona.py poteri --branch zahod/<тема>   # что пропадёт; rc=1 — НЕ удалять
   ```
   **Удаление идёт только через метрику, НИКОГДА через `git branch -d`:** стандартная команда судит по истории и откажет там, где терять нечего, потому что работа у нас доезжает копированием содержимого, а не слиянием.
   *Цена откладывания, замер 03.08: за одну сессию накопилось 17 веток при пяти живых; из них 12 не теряли при удалении ничего. Любой сторож на такой куче становится шумом по построению — не потому что плохо написан, а потому что сторожить дюжину мёртвых объектов бессмысленно.*
   **Ветка, у которой `poteri` даёт `rc=1`, не удаляется никогда** — она уезжает строкой в хэндофф: «висит столько-то с неперенесённой работой, старейшая от такой-то даты».

3. **Пересказ человеческим языком.** Владельцу, простыми словами, максимально понятно: что сделано, что обнаружено, что осталось. НЕ прятать в термины, НЕ пропускать — это частая ошибка.
4. **Рефлексия (короткая, ВСЕГДА).** После реакции владельца Cowork САМ спрашивает: «что здесь было не так и что можно поправить — в заходе / процессе / фабрике?». Не ждать, пока попросят.
5. **Хук «→ фабрика» — ОДНА строка в `UROKI-FABRIKE.md` арки: факт + ЦЕНА. НЕ правка канона** (§Хук ниже: править канон посреди приёмки дорого — потому этого и не делали).

## Хук «→ фабрика» — почему трёх хуков было мало и что вместо них

**Факт, из которого это правило выросло: у фабрики было ТРИ хука «→ фабрика» (после отчёта · хэндофф · закрытие арки). За трое суток они сработали ~1 раз из ~12 возможных — написано 17 секций «→ фабрика», до канона дошла ОДНА.** Проверяется в две команды: `grep -rn "<формулировка урока>" _studio/docs/` (0 файлов) и `git log --since=<начало арки> -- _studio/docs/` (один коммит за трое суток, и не про уроки).

**Три хука доставили меньше, чем один.** Каждый был диффузией ответственности («поймает следующий»), и каждый требовал ДОРОГОГО действия — консолидирующей правки канона — в момент, когда занят другим. Дорогое пожелание не исполняется никогда. «Сделать хуки жёстче» — это то же правило-пожелание в четвёртый раз (`../KONSTITUCIYA.md §11`), поэтому механизм разнесён ПО ЦЕНЕ:

| Когда | Что ДЕЛАЕТСЯ | Цена действия |
|---|---|---|
| **исполнитель, по ходу захода** | секция `## УРОКИ ФАБРИКЕ` в СВОЁМ `kod_<тема>.md` (вшита `bootstrap_zahod.py`): факт + `ЦЕНА:`. **Пишет сам — переносить аналитику не надо** | 0 |
| **после каждого отчёта/хода** (бывш. хук A) | ОДНА строка в `UROKI-FABRIKE.md` арки: **факт + ЦЕНА** (что сломалось и сколько стоило). Не формулировка закона и не правка канона | ~минута |
| **конец сессии** (бывш. хук B) | **ничего отдельного — хук УДАЛЁН.** Он дублировал A и создавал иллюзию второго шанса | 0 |
| **закрытие арки** (бывш. хук C) | **ОТДЕЛЬНАЯ сессия с ПУСТЫМ контекстом:** читает только `UROKI-FABRIKE.md` + канон, выносит вердикт по КАЖДОМУ уроку, правит канон **КОНСОЛИДИРУЯ** (удалить/слить/переписать — можно; терять накопленное и плодить свалку — нет) | сессия |

**Почему вердикт выносит не тот, кто урок записал.** Автор уроков — **лицо заинтересованное**: ему приятно, если его формулировка станет законом, и красивый заголовок от него подозрителен by design. Из механизмов, которые за арку реально ловили аналитика, самый надёжный — **вынос задачи исполнителю с пустым контекстом** (поймал дважды подряд). Поэтому в файл пишется ФАКТ и ЦЕНА, а ЗАКОН формулирует свежая сессия. **Отбраковать слабый урок — результат сессии, а не её провал:** девять законов, вписанных плохо, хуже трёх, вписанных точно, — канон читают ВСЕ будущие проекты, и плохое правило тиражируется.

**Почему исполнитель пишет САМ, а не сдаёт хенд-оффом.** Прежняя цепочка «исполнитель → `## ОТЧЁТ` → аналитик переносит» — это хенд-офф-долг, тот самый, что дал 0/8 по вопросам и 1/17 по урокам. Звено убрано: `kod_<тема>.md` **уже в зоне исполнителя** (проверено по живым заходам, а не по прозе канона), так что писать туда он вправе без расширения зоны и без гонок с параллельными заходами. И пишет тот, у кого ПУСТОЙ контекст, — единственный, кто за арку ловил аналитика дважды подряд. Закрывающая сессия собирает оба источника:
```
grep -A4 '^### ' <арка>/UROKI-FABRIKE.md                    # уроки аналитика
grep -A4 -h '^### ' <арка>/kod_*.md | ...                   # уроки исполнителей (секция ## УРОКИ ФАБРИКЕ)
grep -c '^### ' vs '^ВЕРДИКТ: ' <арка>/UROKI-FABRIKE.md      # разошлось ⇒ арка НЕ закрыта (ARKA §7)
```
🔴 **Заголовок урока — ТОЛЬКО `### `, и пример формата в шапке файла сдвинут внутри кодового блока.** Оба требования оплачены на арке `2026-07-28_konspekt-l1`: три урока с живой ценой были написаны как `## Урок N.` и **не входили в гейт ни строкой** — ни в греп, ни в `check_uroki.py`, который считает той же регуляркой; а образец `### N. <…>` / `ЦЕНА: <…>` / `ВЕРДИКТ: <…>`, стоявший в шапке от нулевой позиции, добавлял по единице каждому из трёх счётчиков и гасил расхождение ПО СОВПАДЕНИЮ, а не по замыслу. Итог: файл выглядел «17 уроков / 18 цен / 1 вердикт», а на деле нёс 17 уроков, 17 цен и 0 вердиктов.

**🔴 В ДНЕВНИКЕ НЕЛЬЗЯ ПИСАТЬ «урок фабрике» — только ссылку на уже записанный.** Урок пишется СРАЗУ в `UROKI-FABRIKE.md`, в `SESSIYA.md` остаётся адрес. Иначе он не существует: закрывающая сессия дневник НЕ читает **по устройству** — это цена самоценности входа, а не небрежность. Проверяемо грепом на закрытии, и это гейт, а не пожелание:
```
grep -in "урок" <арка>/SESSIYA.md      # каждое совпадение обязано иметь пару в UROKI-FABRIKE.md
```
🔴 **Греп — РЕГИСТРОНЕЗАВИСИМЫЙ и по ОДНОМУ слову, и это оплачено.** Прежняя форма `grep -n "урок фабрике\|УРОК ФАБРИКЕ"` на живом дневнике арки `2026-07-28_konspekt-l1` дала **rc=1, ноль совпадений — то есть гейт был ЗЕЛЁНЫМ**, при том что `grep -in "урок"` находит четыре строки и **две из них — готовые уроки с ценой, которых в доме уроков нет**: «пересказ владельца своими словами есть место рождения ошибок» и «устаревший черновик `.commit-plan` блокирует коммит владельца — владелец потерял два захода на попытки». Не ловилось потому, что в дневнике написано «**У**рок **фабрике**»: заглавная «У» при строчном «фабрике» не покрывается ни одной из двух альтернатив. Терпимая форма ловит лишнее — и это ПРАВИЛЬНАЯ сторона ошибки: ложное срабатывание стоит одного взгляда, пропуск стоит урока. *Спасли эти два урока не гейт, а то, что закрывающая сессия усомнилась в ФОРМЕ гейта; предыдущий раз шесть уроков спасла случайность сплошной вычитки — то есть механизм не срабатывал ни разу за два применения.* *Цена: две записи дневника объявили «три урока фабрике» и «три ложные предпосылки» — с ценами, полностью готовые, — и ни один из шести в дом уроков не попал. Шесть оплаченных уроков были обречены умереть вместе с аркой и умерли бы МОЛЧА; спасла случайность — вычитка при закрытии шла сплошной.*

**Уроки собираются СПЛОШНО — исключение «`kod_` регенерируемы» на них не распространяется.** Правило консолидации законно считает файлы-заходы регенерируемым сырьём и исключает их из сплошной вычитки; секцию `## УРОКИ ФАБРИКЕ` внутри такого файла читать ВСЕГДА: заход регенерируем, **оплаченный урок — нет**. *Цена: семь уроков с ценой лежали в `kod_`-файле закрытой арки и попали в класс «сырьё, не читаем»; спасены только тем, что вычитка в тот раз шла сплошной.*

**Гейт с зубами — в pre-commit, а не в уговоре:** `python3 ../../../_generator/tools/check_uroki.py` красит ❌ на урок без `ЦЕНА:` в арке, которую трогает коммит. Ставится один раз: `git config core.hooksPath .githooks`. Проверяет только тронутые арки и молчит, когда чисто, — иначе его отключат, и это будет конец затеи. Урок с `ВЕРДИКТ:` не пересматривает: его уже отсудила закрывающая сессия.
*Обойти — `git commit --no-verify`. Это не дыра: закон (`../KONSTITUCIYA.md §11`) запрещает нарушать МОЛЧА, а не нарушать. `--no-verify` придётся напечатать руками.*
*Чего гейт НЕ проверяет (клауза 3): что цена настоящая, что урок вообще записан (молчание не отличить от «уроков не было») и что он доехал до канона. Считает строки, не правду.*

Цель владельца прежняя: замечания уходят не только в историю ПРОЕКТА, но и правят саму ФАБРИКУ — курсы тестируют фабрику, каждый прогон её улучшает.

## Верификатор (для потерь/перемещений)
Лоссовая операция (синтез/сжатие/архивация/удаление) или правка путей → встрой ОТДЕЛЬНЫЙ свежий субагент-верификатор как ГЕЙТ: «исходный смысл → новый дом» полно (список потерь ПУСТ); каждая ссылка резолвится (битых 0, программно). **Ключ — ДРУГОЙ субагент и ДРУГОЙ метод** (читает оригиналы из бэкапа/`git show`, проверяет программно): у автора правок слепые пятна.

🔴 **Два ТИПА верификатора, и второй идёт ПЕРВЫМ ходом.** ПОСЛЕ-верификатор судит результат (сохранность, потери, битые ссылки) и стоит в конце. **ДО-верификатор судит СОСТОЯНИЕ, которое работа уничтожит** — и после работы неисполним. Порядок разделов файла-захода исполнитель читает как порядок действий, поэтому тип называется прямо в задании. *Цена: заход разреза нёс ДО-верификатор («пройди по 39 секциям и назови, где граница жёсткая»); запущенный по порядку файла, он не сработал бы вовсе — после разреза секций 32, и ровно те границы, о которых нужен вердикт, исчезают вместе со слитыми слайдами. Запущенный первым, он дал 9 расхождений из 38 границ, четыре приняты, четыре слияния отменены — то есть ИЗМЕНИЛ результат работы, а не подтвердил его.*

🔴 **Критерий «текст понятен» не проверяется автором текста ни в каком виде: проверяющий обязан НЕ ВИДЕТЬ источника.** Автор достраивает недостающее из головы, потому что помнит источник. *Цена: самопроверка автора ленты по критерию полноты дала «неполных формулировок 0»; свежий читатель, не видевший конспекта, нашёл **26 мест** — 10 «непонятно, что происходит», 5 немотивированных переходов, 11 оборванных формулировок, — и исполнитель честно переписал свой вердикт на «не 0, а 5». Самая дорогая находка: «Долг из введения» ссылался на факт, которого на слайдах не было нигде, и на том же неувиденном факте стояла строка таблицы другого слайда.* Это тот же закон, что «вердикт по уроку выносит не автор урока» (§Хук ниже), распространённый с уроков на текст.

🔴 **Программная самопроверка называет, ЧТО именно она доказывает. Обратимость ≠ правильность.** Массовая замена по регекспу проверяется вторым, НЕЗАВИСИМЫМ инвариантом (парность разделителей, число вхождений класса символов), а не только откатываемостью. *Цена: замена с `"$\1"` — где `\1` не обратная ссылка, а восьмеричный `\x01` — удалила 115 знаков пунктуации из 43 файлов; «гейты молчали: html не появился, overflow не изменился», нашлось только глазом на кадре. Вторым витком то же правило зацепило открывающий `$` формулы, и **«моя же проверка на обратимость это пропустила»**.*

🔴 **Речь как источник — ДВА независимых движка со сверкой, совпадение печатается числом.** *Цена: один движок на одном акте потерял **309 слов из 1002 — треть акта** (совпадение 0,768); из выброшенного восстановлены вся арифметика бюджета («самое решающее число дня, и в предыдущей версии сводки его НЕ БЫЛО»), системный дефект перечней и три поправки порядка. Без словаря терминов движок написал «объекция» **11 раз** вместо «биекции» — центрального термина слайдов, со словарём 24 раза и 0 искажений. И сводка по речи, собранная одним проходом, дала **220 претензий против 193 — 27 пропусков, 21 искажение и 1 фабрикацию**; два акта из шести вычитку не проходили вовсе, и это названо честно.* Дешевле не выходит: один проход даёт ~14 % пропусков, и обнаруживаются они только вторым.

**🔴 На большом корпусе верификатору задаётся ДОЛЯ ВЫБОРКИ, а не «получает сырьё».** «Пусть прочитает файлы 3–5 другим методом» на 736 позициях и 383 КБ означает «пусть повторит всю стадию» — верификатор дороже проверяемого, и он законно отступит от буквы твоего же обязательного гейта. Пиши явно: «**сплошная выборка не менее трети, назвать какая**» — и требуй охват ВНУТРИ вердикта (клауза 2 выше). *Цена: исполнитель дал сплошные 43 % и честно назвал это в `## ПЛАН` до работы; приёмка обязана была это заметить и могла не принять. А вердикт при таком гейте читается как «потерь нет», означая «потерь нет в проверенной половине» — формулировал заход аналитик.*

## Тип захода и «один риск за раз»
- **Мутирующий** (двигает/правит): откат по блокам (git/zip), сверка после каждого.
- **Аналитический** (только измеряет): данные не трогать; артефакт + предложения; решение — владельцу.
- **Организационный** (порядок папки/доков): содержание/архитектуру не менять.
Тяжёлое режь по риску: read-only АУДИТ → МУТАЦИЯ по плану → read-only СВЕРКА. Перемещение файлов — отдельным заходом с верификатором.

## Скелет захода
**Не пиши с нуля — сгенерируй:** `python3 ../../../_generator/tools/bootstrap_zahod.py <арка> <тема> --branch <ветка> --zone "<пути>"` → `kod_<тема>.md` с вшитым контрактом зоны (шаблон `../../zhurnal/_TEMPLATE-zahod.md`). Ниже — форма (что дозаполняет Cowork в `<...>`):
```
# Канал исполнителя — <КОРОТКОЕ ИМЯ> (один заход до конца)
> Твой единственный файл-заход. Читай ТОЛЬКО его и названные якоря; проект не изучай.
> План/вопросы/отчёт — в секции внизу. Метрика — КАЧЕСТВО. Часы — норма.

КОНТЕКСТ. <проект в 1–2 фразы>. Прошлый этап: <состояние>. ЦЕЛЬ: <что закрыть>.
Приёмка — по ОТЧЁТУ, без построчной сверки. <Если стоп до цели: получишь X, но НЕ Y.>
## 0. ПЕРВЫЙ ХОД. Рабочая папка <путь>; точка отката: git-коммит СВОЕЙ ЗОНЫ (`git add <пути>`, НЕ `-A`) ИЛИ zip;
   прочитать ТОЛЬКО <названные файлы> — для курс-проекта `<курс>/SPEKA.md` ПЕРВОЙ (охват/формат/роутер — истина проекта); ПЛАН — в ## ПЛАН перед действиями.
## 1. ДИСЦИПЛИНА (Карпатов). Предпосылки/развилки назвать; минимум без спекуляций; хирургия
   (строка → к заданию); критерий, который может провалиться. Якорные замены — abort при ≠1.
   Сохранять по умолчанию. Оспорить ложную предпосылку — **включая КРИТЕРИЙ ГОТОВНОСТИ, в `## ПЛАН`, ДО работы**
   (*заход `molchalivye-opory`: мой критерий в буквальном чтении объявлял дырой 12 строк из 37 — назвал до работы,
   применил поправку, в отчёте пригласил возразить. Обратная цена — ход 7: плохой критерий, который никто не
   оспорил, дал «дыр нет» на 2 лекциях из 9*). Субагенты: ≤5, рейт-лимит=отступить+доложить.
## 2. ВЕТКА + ЗОНА + ГРАНИЦЫ. <ВЕТКА: `git checkout <ветка>` первым ходом; не назвали — спроси, чужую не трогай/не переключай>. <ЗОНА: пути, которые МОЖНО менять — обычно своя папка + свой дневник; всё вне — read-only: не править/двигать/удалять>. git: коммить ТОЛЬКО зону (`git add <явные пути>`), НИКОГДА `-A`/`commit -am`; авто-коммит — тоже по явным путям; субагенты не коммитят.
## 3. ЗАДАЧА. <конкретно>. КРИТЕРИЙ ГОТОВНОСТИ: <условие, которое (1) называет артефакт, который ПОКРАСНЕЕТ,
   (2) требует «проверено X из Y» внутри отрицательного вердикта — три клаузы гейта см. §Заход>.
## 4. ВЕРИФИКАТОР (если двигаем/теряем). Свежий субагент, ДРУГОЙ метод, сверка с бэкапом, программно.
## 5. ОТЧЁТ → секция ## ОТЧЁТ внизу: что сделал+ЗАЧЕМ / как проверил / что НЕ трогал / вопросы /
   результат верификатора / **время прогона + токены**.

## ПЛАН — (заполняет исполнитель)
## ВОПРОСЫ — (заполняет исполнитель)
## ОТЧЁТ — (заполняет исполнитель)
```

## Когда НЕ усердствовать
Тривиальный заход (одна правка строки, опечатка) — без церемоний, не спрашивай трактовку «почини опечатку». Эвристика: усердие там, где цена ошибки — переделка; быстро там, где откат дёшев.
