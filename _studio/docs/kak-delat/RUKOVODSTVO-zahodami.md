# RUKOVODSTVO-zahodami — как вести исполнителя (заход + приёмка)

> **КОГДА читать:** когда готовишь заход исполнителю (субагент через Agent tool или Claude Code). · **ЧТО дописывать сюда:** только методологию захода. · **КУДА дальше:** `ARKA.md §5`.

## Единственный принцип
**Состояние живёт на диске (доки проекта + файл-заход), не в памяти сессии.** Исполнитель стартует с ПУСТЫМ контекстом. Отсюда: заход **самодостаточен** (вход, что прочитать, что сделать, как отчитаться — внутри текста), **один заход = одна задача**, durable — сразу в дома.

## Заход — дай всё, иначе соберёт не то
- Несёт ВСЁ: рабочая папка, что прочитать ПОИМЁННО, что сделать, границы, как отчитаться. Явно: «читай только названное, проект не изучай».
- Существующие конвенции и имена — **авансом** → переиспользует, не изобретает своё.
- Есть ошибка/лог — вкладывай RAW и «почини», НЕ пересказ (пересказ теряет деталь).
- **Критерий готовности — условие, которое может ПРОВАЛИТЬСЯ:** «N файлов на местах, битых ссылок 0, регрессия/гейт зелёные», а не «я закончу».
- **Флаг «стоп до цели».** Если заход по замыслу останавливается ДО ожидаемого владельцем результата — скажи это громко и заранее одной фразой («получишь X, но НЕ Y; Y запускается так-то»).
- **Сверка перекрывающей зоны.** Трогает заход то, что только что закрыли, — сверься на живых файлах ПЕРЕД написанием; пометь «уже закрыто — проверить зелёным, не открывать заново».
- Лоссовый/двигающий заход → встрой верификатор (ниже).

## Субагенты — аккуратный режим
Вложенные — можно ОСМЫСЛЕННО и по плану, не случайный рой. Fan-out ≤~5 параллельно (крупную пачку — в очередь). Рейт-лимит = отступить и доложить, НЕ слепой ретрай. Назвать ЯВНО: сколько субагентов и на что. Дешёвое/механическое/параллельное — дешёвым моделям; тяжёлое суждение — сильной. Метрика — стоимость за успешный РЕЗУЛЬТАТ, не за токен.

## Модель в заход (первой строкой) и запуск
**Дефолт — Sonnet.** Opus — только когда рассуждение рождается В ХОДЕ исполнения (не то, что Cowork уже расписал заходом).

| Тип захода | Модель |
|---|---|
| Исполнительный, полностью расписанный (якорные замены, вставки, renumber, рендер/сборка, линтер) | **Sonnet** — механика; abort+верификатор ловят сбой |
| Исследовательский/неоднозначный («разберись и почини» без готовых якорей) | **Opus** — план рождается по ходу, меньше ретраев |
| Смешанный | план на Opus, механику на Sonnet (`opusplan`) |

Чем детальнее заход (точные якоря, критерий, границы), тем увереннее Sonnet — хороший заход удешевляет модель. Бюджет душит не 5-часовое окно, а **недельные капы** (проект из многих прогонов) → тиринг моделей + не разводить рой субагентов.

**Стандартный текст запуска (владелец → Claude Code; ПОЛНЫЙ путь + модель первой строкой):**
```
Модель: <Sonnet | Opus> — <одна фраза почему>.
Claude Code, твой заход — файл <ПОЛНЫЙ_АБСОЛЮТНЫЙ_ПУТЬ>/kod_<тема>.md. Прочитай ТОЛЬКО его и то, что он называет; остальной проект не изучай. <Точка отката: git-коммит / zip-бэкап сразу.> План/вопросы/отчёт пиши в этот же файл внизу (## ПЛАН / ## ВОПРОСЫ / ## ОТЧЁТ). Ничего сверх задачи не трогай.
```

## Приёмка — суди по отчёту, но проверь ГЕЙТЫ (все обязательны)
критерий выполнен · числа сходятся · границы соблюдены (запрещённое не тронуто) · решения обоснованы · вопросы исполнителя разобраны · верификатор/регрессия зелёные · **время прогона + токены в отчёте** · **нет тихого недобора** (стоп до цели должен быть заявлен громко). Дешёвый санити по живым файлам (`tree`/`grep`), не построчно. Дисциплинированное НЕ-действие (отказ от рискованной правки при нулевой пользе, вынесен в отчёт) — это ХОРОШО. Вердикт: **принять** ИЛИ **вернуть на точечную дочистку** (не переделывать всё). Вопрос без ответа → в начало СЛЕДУЮЩЕГО захода.

## Верификатор (для потерь/перемещений)
Лоссовая операция (синтез/сжатие/архивация/удаление) или правка путей → встрой ОТДЕЛЬНЫЙ свежий субагент-верификатор как ГЕЙТ: «исходный смысл → новый дом» полно (список потерь ПУСТ); каждая ссылка резолвится (битых 0, программно). **Ключ — ДРУГОЙ субагент и ДРУГОЙ метод** (читает оригиналы из бэкапа/`git show`, проверяет программно): у автора правок слепые пятна.

## Тип захода и «один риск за раз»
- **Мутирующий** (двигает/правит): откат по блокам (git/zip), сверка после каждого.
- **Аналитический** (только измеряет): данные не трогать; артефакт + предложения; решение — владельцу.
- **Организационный** (порядок папки/доков): содержание/архитектуру не менять.
Тяжёлое режь по риску: read-only АУДИТ → МУТАЦИЯ по плану → read-only СВЕРКА. Перемещение файлов — отдельным заходом с верификатором.

## Скелет захода
```
# Канал исполнителя — <КОРОТКОЕ ИМЯ> (один заход до конца)
> Твой единственный файл-заход. Читай ТОЛЬКО его и названные якоря; проект не изучай.
> План/вопросы/отчёт — в секции внизу. Метрика — КАЧЕСТВО. Часы — норма.

КОНТЕКСТ. <проект в 1–2 фразы>. Прошлый этап: <состояние>. ЦЕЛЬ: <что закрыть>.
Приёмка — по ОТЧЁТУ, без построчной сверки. <Если стоп до цели: получишь X, но НЕ Y.>
## 0. ПЕРВЫЙ ХОД. Рабочая папка <путь>; точка отката: git-коммит ИЛИ zip-бэкап сразу;
   прочитать ТОЛЬКО <названные файлы>; ПЛАН — в ## ПЛАН перед действиями.
## 1. ДИСЦИПЛИНА (Карпатов). Предпосылки/развилки назвать; минимум без спекуляций; хирургия
   (строка → к заданию); критерий, который может провалиться. Якорные замены — abort при ≠1.
   Сохранять по умолчанию. Оспорить ложную предпосылку. Субагенты: ≤5, рейт-лимит=отступить+доложить.
## 2. ГРАНИЦЫ. <что НЕ трогать>.
## 3. ЗАДАЧА. <конкретно>. КРИТЕРИЙ ГОТОВНОСТИ: <проверяемое условие, которое может провалиться>.
## 4. ВЕРИФИКАТОР (если двигаем/теряем). Свежий субагент, ДРУГОЙ метод, сверка с бэкапом, программно.
## 5. ОТЧЁТ → секция ## ОТЧЁТ внизу: что сделал+ЗАЧЕМ / как проверил / что НЕ трогал / вопросы /
   результат верификатора / **время прогона + токены**.

## ПЛАН — (заполняет исполнитель)
## ВОПРОСЫ — (заполняет исполнитель)
## ОТЧЁТ — (заполняет исполнитель)
```

## Когда НЕ усердствовать
Тривиальный заход (одна правка строки, опечатка) — без церемоний, не спрашивай трактовку «почини опечатку». Эвристика: усердие там, где цена ошибки — переделка; быстро там, где откат дёшев.
