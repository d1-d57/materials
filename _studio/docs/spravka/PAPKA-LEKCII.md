# ПАПКА ЛЕКЦИИ — архитектура (канон)

> **Когда читать:** заводишь новую лекцию (`bootstrap_lekcia.py`) или ищешь, где живёт конкретный артефакт фабрики. · **Что это:** контракт ОДНОЙ папки лекции — всё в одном месте, разложено по ролям конвейера (`konvejer/00-KONVEJER.md`, стадии 01–10). Трёхдомная модель проекта «Каталан» (карточки / строгий слой / научпоп-слой), ужатая под одну лекцию. · **Куда дальше:** формат готового дека — `../../konvejer/FORMAT-ISTOCHNIKA.md`; конвейер стадий — `../../konvejer/00-KONVEJER.md` + `ALGORITM.md`; гейты — `../../konvejer/GEJTY.md` (в работе, см. пометки ниже).

## Дерево

```
<лекция>/
  NAVIGATOR.md PLAN.md SESSIYA.md   дневник лекции (шаблоны ARKA §9)
  brief.md                          бриф 8 полей + «слайды: да|нет»
  kartoteka/                        карточный граф (рабочая память ресёрча)
  istochniki/                       провенанс источников
  kotly/                            doc-движок, два котла/вкладки
  chernovik/                        гибрид-источник (черновик рассказа)
  raskadrovka/                      демо слайдов
  src/  dist/                       ОПЦ — только «слайды: да»
```

Порядок сверху вниз = примерный порядок наполнения по стадиям конвейера (01→10), но папки не переименовываются между стадиями — каждая стадия пишет в СВОЙ слой, не трогая чужие (принцип `FORMAT-ISTOCHNIKA.md` §«Обязательство фабрики», перенесённый на уровень всей лекции).

## Дневник — `NAVIGATOR.md` / `PLAN.md` / `SESSIYA.md`

**Назначение:** оперативная память РАБОТЫ НАД лекцией — не путать с содержанием самой лекции. Формат — точная копия шаблонов арки (`ARKA.md` §9), масштабированная с уровня «арка проекта» на уровень «одна лекция»:
- `NAVIGATOR.md` — концепция лекции (throughline, для кого), границы (что НЕ входит), указатели на разделы `_studio/` и `catalan/`, какие скиллы поднимать. Стабилен, читается первым.
- `PLAN.md` — где мы сейчас: шаги ✓ + «⭐ СЕЙЧАС» (первый конкретный шаг следующего хода).
- `SESSIYA.md` — дневник хода работы: детали, решения по этой лекции, история. Дистиллят, не свалка.

**Гейт/хук:** нет отдельного гейта конвейера — это инфраструктура работы, не выход стадии. Дисциплина ведения — `ARKA.md` §3–§4 (staleness-чек на входе, хэндофф §6).

## `brief.md` — бриф лекции

**Назначение:** вход конвейера, снимается аркой-стадией 01 (`konvejer/01-brief/DOK.md`). 8 полей владельца (тема · аудитория · длительность→бюджет слайдов · throughline-кандидат · что резать · материал/референс · уровень строгости · формат события+лекция/курс) + 9-е поле, добавленное этим заходом: **`слайды: да|нет`** — управляет, заводить ли `src/`/`dist/` и применять ли гейты Фазы II (лекция «на доске» без слайдовой сборки → `нет`).

**Гейт:** «дверь в арку 2» из `01-brief/DOK.md` — все 9 полей полны, throughline-кандидат одной фразой, бюджет слайдов посчитан арифметически (не угадан), строгость и формат события названы явно. → `GEJTY.md#brief`.

## `kartoteka/` — карточный граф

**Назначение:** рабочая память ресёрча (стадии 02–03, `02-reserch/DOK.md`), НЕ проза для владельца. Три слоя, перенесённые из `catalan/spravochnik/`:
- `STANDART-uzla.md` — памятка формата карточки-узла (id · род · находка · связи · уровень · источник · статус), скопирована КАК ФОРМА из `catalan/spravochnik/STANDART-uzla.md` (образец не редактируется, это read-only канон).
- `KARTA-OBLASTI.md` — индекс: резолвит каждый `id` (суть строкой), группирует по роду; пуст на старте (заголовок + пустой индекс).
- каталог объектов (стаб, `obiekty.md`) — «объекты-ручки» (общие узлы, на которые ссылаются несколько нитей), по образцу `stati/<нить>-obiekty.md` из `catalan/spravochnik/KARTA-OBLASTI.md`.

Один граф + поле `котёл: математика|научпоп` на карточке (дефолт-развилка из `02-reserch/DOK.md` — тег-над-графом, не два набора карточек); нити нарезаются НЕ сразу — каталог-без-нитей нормален на старте.

**Гейт:** «фактура + разворот» из `02-reserch/DOK.md` — ≥5 разных источников, ни одной находки без карточки, в материале есть «но» (разворот). → `GEJTY.md#fаktura-razvorot`.

## `istochniki/` — провенанс источников

**Назначение:** откуда взята фактура (biblioteka-модель `catalan/biblioteka/`, конкретно форма `catalan/biblioteka/istochniki/`). Стаб-файлы с заголовками (форма скопирована с живых файлов Каталана):
- `MANIFEST.md` — физическая раскладка источников (что где лежит).
- `VYCHITANO.md` — дайджест «что реально ЕСТЬ / чего НЕТ» после каждого чтения (шаблон записи внутри файла); дисциплина — источник без дайджеста = как будто не читан.
- `SPISOK-skachat.md` — чеклист на докачку.
- `TERMINY.md` — per-project список канонических русских написаний терминов/имён (по образцу `catalan/spravochnik/TERMINY-russkie.md`); сверяется ПЕРВЫМ при новом термине, до веб-поиска.
- `pdf/` — физические файлы источников (`.gitkeep`, пока пусто).

**Гейт:** свой отдельный гейт не выделен явно в прочитанных DOK — прошивается через гейт «фактура» кartoteka (находка без источника = невалидная карточка). → `GEJTY.md#fаktura-razvorot`.

## `kotly/` — doc-движковый вид (два котла)

**Назначение:** читаемая проекция карточного графа, показанная как две вкладки doc-движком (`_generator/build_doc.py`, форма — `_generator/doc-demo/{matematika,naupop}.md`). Фронтматтер на файл: `tab` (имя вкладки) · `status` (`chernovik`/…) · `poryadok` (порядок вкладок) · `registr` (`читаемый`/`устный`).
- `matematika.md` — вкладка «Математика»: карточки котла `математика`, растущие в арке 3 в строгий слой `skelet` (Определение/Утверждение/Доказательство/Источник/Уровень, `⚑ Флаг`/`Флаг закрыт` для мат-долга).
- `naupop.md` — вкладка «Научпоп»: карточки котла `научпоп` (приложения/история/люди/отступления), питает нарратив арки 4a.

**Гейт:** «математика верна?» (жёсткая дверь 3→4 из `03-matbaza/DOK.md`) — источники сверены, нотация единообразна по всему потоку, термины сверены с `TERMINY.md`, 0 открытых `⚑ Флаг`. → `GEJTY.md#matematika-verna`.

## `chernovik/` — гибрид-источник

**Назначение:** сборка нарратива (арки 4a/4b, упомянуты в `03-matbaza/DOK.md` «Стык с аркой 4», сама `04-gibrid-istochnik/DOK.md` этим заходом не читана — детали её гейта не додумываю).
- `rasskaz.md` — нить, вытянутая аркой 4a ИЗ наполненного графа в сюжет (затравка → … → кульминация → выход); самостоятельный текст.
- `skelet.md` — сшивка 4b: `rasskaz.md` цитирует строгий слой (сноской), не переписывая вывод — модель Каталана «два параллельных слоя, видимый цитирует строгий». *(Трактовка этого захода: `kotly/matematika.md` — живой рабочий вид графа во время арок 2–3; `chernovik/skelet.md` — его замороженная выжимка для цитирования из `rasskaz.md`. Не проверено по `04-gibrid-istochnik/DOK.md` — см. ВОПРОСЫ в `kod_bootstrap.md`.)*

**Гейт:** не читан явно (см. выше) → `GEJTY.md#gibrid-istochnik` (заглушка, имя уточнит заход, который писал `GEJTY.md`).

## `raskadrovka/` — демо слайдов

**Назначение:** покадровый демо-план слайдов до вёрстки (арка 5, `05-raskadrovka/DOK.md` не читана этим заходом) — текст на слайд + иллюстрация-плейсхолдер, мост между гибрид-источником и `src/`. На старте — пустая папка (`.gitkeep`).

**Гейт:** не читан явно → `GEJTY.md#raskadrovka` (заглушка).

## `src/` / `dist/` — ОПЦИОНАЛЬНО (только «слайды: да»)

**Назначение:** каноническая папка-источник дека (контракт — `konvejer/FORMAT-ISTOCHNIKA.md`), заводится копией `_generator/skeleton/` (ядро: `brief.md · shablon.html · base.css · tokens.css · fonts/faces.css · engine.js · content/ · slides/ · illustrations/`). `dist/index.html` — собранный самодостаточный выход `build_deck.py`, руками не редактируется. Если бриф несёт `слайды: нет` — папки не заводятся вовсе (лекция «на доске»: орнаменты и т.п.).

**Гейт:** линтер `build_deck.py` (0 нерезолвленных `{{...}}`, `slide_order` точно покрывает `content/`+`slides/`) + для greenfield-первой сборки — `audit.py`+глаз вместо render-identity (`_generator/skeleton/SPEC.md` «Гейт greenfield»). Финальный гейт сборки — стадия 10. → `GEJTY.md#format-istochnika`, `GEJTY.md#sborka-qa`.
