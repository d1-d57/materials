# RESHENIYA — принятые решения (что / почему / что отвергнуто)

> **КОГДА читать:** нужно «почему так решено» или свериться перед новой работой. · **ЧТО дописывать сюда:** осевшие решения (живой статус и шаг — в `../sostoyanie/OTKRYTYE-ZADACHI.md`; идеи на будущее — беклог там же). · **КУДА дальше:** `../KARTA.md`. **Числа/факты — сверять по живым файлам, не по памяти.**

## Р1. Источник → генератор → самодостаточный HTML, гейт render-identity
Папка-источник (`content/*.md` + `illustrations/*` + токены + `shablon` + `engine`) собирается `../../../_generator/build_deck.py` в один HTML; правка гейтится нормализованной сверкой с оригиналом. **Почему:** правка = дешёвое изменение markdown, не кода; выход самодостаточен.

## Р2. Формат текста слайда — шорткаты
`{@N}` сцены, `{fill@N|…|…}`, `{blur@N|…}`, `**acc**`, `$tex$` из кэша; `accent_tag` в `brief.md` (`b` Dandelin / `span` Buffon). **Почему:** любое слово/формула/акцент — правка одной строки md.

## Р3. Фабрика самодостаточна, НЕ дирижёр
Внешний скилл — только где способность медиум-независима и инструментальна: 3D → `threejs`, код, маттермины → `math-russian-terminology`. Всё специфичное для презентаций — локально. **Почему:** generic-скилл кодирует чужой формат и активно мешает. **Отвергнуто:** дирижировать цепочкой скиллов — это и было причиной провала прогона «платоновы тела» (`popsci-narrative` срезал математику `popsci-research`).

## Р4. Стиль текста слайдов — локальный инструмент
Плакатный баланс (законченные фразы, минимум символов) — собрать из корпуса старых презентаций. **Почему:** это отдельный стиль; `russian-editor` (литературный) для него неверен.

## Р5. Линчпин — гибрид-источник
ОДИН документ: живая история + математика финального объёма (доказательства в тексте) + свёрнутые `<details>` + описания иллюстраций. **Почему:** он один кормит слайды, поэтому математику не срезают; такого режима нет ни в одном скилле.

**Пересмотрено (Р19, 2026-07-10):** режим «один гибрид-файл» устарел → заменён карточным графом (ресёрч) + двумя слоями `rasskaz` (нарратив) ‖ `skelet` (строгая матбаза), сшитыми цитатой-сноской; `<details>` — только оглавление. Линчпин-идея (математику не срезают) сохранена: `skelet` держит полный объём доказательств.

## Р6. Конвейер — 2 фазы, ~10 шагов
Фаза I «индивидуальность» (бриф→ресёрч→строгая матбаза→гибрид-источник→раскадровка; гейты автора) → Фаза II «механика» (плакатный текст→вёрстка→сцены→иллюстрации→сборка+QA; автомат). **Почему:** индивидуальность автора — только в фазе I; дальше автоматизируется. Детали — `../spravka/ARHITEKTURA-FABRIKI.md`.

## Р7. Math-арк — изолированный Node+katex
Новые формулы рендерит `katex.renderToString`, версия pinned, батчем в тот же `{tex→html}` кэш. **Почему:** чистого stdlib-пути нет; единственный способ совпасть с классом разметки кэша. Ядро-генератор остаётся stdlib — Node ТОЛЬКО в math-арке. **Отвергнуто:** рантайм KaTeX/MathJax (ломает самодостаточность/детерминизм), SVG-движки (несовместимый markup).

## Р8. Дизайн-система — токены-tiers, свой эмиттер
`canon.tokens.json` (primitive: палитра/тип/шрифты) + semantic-алиасы (деки читают ТОЛЬКО их) + пер-дек оверрайд; свой ~50-строчный stdlib-эмиттер инлайнит merged `:root` в каждый дек. **Почему:** «определить раз, наследовать много», без внешнего tokens.css. **Отвергнуто:** Style Dictionary / npm как зависимость.

## Р9. Арк-файлы — паттерн SKILL.md
Триггер-фронтматтер / короткое тело / якоря-по-требованию; REPORT = дистиллят 1–2k токенов (сырой контекст вниз не передавать); явный `next`+checkpoint. **Почему:** конвергенция зрелых агентных фреймворков; чистый контекст на стадию.

## Р10. Иллюстрации — живой inline-SVG
Свой `.svg` на илл., инлайнить как живой `<svg>` (не base64/`<img>`); SVGO-нормализация (pinned + per-file id-prefix); headless-верификатор (пустая/одноцветная зона ловит чёрную заливку). **Почему:** до `<svg>` дотягиваются `var()`/`currentColor`; в `<img>` — нет (изоляция → чёрная заливка).

## Р11. Проект фабрики — в `materials/_studio`, ARC-дисциплина
Живёт в `materials/_studio/`, git-откат из `materials`; дисциплина воспроизведена с `spetsmat`/`kurs leto` (дома, арки, заходы, single-index). **Почему:** фабрика развивается — нужна память и дисциплина, чтобы наработанное не терялось.

## Р12. Старт сборки — с арки гибрид-источника + сбор корпуса
**Почему:** гибрид-источник — линчпин; локальному text-инструменту нужен корпус.

## Р13. Интервью-арка — под матлекцию, не общий скилл
Арка 1 (интервью/бриф) — специально под математическую лекцию (у неё заранее понятная арка: что спрашивать и зачем), НЕ общий `the-interviewer`/`brainstorming`. **Почему:** общий интервью-скилл даёт не то — как `popsci-research`/`popsci-narrative` давали не то в «платоновых телах».

## Р14. Сборка арок — по трём классам
Каждая из 10 арок собирается по своему классу: **ПЕРЕНОС** (вычленить из `html-slides-studio`: вёрстка/сцены/сборка+QA/архетипы) · **ОРКЕСТРАЦИЯ** (тонкая обвязка внешних: 3D→`threejs`, код, термины) · **GREENFIELD** (придумать заново: интервью, ресёрч+матбаза-поток, гибрид-источник, раскадровка, text-стиль). **Почему:** разный способ сборки → разный подход и приоритет. Перенос/harvest — bounded, распараллеливаются агентами; greenfield — интерактивно с вкусом владельца. Разбивка задач — `../sostoyanie/OTKRYTYE-ZADACHI.md`.

## Р15. Семейство движков markdown→HTML — `_generator` дом движков, `_studio` мозг
markdown — источник истины (дёшево править), HTML — вид, пересборка — чистый Python БЕЗ токенов, линтер-гейт. `_generator/` держит ДВА движка одного семейства: **дек** (`build_deck.py`, фикс-канвас 1440×810+сцены, ГОТОВ) и **документ** (doc-движок для растущих markdown-источников Фазы I с полями/`status`, портировать из `build.py` проекта `kurs leto 2026` — СПРОЕКТИРОВАН, не реализован). `_studio` ими пользуется, не содержит. Принцип распространяется на всю Фазу I (один источник istины на всех стадиях). Детали — `../../_generator/DVIZHKI.md`. **Почему:** правка HTML вручную дорога; markdown+пересборка дёшева; у дека и документа общая философия, но разные модели данных. **Отвергнуто:** сливать движки в один код (модели данных различны); слить `_generator` в `_studio` (движок шире фабрики — лекции/питчи `kurs leto`/`catalan` того же семейства). **На будущее:** doc-движок как общий скилл для всей работы; правка «поверх HTML» (in-place, à la Claude Design).

## Р16. База канона = buffon (не dandelin)
Скелет greenfield-`src/` и пер-дековый `base.css` берут за дефолт канон **buffon**. **Почему:** buffon совпадает с Canva-шаблоном автора и большинством референсов (вёрстка, цвета) — это фактический стандарт; dandelin был ПЕРВЫМ пробным прогоном фабрики, собран быстро и «разъехался» (byte-shared общий base на оба эталона невозможен — канон реально расходится, доказано `verifikacia-infra.md`). Отдельные удачные элементы dandelin (обложка, картинки) — свести/доработать позже отдельным заходом дизайн-системы. **Отвергнуто:** dandelin-дефолт (текущий в скелете — переключить на buffon); единый общий base на оба (= рестайл, KONSTITUCIYA §1).

## Р17. Автономность фабрики — скиллы ВНУТРЬ, не в прод (ужесточение Р3)
Фабрика — самодостаточный продукт; внешние скиллы в проде НЕ вызываются, кроме чисто технических (реальный код; иллюстрации/3D → `threejs`). Содержимое полезных скиллов (`popsci-research`, `popsci-narrative`, `the-interviewer`, `math-russian-terminology`…) ПЕРЕНОСИТСЯ внутрь — разбивается на куски и раскладывается короткими конкретными шагами процедуры. Пример: `math-russian-terminology` → заменяется на **per-project документ-список терминов** (заполняется заранее) + шаг «сверься с ним»; сам скилл триггерился после каждого куска и заново гуглил написание — это баг. Метод сборки: перенести ВСЁ многословно → выкинуть лишнее, где неадекватно → свести к чётким коротким шагам, полупустой контекст. **Почему:** generic-скилл кодирует чужую цель/формат (статья в интернете, «сам разобраться») и мешает; нужна адаптация под конкретную задачу. **Ужесточает Р3** (убирает маттермины из списка допущенных внешних — теперь внешние только код+3D).

## Р18. Одна фабрика — и лекция, и курс (нет принципиальной разницы)
Лекция и курс делаются ОДНИМ механизмом; курс = запуск фабрики многократно в разных контекстах (сначала концепт всего курса — набор сюжетов, порядок лекций, мосты; потом каждая лекция, уточняя/наполняя тот же большой документ). Костяк-текст может быть костяком одной лекции ИЛИ целого курса (как `catalan`: документ выглядит как лекция, а это весь курс). Мосты/пересечения между лекциями — фиксируем. Фабрика производит и КОНТЕНТ (история+математика), и презентацию/сайт-материалы поверх (текст+слайды выкладываются). Раньше — два скилла (создание истории; создание презентации из истории), объединены в одну фабрику; при нужде легко разделить. **Почему:** механизм универсален, разделение искусственно. Разворачивается в «фабрику курсов» (масштаб держим в уме, пока не расширяем). Циферблат масштаба «лекция↔курс», реализующий этот принцип операционально, — `../spravka/PROFILI-CIFERBLATY.md`.

## Р19. Верхняя часть Фазы I — редизайн (карточный граф → котлы-теги → нить→rasskaz)

Ресёрч растит **карточный граф** (узлы-стикеры формат Каталана `id·род·находка·связи·уровень·источник·статус` + карта нитей + дисциплина «находка без карточки=потеряна»); карточки тегируются котлом **математика|научпоп** — ОДИН граф, «два котла» = два тег-фильтра, показанные двухвкладочным doc-движковым видом (D1). Критерии: математика — «лекцию можно заменить набором вопросов»; научпоп — «каждый факт = мини-история». Строгая матбаза = слой `skelet`; мат-долг `⚑ Флаг`→`Флаг закрыт` (грепается, снимает арка 3). Раскадровка = дешёвый doc-движковый вид; контракт 5→6 несёт `register`+`word_budget`+`accent_tag`+`slide_order`. Пакеты `konvejer/01–05` переписаны. **Ratified развилки (владелец 2026-07-10):** proof-self-review — метод ВНУТРЬ (не внешний вызов); карточки — тег котла над одним графом (не два набора); нарратив — под-стадия `4a` (без renumber, 06–10 целы); сборка — цитата-сноска (не `<details>`). **Почему:** grounded в живой практике Каталана + Р15/Р17/Р18. **Пересматривает Р5.**

## Р26. Направление Пик↔Эйлер — порядок графы→Пик→многогранники верен

## Р31. Механизм доставки уроков в фабрику перестроен: три хука → один дешёвый + одна отдельная сессия
Стресс-тест 16–17.07 (курс «Теория категорий») дал измеримый факт: **у фабрики было ТРИ хука «→ фабрика» (после отчёта · хэндофф · закрытие арки), и за трое суток они доставили ~1 урок из ~12 — написано 17 секций «→ фабрика», до канона дошла ОДНА** (`git log _studio/docs/`: один коммит за трое суток, и не про уроки).

**Диагноз — не «хуки недостаточно жёсткие».** Три хука доставили меньше, чем один: диффузия ответственности («поймает следующий») плюс дорогое действие (консолидирующая правка канона) в момент, когда занят другим. **Дорогое пожелание не исполняется никогда.** Ещё одно «теперь точно заносим» было бы тем же правилом-пожеланием в четвёртый раз.

**Решено — разнести по ЦЕНЕ** (`kak-delat/RUKOVODSTVO-zahodami.md §Хук «→ фабрика»` — единственный дом; `ARKA §4/§7`, `COWORK §5` только ссылаются):
- после каждого отчёта — **одна строка в `UROKI-FABRIKE.md` арки: факт + ЦЕНА**, ~минута; не формулировка закона и не правка канона;
- хук «конец сессии» — **удалён** как дублирующий (иллюзия второго шанса на том же дешёвом действии);
- при закрытии арки — **отдельная сессия с ПУСТЫМ контекстом**, вердикт на каждый урок, правка канона консолидируя.

**Почему вердикт выносит не автор уроков:** он лицо заинтересованное, красивая формулировка от него подозрительна by design. Из механизмов, реально ловивших аналитика за арку, надёжнее всего — вынос задачи в пустой контекст (поймал дважды подряд). **Отбраковка слабого урока — результат сессии, а не провал.**

**Гейты — грепом** (`^### ` vs `^ЦЕНА: ` vs `^ВЕРДИКТ: `): урок без ЦЕНЫ не идёт в канон (наблюдение, не закон); урок без ВЕРДИКТА держит арку открытой. ## Р32. Тяжёлый сбор — два прохода и экономика моделей (арка `2026-07-20_teorkat-motivacia`)
Сбор материала под курс режется на **полноту** и **точность**, и это разные заходы: полнота — дёшево, механически, **ничего не отбраковывать**; точность — дорого, суждением, по уже собранному. **Почему:** прошлый провал ровно отсюда — один заход собрал 614 примеров и сам же их отфильтровал, владелец не увидел ни одного пригодного. Отбраковка — владельца, не исполнителя.
**Экономика моделей.** Дорогая модель окупается на **выборе угодий** (мало токенов, максимальный рычаг: где вообще искать) и на суде по выжимке; сырьё она не открывает ни разу. Судейская выжимка вместо полного документа — не аккуратность, а арифметика: манифест 127 КБ ≈ 30k токенов на вызов × 20 батчей = 600k на одно перечитывание критерия, выжимка 3–4 КБ даёт ≈ 20k.
**Когда увеличивать выборку бесполезно.** Если собранное с высокой точностью воспроизводит один канон (у нас — nLab + Баэз + HoTT), дыры находятся не в объёме, а в корпусе: **менять корпус, а не увеличивать выборку.** **Отвергнуто:** «прочешем ещё тысячу страниц того же» — проверено, дыр не закрывает.

## Р33. Критерий отбора калибруется эталонами и одной шкалой (там же)
**Критерий, прочитанный строго, обязан пропускать собственные эталоны.** Если не пропускает — ложен критерий, а не эталоны. **Почему:** свежая сильная модель, прочитав наш критерий буквально, показала, что два эталона из трёх его не проходят; это объяснило все мис-сортировки арки разом и заставило переписать критерий из одной формулы в дизъюнкцию трёх каналов. Проверка дешёвая и обязана идти ДО массового применения.
**Калибровочный набор строится из вердиктов на ОДИН вопрос.** Смешение шкал («доступно ли залу» и «пригоден ли сюжет») в одной строке теста даёт ложное расхождение — счёт занижается, и правится несуществующая проблема. Засвеченные случаи в повторную сверку не идут.
**«Утверждён» — операционально:** документ утверждён, когда свежий судья по его выжимке вслепую воспроизводит вердикты владельца на уже осуждённых случаях. **Отвергнуто:** «утверждён = владелец прочитал и не возразил» — не проверяемо и не может провалиться.

## Р35. Проекты и библиотека знаний разъезжаются; развязка — через одну точку (2026-07-20)
**Накопительный актив переживает курс, рамка курса — расходник.** Картотека, источники, каталог находок должны жить отдельно от конкретного курса. **Почему:** владелец понесёт трёхлекционный блок дальше другим людям как свой мини-курс ⇒ будет третий заход и четвёртый; «план курса — ерунда по сравнению с этим ресёрчем». Видение — два рода разделов в `materials/`: проекты и **библиотека знаний** как дополнительная математическая память.

Проверка исправности: если при переезде пришлось править что-то ещё, значит путь утёк, и это дефект.

## Р36. Документ-вид — читаемый подряд, а не пролистываемый по диагонали (2026-07-24)
Разбор doc-вида с владельцем на живой лекции (`lsh-2026-perechislitelnaya/otkrytaya-lekcia-paskal`)
дал набор решений, которые вшиты в `build_doc.py` и потому действуют всегда, а не «если автор помнит».
Полный диалект — `../../../_generator/README.md`; визуальный контракт — `../kak-delat/STANDART-oformlenia.md §3–4`.

- **Номер раздела ставит движок.** Руками номер в заголовке НЕ писать — иначе «1. 1.».
- **Сворачивается всё.** Раздел открыт, подраздел и пункт свёрнуты; `{свёрнуто}` / `{развёрнуто}`
  перебивают поштучно. Оглавление — аккордеон: клик по разделу раскрывает его подразделы, закрывает
  соседние и раскрывает секцию в тексте. **Почему:** длинный энциклопедический текст должен
  пролистываться глазами; иначе навигации нет и читатель тонет.
- **Доказательство свёрнуто по умолчанию и приращено к утверждению** (кат внутри врезки, без зазора).
- **Врезки одной геометрии, различаются цветом метки.** Серых безымянных плашек нет.
- **Поле — абсолютом, не `float`.** `float` заставляет текст обтекать заметку, то есть режет колонку.
  Кегль поля — как у основного текста. Туда же уезжают `*Статус.*`, прозрения и узкие рисунки.
- **Служебное в вид не идёт:** `status`/регистр/счётчик долгов, плашка про KaTeX, `> поле:foot`,
  мат-долги `⚑`. Заголовок страницы — из `#` первого потока. Секция `{скрыть}` остаётся в markdown.
- **Ссылка на прежний результат — автоматическая:** «по утверждению 4» со СТРОЧНОЙ становится
  ссылкой; с прописной — это метка врезки. Автор ничего не размечает.
- **Метка «текст ↔ поле»** — пара звёздочек, ставит движок.
- **Отвергнуто:** держать эти правила «в голове автора» и в чек-листах. Три захода подряд одни и те
  же дефекты возвращались, пока не были вшиты в генератор. Правило, которое не исполняется машиной,
  в doc-виде не существует.

## Р37. Иллюстрация: место решает пропорция, и решается ДО рисования (2026-07-24)
Критерий жёсткий и считается движком из `viewBox`: **высота/ширина ≥ 0,6 → на правое поле, иначе во
всю строку потока.** В поток рисуем **горизонтальным** (траектория, лента шагов, ряд панелей), на
поле — **узким, вытянутым вверх**. **Почему:** широкая полоса в жёлобе сжимается до нечитаемости,
высокая в потоке оставляет по бокам пустоту.
**Следствие важнее самого правила:** рисунок «почти проходит» → **чинить РИСУНОК, а не правило** —
обрезать поля, убрать подписи, дублирующие `figcaption`, урезать хвост, сжать шаг. Прецеденты и
цифры — `../../konvejer/09-illustracii/SLOVAR-primitivov.md`.
Плюс: **служебные подписи к краю, предмет рисунка по центру** (подписи `n = 0…5` слева были включены

## Р38. Как отбирается внешний сюжет — четыре гейта возникновения (2026-07-28)

**Единственный дом формулировок — `../../../teorkat-vvedenie/DUH.md §2а`**, здесь только факт решения и почему оно durable.

Все четыре сформулированы **владельцем** по ходу сплошного разбора 62 групп внешнего корпуса, а не сконструированы аналитиком заранее — то есть выведены из живых реакций на конкретный материал. Гейт 1: знакомый **объект** оказывается ответом на категорный вопрос. Гейт 2: знакомое **утверждение** оказывается свойством мира, а не законом. Гейт 3: игрушечный пример законен, если **рождается ответом** на заданный вопрос. Гейт 4 (отсев): категорный язык обязан **делать работу** — либо формулировать просто то, что без него сложно, либо переносить конструкцию между категориями.

**Почему durable, а не локально для Л1:** они уточняют критерий трёх каналов (`DUH §2`) и, в отличие от него, проверяются на каждом сюжете за минуту. Годятся для любой лекции курса и для любого будущего поиска.

⚠ **Отвергнуто ими же:** «внешний дифференциал — единственная естественная операция» и «инверсия Мёбиуса» — оба переописывают инвариантность, понятную без категорий.
⚠ **Тревожный замер:** носителей гейта-2 нашлось **три на 62 группы**, при том что владелец назвал этот тип бриллиантом. Это заказ на поиск, не изобилие.

## Р39. Ретрактный приём — сквозная линия курса, читается в обе стороны (2026-07-28)

«Функтор сохраняет ретракты» ⇒ **нет ретракции в простом мире — нет функтора в сложном**, и наоборот. Вводится в множествах, повторяется в группах (центр группы не функтор), анонсируется в топологии (Брауэр). Взят всеми тремя ходами как **рабочий инструмент**, а не наблюдение; слово «ретракт» обязано прозвучать.

**Порядок предъявления, уточнённый разбором:** приём показывается там, где он ПРОВЕРЯЕМ (задачи Вербицкого — «Брауэр без топологии», доказывается ретрактом на одноточечном множестве), и применяется там, где он ЦЕНЕН (Брауэр, где руками не видно).

**Отвергнуто:** слоган вместо теоремы («излишне, я не понимаю до конца, что это»). Подаётся теоремой в три шага.

## Р40. Ретракт = вторая половина словаря вопросов к незнакомой категории (2026-07-28)

К каждой новой категории задаются два вопроса: **что здесь изоморфизм** и **что здесь ретракция**. Это превращает галерею примеров из витрины в серию задач и даёт лекции повторяющуюся форму. Изоморфизм при этом — рабочий вопрос, а не определение.

## Р41. Примеры — ВСЕГДА внешнее; пример приходит там, где становится нужен (2026-07-28)

Единственное исключение — $\mathbf{Set}$, она нужна самому словарю. Галерея **не блок**: каждый пример вводится в тот момент, когда его просит материал, и ни минутой раньше. Финальный пример обязан **мотивировать** определение, а не иллюстрировать его (образец: конечный Стоун — сначала показываем, что это НЕ изоморфизм категорий, и только потом называем эквивалентность).

**Отвергнуто:** галерея как отдельный раздел-витрина.

## Р42. Классификация — не задача, а УТВЕРЖДЕНИЕ; у каждого этажа языка свой инструмент (2026-07-28)

Владелец: *«нужно не называть задачи, а называть утверждения; если есть утверждение, работающее в разных контекстах, это ценно»*. Отсюда инвентарь по этажам: объекты и стрелки — «ретракта нет ⇒ функтора нет» · функторы — «Hom это функтор» запаковывает ассоциативность · естественные преобразования — **λ-тест** (подстановка $f=\lambda\cdot\mathrm{id}$ в квадрат естественности даёт четыре запрета одним вычислением) · эквивалентность — критерий «строг + полон + существенно сюръективен».

**Форма ответа классификации** — «пусто · ровно один · полный список» — повторяется на каждом этаже и работает фильтром отбора примеров, но как принцип на лекции не объявляется.

⚠ **Честная слабость λ-теста:** четыре применения, три из них линейная алгебра. У ретракта миры разные — пока не сравнимо. Запрет клонирования ценен тем, что даёт второй мир и чужой приз при том же вычислении.

## Р43. Метод ресёрча: словарь-суррогат вместо термина (2026-07-28)

Функториальность в чужих учебниках ловится **оборотами**, а не словом: `induces a map`, `canonical`, `well-defined`, «не зависит от выбора». Замер на Атья–Макдональде: 2 упражнения по слову «функтор» → **13** по словарю-суррогату.

Отсюда общее: **сначала измерь корпус, потом выбирай источник**; фильтровать по словарю понятий, а не по главам. И: механическому поиску по слову «категор» на русском материале верить нельзя — четыре типа ложных срабатываний.

⚠ Недобор словаря-суррогата **не замерен** — задача открыта.

## Р44. Фаза наполнения ≠ фаза проверки (2026-07-28)

На наполнении вопрос «взять или не взять» задавать **нельзя** — он законен только после закрытия пула. Полу-воспоминание законно с пометкой `не сверено`; верификация идёт потом и только по вошедшему. Цель наполнения — **многообразие**, не глубина.

Отсюда же: **сюжет, который владелец не может оценить по краткому описанию, НЕ отбраковывается** — он ставится в очередь на изложение. И требование к изложению: сказать, **ГДЕ тут категорный язык и КАКИМ словом**; описание без этого не разбор, а пересказ математики.

## Р45. Единица планирования лекции — КУСОК на 5–15 минут, не слайд (2026-07-28)

Слайд не единица времени: кобордизмы — 1 слайд и 3 минуты, ретрактная связка — тоже 1 слайд, но 10 минут и несколько сцен. **Считать надо кусками**, слайд производен от куска.

**Отвергнуто:** планирование в слайдах и вывод «резерва нет», сделанный на нём.

## Р49. Бюджет лекции — ИЗМЕРЯЕМАЯ величина; единица вместимости — ЭКРАН (арка `2026-07-28_konspekt-l1`, закрыта 2026-07-30)
