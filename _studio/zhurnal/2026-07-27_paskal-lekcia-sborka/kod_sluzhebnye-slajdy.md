## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- _generator/build_deck.py _generator/skeleton _generator/tools/sostoyanie.py _generator/tools/fixtures/sostoyanie _studio/konvejer/GEJTY.md _studio/konvejer/FORMAT-ISTOCHNIKA.md _studio/konvejer/07-verstka lsh-2026-perechislitelnaya/otkrytaya-lekcia-paskal/src                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- _generator/build_deck.py _generator/skeleton _generator/tools/sostoyanie.py _generator/tools/fixtures/sostoyanie _studio/konvejer/GEJTY.md _studio/konvejer/FORMAT-ISTOCHNIKA.md _studio/konvejer/07-verstka lsh-2026-perechislitelnaya/otkrytaya-lekcia-paskal/src   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).

### 1. Форма каждого слайда — чью взял и что теряется
Формы действительно разъезжаются; выбираю по одной и называю цену.
- **Обложка — форма Паскаля/fibonacci** (`<section class="slide" data-kind="cover">` → `.wrap > .head > .t-display` (+`.sub`) + `.art > .ill-box`).
  *Почему:* она новее, ею уже написаны два дека из четырёх, и канон-`base.css` скелета несёт под неё анимацию именно с этими именами (`#sl-title .head`, `#sl-title .art`).
  *Теряется:* форма buffon (`.grid > .zone.head + .zone.art`, `#sl-title .grid{grid-template-rows:22px 64px 26px 667px 1fr}`) и её кегль 54px — канон встаёт на паскалевские 96px. Практической потери сейчас нет: buffon не мигрируется, у него рукописный слайд и приоритет за ним.
- **Визитка — форма buffon дословно** (`.grid > .zone.board(.brd-title + .panel.p-photo + .panel.p-qr) + .zone.copy.t-body`), текст — `content/sl-vizitka.md` buffon **дословно**, включая `<b>`, `<br>` и `.tg-link`.
  *Теряется:* форма dandelin (`s11b`) — тот же скелет, но текст рукописным `<ul class="bullets">` в слайде и инлайн-стилями на `<a>`; она хуже, потому что текст биографии не отделён от вёрстки.
- **Финал — форма buffon** (`.thx-wrap > .thx-head + .thx-art`), CSS дословно из `buffon/src/overlay.css`.
  *Теряется:* форма dandelin (`.zone.card > .fit.cer`) — она автофитит заголовок, то есть кегль финала зависит от длины строки; канонный финал строку не меняет, фитить нечего.
  *Одно расхождение с §2.2 называю явно:* buffon пишет «Спасибо за внимание**!**», заход дважды пишет без «!». Беру **формулировку захода** (текст решает владелец, вёрстку — эталон): `Спасибо за внимание`.

### 3. Механизм порождения — и почему он НЕ может сломать три чужих дека
Порождение включается **наличием плейсхолдера `{{SLIDES}}` в `shablon.html`** и больше ничем.
- `{{SLIDES}}` → генератор собирает ВЕСЬ поток слайдов сам: `[обложка] + [визитка] + slide_order + [финал]`, join через `\n`. Порядок берётся из `slide_order`, а не из руки — это заодно закрывает дублирование порядка (сегодня он выписан ДВАЖДЫ: в `brief.slide_order` и списком `{{SLIDE:id}}` в шаблоне — ровно случай H6).
- `{{SLUZHEBNYE_CSS}}` в `<style>` → канон-CSS трёх слайдов из `_generator/skeleton/sluzhebnye/style.css`.
- **Приоритет рукописного:** если `slides/<id>.html` физически есть — берётся он, порождение молчит.
- У `buffon`/`dandelin`/`fibonacci` в шаблонах **0 вхождений** обоих плейсхолдеров (замерено, §0) → ни одна новая ветка кода для них не исполняется; их выход обязан остаться байт-в-байт, и это гейт п.2 критерия.
- Линтер: `slide_order` сверяется с **эффективным** множеством (порождённые id считаются присутствующими) — иначе п.5 линтера объявил бы их сиротами.
- Порождённые слайды **не несут `data-scenes`** (движок читает `dataset.scenes || '1'`) — это целевое состояние H6, и фикстура `zdorovyj-neobychnyj` уже подтверждает, что трекер такой слайд принимает.

`style.css` (CSS трёх слайдов) · `oblozhka.html` · `vizitka.html` · `vizitka.md` (текст дословно с buffon) · `final.html` · `vizitka-photo.html` + `vizitka-qr.html` (активы дословно с buffon).
