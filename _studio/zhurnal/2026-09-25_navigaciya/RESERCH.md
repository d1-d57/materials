## 1. Что следует для арки (выводы аналитика, не решения владельца)

1. **Источник истины — карточка в репозитории.** Из неё скрипт пишет и метки GitHub, и теги Finder; гейт краснеет, если карточка, метки и теги расходятся. Готового синхронизатора в мире нет — только односторонние инструменты. (`metki-github-finder.md` §5–6)
2. **Алфавит меток задаёт GitHub:** строчная латиница, цифры, дефис; ≤50 символов; ≤20 на репозиторий; кириллица, по косвенным данным, не принимается. Finder допускает больше — значит, словарь меток пишется латиницей, русские названия живут в словаре синонимов. Имена меток видны публично даже у приватного репозитория. (`metki-github-finder.md` §1)
3. **Состояние — в карточке, не в имени и не в папке.** «Пауза, вернёмся» = repostatus `Suspended`; «доделано» и «брошено» стандарты различают по наличию годного результата — открытый вопрос владельцу: нужно ли четвёртое состояние «брошено без результата». Архивный флаг GitHub делает репозиторий только-для-чтения и «доделано» от «брошено» не отличает; метки ставить ДО архивации. Custom properties — только у организаций. (`kartochki-…` §2, `metki-…` §2)
4. **Папка кодирует то, что почти не меняется — род работы;** переносить репозиторий дорого, состояние меняется часто. Совпадает с наметкой владельца «по инструментам». PARA складывает доделанное и приостановленное в один архив — трёх состояний не различает. (`kartochki-…` §3)
5. **Синонимы — по схеме SKOS:** одно основное имя + варианты («спецмат / 179 / matclass»), в карточке — только код понятия; словари в одном месте вне репозиториев. (`kartochki-…` §4)
6. **Задел под связи, который дёшево заложить сейчас:** стабильный `id` (не меняется при переименовании), `people{ref,role}`, `subjects`, `part_of`, `related{ref,rel}`; в файле — только прямые связи, обратные строит сборщик. (`kartochki-…` §6–7)
7. **Маршрутизатор (следующее звено):** ни одна среда не даёт Claude заговорить первым; хук лишь подкладывает инструкцию, спрашивает Claude после первой реплики. Единого механизма на три среды нет. (`marshrutizator-sessij.md` §0)

## 2. 🔴 Срочное, вне порядка плана — история сессий на Mac стирается

По документации Claude Code транскрипты сессий удаляются через 30 дней (`cleanupPeriodDays`), а типология сессий по решению владельца выводится ИЗ ИСТОРИИ. (`marshrutizator-sessij.md` §6)

Сверка с переписью Mac: самый старый транскрипт —
`awk -F'\t' 'NR>1 && $3!=""{print $3}' ../2026-09-24_arhitektura-repozitoriev/perepis/sessions.tsv | sort | head -1`
(на 25.09 печатает 2026-08-21, перепись снята 24.09 — т. е. истории старше ~месяца на Mac нет, хотя работа с Claude идёт ~4,5 месяца). Механизм удаления (при запуске или непрерывно) по диску не проверен. Мера — поднять порог и сохранить копию транскриптов — делается ТОЛЬКО на Mac, решение за владельцем.
