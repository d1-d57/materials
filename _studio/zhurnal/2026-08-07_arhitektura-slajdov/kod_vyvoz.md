## 2. ЗАДАЧА

### Шаг 1. Убрать ложное «вывезено» — одна формулировка, не переписывание

`_generator/tools/git_zona.py:2088`:
```python
if rc == 0:
    print("\n✅ ГОТОВО — сохранено и вывезено. Дальше без Claude; вернись, только если увидишь 🔴.")
```
Строка печатается при любом успешном коммите, включая тот, где `--push` не передавали. Слово
**«вывезено» означает «уехало на origin»** — и в этом же файле (около строки 2787) стоит урок
инцидента 04.08, отделяющий «вывезено» от «опубликовано». То есть различие в файле уже признано
важным и тут же нарушено на 700 строк выше.

**Как чинить — минимально:** вердикт зависит от того, вывозили ли на самом деле.
- вывозили (`args.push` и push прошёл) → «сохранено и вывезено»;
- не вывозили → «сохранено» **плюс** сколько коммитов существует только на этой машине, числом,
  снятым командой прямо здесь, а не по памяти.

🔴 **Не трогай ничего сверх этой развилки.** Ни рефакторинга соседних веток вывода, ни
«заодно причешу» — файл общий и им пользуются все заходы. *Правило репозитория: хирургия — строка
к заданию.*

## 3. ВЕРИФИКАТОР (если двигаем/теряем/жмём)
**Вывоз не лоссовый** (добавляет на `origin`, ничего не удаляет) — субагент-искатель потерь не
нужен. Но у новой подкоманды есть свой способ соврать, и его проверь:

🔴 **Проверь ДЕЙСТВИЕМ, а не кодом возврата.** `git push`, которому нечего вывозить, возвращает 0 —
и подкоманда, докладывающая по `rc`, скажет «вывезено» на пустом месте. Поэтому вердикт снимается
**замером после**: сколько коммитов осталось только на этой машине. Покажи в отчёте, что при
повторном вывозе (вывозить уже нечего) сообщение честное, а не победное.

*Это ровно тот класс, ради которого заход и существует: солвер считал заполненное обязательное поле
«выбором автора» и не тронул ни одной полосы из девяти; исполнитель искал браузер по наличию
каталога вместо запуска и встал на ложном блокере; финальная строка `commit` печатала «вывезено»
потому, что коммит удался.*

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- _generator/tools/ · _studio/zhurnal/                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- _generator/tools/ · _studio/zhurnal/   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
