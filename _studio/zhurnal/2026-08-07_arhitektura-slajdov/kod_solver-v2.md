## 2. ЗАДАЧА — спецификация целиком, ссылок наружу нет

Семь шагов. Э1 и Э2 — фундамент, без них остальное не имеет смысла.

### Э1. 🔴 ЖЁСТКИЕ ОГРАНИЧЕНИЯ — до всякой оптимизации

**Правило:** решение, нарушающее ограничение, **отвергается ДО поиска** — оно не рассматривается,
а не штрафуется. В терминах Кнута–Пласса это `penalty = +∞`, а не большое слагаемое.

Перед написанием целевой функции **перечислить ВСЕ зоны слайда и дать каждой явный минимум и
максимум**. Это чек-лист, а не пожелание: ровно его отсутствие и породило дефект.

Границы `liniya` — **разные по типу линии** (поправка владельца 2026-08-08):
- **вертикальная полоса — свобода УЗКАЯ**, порядка 15–23 % ширины слайда;
- **горизонтальная — свобода ШИРОКАЯ**, ориентировочно 15–80 %: бывает узкая подпись под большой
  картинкой, бывает наоборот.

⚠ Числа выше — прикидка владельца. **Заменить измеренными на Э2**; пока не измерены, действуют они.
Пол обязателен всегда.

### Э2. Диапазоны из корпуса — солвер ищет среди «похожего на одобренное»

По Я4 (343 живых правила из трёх деков) снять:
- перцентили **p5 / медиана / p95** по каждому числовому параметру, отдельно по типу вёрстки;
- 🔴 **связку `line-height / font-size` как ОДНО отношение** (ожидаемо 1,2–1,5). Это снижает
  размерность поиска вдвое: ищем не две независимые оси, а базовый кегль и отношение;
- если в корпусе видны разные семейства слайдов (много текста против много иллюстрации) —
  сначала разделить, потом брать диапазон по своему семейству, иначе смешаются крайности.

**Как это использовать: p5–p95 — мягкий приор, а не отсечка.** `штраф += w · |z-score|` относительно
медианы корпуса. Тогда солвер среди нескольких влезающих решений предпочитает типичное, но
редкий законный случай не отбрасывает.

### Э3. Лексикографический порядок с ε-полосой

Взвешенная сумма запрещена: она позволяет обменять несравнимое («зато текст влез») — именно так и
была ужата иллюстрация. Порядок уровней, сверху вниз:

1. **жёсткие ограничения** (Э1) — проходит или нет;
2. **вмещение** — текст не обрезан;
3. **читаемость**: кегль не ниже пола · **символов в строке 45–75**, оптимум ≈66, никогда >80;
4. **консистентность и эстетика**: заполнение зоны 75–90 % · близость к медиане корпуса (Э2) ·
   ровность правого края.

🔴 **ε-полоса.** Чистая лексикографика теряет мелкие выигрыши нижних уровней. Поэтому на каждом
уровне берётся не единственный оптимум, а полоса `[opt, opt + ε]`, и внутри неё спускаемся ниже.

**Мягкие штрафы — выпуклые (кубоподобные), а не линейные.** Малое отклонение почти бесплатно,
большое — резко дорого. Линейный штраф «размазывает боль» поровну по всем ручкам; выпуклый
заставляет солвер держать каждую ручку близко к идеалу.

### Э4. Дискретная решётка вместо континуума

Кегль и межстрочье снапить на небольшую фиксированную решётку (порядка 5–10 ступеней), как это
делает PowerPoint своей таблицей `fontScale`. Причина не в скорости, а в **визуальной
стабильности**: непрерывный подбор даёт «дрожание» между соседними слайдами — 22px против 21px на
почти одинаковом содержании, и дек выглядит неряшливо.

Финальный шаг: **округлить вниз до целого пикселя и перепроверить вмещение** — дробный px после
растеризации переполняет незаметно для `scrollHeight`.

🔴 **Иерархия блоков не должна стираться.** У каждого типа блока — свой допуск относительно
базового кегля (например, `primer` ∈ [base−2, base]), иначе пример визуально сольётся с
определением. Плюс штраф за резкий скачок параметров между соседними блоками.

### Э5. Скорость — не алгоритм, а работа с DOM

Порядок поиска: **бинарный по базовому кеглю** (вмещение монотонно — меньше кегль помещается не
хуже, 8 итераций при точности 0,25px), затем покоординатный проход по отношению отношение межстрочья к кеглю и отступу.

🔴 **Батчинг: все записи CSS-переменных одним ходом, потом ОДИН `scrollHeight`.** Чередование
запись-чтение-запись-чтение — layout thrashing, оно на порядок дороже лишней итерации поиска.
Плюс мемоизация `(id блока, кегль, межстрочье) → высота`: при покоординатном поиске соседние блоки
между пробами часто не меняются.

### Э6. Типографские метрики — дёшево, через один вызов

`Range.getClientRects()` на текстовом узле возвращает **массив прямоугольников по одному на строку
за один вызов** — не создавать Range на каждый символ, это O(N) перевёрсток.

Отсюда две метрики почти бесплатно:
- **одинокое слово в конце абзаца**: считаем слова в последней строке; одно — дефект;
- **ровность правого края**: стандартное отклонение правых границ строк.

⚠ **«Реки» не детектировать вовсе** — дорого и не нужно: они возникают при выключке по формату,
а мы её просто не используем, и тогда их нет по построению.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).
