# ЭТАП 2 — СМЕТА ВМЕЩЕНИЯ

🔴 **Главное архитектурное решение, оно уже принято, не пересматривай его: формулу НЕ ПРИДУМЫВАЮТ,
её КАЛИБРУЮТ по тому же браузеру, которым меряет солвер.** Придуманная формула — это второй
источник правды о вёрстке; он молча разойдётся с первым, и мы получим ровно тот класс, который эта
фабрика ловит весь день (`sostoyanie.py` описывает конвейер, которого нет; `NAVIGATION.md` говорил
«14 слайдов»). Поэтому: константы — из замера, а честность — из гейта расхождения (Э2.4).

**Единица измерения — СТРОКА, а не слово.** Абзац из двух слов занимает строку целиком. Слово не
единица вёрстки; строка — единица, всё остальное из неё выводится.

### Э2.1. ГЕОМЕТРИЯ ЗОНЫ — что снимается браузером

Для каждого `tip_verstki` × сетки значений `liniya`: **ширина `W` и высота `H` текстовой зоны в
px**. Мерить тем же `izmerit()`/`page.evaluate`, что уже в Я1, — **не заводить второй замерщик.**
⚠ `liniya` двигает **ширину** зоны, а не число строк: от неё зависят знаки в строке, не строки.

### Э2.2. ТРИ КОНСТАНТЫ ШРИФТА — замерить один раз, не угадывать

- `k_znak` — средняя ширина знака, делённая на кегль (для основного шрифта);
- `h_formula` — высота выносной формулы в долях строки (KaTeX display выше текстовой строки);
- `k_inline` — надбавка инлайн-формулы к длине абзаца в знаках-эквивалентах.

🔴 **Каждая снимается замером и записывается ВМЕСТЕ с командой, которая её сняла** (`KONSTITUCIYA §10`).
Константа без команды рядом — то же вписанное руками число, из-за которого мы здесь.

### Э2.3. ФОРМУЛА СМЕТЫ — чистый питон, без браузера, `_generator/sborka/smeta.py`

```
строка_px       = lh * kegl
строк_в_зоне    = floor(H / строка_px)
знаков_в_строке = floor(W / (k_znak * kegl))

абзац_строк(t)  = max(1, ceil(длина_с_учётом_инлайн_формул(t) / знаков_в_строке))
зазор_строк     = blok_koef * kegl / строка_px  =  blok_koef / lh
формула_строк   = h_formula

ИТОГО = Σ абзац_строк + (N_блоков − 1) * зазор_строк + Σ формула_строк
влезает ⟺ ИТОГО <= строк_в_зоне
```

🔴 **Поправка владельца, не потеряй её: зазор между абзацами — ДРОБНОЕ число строк, не «+1».**
`blok_koef / lh` — при крупном кегле и мелком отступе это может быть 0.4 строки. Кегль сокращается,
поэтому зазор от него не зависит вовсе — это и есть проверка, что формула выведена, а не подогнана.
⚠ `max(1, …)` обязателен: абзац из двух слов — это строка. То же для каждого пункта списка.
⚠ Все параметры (`kegl`, `lh`, `blok_koef`, `liniya`) берутся **из коридора `build_zones` Я1**. Не
заводи собственный коридор — третьего не должно существовать.

### Э2.4. 🔴 ГЕЙТ РАСХОЖДЕНИЯ — без него первые три пункта сгниют за неделю

После реальной сборки: смета сказала N строк, браузер намерил M. Разошлись больше допуска →
**красный на СМЕТЕ**, не на слайде: «оценщик разошёлся с реальностью, калибруй». Допуск выбери сам
по калибровке на L2 и **обоснуй числом в `## ПЛАН`**.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `_generator/sborka/**`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `_generator/sborka/**`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).

## 5. ОТЧЁТ → секция `## ОТЧЁТ` внизу
Что сделал + ЗАЧЕМ / как проверил / что НЕ трогал / вопросы / результат верификатора / открытое «возвращаться» / **время прогона + токены — на канале `app` НЕПРИМЕНИМО, снимать неоткуда** (лог прогона существует только на канале `terminal`, где его кладёт `tee`; сессия в приложении Claude Code такого следа не оставляет). Строку не заполнять числом и не извиняться за его отсутствие — это не недосмотр исполнителя, а свойство канала) / **ПОВТОРЯЕМОСТЬ находок (строка обязательна — см. ниже)** / **АРТЕФАКТ (строка обязательна)** / **КОММИТ (строка обязательна, см. §4)**.

🔴 **АРТЕФАКТ — АБСОЛЮТНЫЙ ПУТЬ К СОБРАННОМУ ФАЙЛУ, отдельной строкой.** Не «колода пересобрана», не «см. `dist/`», а путь, который владелец скопирует и откроет. *Цена 31.07: за сессию собрано три артефакта, ни один путь не был назван в отчёте — владелец не нашёл ни одного и сказал прямо: «я всё время не могу найти твои новые файлы». Хуже: он открыл СТАРУЮ колоду, потому что сборка молча не запустилась, и решил, что правка не сработала; ушёл целый круг на диагностику того, чего не было. Отчёт без адреса артефакта — это отчёт о работе, которую нельзя посмотреть.*

🔴 **НЕОБРАТИМОЕ — ОТДЕЛЬНЫМ СПИСКОМ, даже если оно стояло в задании.** Удаление, перезапись, переименование, перемещение, `git reset`/`checkout` поверх несохранённого, любая правка, вышедшая за зону, — каждое ОДНОЙ строкой: **что · где · чем восстанавливается** (хэш коммита, путь к бэкапу). Ты запущен без запроса разрешений (`--dangerously-skip-permissions`): владелец НЕ видел ни одного из этих действий в момент, когда оно происходило, и этот список — единственное место, где он о них узнаёт. **Необратимого не было — напиши «необратимого нет».** Молчание от пустоты не отличается, и приёмка прочитает его как пустоту.

🔴 **ПОВТОРЯЕМОСТЬ находок — назови, какие из них повторятся на СЛЕДУЮЩЕЙ единице работы** (лекция/слайд/заход). Критерий вычислимый, не про приоритет: повторится — это НЕ пункт очереди, а заход ДО следующего прогона (правило «класс НЕМЕДЛЕННОЕ», `../../docs/kak-delat/RUKOVODSTVO-zahodami.md`). Не повторится — законно уходит в `## ВОПРОСЫ` пунктом очереди. *Пример владельца: белый фон иллюстраций повторился бы тринадцать раз, каждый раз ценой переделки картинки — заход, а не запись; число, вписанное аналитиком не глядя, на следующих слайдах не повторяется — запись, а не заход.* Находка сделана ПРОБНЫМ прогоном — чинится ДО следующего прогона: «проба, после которой ничего не починили, — потраченные токены».

### ВЕРИФИКАТОРЫ Э2 — оба нашли настоящие дефекты, все починены

**(а) Проверка на НЕ-калибровочном материале.** Живой не-калибровочный материал в репозитории
отсутствует (см. `## ВОПРОСЫ` п.3), проверка сделана на 23 карточках фикстур. Нашла **четыре**
механические причины промахов, из них один — настоящий баг:
1. 🔴 **Пустые теги съедали блоки.** `HTMLParser` зовёт `handle_starttag` и на `<br>`, парного
   закрытия не будет — стек глубины уезжал НАВСЕГДА, и все последующие абзацы молча выпадали из
   сметы. `buffon/sl-grid`: один блок вместо трёх, занижение на 6.9 строки. На L2 `<br>` не
   встречается ни разу — калибровка этого видеть не могла.
2. Заголовок входил в высоту, но не в счёт строк — занижение ровно на 1.35 строки на каждой
   карточке с заголовком.
3. `.lestnica/.spisok .lst` — `display:block`, каждая ступенька своя строка; считались как текст.
4. Узкая колонка: занижение из-за переноса по словам.

**(б) Независимый вывод формулы** (субагент выводил всё сам, до чтения `smeta.py`). Сошлось 2 пункта
из 6 полностью, ещё 2 в главной части, **2 разошлись — и прав был он**:
1. 🔴 **`ceil(знаков / знаков_в_строке)` — это НИЖНЯЯ оценка, а не оценка.** Браузер переносит по
   пробелам и слово пополам не рвёт. Предъявил контрпример: карточка, где смета говорит «влезает,
   запас 4.16 строки», а браузер обрезает текст. Это ПРОПУСК переполнения — опасная сторона ошибки.
2. 🔴 **Три правила `base.css` — без комбинатора и срабатывают на ПЕРВОМ ребёнке зоны**
   (`ul.tlist`, `p.formula`, `p.op-*`). Доказал одной карточкой: `napominanie` — единственная в L2,
   чья зона начинается с `<ul>`; её расхождение было ровно −0.42 = 26/58.06.
3. `op-def/op-utv/op-task` имеют свой кегль 0.8em и свой межстрочный 1.12 — одна высота строки на
   все блоки завышала такой блок на 0.41 строки.

Починено всё: разборщик копит СЛОВА и укладывает их жадно (как вёрстка), безусловные зазоры первого
блока учтены, у `op-*` своя метрика, `.acc` учтён коэффициентом 1.0658, `sverit` больше не падает
трейсбеком на лекции без кэша формул. **Эффект на калибровке:** `napominanie` −0.42 → +0.02,
`nekanonicheskij-izomorfizm` −0.98 → +0.02, `centr-gruppy` −0.95 → +0.05,
`vektornye-prostranstva` −0.93 → +0.07. Одиннадцать карточек из 14 теперь в пределах ±0.07 строки.

Остаточное расхождение — три карточки по ~±0.96, причина названа и измерена: разброс ширины
отдельной формулы (остаток подгонки p95 = 3.5 знака). Допуск 1.5 держится.
