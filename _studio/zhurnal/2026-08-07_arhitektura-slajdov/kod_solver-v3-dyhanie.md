## 2. ЗАДАЧА — четыре правки, все против одного механизма

### Э1. 🔴 СВЯЗАТЬ ОТСТУП С КЕГЛЕМ ОТНОШЕНИЕМ — главная правка

Сейчас отступ блока — отдельная ручка, и солвер платит ею за кегль. **Пола на отступ
НЕДОСТАТОЧНО:** при отдельной ручке солвер прижмёт её к полу и снова раздует кегль, размен лишь
уменьшится.

Сделать отступ **долей кегля** — так же, как уже связано межстрочье. Тогда выиграть место,
поджав отступ, физически нельзя: он едет вместе со шрифтом. Размен исчезает по построению, и
размерность поиска падает.

Отношение снять по эталонным декам, а не назначить. **Абсолютный пол оставить** как страховку.

### Э2. Похожесть на корпус ВЫШЕ максимизации кегля

Порядок уровней меняется: жёсткие ограничения → вмещение → читаемость → **похожесть на корпус** →
кегль как тай-брейк между одинаково похожими → заполнение.

Владелец: цель не «как можно крупнее», а «как сделал бы я». Плюс **приглушить потолок кегля
сверху** — он сейчас 41,9 px, и солвер регулярно упирается в него.

⚠ Известный контрпример, найденный обратным прогоном: на слайды `sl-circle` и `sl-plan` дека «Игла Бюффона»
человек САМ взял кегль у потолка (41). Потолок нельзя опустить настолько, чтобы эти два слайда
стали недостижимы — **проверить их до правки и после**.

### Э3. 🔴 МЕРА ДЫХАНИЯ — новый уровень предпочтений

Владелец описал дефект точно: «текст мельчит и наслаивается кверху, а снизу есть свободное место».
Так выглядит слайд, где блоки слиплись: высота набрана крупным шрифтом, промежутков нет, внизу
хвост пустоты.

**Померить:** доля высоты зоны, занятая межблочными промежутками. Снять её по эталонным декам —
получится нормальный уровень. Ввести как отдельный уровень предпочтений: не «побольше кегль», а
«промежутков столько же, сколько у владельца обычно».

Считается тем же способом, что и остальные метрики — одним `getClientRects()`, без лишних проб.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие».
