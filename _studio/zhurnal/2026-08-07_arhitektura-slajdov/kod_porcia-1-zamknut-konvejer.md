## 2. ЗАДАЧА

### 🔴 П0. ПРИНЦИП, который важнее любой из четырёх починок. Читай его первым

Требование владельца дословно: **«дисциплина должна быть записана так, что её невозможно
игнорировать физически».** Не «напомнить», не «описать в документации» — сделать так, чтобы забыть
было нельзя.

Разворачивается в четыре требования:
1. **У каждой фазы чёткий вход, чёткий выход и артефакт.**
2. **Артефакт выхода подключается ко входу следующего шага поимённо**, а не «по смыслу».
3. **Артефакты порождаются генератором, а потом заполняются.** Руками структуру не заводят.
4. 🔴 **В сам порождаемый артефакт вписывается то, что нельзя забыть — включая команды следующих
   шагов.**

**Образец уже работает в этом же репозитории, и это Я4.** `bootstrap_zahod.py` вписывает в каждый
порождаемый заход блок «КОММИТ» с готовыми командами, а верификатор краснеет на незаполненном поле.
Поэтому забыть коммит физически нельзя — не потому что кто-то помнит, а потому что файл сам
говорит, и гейт краснеет.

🔴 **Твоя главная работа — повторить этот приём для `slaid.md`.** Смотри Р1.

### Р1. 🔴 КАРТОЧКА ПОРОЖДАЕТСЯ ПОЛНОЙ И САМООБЪЯСНЯЮЩЕЙСЯ

**Дефект, воспроизводится за две команды:**
```
rm -rf /tmp/p1 && python3 _generator/sborka/bootstrap_lekcii.py /tmp/p1
# заполнить slide_order тремя именами, повторить вызов
python3 _generator/sborka/gejt_kartochki.py /tmp/p1
→ ✗ не хватает раздела(ов) тела: Правки (нужны все три:
   Математика — развёрнуто, Текст слайда — сжато, Правки)
```
`bootstrap_lekcii.py` создаёт **только шапку**. Гейт требует **три раздела тела**. То есть
порождённая структура красна по построению, и фаза 1 формально не закрывается никогда.

**Что сделать — две вещи, и вторая важнее первой.**

**(а)** Порождать все три раздела тела пустыми, с пометкой «заполнить», ровно как уже сделано для
полей шапки.

**(б)** 🔴 **Вписать в порождаемую карточку ПЛАН ЕЁ ЖИЗНИ — сверху, до шапки, комментарием.**
Требование владельца дословно: *«чтобы если этот файл попадёт к агенту, который вообще не понимает
контекста, он бы разобрался, нашёл бы там солвер, компилятор, все шаги»*.

Значит в шапке каждой порождённой карточки стоит блок вида «что с этим файлом происходит дальше»:
на какой фазе какой раздел заполняется, **и какой командой этот шаг проверяется или выполняется** —
поимённо, с путями от корня репозитория. Ф2 наполняет «Математика — развёрнуто», Ф3 — «Текст
слайда — сжато», Ф4 зовёт компилятор и солвер, Ф6 собирает дек. Команды бери **из живого кода**
(`--help` каждого инструмента), а не из этого захода: заход может устареть, код — нет.

⚠ **Блок должен быть машиночитаемым, а не только человекочитаемым**, иначе он через неделю
разойдётся с реальностью молча. Как именно — твоё решение, назови его в `## ПЛАН`; годится и
комментарий фиксированной формы, который проверяет гейт.

**КРИТЕРИЙ Р1 (может ПРОВАЛИТЬСЯ):**
1. `bootstrap_lekcii.py` на чистой папке → досыпать → `gejt_kartochki.py` даёт **ЗЕЛЁНЫЙ** без
   единой ручной правки тела. Сегодня даёт красный. Команды и `rc` — в отчёт;
2. в порождённой карточке есть блок «что дальше», он называет **все фазы от Ф2 до Ф6** и **хотя бы

3. гейт краснеет, если блок «что дальше» из карточки убрать. Не краснеет — значит это украшение,
   а не дисциплина, и Р1 не выполнен.

### Р3. 🔴 СОЛВЕР ВСТРОЕН В СБОРКУ

**Дефект:** `deck.py /tmp/p1 -o dek.html` собирает дек и **ни разу не зовёт** `vmeshchenie.py`.
Подбор типографики — отдельная команда, которую надо не забыть. Главный инструмент арки к
конвейеру не подключён.

Сделать так, чтобы **одна команда** давала дек с подобранной типографикой. Форма — твоё решение
(флаг у `deck.py` либо отдельный `sobrat.py`, который зовёт подбор и сборку по порядку); назови
выбор в `## ПЛАН` с причиной.

🔴 **Обязательные свойства, они не обсуждаются:**
- **подбор по умолчанию ВКЛЮЧЁН.** Выключается явным флагом. Умолчание, которое надо не забыть
  включить, — это не умолчание;
- **явный `kegl`/`liniya` в шапке карточки солвер НЕ ПЕРЕТИРАЕТ.** Если человек проставил число
  руками — оно выигрывает. Это решение владельца: *«в HTML руками не лезем принципиально»*, значит
  карточка — единственная его ручка, и отнимать её нельзя;
- **`playwright` не установлен — команда обязана сказать это ВНЯТНО и остановиться**, а не собрать
  дек молча без подбора. Молчаливая деградация здесь хуже отказа: получится дек, который выглядит
  собранным и не влезает.

**КРИТЕРИЙ Р3:** одна команда на папке лекции печатает и факт подбора, и факт сборки, и путь к
деку. Слайд с явным `kegl` в шапке после прогона имеет **тот же** `kegl` — показано числом до и
после. Без `playwright` команда даёт ненулевой `rc` и внятное сообщение — показано прогоном.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).
