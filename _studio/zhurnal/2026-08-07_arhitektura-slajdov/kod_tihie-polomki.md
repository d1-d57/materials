## 2. ЗАДАЧА — три тихих класса, в этом порядке

### П1. 🔴 СПИСОК ВНУТРИ СЦЕНЫ СХЛОПЫВАЕТСЯ В АБЗАЦ (Д17)

**Воспроизводится одной командой** (она же записана в метке долга):
```
cd _generator && python3 -c "from build_deck import render_md; print(render_md('{@3}\n- раз\n- два', {}, None))"
→ список схлопнулся в абзац, <ul> не родился
```
Движок читает тег сцены у абзаца и **не читает у пункта списка**. При этом `status-bloka.md`
разрешает списки внутри блоков — то есть блок-пример списком плюс пауза для зала сегодня
**не собираются вместе**.

🔴 **Почему это тихо и почему это первое в заходе.** Ошибки нет, гейт зелёный, HTML валидный —
просто вместо списка абзац. Автор увидит это на собранном слайде и полезет переделывать текст,
хотя дефект в движке.

⚠ **Проверь предпосылку до правки.** Решение Р-Г говорит: «сцена — свойство БЛОКА, а не абзаца»,
и раз тег висит на блоке, а список лежит внутри — механического блокера может уже не быть.
Команда выше говорит, что есть. Разберись, кто прав, и **скажи это в `## ПЛАН` до кода**: может
оказаться, что чинить надо не движок, а то место, где тег снимается с блока.

**КРИТЕРИЙ П1:** та же команда порождает `<ul>` с двумя `<li>`, и тег сцены применён к списку

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `_generator/build_deck.py` `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `_generator/build_deck.py` `_generator/sborka/**` `_generator/tools/fixtures/sborka/**`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).

### П1 — предпосылка проверена, команда права, а не Р-Г буквально
Прогнал команду из захода на слитом коде: `render_md('{@3}\n- раз\n- два', {}, None)` даёт
`<p data-scene-from="3">- раз - два</p>` — баг живой. Причина в `render_md` (`build_deck.py:238-264`):
ветка «список с тегом над ним» проверяет **только** `^\{\.([\w-]+)\}$` (regex `mcls`) — узкую форму
«только один класс, без `@N`». `{@3}` под этот regex не подходит, `mcls` не срабатывает, весь блок
(включая строку тега) уходит в ветку абзаца, где тег снимается уже с абзаца — список рушится в текст.
**Кто прав:** Р-Г («сцена — свойство блока») в коде реализован лишь ЧАСТИЧНО — только для класса,
не для `@N`/комбинаций. Блокера для списка «по конструкции» нет, чинить нужно именно `render_md`, как
и предполагает команда захода.

**Фикс:** объединить извлечение тега в ОДНУ точку до развилки «список или абзац» — если первая строка
блока целиком совпадает с `SCENE_PREFIX` (тег без хвоста текста), это тег БЛОКА: снимается один раз,
дальше решается, список это или абзац, и тег прикладывается к `<ul>`/`<p>` одинаково через
`_attrs_from_tag`. Для этого у `_attrs_from_tag` добавляется необязательный `default_cls` (нужен
списку без явного класса — сохранить дефолт `tlist`, который раньше был жёстко вписан отдельной
переменной `ul_cls`). Прогнал вручную все ветки (тег+текст в одной строке, тег один на всю строку,
список без тега, `{.cls}` без `@`, список с `@N` — новый случай) — совпадает с текущим выводом байт-
в-байт везде, кроме нового случая. Меняется только `render_md`/`_attrs_from_tag`, `render_inline_md`
не трогаю.
