# Дистиллят: техника md→HTML + пометки на полях

Разведано: `kurs leto 2026/{istochnik/, tools/, 6-lending/, NAVIGATION.md}`, `materials/catalan/kurs/*.html|md`, `materials/_generator/{build_deck.py,DESIGN.md}`.

## 1. Техника md→HTML

В `kurs leto 2026` — ДВА разных инструмента, оба чистый stdlib (re/pathlib/argparse/html/base64), без pip/сети, детерминированные:

- **`tools/render-pitch.py`** — НЕ md→HTML, а md→md синхро-чекер: тянет манифест+7 карточек `{L:id}` из `0-koncept/KONCEPT.md` → генерирует `6-lending/_out/pitch-generated.md` (справочный вид, не мастер). Цель — поймать расхождение рукописного `pitch-kurs.md` с источником, а не отрендерить страницу.
- **`istochnik/_generator/build.py`** — это и есть настоящий md→HTML движок (и главный ответ на вопрос 1). Источник — `istochnik/L{N}-{id}.md` (YAML-шапка id/poryadok/status/budget + типизированные `## §N · ТИП · title` разделы: КРЮЧОК/МАТЕМАТИКА/РАССКАЗ/ТЕХБЛОК/ЧЁРНЫЙ-ЯЩИК/ДОМАШКА). Рендер в `_out/L{poryadok}-{id}.html` через `_dizajn/shablon.html`+`stil.css`, фото вшиты base64 (офлайн). Перед сборкой — ЛИНТЕР-гейт (структурные ошибки валят exit 1: дубли id, битые `→[id]`-ссылки, обязательные поля матблока); собирается только если гейт зелёный. Цикл правки: правишь `L4-kriptografiya.md` → `python3 istochnik/_generator/build.py --build kriptografiya` (или без `--build`, дефолт) → смотришь `_out/L4-kriptografiya.html`. Каждый HTML-блок несёт `data-source="L4-kriptografiya.md §N"` + HTML-коммент — редакция из HTML однозначно возвращается в MD («md-redline»). Явное правило зашито в `istochnik/README.md`: «Правь источник, не HTML».
- **`tools/check_docs.py`** — репо-уровневый анти-дрейф гейт (порт из другого проекта): сироты вне `NAVIGATION.md`, битые относительные пути, NFC-имена файлов (анти-дубль й/ё), нет абс-путей песочницы, карта-папок↔ФС, и отдельно — `check_id_sync()`: `KONCEPT.md` якоря `{L:id}` ↔ `istochnik/L*.md` id/poryadok строго 1:1. Запуск: `python3 tools/check_docs.py`, ненулевой exit при любом нарушении.

В `materials/catalan/` — **такого инструмента НЕТ вообще**: 0 файлов `.py` вне `spravochnik/verify/*` (это proof-checkers по математике, не рендер). HTML-лекции (`mir2-statya.html`, `kurs-lekcii.html`, `kurs-obshchiy.html`, `lekciya-vetvyashchiesya.html`) — написаны напрямую (агентом/вручную) поверх нарративных `.md`-черновиков (`mir1-rasskaz.md`, `mir2-rasskaz.md`, `mir2-skelet.md`); нет компилятора, нет линтера, нет `mir2-statya.md` как отдельного файла-источника для `mir2-statya.html` — сам narrative-md и есть предпоследняя стадия, HTML пишется как отдельный авторский проход. Token-free Python renderer — техника ТОЛЬКО первой папки.

## 2. Пометки на полях — точный механизм (дословно)

CSS-класс `.mn` (найден идентично в `kurs-lekcii.html`, `kurs-obshchiy.html`, `mir2-statya.html`):
```css
.mn{float:right;clear:right;width:172px;margin:.35em -195px 1.1em 22px;
  font-family:"Source Sans 3",system-ui,sans-serif;font-size:.8rem;line-height:1.5;
  color:var(--muted);border-left:2px solid var(--rule);padding-left:.75em}
.mn b{color:var(--text)}
@media (max-width:900px){ .mn{float:none;width:auto;margin:1.2em 0;
  border-left:3px solid var(--rule);padding:.4em 0 .4em .9em} }
```
Разметка в источнике HTML — просто `<p class="mn">текст</p>`, вставленный инлайн в поток сразу после абзаца, к которому относится заметка (пример: `<p class="mn">Договоримся об обозначениях: <b>[n]</b>=…</p>`). Никакой нумерации/сносок/JS-переключателя (это НЕ classic Tufte sidenote с checkbox-хаком) — просто float-параграф, вытянутый в правый жёлоб отрицательным `margin-right:-195px` (главная колонка у́же контейнера `.layout` намеренно, жёлоб зарезервирован). На мобиле `float:none` — заметка падает в обычный поток как блок с левой чертой (граничная деградация, без потери контента).

Важный нюанс: `.mn` есть в трёх «зрелых» документах, но НЕТ в `lekciya-vetvyashchiesya.html` (более раннем) — там вместо этого `.caveat` (инлайн warning-бокс, другой паттерн). Похоже, `.mn` — техника, стандартизированная ПОСЛЕ первой лекции и не ретрофиченная назад.

Маркировка в исходнике-markdown: **не найдена**. `.mn` рождается как решение HTML-авторства над готовым текстом; в `mir2-skelet.md` (стадия планирования) есть просто пронумерованные «Замечание N.M» в прозе — обычные ремарки, не машиночитаемый маркер полей.

Контраст — у `istochnik/_generator/build.py` ЕСТЬ markdown-уровневый маркер сносок/полей: строки `> поле:нить …`, `> поле:честно …`, `> поле:отступление …`, `> поле:cue-визуал …` внутри раздела, парсятся `footnotes_of()` + `FOOTNOTE_MAP` → `<aside class="note ...">`/`<div class="cue">` (не float в поля, а инлайн-aside после раздела; каждый несёт `data-source`). Это настоящий авторский примитив «заметка на полях» на уровне markdown — просто стилистически рендерится как aside, а не как float-в-жёлоб.

## 3. Единый источник по стадиям

Да, реально и явно (не только заявлено — проверено кодом). `0-koncept/KONCEPT.md` — мастер (манифест + 7 карточек-якорей `{L:id}`), в `NAVIGATION.md` прямо помечен как «источник правды» для «Что за курс», а `istochnik/` — «ЕДИНЫЙ ИСТОЧНИК ПРАВДЫ ЛЕКЦИЙ (активен)». Каждый `istochnik/L*.md` несёт `status:` в шапке со стадийностью **skelet → chernovik → … → polno** (буквально встречены в коде/данных: `L4-kriptografiya.md` сейчас `status: chernovik`). Гейт-дисциплина привязана к стадии: `status: skelet` → «собирать нечего» (build.py отказывает); на `status: polno` редакционные предупреждения (бюджет матблоков, число домашних задач вне 5–10, квоты графа нитей) **эскалируют в жёсткие ошибки** — планка растёт вместе с созреванием ОДНОГО и того же файла, без форк-копий по стадиям. `check_docs.py::check_id_sync()` держит `KONCEPT.md`↔лекции синхронно на каждом прогоне. `PROTOKOL.md` фиксирует ещё один слой дисциплины: имя файла `L{N}-{id}.md` — стабильный id (N — порядок СОЗДАНИЯ, не показа); текущий порядок — только поле `poryadok`; ренумерация НЕ трогает имена файлов/ссылки, только эту шапку (задокументированная «мина»: после ренумерации надо чистить `_out/`).

В `catalan/` — тот же паттерн заявлен НАМЕРЕНИЕМ («`kurs/` = Слой 2 поверх `spravochnik/`, ссылается по id, не дублирует»), но НЕ гейтится машиной (0 чекеров) — и уже разъехался: `kurs/README.md` пишет «Пусто: наполняется в арке…», хотя в папке реально ~17 наполненных файлов. Т.е. сама идея «один источник растёт по стадиям» жива, но без скрипта-гейта она дрейфует незамеченной.

## 4. Объединять движки — рекомендация: НЕТ (держать раздельно)

Важно: `materials/_generator/build_deck.py` + `DESIGN.md` уже САМИ документируют родство — «Наследует философию `kurs leto 2026/istochnik/_generator/build.py`, но для формата слайд-колод… Границы: не переписывать `istochnik`/`spetsmat`». То есть вопрос уже разбирался один раз при проектировании `build_deck.py`, и мой разбор подтверждает то же решение.

Общая (реально общая, не случайно совпавшая) философия: только stdlib, лоwinter-гейт до сборки (structural error → exit 1, editorial → warn), HTML — чистая функция источника + видимый баннер «СГЕНЕРИРОВАНО — РУКАМИ НЕ ПРАВИТЬ», самодостаточный офлайн-выход (base64), `data-source`/provenance-комментарии для редлайна назад в md.

Расхождение данных — реальное, не косметическое: `build.py` — единица = один непрерывно текущий документ (лекция) из типизированных §-разделов с margin/footnote-асайдами СБОКУ от прозы, порядок чтения = порядок в файле, длина не фиксирована. `build_deck.py` — единица = дека фиксированного канваса 1440×810, собранная из ЯВНО упорядоченного списка slide-фрагментов (`brief.md: slide_order`), со scene-based progressive reveal (`{@N}` → `data-scene-from/until`) и иллюстрациями как отдельно версионируемыми файлами в template-реестре; порядок чтения = декларация, канвас не течёт. «Умный» шаг тоже разный: `render_inline` в `build.py` — типизированный DSL разделов + реестр кросс-ссылок/бэклинков; `render_inline_md` в `build_deck.py` — scene-теги + подстановка слотов в готовый slide-HTML.

Вывод: не сливать в одну библиотеку/движок — оба скрипта дёшевы (один файл, сотни строк, только stdlib), а абстракция, которая обслужила бы одновременно «текущий документ с полями» и «фиксированный канвас со сценами», добавит косвенности больше, чем стоит поддержка двух параллельных скриптов. Вместо слияния — зафиксировать общий контракт ОДНИМ коротким документом (constitution: stdlib-only · линтер-гейт жёсткий/мягкий · self-contained output · провенанс-комментарий · баннер «не править руками»), который любой ТРЕТИЙ будущий рендер (лекции/питч-HTML для Ф5 курса, или Ф5 фабрики) берёт как чек-лист, а не как код.

## 5. Что берём в Фазу I (арки 1/4/5) и в «мат-долг» (арка 4)

- **Арка 4 (мат-долг/авторские заметки):** взять CSS-механику `.mn` (float:right; clear:right; отрицательный margin-right; мобильный фолбэк `float:none`) как визуальный приём для полей — простой, без JS, чисто деградирует. НО источник маркировать НЕ сырым HTML (как в catalan), а markdown-примитивом по образцу `build.py`: `> поле:<вид> …` → таблица типов (`FOOTNOTE_MAP`) → рендер в `.mn`-float вместо `<aside>`. Так автор пишет заметку в markdown, не трогая HTML.
- **Арки 1/5 (пайплайн/сборка):** взять `check_docs.py`-стиль детерминированного анти-дрейф гейта для доков самой фабрики (сироты/битые ссылки/id-sync) — дёшево, stdlib, и уже видно живым примером (catalan/kurs/README.md), что без гейта документация тихо расходится с реальностью. Взять паттерн «стадия в шапке (`status: skelet/chernovik/.../polno`) + линтер ужесточается вместе со стадией» как конкретный механизм «один md растёт по стадиям» — он проверен на практике в `istochnik/`, устойчивее, чем форк-файлы на каждую стадию.
- Для декового рендера отдельного движка не нужно — `build_deck.py` уже несёт правильную ДНК (сам это документирует); держать в поле зрения только общий контракт (см. §4), чтобы не разошёлся молча.
