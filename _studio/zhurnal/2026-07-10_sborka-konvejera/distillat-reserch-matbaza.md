# ДИСТИЛЛЯТ — ресёрч + строгая матбаза как ОДИН поток

## Семя для арк-файлов

Семя для арк-файлов **2 (ресёрч)** и **3 (строгая матбаза)** конвейера `_studio` (паттерн SKILL.md, Р9), Фаза I «индивидуальность». Прочитано: `popsci-research/SKILL.md`, `popsci-narrative/SKILL.md` + `references/sources.md`, `math-russian-terminology/SKILL.md`, `FAZA-1-BLUEPRINT.md`, сверено с `RESHENIYA.md` (Р3, Р5, Р6, Р9, Р13). Чиним провал «платоновых тел»: ресёрч и нарратив как два отдельных вызова скиллов → математика срезана. Лечение — один локальный поток, растящий один HTML-файл.

## Контракт арки 2 — ресёрч

**Вход:** бриф 5 строк из арки 1 (Р13): тема · аудитория · длительность→бюджет слайдов (1 содерж. ≈ 2 мин, ≤3 сцены) · throughline-кандидат · что резать · референс.

**Действие** (перенято из popsci-research §2–4, без отдельного диалога-этапа): 5–15 разноплановых поисковых заходов, не один — канонические источники (оригинальные статьи, учебники) · лучшие научпоп-пересказы (3Blue1Brown, Quanta, Квантик, elementy.ru...) · неожиданные углы и связи (история, другие науки, недавние находки) · существующий визуальный пейзаж (сырьё для арки 9) · русскоязычные источники. Минимум 5 разных источников, не Wikipedia-only. Каждый нетривиальный факт — сразу с источником (автор, год, что именно оттуда). Отдельно и явно помечаются **«мат-долги»** — утверждения, которым нужен строгий вывод: это единственный мост к арке 3, без него математика теряется молча, как в провале. Плюс черновой скелет актов (3–5, «парадокс→разрешение→расширение→применение», не «определение→теорема→пример») и throughline-кандидат одной фразой — уровень скелета, не прозы.

**Выход** — пишется прямо в растущий HTML-файл (будущий гибрид-источник), не в отдельный md: факты+ссылки с якорями · список мат-долгов с адресом («в акте 3 нужен вывод формулы Эйлера») · throughline-кандидат + скелет актов.

**Гейт:** фактура (≥5 источников, ни одного факта без ссылки) + throughline одной фразой + в материале реально есть «но» (разворот, не пересказ). Если разворота нет — тема нечестно не тянет, сказать прямо, не тянуть дальше.

## Контракт арки 3 — строгая матбаза

**Вход:** список мат-долгов из арки 2 + факты/источники того же файла (тот же документ, не пересборка с нуля).

**Действие** (перенята дисциплина popsci-research §6–7, но без отсрочки — это обязательный этап с гейтом, не опциональный «черновик для себя»): на каждый мат-долг — точная формулировка (теорема/лемма) + доказательство целиком из литературы, с источником; если короткого доказательства в литературе нет — честно так и написать, не выдумывать. Пишется сразу в HTML+MathJax+SVG (формат-инвариант с этого этапа, не Markdown) — это «эталон истины» для авторской вычитки, несвёрнутый, в полном объёме. Каждой единице — стабильный якорь/id, чтобы арка 4 могла сослаться, сворачивая в `<details>`. Рядом со сложным шагом вывода — пометка, где нужна картинка, но саму иллюстрацию не рисовать (территория арки 9 через 🖼-слой арки 4).

**Выход:** доказательства в финальном объёме, вписанные в тот же growing-файл рядом с фактами арки 2, с якорями.

**Гейт «математика верна?»:** каждое утверждение сверено с ≥1 авторитетным источником · каждый шаг вывода без логических прыжков · нотация единообразна по всему файлу · русские имена/названия теорем/специфические термины точечно прогнаны через `math-russian-terminology` (см. ниже). Это дверь МЕЖДУ аркой 3 и аркой 4: арка 4 не начинает нарративную полировку, пока гейт не закрыт — иначе воспроизводим ровно провал «платоновых тел» (нарратив стартует раньше, чем математика заперта).

## Как это ОДИН поток (антипаттерн срезания математики + как чиним)

**Что было в провале:** `popsci-research` и `popsci-narrative` — два отдельных вызова с обнулением контекста между ними → два артефакта. Ресёрч собрал математику, но передал нарративу сжатый бриф, где мат-долги превратились в «добавим строгость потом» — обещание без якоря. `popsci-narrative` по собственному контракту НЕ занимается фактами и доказательствами («НЕ для сбора фактов»), поэтому честно проигнорировал математику как чужую зону. Итог: математика нигде явно не запрещена, но нигде и не является ничьей обязанностью в моменте — и исчезает.

**Чиним:** арки 2 и 3 — один локальный поток (одна агентская сессия/один заход без обнуления контекста между «ресёрчем» и «матбазой»), растящий ОДИН HTML-файл. Правило персистентности:
1. Всё, что нашла арка 2 (факт+источник, мат-долг, скелет актов), пишется прямо в файл с якорем — не пересказывается словами в следующий промпт, а физически остаётся.
2. Арка 3 не пересоздаёт материал — заполняет уже существующие мат-долги прямо в том же файле, полным выводом, без плейсхолдеров «допишем позже» без даты возврата.
3. Контент (факты+математика) всегда идёт ПЕРЕД нарративной полировкой, в одном файле: сначала полнота, потом красота. Нарративную полировку (сцены, склейки «из-за этого», small-big-small, закольцовка — §C–§L `popsci-narrative`) дёшево переделать поверх уже полного файла; математику дорого восстановить, если её не дописали сразу. Поэтому черновая нарративная разметка (throughline, скелет актов, проверка «есть ли но» на уровне целого текста) делается на уровне скелета уже в арке 2 — чтобы знать, куда лягут мат-долги, — а прозовая полировка глав откладывается до арки 4, когда математика уже заперта.
4. Гейт «математика верна?» — жёсткая дверь между 3 и 4.

## Стык с аркой 4

Арка 4 получает не два документа и не отдельный `scenario.md`, а тот же растущий HTML-файл с двумя уже персистентными слоями: **слой фактов+нарративного скелета** (арка 2: throughline, акты-кандидаты, факты с источниками) и **слой математики финального объёма** (арка 3: доказательства целиком, с якорями, уже верифицированные). Арка 4 применяет нарративную полировку (§C–§L: сцены с местом/временем/героем, «из-за этого» между актами, small-big-small, закольцовка финала с началом) к видимой прозе ВОКРУГ уже вписанной математики — не переписывает вывод, а обрамляет его сценой. Часть строгости арки 3 (полные технические варианты, крайние случаи, лишняя формальность) сворачивается в `<details>` со ссылкой на якорь; в видимой части остаётся математика в объёме настоящего доказательства, не выхолощенного пересказа (смысл Р5). Арка 4 добавляет третий слой — 🖼-описания на каждый такт, используя пометки-о-картинке, оставленные аркой 3 у сложных шагов вывода, как сырьё.

## Что перенимаем из popsci-* и как ре-хоумим

**Из popsci-research (метод, не вызов скилла):** дисциплина «5–15 заходов, ≥5 источников, каждое утверждение со ссылкой, доказательство только из литературы» → ядро арки 3 буквально. Шаблоны `<details>`-с-доказательством и подключение MathJax CDN → берём как конкретный HTML-инвентарь. «Критическая оценка темы» (тянет ли тема wow) → сливаем с ABT-проверкой popsci-narrative в ОДИН гейт арки 2, не гоняем две проверки одного вопроса из двух скиллов. НЕ перенимаем: собственную стадийность popsci-research, где строгая математика — опциональный «research-черновик для себя», который «не идёт в финал» (шаг 7 его SKILL.md) — это ровно то, что срезает математику; у нас она обязательна и с гейтом. НЕ перенимаем как живой вызов: `humanizer`/`russian-editor` в конце — это территория других арок (текст-стиль — арка 6, локальный корпус, Р4), не арок 2–3.

**Из popsci-narrative (метод, не вызов скилла):** throughline-тест (§A) и Story Spine-скелет (§C) → используются в арке 2 как скелет (одна фраза + позиции на акт), не как полная прозовая проходка. Проверка «из-за этого, не и ещё» между актами (§D) и ABT целого (§B) → сливаются с «критической оценкой темы» в один гейт арки 2. Сцены/status detail (§E), small-big-small (§F), imperfect puzzle (§G), закольцовка (§L) → чистая прозовая полировка, целиком откладывается до арки 4, когда математика уже на месте, не раньше. НЕ перенимаем: собственную цепочку скилла «popsci-research → popsci-narrative → russian-editor» как последовательность отдельных вызовов — это буквально диаграмма провала (Р3). Ре-хоумим как чек-листы внутри одной сессии, не как звонки наружу.

**math-russian-terminology — точечно, не блоком:** вызывается в арке 3, в момент первого появления имени автора / названия теоремы / специфического термина в доказательстве («Серпинский», «формула Эйлера», «лемма о...») — сразу на месте, по живой методике скилла (рус. Википедия → МЦНМО/НМУ/мехмат-конспекты → Квант), не финальным сплошным проходом по всему файлу. Лёгкий повторный точечный вызов возможен в арке 4, если в нарративной прозе всплывает новый термин, которого не было в математике арки 3.

## Next / чего не хватает

- Не спроектирована механика «мат-долга»: нужен конкретный синтаксис (HTML-комментарий / `data-`атрибут / плейсхолдер-`<details>`) для метки «здесь нужен вывод X», физически видимый в файле, который нельзя молча пропустить. Без этого «правило персистентности» — декларация, не механизм.
- Открыт вопрос, звать ли `proof-self-review` для гейта «математика верна?» — по духу Р3 (внешнее только медиум-независимое и инструментальное: 3D/код/термины) подходит не хуже threejs, но сейчас не в явном списке допущенных внешних скиллов. Решение — за владельцем.
- Не решено технически, как в реальном харнессе гарантировать «одна сессия без обнуления контекста» между ресёрчем и матбазой — раз кастомных `subagent_type` нет (ARKA.md), нужно явно писать арки 2–3 как один заход/один субагент с инлайн-ролью на обе стадии, либо как два арк-файла, которые заход прогоняет подряд без compact/clear между ними. Решение по `RUKOVODSTVO-zahodami.md` ещё не зафиксировано.
- Не решено, куда девать честный «no-go» из «критической оценки темы» (тема не тянет) — раз фабрика не диалог, это либо чекпоинт владельцу внутри арки 2, либо тихий сдвиг акцента без остановки. Блюпринт называет гейты «гейтами автора» (Р6) — вероятно чекпоинт, но явно не проговорено.
- Бюджет длины видимой математики (popsci-research: 600–800 слов/акт) не сверен с бюджетом слайдов из брифа (1 содерж. слайд ≈ 2 мин) — возможен конфликт объёма, который проявится только на арке 4/5.
- Не зафиксировано, должна ли арка 3 сама рисовать SVG-наброски для сложных шагов вывода, или только оставлять текстовую пометку «нужна картинка» — по границам (арка 9 = иллюстрации, арка 4 = только 🖼-описания) похоже на второе, но явно не проговорено.
