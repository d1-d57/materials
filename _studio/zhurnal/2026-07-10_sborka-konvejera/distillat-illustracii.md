# ДИСТИЛЛЯТ — Арка 9 «Иллюстрации»: оркестрация локальный-SVG / threejs / код

Источники: `html-slides-studio/references/{images,simulations,slide-engine}.md`, `html-slides-studio/scripts/audit.py`, `threejs/SKILL.md` + `references/{embedded-scene-in-slides,translucent-depth}.md`, `_generator/build_deck.py`, `dandelin/src/{brief.md,tokens.css,illustrations/*,chapters/spheres.html,drivers/01.js}`, `buffon/ANIM-01-cos-area-spec.md`, `RESHENIYA.md` (Р1/Р3/Р10), `ARHITEKTURA-FABRIKI.md`, `PRAJOR-ART.md` §5, `FAZA-1-BLUEPRINT.md`.

## Контракт арки 9

**Вход** — два уровня одного и того же описания:
1. Гибрид-источник (шаг 3, Р5): «описания иллюстраций 🖼» по тактам — проза «что показать» + к какой сцене привязано.
2. Раскадровка (шаг 4/5): per-slide `archetype + сцены + описание илл.`, материализовано как **плейсхолдер-файл** прямо в `illustrations/*` (или `chapters/*` для 3D) — это НЕ метафора, а реальный формат уже в эталоне: `dandelin/src/illustrations/spheres.html` = `<div class="ph"><div class="ph-t">Шары Данделена</div><div class="ph-s">3D ЯДРО · ждём файл · 4 сцены<br>конус → верхний → нижний → F₁ F₂</div></div>`. Выход раскадровки (`FAZA-1-BLUEPRINT.md`) прямо назван «кликабельное HTML-демо (плейсхолдеры илл. + сцены + рамочные слайды)».

Значит вход арки 9 конкретно = **заменить плейсхолдер, сохранив stem/id**, чтобы `data-ill="name"` / `data-iframe="tpl-name"` в `slides/*` и `chapters/*` не пришлось трогать.

**Выход** — файл в `illustrations/*` (2D) или пара `chapters/<name>.html` + `drivers/NN.js` (3D), никогда правка `shablon.html`/`engine.js`. Три реальных формы (см. `dandelin/src/brief.md`):
- `.svg` — живой инлайн-вектор (схема/диаграмма);
- `.html` с `<img src="data:…base64">` внутри — фото/растр (пайплайн `images.md`, не Р10);
- `chapters/*.html` + `drivers/NN.js` — 3D-глава для iframe (авторится `threejs`-скиллом).

Все три попадают в генератор ОДИНАКОВО дословно: `build_deck.py.load_dir()` читает файл целиком → `{{ILL:name}}`/`{{CHAPTER:name}}` → подставляется в `<template id="ill-name">`/`id="tpl-name"` в `shablon.html`. Генератор НЕ трансформирует иллюстрации (единственный «умный» шаг генератора — markdown в `content/*`) — вся ответственность за палитру/размер/id лежит на арке 9 ДО того, как файл лёг в папку.

**Гейт (сдача слайду)** — двухслойный:
1. Статический lint, уже реализован в `build_deck.py.lint()`: `data-ill`/`data-iframe` резолвится на существующий файл (п.2); каждый `var(--x)` внутри illustrations-файла определён в `tokens.css`, иначе явная ошибка с текстом **«→ чёрная заливка»** (п.3) — без браузера, мгновенно.
2. Headless render-гейт, ЧАСТИЧНО реализован в `audit.py` (Playwright, headless Chromium): SVG не переполняет свой бокс (`svgOverflow`), нет текста-прозы внутри `<svg><text>` (`svgProse`, сейчас WARN, не FAIL). НЕ реализовано: пиксельная проверка «весь бокс иллюстрации — не один плоский цвет» — см. «Next».

## Правило оркестрации — 4 ветки, не 2

Р3: внешний скилл только там, где способность медиум-независима. «Иллюстрация» на этой фабрике — фактически 4 разных медиума с разными файлами/registries, отсюда четыре ветки решения:

1. **Статичная схема, линия+заливка, без движения → локальный `.svg` руками.** Дефолт, ~90% случаев. Канон рисунка — `images.md`: тонкая линия 1.5–2.5px, канон-палитра, БЕЗ текста-комментария на картинке (только идентификаторы вроде `F₁`, `P`).
2. **Интерактив/анимация, но плоский 2D (счётчики, брошенные фигуры, drag) → локальный canvas + `lab.js`/`lab-ext`** (`simulations.md`). НЕ внешний скилл: способность специфична презентации (зоны, сцены, dock-панель) — Р3 carve-out сюда не относится.
3. **По сути трёхмерный объект (тело, сечение, вращение, вложенные поверхности) → вызвать `threejs`.** Строить сцену STANDALONE за render-harness'ем (Playwright+SwiftShader, `window.__shot()`, `translucent-depth.md`) ПЕРВОЙ, только потом встраивать. Результат уходит в `chapters/*` + `drivers/*`, НЕ в `illustrations/*` — другой registry, другой контракт (см. ниже).
4. **Нужен готовый растр из данных/фото (вычисленный график, историческое фото) → код (matplotlib→PNG) или пайплайн `images.md`** (Wikimedia/NASA/Met/LoC) → base64 `<img>` внутри `illustrations/<name>.html`. Здесь `<img>`-изоляция ОК: цвет — часть содержимого (фото), не тема.

Критерий одной фразой (когда звать `threejs`, а не рисовать SVG): если убрать глубину/поворот — картинка перестаёт быть понятной? Да → 3D. Нет → плоский SVG дешевле и надёжнее.

## Пайплайн Р10 по шагам (ветка 1 — основная нагрузка арки)

1. **Авторинг `.svg`.** Обязательно `viewBox` + `preserveAspectRatio="xMidYMid meet"` + `width:100%;height:100%;display:block` (без этого — фолбэк на intrinsic viewBox-размер и обрезание при масштабе деки; ловится `audit.py`'s `svgOverflow`). Заливки/обводки — токенами (`--ink --brick --steel --mustard --marker --board --card …`, полный список `tokens.css`), не произвольным hex.
2. **SVGO-нормализация** — pinned-версия (зафиксирована в конфиге, не «latest») + `prefixIds` с per-file префиксом (по stem файла). Зачем именно per-file: все `<template id="ill-*">` лежат в ОДНОМ финальном документе одновременно (слайды не перемонтируются при навигации) — если два файла независимо заведут внутренний `id="clip1"`, второй тихо ломает `clipPath`/`gradient`/`mask` первого через общий id-namespace документа. Прецедент такого локального id уже есть: `cone-title.svg` → `<clipPath id="waffle">` — риск не гипотетический.
3. **Headless-верификатор — два слоя:**
   - a) статический (уже работает) — regex вытаскивает `var(--x)` из illustrations-файла, сверяет с `tokens.css`, недостающий токен → ошибка ДО рендера;
   - b) рендер-уровень (частично есть) — `svgOverflow`+`svgProse` уже читаются с живого DOM headless Chromium. ОТСУТСТВУЕТ пиксель-семпл бокса иллюстрации на «один плоский цвет» — `audit.py` сегодня семплит только CSS `background-color`/`color` обычных DOM-узлов (>8000px²), SVG `fill`/`stroke` не читает и скриншот бокса не делает.
4. **Вшивание** — файл кладётся в `illustrations/` под именем, которое ждёт слайд (`data-ill="name"`); дальше чисто механически — byte-подстановка `{{ILL:name}}` генератором. Арка 9 не пишет ничего в `shablon.html`/`engine.js`.

## Стык с аркой 8 (сцены) и Р1 (генератор)

- **С Р1/генератором:** иллюстрации живут в `illustrations/*` рядом с `content/*.md`, `slides/*.html`; `build_deck.py` их не трансформирует (дословная конкатенация) — корректность гарантирует арка 9 ДО попадания файла в папку, не генератор постфактум.
- **С аркой 8** — два разных механизма синка по типу медиума:
  - *Плоский SVG:* поэтапное появление частей — обычный CSS scene-reveal слайда (`data-scene-from/until`, opacity/visibility), арка 8 вешает эти атрибуты прямо на `<g>`/элементы внутри уже вшитого SVG или на весь `.ill-box`. Отдельного контракта не нужно — только не делать картинку одним неделимым `<path>` там, где сценарий требует поэтапности.
  - *3D-глава (iframe):* отдельный контракт «deck↔scene» (`slide-engine.md` «Embedded synchronized chapter» + threejs `embedded-scene-in-slides.md`). Слайд несёт `data-scenes="N"` + `data-step-offset="K"`; движок шлёт `{goStep}`/`{ride:true}` через `postMessage` (~150мс поллинг хэша); глава реализует `goStep(n)`/`resize()`, никогда не дёргает свою навигацию мимо родителя (клик по точке-шагу → `{navSub}` родителю, не `goStep` напрямую). Арка 9 обязана заранее знать число сцен от арки 8 и либо построить сцену с ровно таким числом внутренних шагов, либо расщепить один сценарий на несколько слайдов через `data-step-offset` (пример: «Геометрия мороженого» / `chapters/spheres.html` + `drivers/01.js`).
  - Параллелизация 8↔9 (заявлена в `ARHITEKTURA-FABRIKI.md`) технически возможна именно потому, что контракт — это имя ассета + число сцен, а не совместная правка одного файла.

## Ловушки

- **Изоляция `<img>`/base64** — `var()`/`currentColor` внутри растра не работает; схематический рисунок, случайно завёрнутый в `<img>` вместо живого `<svg>`, либо не подхватит перекраску темы, либо (при недостающих inline-стилях) даст чёрную заливку. Фото/растр — единственный законный кейс `<img>`.
- **Конфликт id при инлайне нескольких SVG** — см. пайплайн-шаг 2; лечится только per-file id-prefix на этапе SVGO, руками не углядеть.
- **Одноцветные зоны / «нет ошибки = отрисовалось»** — undefined `var(--x)` → `fill` резолвится в чёрный БЕЗ ошибки в консоли. `tokens.css` дандэлина сам несёт предупреждающий комментарий: *«define ALL (undefined var in extracted SVG = black fill)»* — то есть баг уже случался на практике до формализации Р10 (см. `slide-engine.md` «SVG palette gotcha», кейс `--accent`).
- **Хардкод-hex вместо `var()` в самих эталонах** — все 4 `.svg` дандэлина (`cone-title`, `axial-section`, `tangent-ray`, `montage`) сегодня НЕ используют `var()`, только литеральный hex, вручную совпадающий с палитрой. Работает, но не масштабируется и не даёт статическому lint'у (шаг 3a) что-либо реально проверить. Для новых иллюстраций арки 9 — писать через `var(--token)` с первого дня, дандэлин тут образец СТИЛЯ рисунка (плотность линии, палитра, «без текста на картинке»), не образец механики токенов.
- **Текст/подписи на картинке** — жёсткое авторское правило (`images.md`): никаких комментариев, только идентификаторы. Ловит `svgProse` в `audit.py`, но это WARN, не FAIL — сборка сама не остановится; для арки 9 стоит решить, ужесточать ли до FAIL.
- **3D, отлаженный прямо в деке** — самый дорогой антипаттерн, задокументирован на «Геометрия мороженого»: каждая правка требует пересборки всей колоды, а canvas 0×0 пока слайд скрыт. Всегда строить сцену standalone за harness'ем сначала (`embedded-scene-in-slides.md`).
