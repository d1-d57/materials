# РАЗБОР ПОВТОРОВ — что ломается снова и снова и не становится решением

**Дата данных: 2026-08-04.** Числа сняты командами, не по памяти; команда пересчёта названа у каждой таблицы.

Разбор отвечает на один вопрос владельца: *какие ошибки повторяются и почему они не превращаются в решения*. Отдельные строки инцидентов сами по себе бесполезны — их 90, читать их никто не будет. Полезно другое: **сколько раз повторился КАЖДЫЙ класс, жив ли он сегодня, и что должно покраснеть, чтобы он не повторился завтра.**

---

## §1. Главный факт: разбора не было вообще

```
grep -c '^- 20' _studio/zhurnal/_INFRA-git/INCIDENTY.md          # строк-инцидентов
grep -c 'статус: → ZHURNAL' _studio/zhurnal/_INFRA-git/INCIDENTY.md   # доведено до урока
```

**90 инцидентов за 10 дней. Один доведён до урока. 89 висят со статусом «открыт».**

Инструмент честно пишет строку при каждом срыве — механизм сбора работает. Не работает следующий шаг: у «входящей корзины» нет процедуры разгрузки и нет ничего, что покраснеет от её переполнения. Корзина, из которой никогда не выгребают, — это не корзина, а свалка, и именно поэтому один и тот же класс повторялся 26 раз, прежде чем его починили.

🔴 **Это и есть ответ на вопрос «почему ошибки не превращаются в решения»: превращать их в решения никто не обязан.** Дальше по документу — исправление этого, а не только исправление отдельных классов.

## §3. Хэндоффы — один класс, 20 повторов

```
find _studio -name 'HANDOFF*' | wc -l                                    # всего
for f in $(find _studio -name 'HANDOFF*'); do head -8 "$f" | grep -ql 'sdelat_handoff.py' || echo "$f"; done | wc -l   # прозой
```

**22 хэндоффа, 20 написаны прозой по памяти, 2 собраны скриптом (оба 04.08).**

Чего не хватает в написанных прозой:

| Чего нет | В скольких из 22 |
|---|---:|
| стартовой строки — куда бежать в новом чате | 20 |
| указания канала и папки запуска | 20 |
| интервью первым ходом | 20 |
| числа «сколько закрывает» | 20 |
| критерия готовности, который может ПРОВАЛИТЬСЯ | 19 |
| даты данных у чисел | 19 |

Диагноз тот же, что у коммитов: **инструмент есть, обязанности им пользоваться нет.** `sdelat_handoff.py` появился 04.08 и сразу дал два корректных хэндоффа — механика работает. Но закрыть сессию можно и без него, и двадцать раз именно так и вышло.

Цена названа владельцем прямо: *«я запускаю новую сессию, она очень долго работает, делает что-то не то»*.

Смежные долги того же корня (из хэндоффа 04.08, проверены живыми командами):
- `poteri` не вызывается при закрытии сессии — потерянная работа обнаруживается на следующий день, а не в момент;
- гейт Г0 не различает «зона чиста» и «работа перенесена ко мне» — зона была чиста ровно потому, что файлы не приезжали;
- `_studio/outputs/gipoteza-yakobiana-dajdzhest.md` не зарегистрирован и роняет широкие коммиты по `_studio`; описание знает только владелец.

**Заход 2 поднят на второе место сознательно.** Без него шесть остальных починок закроют шесть классов, а седьмой родится и снова будет копиться месяц никем не читаемый. Механизм важнее любой отдельной починки: он единственный, кто напомнит про остальные.

**Порог — 7 дней, и это не «чем строже, тем лучше».** Владелец назвал пять дней между разборами нормальным ритмом, и он прав: 30.07 разобрали, 04.08 разбираем снова — это не «забили». Гейт обязан пропускать нормальный ритм и краснеть только на ненормальном, иначе он шумит, а шумящий гейт отключают (`KONSTITUCIYA` Р31). Второй порог — 21 день на вердикт «дефект → заход»: три недели молчания это уже не «руки не дошли».

## §5. Что покраснеет — по каждой починке

Правило фабрики: правило заводится вместе с тем, что покраснеет при нарушении (`KONSTITUCIYA §11`). Для очереди выше это значит:

| Заход | Что краснеет |
|---|---|
| 2 | фикстура: подсунуть заведомо недоехавший путь — вывод обязан назвать его дословно |
| 3 | `zakryt_sessiyu.py` завершается с ненулевым кодом, если хэндофф не собран скриптом или `poteri` не запущен |
| 4 | фикстура: план возрастом старше N часов — `commit` обязан отказать с названным возрастом |
| 5 | фикстура без playwright: прогон обязан быть зелёным со строкой «пропущено», а не красным |
| 6 | `git_zona.py --nesuschestvuyuschiy-flag` — в выводе обязано быть имя флага и список существующих |
| 7 | гейт на числе открытых строк в `INCIDENTY.md`: больше порога — красное на закрытии сессии |

Строка «покраснеет» без фикстуры — это надежда, а не гейт. В каждый заход очереди фикстура входит обязательным пунктом.

## §6. Как пересчитать таблицу §2

```bash
cd <корень репо> && python3 - <<'EOF'
import collections
rows=[l for l in open('_studio/zhurnal/_INFRA-git/INCIDENTY.md',encoding='utf-8')
      if l.startswith('- 20')]
def cls(s):
    b=s.split('·')[2].strip(); low=s.lower()
    if b.startswith('коммит с --no-verify'):
        if 'karta' in low and ('read-only' in low or 'регистр' in low): return 'A регистрация .md vs зона'
        if 'playwright' in low or 'chrome-headless' in low: return 'B окружение песочницы'
        return 'C прочий чужой долг'
    if b.startswith('merge'):
        if 'грязные пути' in b: return 'D merge отбит грязным деревом'
        if 'конфликт' in b: return 'E конфликт путей'
        return 'F merge без диагноза'
    if 'не целиком' in b: return 'G коммит не целиком'
    if 'без плана при грязном' in b: return 'H commit без плана'
    if 'план не готов' in b: return 'I план битый'
    if 'путей, которых нет' in b: return 'J пути не существуют'
    if 'мусорными аргументами' in b: return 'K мусорные аргументы'
    if 'запись в .git' in b: return 'L песочница'
    return b
d=collections.defaultdict(list)
for r in rows: d[cls(r)].append(r[2:12])
for k in sorted(d,key=lambda x:-len(d[x])):
    v=d[k]; print(f'{len(v):3}  {k:34} {min(v)} → {max(v)}')
EOF
```
