Операция лоссовая по последствиям: если файл не доедет, это обнаружится тем, что у живого сайта пропадёт страница, — и обнаружит это читатель, а не мы.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `sayt/` `.github/workflows/hugo.yml` `_studio/zhurnal/2026-07-30_dovodka-fabriki/kod_odna-vetka.md`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `sayt/` `.github/workflows/hugo.yml` `_studio/zhurnal/2026-07-30_dovodka-fabriki/kod_odna-vetka.md`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).

### Числовой критерий готовности написан «на глаз» и проваливается на ВЕРНОМ результате
Пункт 1 критерия («14 файлов `main` vs файлов в `sayt/` → сходится, минус `.gitignore`») даёт ожидание 13. Верное число — 12: из `main` в `sayt/` не едут ДВА файла, а не один. `.github/workflows/hugo.yml` по Шагу B обязан остаться в `.github/workflows/` в корне репозитория — оттуда его читает GitHub Actions. Аналитик вычел из головы одно исключение из двух, хотя оба записаны его же рукой в соседних абзацах того же захода.
ЦЕНА: заход выполнен верно и при этом валит собственный гейт — исполнитель обязан либо оспорить критерий (стоит круга согласования), либо подогнать под него факт. Подгонка здесь означает перенос `hugo.yml` в `sayt/` ради совпадения цифры — а это ровно тот файл, который в `sayt/` перестаёт работать: workflow вне `.github/workflows/` GitHub не видит, сборка не поднимается никогда, и обнаруживается это не гейтом, а мёртвым сайтом. Прямое нарушение `KONSTITUCIYA §10`: в критерий вписано число, а не команда, которая его считает.

### Гейт веса не отличает «в git заезжает 6.7 МБ» от «у уже хранимого блоба появился второй путь»

### 🔴 ДОЛГ — один обход `--no-verify`, причина названа

**Критерий готовности п.6 провален честно: обход был, ровно один, на коммите `sayt/`.** Не прячу его в таблице — вот он полностью.

Гейт веса `check_ves.py` покраснел на `sayt/static/teorkat/lekciya-1.pdf` (6.7 МБ, порог 5 МБ). Проверил его посылку, прежде чем что-либо делать: гейт читает `git diff --cached` и берёт **размер файла на диске**, не спрашивая, есть ли такой блоб в базе. А он есть: `git rev-parse main:static/teorkat/lekciya-1.pdf` и `git rev-parse :sayt/static/teorkat/lekciya-1.pdf` дают **один и тот же `05ef399d482d9263d2a9a5d1b71e23ec89030b63`**. Git хранит содержимое один раз по хэшу — этот PDF лежит в `.git` с публикации сайта и никуда оттуда уже не денется. Мой коммит добавляет к нему **вторую запись в дереве, а не 6.7 МБ**.
