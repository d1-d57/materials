## 2. ЗАДАЧА — три удара с общим корнем

Инцидент сводится к двум корням арки, всплывшим в новой арене (bootstrap + гигиена): №1 — «на кривом входе инструмент обязан ГРОМКО падать, а не тихо делать не то» (флаг проглочен как данные); №2 — мета-корень арки «пометка ≠ механизм» (в HANDOFF стояло «удалить» — не удалило). Три удара, каждый заканчивается ПАДАЮЩЕЙ фикстурой.

**Удар 1 — `bootstrap_*` валидируют имя.** Отвергать имя арки/захода/лекции, начинающееся с `-` ИЛИ не проходящее слаг-валидацию (пустое, пробелы, слэши, ведущая точка) → `SystemExit` с внятным текстом (напр. «'--help' похоже на флаг, а не имя арки; имя — слаг вида `2026-07-23_tema`»). Пройди по ВСЕМ трём: `bootstrap_arka.py` берёт `argv[0]` сырым (худший), у `bootstrap_zahod.py`/`bootstrap_lekcia.py` проверь, как принимается слаг, и закрой ту же дыру. Общий хелпер — если дёшево; не рефактори ради рефактора.

**Удар 2 — `plan`/`check` карантинят подозрительный untracked (убирает РЕГУЛЯРНУЮ цену).** `plan` детектит untracked-пути с ведущим `-`, НЕ включает их в черновик и выносит отдельным блоком: «подозрительный мусор — не в плане, снять `git_zona.py purge`». Эвристика — начни со СТРОГОЙ «только ведущий `-`»: ноль ложных срабатываний (легитимной арки с таким именем не бывает). Список известных «к удалению» — только если дёшево и без ложных; сомневаешься — оставь на ведущем `-` и скажи в отчёт. `doctor` тоже пусть называет такой мусор отдельно от честного «вне git».

**Удар 3 — подкоманда `purge` снимает помеченный мусор.** Почему подкомандой, а не shell: имя `--help` начинается с `-`, любой `rm` примет его за флаг (нужен `rm -- --help`), а выдавать такое владельцу — ровно ловушка §0 (bash-в-чат ломается о zsh). Пути — явным аргументом или из карантин-списка `plan`. Удаление — Python (`shutil`/`pathlib`), не shell. ## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- _generator/tools/bootstrap_arka.py _generator/tools/bootstrap_zahod.py _generator/tools/bootstrap_lekcia.py _generator/tools/git_zona.py _generator/tools/fixtures/git_zona _studio/docs/kak-delat/GIT-disciplina.md _studio/zhurnal/_INFRA-git                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- _generator/tools/bootstrap_arka.py _generator/tools/bootstrap_zahod.py _generator/tools/bootstrap_lekcia.py _generator/tools/git_zona.py _generator/tools/fixtures/git_zona _studio/docs/kak-delat/GIT-disciplina.md _studio/zhurnal/_INFRA-git   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` («УРОК БЕЗ ЦЕНЫ») судит staged-пути.** Коммитишь свою зону — там только твоё, `--no-verify` не нужен. Хук покраснел — значит в коммит уехало чужое: **не обходи, пересобери коммит.**
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).
