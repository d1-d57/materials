## 2. ЗАДАЧА — сгладить путь коммита для владельца

### Отчёт: ПОЧЕМУ коммиты систематически не проходят (живые случаи 2026-07-23)

Каждый — потеря минут на стыке «Cowork готовит → владелец жмёт». Пять разных, одна суть: путь «сохранить зону» слишком многошаговый и рвётся на ровном месте.

1. **Запуск из `~`, а не из корня репо** → `python3 _generator/tools/git_zona.py …` = `can't open file '/Users/…/_generator/…'`. Дважды подряд. Инструмент даже не загрузился, подсказать не мог.
2. **Инлайн `# комментарий` в команде** → у владельца zsh без `interactivecomments`, `#` уехал в argv → `unrecognized arguments: # предпросмотр`. Обе `adopt`-команды упали так.
3. **`commit` без `plan`** → «Плана нет». Двухшаговость (`plan` → `commit`) не очевидна.
4. **`plan` пишет заглушку `== <переписать>` в `.commit-plan`, `commit` отказывается, пока её не переписали** → «В плане остались неотредактированные сообщения — их 1». Владелец про шаг «впиши сообщение» не знал. А вписать его должен **Cowork** (у него текст в голове), но Cowork из песочницы коммитить не может → сообщение вписывает один, жмёт другой, и этот стык нигде не выделен как одна тропа.
5. **worktree/adopt для параллельных заходов** — сам по себе многоходовый (был отдельно вылечен подкомандой `adopt`, но общая тяжесть осталась).

**Диагноз (гипотеза аналитика — оспорь, если неверна):** для 90% случаев владельцу нужно одно — «сохрани вот эту зону с вот этим сообщением». Сейчас это 2–3 команды + ручная правка файла + запуск из верного каталога без комментариев. Каждый шаг — точка отказа. Инварианты (sandbox-отказ, pathspec, зонирование) при этом правильные и трогать их нельзя — лечить надо ОБЁРТКУ, а не ядро.

### Что сделать

**Спроектируй и внедри ОДНУ надёжную тропу коммита зоны** — минимум шагов, минимум мест для ошибки. Форму выбираешь ты; направления (не приказ):

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- _generator/tools/git_zona.py _generator/tools/fixtures/git_zona _studio/docs/kak-delat/GIT-disciplina.md _studio/zhurnal/_INFRA-git                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- _generator/tools/git_zona.py _generator/tools/fixtures/git_zona _studio/docs/kak-delat/GIT-disciplina.md _studio/zhurnal/_INFRA-git   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` («УРОК БЕЗ ЦЕНЫ») судит staged-пути.** Коммитишь свою зону — там только твоё, `--no-verify` не нужен. Хук покраснел — значит в коммит уехало чужое: **не обходи, пересобери коммит.**
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).
