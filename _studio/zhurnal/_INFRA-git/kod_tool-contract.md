## 2. ЗАДАЧА — контракт инструмента как МЕХАНИЗМ, не проза

Корень эпистемический: урок живёт текстом и не переносится на следующий инструмент. Лечение — машинная проверка, которую хук гонит на каждый staged-инструмент. **Держись MVP:** дешёвые статические проверки, покрывающие корпус; без золочения (это и токены, и риск ложных).

**Шаг 1 — `_generator/tools/check_tool_contract.py --staged`**, статический линтер staged `_generator/tools/*.py`. Проверки грепом/AST, БЕЗ запуска инструмента:
- **Переносимость (кластер B):** нет GNU-измов (`touch -d`,`date -d`,`sed -i`,`grep -P`,`stat -c`,`xargs -r`) в коде и в печатаемых строках; каждый вызов git несёт `--no-optional-locks`; нет печати владельцу сырого shell (`rm `,`&&`,`$(`,glob) — только `git_zona.py <cmd>`.
- **Запись отказывает в песочнице (E/B):** файл, импортирующий снос/запись (`shutil`,`os.remove/rmdir`,`unlink`, git-`commit`/`worktree add`) или трогающий `.git`, обязан ссылаться на детект песочницы/`refuse_write`. Проверка ПРИСУТСТВИЯ защиты, не её работы.
- **Нет тихого «не то» на входе (кластер A):** файл с `argv`/`argparse` обязан иметь спутник-фикстуру, доказывающую отказ на кривом входе, ИЛИ пометку `# TOOL-CONTRACT: no-input`. Линтер проверяет НАЛИЧИЕ фикстуры/пометки — мусорный вход сам НЕ подаёт.
- **Честный сигнал (A/E):** только если дёшево и без ложных (напр. греп `print("❌"` в ветке нормального исхода); сомневаешься — оставь на фикстуры конкретных инструментов, скажи в отчёт. Ложных ради полноты не гони.
🔴 Судит **staged-диф** (как `check_kartoteka --staged`): пре-существующее нарушение НЕ блокирует, пока файл не правят. Молчит, когда чисто. Rc=1 только на реальном нарушении — с человеческим сообщением и путём к правилу.

**Шаг 2 — хук.** В `.githooks/pre-commit`: если в staged есть `_generator/tools/*.py` — гнать `check_tool_contract.py --staged` (с `env -u …` как у фикстуры git_zona), и если среди staged есть инструмент со спутник-фикстурой — поднять её. Это ОБОБЩАЕТ узкий триггер (сейчас только `git_zona.py`) на все инструменты. Три существующих гейта — не трогать, порядок и форму `if … || exit 1` сохранить.

**Шаг 3 — мета-фикстура** `_generator/tools/fixtures/tool_contract/PROGNAT.sh` на одноразовом репо: на КАЖДУЮ проверку — временный инструмент-нарушитель → линтер КРАСНЕЕТ; здоровый временный → ЗЕЛЁНЫЙ (обе стороны). Боевой репо не трогать, окружение вычистить (`unset $(git rev-parse --local-env-vars)`).

**Шаг 4 — калибровка (гейт безопасности, не формальность):** прогнать `check_tool_contract.py` по ВСЕМ текущим `_generator/tools/*.py` — **все обязаны пройти, ноль ложных.** Проверка, краснящая на здоровом коде, → СМЯГЧИТЬ проверку (она кривая), а не чинить инструмент (вне зоны, риск). Настоящую латентную дыру, если нашёл, — строкой в ОТЧЁТ, здесь не чини.

**Шаг 5 — канон/журнал:** `GIT-disciplina.md` — ОДНА ссылка (§0 или §5): «новый/правленый инструмент фабрики → контракт; держит гейт, не память; обход `--no-verify` — громко». `SOSTOYANIE` §механизмы (+строка). `ZHURNAL` — запись про эпистемический корень и его закрытие механизмом, с ЦЕНОЙ (тот же класс возвращался каждой сессией новой ареной; последняя цена — bootstrap-мусор чуть не уехал в гейт-коммит).

**КРИТЕРИЙ ГОТОВНОСТИ (может ПРОВАЛИТЬСЯ):**
1. **Ноль ложных на текущем дереве:** линтер по всем `_generator/tools/*.py` не покраснил ни одного здорового — проверено N из N (перечисли).
2. **Реальное нарушение краснеет:** мета-фикстура, каждая проверка мутационно ловит нарушителя И пропускает здорового (проверок K → 2K мутаций).
3. **Три старых гейта хука целы:** healthy-коммит проходит; посаженное нарушение каждого из трёх (урок без цены, .md без KARTA, регрессия git_zona) по-прежнему краснеет.
4. **Триггер = охват:** правка ЛЮБОГО `_generator/tools/*.py` (не только `git_zona.py`) поднимает контракт — показать на `bootstrap_*`.
5. **Тихо когда чисто, быстро:** коммит, не трогающий инструменты, гейт не будит; линтер < ~1–2 с.
6. **Клапан и канон:** `--no-verify` по-прежнему обходит (не молча); контракт описан в каноне, ловушка «канон отстал» зелёная.
**Отрицательный вердикт несёт ОХВАТ:** «проверено N из N», а не «вроде норм».

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- .githooks/pre-commit _generator/tools/check_tool_contract.py _generator/tools/fixtures _studio/docs/kak-delat/GIT-disciplina.md _studio/zhurnal/_INFRA-git                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- .githooks/pre-commit _generator/tools/check_tool_contract.py _generator/tools/fixtures _studio/docs/kak-delat/GIT-disciplina.md _studio/zhurnal/_INFRA-git   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).
