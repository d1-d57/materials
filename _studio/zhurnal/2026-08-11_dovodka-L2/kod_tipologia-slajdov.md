Владелец: *«старые слайды писались вручную, они могут не соответствовать правилам, которые
идеальные, которые мы хотим выстроить. Поэтому для аксиом мы отталкиваемся от последней лекции. Но
для понимания того, как устроены могут быть эти типы, можно обратиться к старым лекциям»*.

⇒ **Слайд Бюффона, нарушающий раскладку, — не контрпример, а слайд, написанный до правил.**
Отмечай пометкой `до правил`, не считай опровержением типа и не правь.

важнее подтверждений: значит в L2 нет вида слайда, который автор на самом деле использует.

### 2.3 ЧАСТЬ 2 — ТИПЫ: группировка назначений

Сгруппируй назначения в **виды слайдов**. Стартовые кандидаты названы владельцем — бери как
гипотезу, а не как ответ; сливай, дроби и переименовывай свободно:

`вводный / заход` · `введение понятия с иллюстрацией` · `только примеры` ·
`доказательство утверждения` · `итоговый` · `разделитель / переключение темы`.

🔴 **ГЕЙТ ПРОТИВ СОЧИНИТЕЛЬСТВА — тип существует, только если выполнены ВСЕ ТРИ условия:**

1. под него подпадает **не меньше двух слайдов L2** — тип, у которого в L2 один представитель,

2. назван **признак узнавания из содержания** — по чему видно, что слайд этого типа, до того как
   посмотрели на его блоки;

🔴 **Отдельно, четвёртым полем, но НЕ условием существования: сколько слайдов Бюффона под тип
подпало.** Ноль — тип может быть про L2, а не про метод; это помечается, но типа не отменяет:
контрольная дека мала и жанрово далека.

Не выполнено хоть одно — это **не тип**. Такие слайды уходят в отдельный список
«не типизированы, N штук» с одной строкой на каждый, почему. **Непустой список „не типизированы" —
законный и полезный результат; таксономия, где всё разложилось без остатка, — подозрительная.**

По каждому выжившему типу выдай: **имя · назначение · признак узнавания · слайдов в L2 · слайдов в
Бюффоне · все представители поимённо.**

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- _studio/zhurnal/2026-08-11_dovodka-L2/TIPOLOGIA-SLAJDOV.md                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- _studio/zhurnal/2026-08-11_dovodka-L2/TIPOLOGIA-SLAJDOV.md   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).
