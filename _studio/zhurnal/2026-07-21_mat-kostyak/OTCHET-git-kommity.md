# Отчёт в чат «настройка коммитов»: что ломалось 21.07 и чем чинилось

> Самоценный: читать без контекста этой сессии. Репозиторий `materials/`, инструмент `_generator/tools/git_zona.py`, хук `.githooks/pre-commit` → `_generator/tools/check_uroki.py`.
> **Дата данных: 2026-07-21, вечер.** Числа и выводы верны на неё.

## Симптом

`python3 _generator/tools/git_zona.py commit` по плану из 10 блоков **дважды подряд завалил все 10 коммитов**. Владелец видел две разные простыни ошибок и не мог понять, всё ли хорошо. В git не доехало ничего: 125 путей вне git, включая работу трёх заходов и правки канона.

## Три причины, независимые друг от друга

**1. Фикстуры гейта заблокировали весь репозиторий.**
К `check_uroki.py` (гейт «урок без ЦЕНЫ → ❌») завели фикстуры: четыре файла, два из них намеренно ломающие. Чтобы скрипт их видел, они лежат в структуре `zhurnal/<арка>/kod_*.md` — по ней он выбирает цели. Для pre-commit-хука это неотличимо от настоящей арки с долгом, и он валил **каждый** коммит плана, включая тот, что вносил сами фикстуры.
**Починка:** в `staged_files()` пути с `/fixtures/` исключены из автоподбора из индекса; при явной передаче аргументом проверяются по-прежнему — иначе `PROGNAT.sh` перестал бы видеть падение и фикстура умерла бы как фикстура.
**Общий вопрос к настройке:** фикстура ломающего гейта — это диверсия, встроенная в репозиторий. Стоит решить раз и навсегда, где живут такие фикстуры и как каждый потребитель гейта их отличает.

**2. Гейт судил оформление, а не суть — и годами держал ложный долг.**
`check_uroki.py` требовал `^ЦЕНА: ` строго с начала строки. В закрытой арке `2026-07-20_vvedenie-sborka` лежат семь уроков, где цена есть и подробная, но написана `**ЦЕНА: …**` — жирным. Гейт объявлял их «уроками без цены» и блокировал коммиты **чужих** заходов. Из-за этого один заход ушёл через `--no-verify` (обход протоптан), а в канон попал ложный урок «гейт штрафует за чужой долг ⇒ чинить гейт».
**Починка:** `PRICE = ^\*{0,2}ЦЕНА: *(.*?)\*{0,2}$`. Пустую цену по-прежнему валит — проверено фикстурой.

**3. Сам `git_zona.py` коммитил парой `add` → `commit`, и это в этом репозитории небезопасно.**
В репозитории живёт авто-коммит (`core.hooksPath=.githooks`, `_studio/.commit-plan`), который стейджит всё рабочее дерево между командами. `git commit` без путей забирает индекс целиком: цена — коммит из **89 файлов вместо трёх** (заход `zamykanie`), и он же превращал план из 10 осмысленных коммитов в один свальный.
**Первая попытка починки была неверной:** заменили пару на один pathspec-коммит `git commit -m … -- <пути>`. Это завалило всё повторно, потому что **pathspec понимает только отслеживаемые пути** — новый файл даёт `did not match any file(s) known to git`, а в плане новых было около трёх четвертей.
**Верная форма — оба хода:**
```
git --no-optional-locks add -- <пути>                 # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "…" -- <пути>       # ограничивает коммит ими же
```
`add` решает проблему новых файлов, pathspec в `commit` — проблему чужого стейджа.

## Что стоит решить в чате настройки — три вопроса, которые мы закрыли локально

1. **Авто-коммит и ручные коммиты живут в одном индексе.** Все три инцидента сводятся к этому: индекс — общий разделяемый ресурс, а писателей трое (владелец, Cowork, Claude Code). Локальный ответ — pathspec + `--no-optional-locks`. Системный ответ, возможно, другой: отдельный индекс на писателя (`GIT_INDEX_FILE`), либо отключение авто-коммита на время плановых коммитов, либо worktree на исполнителя.
2. **Хук судит staged-пути — это верно, но `targets_from()` расширяет проверку до всей тронутой арки.** Поэтому один тронутый файл арки поднимает проверку всех её уроков. Задумано так специально; стоит подтвердить, что это по-прежнему нужное поведение.
3. **Диагностика для владельца.** Сейчас при падении печатается 10 одинаковых простыней `git status`. Полезнее: печатать код возврата и первую строку `stderr`, а полный статус — один раз в конце.

## Чем проверять, не делая коммита

- знает ли git путь: `git ls-files --error-unmatch -- <путь>`
- что реально уедет: `git --no-optional-locks diff --cached --name-only`
- фикстуры гейта уроков: `sh _generator/tools/fixtures/uroki/PROGNAT.sh` (ожидание: `bez-ceny=1 · zhirnaya=0 · golaya=0 · pustaya=1`)
- ⚠ **в песочнице Cowork git-поведение проверять нельзя:** она не даёт `unlink` в `.git/objects`, тестовый коммит падает с `rc=128`, и это выглядит как содержательный отрицательный результат. Четыре ложных прогона за сессию.
