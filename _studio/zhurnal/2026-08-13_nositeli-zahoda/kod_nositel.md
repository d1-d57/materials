## 2. ЗАДАЧА

Три шага, строго в этом порядке: сначала генератор кладёт секцию, потом линтер её сторожит, потом фикстура сторожит линтер.

### Шаг 1 — `bootstrap_zahod.py` кладёт стартовое сообщение В ФАЙЛ, а не только в stdout

**Куда:** секцией `## СТАРТОВОЕ СООБЩЕНИЕ ВЛАДЕЛЬЦУ` в **НАЧАЛО** файла-захода — сразу после блока-шапки (после строк `>` и до `── СЧЁТ НЕЗАКРЫТОГО ──`). Начало, а не конец, — решение владельца 13.08 дословно: *«лучше ставить секции в начало файла… я захожу, копирую и отправляю»*. В конце ему пришлось бы искать.

🔴 **Секция начинается строкой-адресатом, потому что читать её первым будет ИСПОЛНИТЕЛЬ, а адресована она владельцу.** Первой строкой секции — ровно это: `> Это блок для владельца — то, чем тебя запустили. Исполнителю здесь делать нечего, твоё задание ниже.` Без такой строки исполнитель получает в самом начале файла инструкцию, обращённую не к нему, и обязан гадать, чья она.

**Что именно кладётся:** тот же текст, что уходит в stdout, **байт в байт, из одной переменной**. 🔴 Не «собрать похожий блок ещё раз» — это дало бы два дома у одного решения, и они разъедутся при первой правке. Значит:

- собери блок в переменную ДО записи файла (сейчас он собирается в самом хвосте `main()`, после `dst.write_text`, — эту часть надо поднять выше);
- вставь переменную в `text`, потом прогоняй линтер, потом `dst.write_text(text)`;
- печатай в stdout **ту же переменную**.

**Оба канала.** У `--kanal app` блок — стартовое сообщение (`Модель: … / Ты исполнитель в репозитории … / Твой единственный вход …`). У `--kanal terminal` блок — стартовая КОМАНДА (`cd … && claude -p …`, плюс первая строка `worktree add`, когда она есть, плюс команда снятия токенов). В файл кладётся то, что соответствует выбранному каналу; в кодовом блоке ` ``` `, чтобы владелец копировал одним движением. **Прочее, что генератор печатает вокруг** (пояснения про `stream-json`, предупреждение о гонке checkout, «путь от места запуска») в файл НЕ едет: это разговор с аналитиком в момент сборки, а не то, что отдают владельцу.

**Порядок в коде — не косметика.** Структурный линтер (`check_zahod.judge(text, checks=STRUCTURAL_CHECKS)`) стоит ДО `dst.write_text` и судит собранный `text`. Секция обязана быть в `text` к этому моменту — иначе новая клауза (шаг 2), попав в `STRUCTURAL_CHECKS`, уронит генератор на его собственном свежем файле.

🔴 **ГЛАВНАЯ ЛОВУШКА, НАЙДЕННАЯ ЖИВЫМ ПРОГОНОМ ПРИ СБОРКЕ ЭТОГО ЗАХОДА — ПРОЧТИ ДО ПЛАНА.** Секция с блоком вписана в начало этого файла руками, и `check_zahod.py` тут же дал **три красных**: `З9` («секция „план" встречается 2 раза»), `З10` («нет блока §0.1 ГИТ-КОНТУР»), `З12` («нет строки „0. ВЫЧИТАТЬ ОЧЕРЕДЬ"»). Механизм не в секции как таковой:

- блок канала `app` содержит строку `## ПЛАН внутри него — до всяких действий`;
- `З10` и `З12` судят **только текст ДО `## ПЛАН`** (`ZADANIE_KONEC_RE`) — а этот `## ПЛАН` теперь стоит в НАЧАЛЕ файла, и «задание» схлопывается до нескольких строк, где блока §0.1 нет по построению;
- `З9` считает заголовки регуляркой `^##\s+ПЛАН\b` и получает два.

⇒ **Значит правка не сводится к «положить секцию».** Секция-носитель есть ЦИТАТА, а не текст задания, и все клаузы обязаны её игнорировать. Дешёвое лечение — одно и в одном месте: **вырезать секцию `## СТАРТОВОЕ СООБЩЕНИЕ ВЛАДЕЛЬЦУ` из текста ОДИН раз, в `judge()`, до раздачи клаузам** — а не чинить З9, З10 и З12 по отдельности (три места разъедутся, четвёртая клауза про это не узнает). Сама З13 при этом должна смотреть на ПОЛНЫЙ текст: ей нужна как раз вырезаемая секция.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- _generator/tools/bootstrap_zahod.py _generator/tools/check_zahod.py _generator/tools/check_sborki.py _generator/tools/fixtures/zahod/PROGNAT.sh _generator/tools/fixtures/sborka/PROGNAT.sh                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- _generator/tools/bootstrap_zahod.py _generator/tools/check_zahod.py _generator/tools/check_sborki.py _generator/tools/fixtures/zahod/PROGNAT.sh _generator/tools/fixtures/sborka/PROGNAT.sh   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).
