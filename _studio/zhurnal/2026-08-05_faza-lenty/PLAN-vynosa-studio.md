## §1. Числа прогона (все — вывод команды, не оценка)

Прогон: `git clone` живого репо в `/tmp/materials-probe`, затем
`git subtree split --prefix=_studio -b probe-studio`.

| Величина | Значение | Чем измерено |
|---|---|---|
| Свободно на `/tmp` | 103 Gi из 228 Gi | `df -h /tmp` |
| Вес живого репо | 1.7 G (из них `.git` — 1.0 G, `_studio` — 53 M) | `du -sh` |
| Коммитов в репозитории (HEAD) | **761** | `git rev-list --count HEAD` |
| Коммитов уезжает с `_studio` | **559** (73.5 %) | `git rev-list --count probe-studio` |
| Файлов уезжает (трекаемых) | **674** | `git ls-files _studio \| wc -l` |
| Время клонирования копии | **2.4 с** | `time git clone` |
| Время `subtree split` | **29.4 с** (user 14.9 + sys 12.7) | `time git subtree split` |
| Вес результата: упакованная история | **21.69 MiB** | `git count-objects -vH` в клоне `--no-local` |
| Вес результата: `.git` + рабочее дерево | **22 M + 53 M = 75 M** | `du -sh` |
| Невлитых `_studio`-коммитов на других 10 ветках `origin` | **0** | цикл `git rev-list --count HEAD..$b -- _studio` |

🔴 **Ловушка замера веса.** Первый замер дал 963 MiB и был НЕВЕРЕН: локальный
`git clone` (даже с `--no-hardlinks`) копирует весь каталог объектов, а не только
достижимые. Настоящий вес виден только через `--no-local`. Если утром цифра
«отщеплённый репозиторий весит гигабайт» — это артефакт локального клона, а не
правда; гоняй `git gc --prune=now` или клонируй с `--no-local`.

| Команда | Исходный репозиторий | Отщеплённая ветка |
|---|---|---|
| `git log --follow --oneline -- .../KARTA.md` | **117** | **117** |
| `git log --oneline -- .../KARTA.md` (без `--follow`) | **114** | **114** |

Сверка не только числом, а построчно: `diff` списков `%ci\|%an\|%s` по обеим
историям дал **0 строк расхождения** — совпали дата, автор и сообщение каждого
из 117 коммитов.

Дерево на вершине тоже совпало побитово: `diff` между `git ls-tree -r HEAD:_studio`
и `git ls-tree -r probe-studio` — пусто.

Отдельно проверено, что до-префиксной истории терять нечего: `_studio` никогда не
переименовывался и ничто в него не переезжало снаружи

ограничение `subtree split` — «видит только то, что лежало под префиксом» —
здесь ничего не режет.

## §6. Шаблон текста указателя (ОДИН на все случаи)

Образец, по которому собран шаблон: `_studio/konvejer/09-illustracii/SLOVAR-primitivov.md`
(отработал на 51 внешней ссылке) и его младший близнец
`_studio/docs/kak-delat/ARKA.md` (111 ссылок, 2026-08-06). Шаблон — их общая форма.

**Подстановки** (все помечены угловыми скобками, при применении заменяются):

| Подстановка | Что подставить | Как получить |
|---|---|---|
| `<ИМЯ>` | имя файла без пути, напр. `RUKOVODSTVO-zahodami.md` | — |
| `<ЧТО>` | о чём канон, родительный падеж: «канона арок», «методологии заходов» | — |
| `<КУДА>` | путь-цель ОТ КОРНЯ репозитория, напр. `_meta/disciplina/ARKA.md` | — |
| `<ОТН>` | тот же путь ОТНОСИТЕЛЬНО стаба | `../` × (глубина стаба от корня), затем `<КУДА>`. Для `catalan/X.md` глубина 1 → `../_meta/…`; для `_studio/docs/kak-delat/X.md` глубина 3 → `../../../_meta/…` |
| `<РАЗДЕЛЫ>` | таблица или список разделов, переехавших под теми же именами | `grep -n '^#\{2,3\} ' <КУДА>` |
| `<ДОМ>` | папка-дом одной строкой, напр. `_meta/` | — |
| `<N>` | сколько живых ссылок на старый адрес | команда в строке ниже |
| `<ДАТА>` | дата данных для `<N>`, формат `2026-08-06` | `date +%F` |
| `<КОМАНДА-ПЕРЕСЧЁТА>` | `grep -rlF '<ИМЯ>' --include='*.md' --include='*.py' --include='*.sh' . \| grep -v '^./<ДОМ>'` | — |
| `<ЗАХОД>` | относительный путь к файлу-заходу, который делал перенос | — |

🔴 Три вещи в шаблоне несущие, их нельзя выкинуть как «воду»: **абзац про §-разделы**
(без него ссылка `<ИМЯ> §5` молча приведёт в файл, где §5 нет), **число `<N>` с датой
и командой пересчёта** (`KONSTITUCIYA §10`: пишем команду, а не цифру) и **условие
снятия указателя** (иначе стаб живёт вечно).

---

```markdown
# <ИМЯ> → ПЕРЕЕХАЛ

> 🔴 **Дом <ЧТО> теперь `<КУДА>`** (от корня репозитория). Здесь остался только указатель.

🔴 **Ссылка вида `<ИМЯ> §<раздел>` теперь ведёт СЮДА, а раздела здесь нет.** Все разделы переехали целиком и под теми же именами и номерами в `<ОТН>`:

<РАЗДЕЛЫ>

Ищи раздел там — номера не менялись.

**<ЧТО с заглавной, одной фразой: «Как мы вообще работаем» / «Работаешь с изображением»> — идёшь в `<ДОМ>`.**

| Что нужно | Куда |
|---|---|
| <строка про сам переехавший канон> | `<ОТН>` |
| <соседний канон того же дома> | `<ОТН-соседа>` |
| что этот дом вообще есть и чего он НЕ делает | `<ОТН-README дома>` |

**Почему файл не удалён, а стал указателем.** На старый адрес ссылались <N> живых мест по всему репозиторию (дата данных <ДАТА>; пересчёт — `<КОМАНДА-ПЕРЕСЧЁТА>`), и большинство лежит вне зоны того захода, который делал перенос (`<ЗАХОД>`). Мёртвая ссылка обнаружилась бы не у автора переноса, а у следующего, кому канон понадобится. Указатель снимается вместе с последней ссылкой на него, не раньше.

*История файла целиком уехала вместе с содержанием: `git log --follow <КУДА>`.*
```

---

**Оговорка по применимости.** Шаблон писан для случая «дом переехал внутри того же
репозитория», и на трёх файлах §5 он ложится прямо. Для выноса `_studio` в ОТДЕЛЬНЫЙ
репозиторий `<ОТН>` относительным путём не выражается — там придётся выбрать форму
ссылки из §3 шага 6 (URL / префикс / соседняя папка), и только после этого шаблон
станет применим. Одной строкой шаблона это не чинится; помечено как незакрытое.
