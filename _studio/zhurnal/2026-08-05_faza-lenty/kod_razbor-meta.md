## 2. ЗАДАЧА

### 2.1 Собрать список рычагов, которые УЖЕ есть

До того как что-то сопоставлять, выпиши инвентарь: что в фабрике работает как рычаг и **что именно оно ловит**. Источники — код и его докстринги, а не память:

- **инструменты** `materials/_generator/tools/*.py` — по каждому: что проверяет, чем краснеет, обязателен ли (хук / вызывается руками);
- **гейты внутри инструментов** — например восемь проверок `check_zahod.py` (З1–З8) ловят разные классы, и это восемь рычагов, а не один;
- **хук** `.githooks/pre-commit` — что в нём стоит сегодня;
- **правила канона без кода** — они тоже рычаги, но **процедурные**, и считаются отдельно.

По каждому рычагу — строка «что ловит» своими словами и адрес. **Число рычагов назови командой** (`ls`, `grep -c`), не значением.

Выжимка годится **отобрать** записи, судить надо по адресу.

### 2.3 Четыре вида вердикта, и третий — не поражение

| вид | когда | пример |
|---|---|---|
| **машинный** | есть код, который краснеет сам | «ловится З3 линтера входа» |
| **процедурный** | правило есть, носителя нет — держится на внимании | «канон велит, но проверить нечем» |
| **не накрывается** | машинного гейта не существует и не может | образец — КРВ-40 у иллюстраций |
| **не накрыто** | рычага нет, но он возможен | вход следующей работы |

**Разница между «процедурным» и «не накрыто» — самая ценная часть разбора.** Первое означает «мы это знаем и помним», второе — «мы это забудем». Владельцу нужен именно второй список.

### 2.4 Форма записи — контракт, который читает метрика

Метрика `pokrytie_rychagami.py` читает **ровно одну форму**: строка markdown-таблицы, **первая клетка — id записи корпуса, последняя — рычаг**. Проверь это по коду счётчика, а не по моему описанию, и пиши так, чтобы он увидел.

## 3. ВЕРИФИКАТОР

**Нужен, и вопрос у него ровно один: какие «накрыто» — натянуты.**

Свежий субагент получает **твою таблицу и записи корпуса**, но НЕ получает твоих рассуждений. По выборке (не меньше 15 записей, отобранных им, а не тобой) он проверяет: **действительно ли названный рычаг покраснеет на этой записи?** Не «про то же ли это», а «сработает ли».

Каждое расхождение разбирается поимённо. Натянутое «накрыто» дороже пропущенного: пропуск виден как ноль и зовёт работать, а натяжка выглядит как готовность и работать не зовёт.

Вторая задача ему же: пройти по списку «не накрыто» и сказать, **нет ли там того, что уже ловится** каким-нибудь инструментом, о котором ты не вспомнил. Инвентарь §2.1 собирал ты, и он мог быть неполон.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- doma/meta/POKRYTIE.md doma/README.md
git --no-optional-locks commit -m "дом МЕТА: 775 записей сведены с рычагами; контракт формы в README" -- doma/meta/POKRYTIE.md doma/README.md
GIT_ZONA_REPO=~/Documents/GitHub/disciplina python3 $MAT/_generator/tools/git_zona.py check --zone doma/
git --no-optional-locks show --stat                        # обязаны быть ровно два пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие».
