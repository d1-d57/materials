# Скилл или папка — где живёт дисциплина

> **КОГДА читать:** решаешь, куда девать мета-дисциплину (сессии, коммиты, дневник, арки) и любую другую — иллюстрации, ленту, ресёрч. · **ЧТО это:** research по документации Anthropic и по инженерной практике + вердикт с критерием разреза. · **Дата данных: 2026-08-06.**
>
> Заказ владельца дословно: *«это не скилл, а система-промпт, который у меня в каждой сессии работает… оно бессмысленно в облаке, работает только для Cowork на моём компьютере, потому что оно про то, как заводить папки на моём компьютере, как писать дневник, как делать коммиты. Его нужно сделать абсолютно универсальным и убрать полностью из папки студии — он к студии не имеет отношения»*.

---

## 1. Главный вывод одной строкой

**Скилл — это то, что ЧИТАЮТ. Папка — это то, что ПИШУТ.**

Дисциплина (как делать) — читается всегда и не меняется от проекта к проекту ⇒ **скилл**. Инциденты, арки, дневники, отчёты, эталоны, генераторы — накапливаются и переписываются ⇒ **папка на диске**. Это не компромисс и не «пока так»: у двух видов содержания разные жизненные циклы, и смешение их — ровно тот дефект, который отраслевая практика называет главным в документации (см. §5).

Критерий проверяемый, спорить не о чем: **если файл дописывается по ходу работы — он не может быть скиллом.**

---

## 2. Что скилл физически может — по документации, а не по слухам

| вопрос | ответ | источник |
|---|---|---|
| грузится ли всегда | нет, и это его главное свойство: на старте в системный промпт уходят только `name` + `description` всех скиллов; тело читается, **только когда скилл стал релевантен** | best-practices, «How Claude accesses Skills» |
| размер тела | «Keep SKILL.md body under 500 lines for optimal performance» | best-practices |
| размер описания | ≤ 1024 символа, ≤ 64 символа имя, только строчные+дефисы | best-practices |
| вспомогательные файлы | лимита нет и штрафа нет: «No context penalty for large files: Reference files, data, or documentation don't consume context tokens until actually read» | best-practices |
| исполняемые скрипты | да: «Scripts executed efficiently: Utility scripts can be executed through bash without loading their full contents into context. Only the script's output consumes tokens» | best-practices |
| файловая система | «Skills run in a code execution environment with filesystem access, bash commands, and code execution capabilities» | best-practices |
| накопление состояния между сессиями | **в документации не сказано ничего** — ни памяти, ни персистентности | — |
| версионирование | **в документации не сказано** — ни поля `version`, ни changelog; устаревание предлагается закрывать секцией «Old patterns» | — |
| можно ли дописывать со временем | да, но руками: описан ручной цикл «наблюдай за исполнителем → уточни → протестируй → повтори». В Cowork для этого есть дверь — инструмент `save_skill` с `overwrite: true`, и **это единственный способ изменить сохранённый скилл: правка файлов скилла на диске не сохраняется** | best-practices + контракт `save_skill` |

🔴 **Ограничение, которое решает половину спора: глубина ссылок ровно ОДИН уровень.** «Keep references one level deep from SKILL.md… Claude may partially read files when they're referenced from other referenced files» — при большей вложенности файл читается частично (`head -100`) и информация приезжает неполной. То есть скилл не может быть входом в большое дерево документов. Дерево — это папка.

## 3. Почему перенос дисциплины из `CLAUDE.md` в скилл — выигрыш, а не перекладывание

Сегодня мета-дисциплина живёт в файлах, которые читаются **всегда**: корневой `CLAUDE.md` автозагружается целиком, `KARTA.md` предписан Правилом №0 первым ходом. Скилл устроен наоборот: имя и описание всегда, тело — по релевантности.

Отсюда три следствия, все в пользу переноса:

1. **Контекст экономится.** «The context window is a public good» — дисциплина коммитов не должна занимать место в сессии, где ничего не коммитят.
2. **Срабатывание становится автоматическим.** Сегодня правило работает, если исполнитель дошёл до нужного файла. У скилла триггером служит `description`, и он в системном промпте всегда. Это ровно `KONSTITUCIYA §11` («правило без механизма — пожелание»), только механизмом становится сама подгрузка.
3. **Адресация перестаёт быть проблемой.** Скилл вызывается **по имени**, а не по пути. Это снимает ограничение, которое иначе делает вынос дорогим (§4).

## 4. Ограничение, которое обнаружилось при выносе, и чем оно снимается

Ссылки в доках относительные — абсолютные запрещены `KONSTITUCIYA §16`. **Относительный путь не живёт через границу репозитория.** Замер на 2026-08-06:

| документ | журнал | канон фабрики | проекты |
|---|---|---|---|
| `GIT-disciplina.md` | 100 | 7 | **2** |
| `ISTOCHNIK-PRAVDY.md` | 11 | 3 | **0** |
| `ARKA.md` | 70 | 15 | **27** |
| `RUKOVODSTVO-zahodami.md` | 82 | 17 | **40** |

Предпосылка владельца «на это, наверное, нет никаких ссылок» **верна для дисциплины коммитов и источника правды и неверна для заходов и арок**: их зовут из проектов 67 раз, причём из `kurs leto 2026` (22 и 18) и `catalan` (14 и 5) — то есть из проектов, которые в `materials` остаются.

Пересчитать:
```bash
for d in GIT-disciplina.md ARKA.md RUKOVODSTVO-zahodami.md ISTOCHNIK-PRAVDY.md; do
  echo "$d журнал=$(grep -rl "$d" --include='*.md' _studio/zhurnal | wc -l)" \
       "канон=$(grep -rl "$d" --include='*.md' _studio/docs _studio/konvejer _studio/*.md | wc -l)" \
       "проекты=$(grep -rl "$d" --include='*.md' . | grep -v '^./.git' | grep -v '^./_studio' | wc -l)"
done
```

⇒ Это не довод против выноса. 67 обращений извне фабрики — доказательство, что дисциплина давно универсальна и лежит не там. Но **вынос папкой требует переписать 67 адресов и придумать, как они пишутся через границу**, а вынос скиллом — не требует ничего: у скилла адреса нет.

## 5. Что говорит инженерная практика — тот же разрез, другими словами

Отраслевой канон документации формулирует ровно это разделение как главную гигиену: **постоянное знание отделяется от временных записей проекта**, и смешение двух видов «производит репозитории, забитые устаревшим материалом, который заслоняет по-настоящему ценное». Рекомендуемый режим: проектные артефакты периодически архивируются, операционная документация непрерывно уточняется.

В переводе на нашу систему это буквально `ISTOCHNIK-PRAVDY §1`: *нарратив сессии умирает вместе с аркой, а то, что должно её пережить, переносится в дома при закрытии*. Разрез «скилл / папка» — то же самое правило, поднятое на этаж выше: **дисциплина переживает всё и потому уходит в скилл; арка не переживает и потому остаётся папкой.**

Отдельный прецедент — **распространение гейтов между репозиториями**. Задача «дисциплина обязана исполняться на моей машине в каждом репозитории» решена в отрасли фреймворком `pre-commit`: хуки описываются конфигом, ставятся менеджером, версионируются централизованно; альтернативы — `core.hooksPath` (проще, но негибко) и submodule (плохо совместим). У нас сегодня третий вариант, самый хрупкий: хук лежит в одном репозитории (`materials/.githooks/pre-commit`) и в новый репозиторий не приезжает вовсе.

## 6. Вердикт по каждому куску

| что | куда | почему |
|---|---|---|
| **дисциплина сессии, заходов, приёмки** | **скилл** | чистый текст «как делать», ≤500 строк, нужен в каждой сессии. Заготовка уже есть — установленный скилл `agentic-coding-session-brief` |
| **дисциплина git и коммитов** | **скилл + скрипт внутри него** | текст читается, `git_zona.py` исполняется. Документация прямо разрешает: скрипт не грузится в контекст, тратится только вывод |
| **дисциплина арок и дневника** | **скилл** | `ARKA.md` — текст правил |
| **словарь примитивов иллюстраций** | **скилл** | это язык, а не запись. 139 строк — влезает с запасом. Зовёт соседний скилл `threejs` по имени, как рекомендует документация |
| **инциденты, `POKRYTIE`, `UROKI`, автолог, `VERDIKTY`** | **папка** | дописываются. Скилл состояния не хранит — в документации об этом нет ни слова, а значит рассчитывать нельзя |
| **арки, дневники, файлы-заходы, отчёты** | **папка** | пишутся по ходу и умирают с аркой |
| **генераторы (`build_doc.py`, `build_deck.py`), эталоны, рендеры** | **папка** | правятся руками, весят, версионируются git |
| **гейт коммита (`.githooks/`)** | **папка каждого репозитория** | хук обязан лежать в том репозитории, чьи коммиты сторожит |

## 7. Форма выноса: не «папка рядом», а плагин

Ключ, который меняет ответ на вопрос «куда положить». Плагин — это **набор скиллов, команд, MCP и хуков, ставящийся одной командой**, а маркетплейс для него — «all you need is a git repository… with a properly formatted `.claude-plugin/marketplace.json`».

⇒ «Одно хорошее место», которое хочет владелец, — это **git-репозиторий-плагин**, а не папка рядом с `materials`. Тогда:

- дисциплины едут скиллами внутри плагина и грузятся **в любой сессии и в любой папке**, без путей и без монтирования;
- обновление — обычный git-цикл, а не копирование;
- инструменты (`git_zona.py` и прочие) едут тем же плагином как скрипты скиллов;
- накопительное (инциденты, арки) остаётся в рабочем репозитории — там, где идёт работа.

Это же снимает практическую стену, о которую разрез бьётся сегодня: **папка вне `materials` невидима Cowork, пока её не смонтируют второй рабочей папкой; скилл виден всегда.**

## 8. Что это меняет в плане разделения

Порядок из `RAZDELENIE-issledovanie.md §9` не отменяется — уточняется цель каждого шага. Каждая фабрика расщепляется НЕ на «папку», а на пару:

```
<фабрика> = скилл (дисциплина, читается)  +  папка (инциденты · арки · эталоны · инструмент)
```

Проверка на каждом шаге одна: **взял файл — спроси, дописывается ли он по ходу работы.** Дописывается — папка. Нет — скилл.

✅ **Померено 2026-08-06 — в 500 строк влезает ВСЁ, резать ничего не надо:**

```bash
wc -l _studio/docs/kak-delat/{ARKA,RUKOVODSTVO-zahodami,GIT-disciplina,ISTOCHNIK-PRAVDY}.md \
      _studio/konvejer/06-tekst/FORMA.md
```

| дисциплина | строк | запас до 500 |
|---|---|---|
| `GIT-disciplina.md` | 448 | 52 — тесно, но влезает |
| `RUKOVODSTVO-zahodami.md` | 349 | 151 |
| `FORMA.md` (лента) | 331 | 169 |
| `ARKA.md` | 161 | 339 |
| `ISTOCHNIK-PRAVDY.md` | 92 | 408 |

⚠ У `GIT-disciplina.md` запас всего 52 строки, и она растёт быстрее прочих — каждый разбор инцидента дописывает клаузу. Ей паттерн «SKILL.md как оглавление + `references/` одним уровнем» понадобится раньше всех; закладывать его лучше сразу, а не когда упрётся.
