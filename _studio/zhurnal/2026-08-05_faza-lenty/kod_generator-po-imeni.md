**Мешает одно, и оно измерено.** Движок адресуется **местом**, а не именем. Одиннадцать скриптов курсов зовут его кодом, и каждый вычисляет путь, поднимаясь вверх от себя:

```python

```

`ROOT` тут — корень репозитория, найденный через `parents[N]`. Пока это так, вынести папку нельзя: все одиннадцать сломаются одновременно, а сломаются они у курсов, а не у фабрики.

Владелец сформулировал лечение сам, раньше меня: *«ей не нужно расположение знать, а нужно просто в системе знать её название»*.

ЦЕЛЬ: дать движку **имя вместо места**, чтобы вынос стал возможен позже одним `git mv`.

Приёмка — по ОТЧЁТУ, без построчной сверки.

🔴 **СТОП ДО ЦЕЛИ — папку ты НЕ выносишь.** Заход только развязывает адресацию; сам переезд — отдельное решение владельца и отдельная работа. После тебя `_generator/` остаётся ровно там, где лежит.

🔴 **И второй запрет, важнее первого: ты не меняешь поведение ни одного скрипта.** Все одиннадцать обязаны делать после правки ровно то же, что делали до. Это рефакторинг адресации, а не улучшение кода: любая «заодно» правка логики здесь — брак, потому что проверить её нечем, а сломается она у живого курса.

### 2.2 Дать движку имя

Упаковать `_generator` так, чтобы он ставился один раз (`pip install -e`) и звался **по имени команды**, а не по пути. Конкретную форму — консольные точки входа, имена команд, структуру пакета — **выбираешь ты**; требования всего три:

- **вызов не содержит пути** к `_generator`, ни абсолютного, ни вычисленного от `ROOT`;
- **работает из любой рабочей папки**, включая worktree и папку курса;
- **ставится одной командой**, и эта команда написана в `_generator/README.md` (или заведена, если его нет).

⚠ **Имена команд подбери говорящие и не конфликтующие** с тем, что уже стоит в системе: проверь `command -v <имя>` до выбора, вывод приложи.

### 2.3 Переписать одиннадцать вызовов

Каждый — якорной заменой, **abort при ≠1 совпадении**. Правится **только адресация**: аргументы, порядок, обработка кода возврата остаются теми же.

🔴 **Тонкое место, названное заранее.** Часть вызовов запускает движок `sys.executable`, то есть тем же интерпретатором, что и сам скрипт. Консольная команда после `pip install -e` может оказаться в другом окружении — и тогда правка молча сменит интерпретатор. **Проверь это явно** и, если риск есть, оставь запуск через `python3 -m <пакет>` вместо голого имени: модульный вызов сохраняет интерпретатор и всё равно не содержит пути.

### 2.4 Доказать, что ничего не сломалось

Это главная часть работы, а не финальная формальность.

По каждому из одиннадцати: **прогнать до и после** и сравнить. Не «скрипт запустился», а **тот же выход**: код возврата плюс что-то содержательное — размер собранного файла, число строк, хэш. Скрипт, который нельзя прогнать (нужны данные, которых нет), — назови поимённо и скажи, чем проверил вместо прогона.

⚠ **Прогон меняет файлы курсов.** Собранное после проверки верни в исходное состояние (`git checkout -- <путь>` по конкретным файлам, не по дереву) и **покажи, что вернул**: `git status --short` в конце обязан содержать только твою зону.

---

**КРИТЕРИЙ ГОТОВНОСТИ (может ПРОВАЛИТЬСЯ).** Семь условий:

1. Число вызывающих снято командой ДО работы и названо; охват «переписано X из X».
2. **Вызовов, содержащих путь к `_generator`, в коде курсов — 0.** Проверяется той же командой из §2.1: она обязана вернуть пустой список либо только упоминания в комментариях, и каждое такое упоминание названо.
3. Установка одной командой описана и **прогнана** — вывод в отчёте.
4. **Живой прогон на реальных скриптах, не на фикстуре:** таблица «скрипт · rc до · rc после · сверяемое значение до/после». Расхождений — 0, либо каждое объяснено.
5. Скрипты, которые прогнать нельзя, названы поимённо с причиной и способом проверки вместо прогона.
6. `git status --short` в конце — только пути зоны; собранные артефакты курсов возвращены.
7. `git_zona.py check --zone .` → ✅; `git show --stat` — только свои пути.

**Условие 4 — главное.** Заход трогает код одиннадцати живых курсов; единственное доказательство, что он безвреден, — одинаковый выход до и после.

⚠ **Условие 2 может провалиться честно:** если у какого-то вызова путь снять нельзя без смены поведения — **не снимай**. Назови его, объясни чем мешает, оставь как есть. Один честно оставленный вызов лучше одного молча сломанного курса.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
cd ../materials-wt/wt-genname
git --no-optional-locks add -- _generator/ krivaya-drakona/ obzory/ teorkat-vvedenie/ lsh-2026-perechislitelnaya/
git --no-optional-locks commit -m "генератор адресуется именем: пакет + консольные команды, вызовы переписаны" -- _generator/ krivaya-drakona/ obzory/ teorkat-vvedenie/ lsh-2026-perechislitelnaya/
python3 _generator/tools/git_zona.py check --zone .
git --no-optional-locks show --stat
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).

### В. Форма упаковки — выбрана ЗАМЕРОМ СРЕДЫ, а не по памяти

Среда (снято командой): единственный `python3` — `/usr/bin/python3` 3.9.6 (CommandLineTools),

| проба | итог |
|---|---|
| `pip install --user -e .`, метаданные только в `pyproject.toml` | ❌ `File "setup.py" or "setup.cfg" not found` — pip 21.2 не умеет PEP 660 |

1. **Метаданные — в `setup.cfg`** (его читают и setuptools 58, и современные), плюс

2. **Команда установки — одна:** `python3 -m pip install --user -e _generator/ --no-build-isolation`.
3. **Пакет — ОДИН модуль верхнего уровня `_generator/dvizhki.py`** (диспетчер). Не подпапка-пакет:
   пакет-подпапка потребовал бы перенести 28 файлов внутрь `_generator/`, а это уже переезд,
   который заходу запрещён 🔴-стопом. Имя `dvizhki` — слово самого репозитория
   (`_generator/DVIZHKI.md`); `command -v dvizhki` → свободно (вывод в отчёт).
4. **Вызов в коде курсов — модульный, `python3 -m dvizhki <движок> <аргументы>`**, ровно как велит
   §2.3: он сохраняет интерпретатор (`sys.executable` там, где он был; литерал `python3` там,
   где был он) и не содержит пути. Движки: `doc` → `build_doc.py`, `dek` → `build_deck.py`,
   `vid` → `tools/check_view.py`.
5. **Консольная команда `dvizhki` объявляется, но в вызовах НЕ используется** — и в README это

   README даёт строку для `PATH` и говорит, что штатная форма — `-m`.
6. **Как диспетчер находит движки:** `Path(__file__).resolve().parent` — то же само-наведение,

   переменная была бы спекулятивной абстракцией, а не переиспользованием приёма.

### Что сделано лучше задания

**Форма упаковки выбрана замером среды, а не по памяти.** Три очевидных варианта проверены на пакете-пробе и отброшены с причиной: pip 21.2 не умеет PEP 660; `--user -e` без изоляции гасит user-site; setuptools 58 не читает `[project]` из `pyproject.toml`. Осталась одна рабочая комбинация. Проба снята, `easy-install.pth` проверен пустым.

**Запуск через `runpy.run_path`, а не импорт и не подпроцесс** — движку остаются его настоящий `__file__` (важно: `build_deck.py` ищет `skeleton/` относительно себя), его `argv[0]`, его код возврата. **Ни один байт движков не тронут** — это и есть доказательство, что поведение сохранено.

**Интерпретатор у каждого вызывающего остался тот же** — то самое тонкое место, которое заход назвал заранее, и оно не сдвинуто.
