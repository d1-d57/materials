## 2. ЗАДАЧА

### 2.1 Флаг `--vlit` у `bootstrap_zahod.py`

Принимает ветки, которые заход обязан влить первым ходом (одну или несколько). Генератор вписывает в `§0` готовый блок — не пожелание, а команды с проверкой:

```
### 0.1 🔴 ВЛИТИЕ — ДО ВСЕГО ОСТАЛЬНОГО
python3 _generator/tools/git_zona.py merge <ветка> --zone <зона захода>
```
и следом — **проверка фактом на диске, а не словом инструмента**: `git log --oneline` содержит коммит ветки. Образец обеих половин — `kod_etap-20.md §0.1`.

Слияние идёт **в основной папке**, до захода в worktree: заведёшь рабочую папку раньше — получишь её на состоянии до слияния. Порядок в блоке жёсткий: **влитие → worktree → чтение → ПЛАН**.

### 2.2 Отсутствие влития объявляется, а не молчит

`--vlit` не задан — генератор всё равно вписывает строку: «вливать нечего, проверено при сборке: невлитых веток 0». **Молчание и «нечего вливать» должны различаться в тексте захода** — исполнитель с пустым контекстом иначе не знает, забыл ли аналитик или проверил.

### 2.3 🔴 СТОРОЖ НЕВЛИТОГО — то, ради чего заход и делается

Это единственное место захода, где есть выбор, и он решён здесь, чтобы ты не решал молча.

При сборке любого захода генератор **сам** смотрит, есть ли в репозитории невлитые ветки заходов (`git branch --no-merged <текущая>`, отфильтровать по префиксу `zahod/`), и:

- невлитых **нет** → вписывает строку из §2.2, собирает молча;
- невлитые **есть, и `--vlit` их называет** → вписывает блок §2.1;
- невлитые **есть, а `--vlit` не задан или называет не все** → **ПРЕДУПРЕЖДЕНИЕ в вывод генератора, с перечислением имён; заход при этом СОБИРАЕТСЯ.**

🔴 **Именно предупреждение, а не отказ, и вот почему.** Невлитая ветка — законное состояние: рядом может идти чужой заход, ветка может быть непринятой, старые ветки арок владелец не удаляет принципиально (`poteri` это прямо говорит). Отказ собирать заход из-за чужой невлитой ветки — гейт, краснеющий на здоровом дереве; такие обходят, и вместе с ними перестаёт работать всё остальное (`konvejer/GEJTY.md`, цена названа заранее). А **предупреждение с именами** делает ровно то, что нужно: аналитик видит список в момент сборки и решает осознанно.

Строка предупреждения обязана быть **исполнимой**: не «есть невлитые ветки», а готовая команда с подставленными именами, которую можно скопировать в `--vlit`.

### 2.4 Фикстура

В `PROGNAT.sh`, сохранив её стиль и функцию `krasnet`:

- `--vlit` с веткой → в собранном заходе есть блок `§0.1` с `merge` и проверкой фактом;

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `_generator/tools/bootstrap_zahod.py`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `_generator/tools/bootstrap_zahod.py`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
⚠ **Хук `pre-commit` покраснел — сначала посмотри, на ЧЬИХ путях.**
- Красное на ТВОИХ путях (новый `.md` не зарегистрирован в `../../docs/KARTA.md §6`, битая ссылка) — **чини, не обходи**: там только твоё, обходить нечего.
- Красное на ЧУЖОМ, унаследованном долге (ворота дают сотни ❌ старых нарушений) — законный обход, но ТОЛЬКО с причиной; голый `--no-verify` инструмент отклонит, а причина сама уедет в `INCIDENTY.md`:
```
python3 _generator/tools/git_zona.py commit --zone <зона> \
    --no-verify "чужой долг: <что именно покраснело>" -m "<что и зачем>" --push
```
Ту же причину назови отдельной строкой отчёта долгом. *Урок 9: обход был законен по канону и не существовал в инструменте — первый же коммит владельца встал на чужом долге.*
**Коммит не прошёл по ВНЕШНЕЙ причине** (чужой лок, конфликт, detached HEAD) — чужое состояние репозитория НЕ чини: зафиксируй файлы и напиши в отчёт отдельной строкой «коммита нет, причина такая-то, нужно ваше действие». Это законный отчёт. Молчаливое «сделано» при незакоммиченной зоне — брак: приёмка гоняет тот же гейт первым ходом и завернёт отчёт, не читая (`RUKOVODSTVO §Приёмка`, гейт 0).

### Что решено верно и почему это важно

**Три исхода сторожа разведены, и средний — самый тонкий.** Невлитых нет и `--vlit` не задан → в заход идёт строка «вливать нечего, проверено». Невлитые есть, но не названы → **в файл не идёт ничего**, предупреждение уходит в консоль генератора. Формулировка исполнителя точная: *«молчание файла ≠ ложь про „нечего“»*. Написать в заход «нечего вливать», когда есть невлитое, было бы хуже, чем не написать ничего.

**Предупреждение исполнимо, а не декоративно:** печатает имена и готовую строку `--vlit <имена>` для копирования.

**Отдельно ценно, что заход не сработал вслепую на своих же прогонах:** все проверки с побочными следами (регистрация в `KARTA.md`, заведение веток) сделаны на одноразовых репозиториях, а не в живом `materials`. Реальный репозиторий не получил ни одной мусорной строки от тестов.

**З8 на собранном заходе молчит, и молчит по правильной причине** — проверено ловушкой 20: требование глагола ищется только внутри секции критерия, а блок `§0.1` живёт в `## 0. ПЕРВЫЙ ХОД`, до неё. Находки про З8 нет.

### 🔴 Вопрос исполнителя — снова дефект захода, и подкласс НОВЫЙ

Критерий п.3 требовал «собери пробный заход в `/tmp`», а `bootstrap_zahod.py` отказывает на папке арки вне корня репозитория (строка 365). Составитель читал этот файл при сборке и всё равно потребовал невозможного.

**Это пятый за двое суток случай критерия, который нельзя исполнить** (уроки 12, 14, 18, 22, 25) — и каждый раз причина новая. Здесь З8 не помогает по построению: она судит «глагол в критерии против запрета в теле», а тут запрета нет, требование невыполнимо **технически**, и знание об этом лежит в чужом файле.

Вердикт урока 25 процедурный, а не гейтовый: **команда, названная в критерии, прогоняется составителем при сборке** — клауза 5 уже требует этого для греп-критериев, распространить на любую команду, чей результат критерий предсказывает. Ещё один гейт здесь только сузит уже суженное (урок 23).

### Что это меняет для фабрики

С этого коммита **отдельные заходы «влить ветки» больше не нужны**: влитие вписывается в `§0` любого захода флагом `--vlit`, а забытое влитие видно предупреждением в момент сборки. Класс проблем, стоивший этой арке одного целого захода (`kod_vlitie-i-lok.md`) и одного заклинившего `.git/index.lock`, закрыт инструментом.

**Ветка не влита** — по контракту это ход приёмки, а Cowork влить не может (тот самый дефект, который заход и чинил). Ляжет первым ходом следующего захода в `materials` через новый же `--vlit`.
