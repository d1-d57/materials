### 2.2 Метод гейта — по утверждениям, а не по впечатлению

Для каждого кандидата:

1. **Выписать нормативные утверждения оригинала** — то, что он предписывает делать или запрещает. Не абзацы, не темы: утверждения, каждое проверяемо. Число снять **до** сверки: «выписано N».

   - **покрыто** — есть адрес (файл + место), содержание то же по существу;

3. Отчёт: «проверено N из N», пустых клеток ноль.

Образец метода уже отработан в этой арке: верификатор этапа 20 выписал **220 утверждений из старых тел и проверил 220 из 220** грепом по каталогу. Делай так же.

## 4. 🔴 КОММИТ СВОЕЙ ЗОНЫ — ПОСЛЕДНИЙ ХОД ЗАХОДА, НЕ ОПЦИЯ
Ты работаешь host-side и в `.git` ПИШЕШЬ — значит коммитишь САМ, никому не передавая:
```
git --no-optional-locks add -- `disciplina/arhiv-skillov/` `_studio/zhurnal/2026-08-05_faza-lenty/kod_gejt-vhozhdeniya.md`                     # вводит НОВЫЕ пути в индекс
git --no-optional-locks commit -m "<зона>: <что сделано>" -- `disciplina/arhiv-skillov/` `_studio/zhurnal/2026-08-05_faza-lenty/kod_gejt-vhozhdeniya.md`   # отсекает всё чужое
python3 _generator/tools/git_zona.py check --zone <зона>   # из корня репо; должен быть ✅
git --no-optional-locks show --stat                        # обязаны быть ТОЛЬКО твои пути
```
🔴 **ОБА хода обязательны, ни один не лишний** (полное «почему» и цена — `../docs/kak-delat/GIT-disciplina.md §3`):
- **`add`** — pathspec-коммит знает только **отслеживаемые** пути; новый файл без `add` даёт `did not match any file(s) known to git`.
- **`-- <пути>` в самом `commit`** — иначе `commit` забирает индекс ЦЕЛИКОМ, вместе с чужим, застейдженным кем угодно рядом с тобой (репо `materials/` общий, писателей трое). *Обе половины оплачены 21.07 в один вечер: голый `commit` подмёл чужой индекс — коммит на 89 файлов вместо трёх; «починка», убравшая `add`, завалила все 10 коммитов повторно.*
