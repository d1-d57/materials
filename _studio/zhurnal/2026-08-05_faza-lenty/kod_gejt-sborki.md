## 2. ЗАДАЧА

### 2.1 🔴 Сначала граница безопасности, потом проверки

**До первой проверки реши и запиши в `## ПЛАН`: что гейт выполняет, а что только читает.**

Опорное правило, которое ты вправе ужесточить, но не ослабить: **выполняются только команды, не меняющие состояние** — `git rev-parse`, `git show`, `git branch --list`, `ls`, `test -e`, `grep`, `wc`, `<инструмент> --help`. Всё остальное — **читается и не выполняется**, даже если выглядит безобидно.

Запрещено безусловно: любой `rm`, `mv`, `checkout`, `reset`, `merge`, `commit`, `push`, `pip install`, перенаправление в файл, `sudo`, всё с `&&` и `;` внутри, всё, чего нет в белом списке. **Белый список, а не чёрный** — чёрный неполон по построению.

⚠ Плюс два ограничителя: **таймаут** на каждую команду и **потолок числа команд** на один заход. Гейт, который висит, — это гейт, который отключат.

### 2.3 Что делать с расхождением — краснеть не всегда

Три исхода, и различать их обязательно:
- **красное** — утверждение опровергнуто прогоном (ветки нет, путь не существует, подкоманды нет);
- **⚠ печать** — проверить не удалось (команда вне белого списка, таймаут, нет доступа). **Это не зелёное и не красное**, это «смотри руками»;
- **молчание** — подтверждено.

🔴 **Слепые зоны печатать всегда**, даже когда всё зелёное — как это делает `priyomka.py`. Зелёный гейт с необъявленной слепой зоной опаснее красного: ему верят.

## 3. ВЕРИФИКАТОР

**Нужен, и вопрос у него один: чем этот гейт можно навредить.**

Свежий субагент получает **только код инструмента**, без твоего разбора и без фикстуры. Задача — написать файл-заход, при разборе которого гейт **сделает что-нибудь необратимое**: выполнит команду с побочным эффектом, уйдёт в бесконечный цикл, прочитает файл вне репозитория, съест память. Нашёл — дыра закрывается до сдачи.

Вторая задача ему же, слабее первой, но нужная: **написать заход с ложным утверждением, которое гейт пропустит.** Пропуск — не провал, но должен быть назван в слепых зонах докстринга.

## 1. ДИСЦИПЛИНА (Карпатов)
🔴 **Код возврата — ПЕРВЫМ, до содержательного вывода команды.** «Отработала» и «упала, а я читаю прошлое состояние» выглядят одинаково; сначала `echo $?`, потом выводы. То же с гейтами. *Цена 21.07: `rc=128` (сбой прав окружения) четырежды прочитан как результат — едва не откатили верное правило по ложным данным.*
Предпосылки/развилки назвать вслух; минимум без спекуляций; хирургия (строка → к заданию); критерий, который может провалиться. Якорные замены — abort при ≠1. Сохранять по умолчанию. **Оспорить ложную предпосылку — включая КРИТЕРИЙ ГОТОВНОСТИ: считаешь его кривым — скажи в `## ПЛАН`, ДО работы, и предложи поправку.** Субагенты: ≤5, рейт-лимит = отступить + доложить (не слепой ретрай).

🔴 **Пишешь содержательный текст — термин НЕ употребляется раньше, чем определён**, включая заголовки, подводки и формулировки теорем. «Определение в тексте есть» не считается: если оно ниже первого рабочего употребления, читатель встаёт ровно там. ### П1. 🔴 Граница безопасности — решение ДО первой проверки (§2.1)

**Опорное правило §2.1 ужесточаю в четырёх местах, не ослабляю ни в одном.**

1. **Никакого shell вообще.** `subprocess.run(argv, shell=False)`. `&&`, `;`, `|`, `>`, backtick, `$(...)`, glob не «фильтруются регуляркой» — они не существуют по построению. Строка команды сперва проверяется на метасимволы и, если хоть один есть, **не токенизируется вовсе** (уходит в ⚠), и только чистая строка идёт в `shlex.split`.
2. **Белый список по паре (программа, подкоманда), а не по программе.** `git` целиком не разрешён: разрешены `rev-parse`, `show`, `branch`, `log`, `ls-tree`, `ls-files`, `cat-file`, `merge-base`, `diff`. Токен сразу после `git` обязан быть подкомандой из списка — этим закрывается инъекция через глобальные опции (`git -c alias.x='!sh' …`).
3. **Флаги — тоже белым списком там, где у команды есть разрушительная форма.** `git branch` без `-d/-D/-m/-M/-c/-C/--force/--set-upstream-to`; `git diff/show/log` без `--output=`, `--ext-diff`, `--textconv` (последние два запускают внешние драйверы из конфига — это исполнение произвольного кода через якобы read-only команду).
4. **Каждый путь-аргумент обязан резолвиться ВНУТРИ репозитория.** Иначе `grep -c x /Users/…/.ssh/id_rsa` — законная read-only команда, которой гейт читает чужой файл. Вне репо → ⚠, не выполняется.

Плюс: таймаут на команду, потолок команд на файл, `--no-optional-locks` вклеивается в каждый git-вызов самим гейтом (канон: голый git берёт `.git/index.lock` и роняет параллельный коммит), окружение подчищается (`GIT_CONFIG_NOSYSTEM=1`, `GIT_PAGER=cat`, `GIT_TERMINAL_PROMPT=0`).
