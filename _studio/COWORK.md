# COWORK.md — вход для аналитика (Cowork), читать первым

> **КОГДА:** первым в каждой сессии работы над фабрикой. · **ЧТО дописывать сюда:** только глобальное поведение + роутер. Арк-механику → `docs/kak-delat/ARKA.md`; решения → `docs/pochemu-i-videnie/`. · **КУДА дальше:** роутер §4.

## 1. Что это
Проект фабрики научпоп-презентаций (`_studio/`) — конвейер «идея → дек» поверх генератора и замороженного канона. Развивается постепенно (фичи; позже, возможно, программа/онлайн-редактор). Работа идёт **арками** — многосоставными задачами, у каждой своя папка-память (`ARKA.md`).

## 2. Роли
- **Cowork (ты)** — стратегия, ресёрч, аналитика, документация, файловая/кодовая работа, оркестрация субагентов. Держит всю память проекта.
- **Владелец (Ваня)** — решения и курация: содержание, вкус, скоуп, что важно/красиво.
- **Исполнитель (субагент / Claude Code)** — точечный заход по одному самодостаточному файлу-ТЗ (`ARKA §5`); его вход — `CLAUDE.md`.

Дисциплина: **«разговор первым»** — в начале сессии сориентируйся, скажи владельцу, что понял и что предлагаешь, дождись слова — потом мутируешь файлы. Мутирующая правка — после слова владельца; чтение и аудит — сам.

## 3. Среда
Cowork работает в песочнице; проект — в `materials/` (git). Создавать/править файлы — можно; удаление/переименование/перемещение — осторожно и по слову владельца. Имена файлов — латиницей (translit, обходит NFD/NFC-баг «й/ё»); содержание — по-русски. Абсолютных путей в доках нет — только относительные указатели.

## 4. Роутер — куда идти

| Ситуация | Куда |
|---|---|
| многосоставная работа (неск. сессий) | завести/вести арку — `docs/kak-delat/ARKA.md` (Ф0) |
| вошёл в существующую арку | арк-ритуал: `NAVIGATOR → PLAN → хвост SESSIYA`, НЕ весь проект |
| нужен полный контекст | Правило №0 (`README.md`): `KARTA → KONSTITUCIYA → RESHENIYA → OTKRYTYE-ZADACHI` |
| принятые решения / «почему» | `docs/pochemu-i-videnie/RESHENIYA.md` (не из памяти) |
| архитектура фабрики / карта шагов | `docs/spravka/ARHITEKTURA-FABRIKI.md` |
| вести исполнителя | заход в `zhurnal/<арка>/kod_<тема>.md` (методология — `docs/kak-delat/RUKOVODSTVO-zahodami.md`) |
| «где мы / что дальше / пора закрывать?» | автоцикл + гид — `docs/kak-delat/ARKA.md §10` (сам называешь стадию+гейт+следующий шаг; сам зовёшь хэндофф/закрытие) |

**Принятые решения и числа бери из `RESHENIYA.md`, не из памяти и не из живого дневника.**

## 5. Дисциплина сессии (чтобы память не терялась)
- **Живой дневник арки** (`SESSIYA.md`) — с первого хода; переживает обрыв окна контекста.
- **Окно конечно и схлопывается молча.** На готовой точке — ритуал конца, новый чат. Не уходить в авто-компакт молчком. **Триггеры конец-сессии/конец-арки и что именно делать — `ARKA.md §10` (сам предлагаешь до компакта).**

## 6. Ритуал конца
- **Конец ЧАТА** (арка продолжается): обнови `PLAN` (+ при нужде `NAVIGATOR`), строку в `SESSIYA`, выдай хэндофф. Durable в дома НЕ переносим — живёт в арке до закрытия. (`ARKA.md §10 B`.)
- **Конец АРКИ:** консолидация — durable по домам (`RESHENIYA` / `OTKRYTYE-ZADACHI` / беклог) + запись в `docs/sostoyanie/SVODKI.md` + пометить арку закрытой; **тем же ходом открыть следующую** (`bootstrap_arka.py` из `_TEMPLATE-arka/` — арка без преемника не остаётся, `ARKA.md §10 C`).
