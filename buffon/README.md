# Дек «Игла Бюффона» — карта проекта

Один самодостаточный файл `index.html` (23 слайда, холст 1440×810). Собран по контракту
скилла **html-slides-studio** (исходно был байт-в-байт равен его эталонному примеру
`buffon-canon-EXAMPLE.html`; сейчас правлен — ЗАХОД-01/02/03, ветка `buffon-zahod-01`).
Почти весь вес файла (2.8 МБ) — вшитые шрифты.

Эта карта — не дубликат скилла, а *указатель сверху*: где что лежит, что нельзя трогать,
как править безопасно. Архитектурная документация живёт в самом скилле; здесь — привязка
к конкретному файлу.

## Документы проекта (начни с `HANDOFF.md`)

- **`HANDOFF.md`** — точка входа: текущее состояние, что сделано (ЗАХОД-01/02/03), что дальше, ключевые решения, грабли.
- **`README.md`** (этот файл) — карта дека: 4 блока, индекс 23 слайдов, инварианты, радиус правки, dev/QA.
- **`WORKLIST.md`** — живое состояние: правила G1–G6, пер-слайдовые правки, §5 диагностика кода, §6 идеи финализации, приёмки заходов.
- **`ZAHOD-01/02/03.md`** — заходы для Claude Code + отчёты исполнителя.
- **`ANIM-01-cos-area-spec.md`** + **`anim-01-prototype.html`** — спека и прототип анимации «площадь под косинусом».

## Как смотреть и проверять

Открыть `index.html` в браузере. Управление (движок, блок `[4]`):

| Клавиша | Действие |
|---|---|
| `→` / `PageDown`, `←` / `PageUp` | вперёд/назад по сценам и слайдам |
| `O` | обзор всех слайдов (zoom-overview) |
| `B` | затемнить экран, `F` | полноэкранный режим |
| `G` | наложить кальку эталона (сверка геометрии) — только в dev |
| `?dev=1` в URL | dev-режим (сетка, калька по `G`) |
| `?only=N` в URL | показать один слайд N крупно — для рендера кадра (PNG-QA) |

## Симуляции (канвасы)

Контракт: `<canvas data-sim="…">` внутри `.panel`; в покое канвас неотличим от статичного слайда.

| `needles`, `yellow`, `coords-needles`/`coords-phase` | ядро `lab.js` (L783) | 4, 10, 18 |
| `convergence` | `lab-ext/convergence.js` (L1297) | 5 |

Два патча движка (см. `buffon-canon-build.py` в скилле):
- **`patch_sim_reset`** — канвас открывается «на нуле» **и авто-запускается** при входе на сцену.

Кнопки контролов — только текстовые глифы (`▸ ▸▸ ❚❚ ↺`), не эмодзи.

## Инварианты (не ломать)

1. **Блок `[4]` ENGINE — verbatim.** Навигацию/сцены/фуллскрин не переписывать по слайду.
2. **Холст фиксирован 1440×810**, масштабирует его *сцена*. Никаких `clamp()`/`vh` внутри слайдов.
3. **Тело текста не автофитится** (`--t-body`, L30). Автофит — у прочих зон, через `data-max`/`data-min`.
   Огромный кегль лечится геометрией зоны (уже уже), не ослаблением фиттера.
4. **Сцены прячут шаги через `visibility`, никогда `display`** (L64) — иначе геометрия «прыгает».
5. **Палитра ограничена** (проверяет `audit.py`). Неопределённая CSS-переменная в SVG-заливке
   рендерится **чёрным** — при правке `<template>` задавать все переменные.
6. **Симуляции:** свежий seed на каждом входе, `settle()` → «покой = слайд».

## Как править безопасно (радиус правки)

| Просьба | Трогать | НЕ трогать |
|---|---|---|
| поправить текст/формулировку | текстовый узел в этой зоне | сетку, движок, размеры |
| подвинуть/сузить зону, поля | grid-CSS этого слайда | текст, другие слайды, движок |
| «текст слишком крупный/мелкий» | геометрию зоны или `data-max`/`data-min` элемента | код фиттера |
| заменить иллюстрацию | её `<template>` в блоке `[3]` | слайды, раскладку |
| перекрасить дек | CSS-переменные / `@font-face` | структуру разметки |
| поправить симуляцию | её модуль `lab-ext/<sim>.js` | ядро `lab.js`, движок `[4]` |

**Цикл одной правки:**
1. `.bak` перед батчем правок (`cp index.html index.html.bak`).
2. Хирургическая правка; убедиться, что якорь замены найден (никаких «тихих» no-op).
3. Рендер **обоих** видов: масштабированный слайд + кадр `?only=N`. Смотреть на **картинку**, не на код.
4. Критерий приёмки: *«выглядит как чистый модельный слайд нашего дека?»*
5. `python3 audit.py index.html` (+ `--scene-diff` для многосценовых слайдов). Exit 1 = FAIL.
6. Сверка с эталоном (см. ниже).
7. **Стоп-правило:** третья правка одного слайда = пропущенный гейт, а не норма. Остановиться и проверить процесс.

## QA-инструменты (в скилле html-slides-studio)

- **`scripts/audit.py`** — машинная проверка канона (пол текста, палитра, запрещённый CSS,
  переполнение, пустые сцены). `--scene-diff` FAIL-ит пустую сцену и прыжок геометрии.
- **`assets/etalons/buffon-p*.jpg`** — исходные Canva-кадры (p05, p07, p13, p21, p25, p31, p36, p43, p45).
  Это **дизайн-истина** для визуальной сверки: как слайд должен выглядеть.
- **`assets/etalons-html/00…22.jpg`** — рендер *этого же* (идентичного) файла. Это снимок
  **текущего состояния** — в нём есть и репортируемые баги, поэтому это не «правильный ответ»,
  а точка отсчёта «было».
- **`references/decks/buffon-canon-build.py`** — читать как «почему»: какой канон-трансформ
  применён к каждому слайду и что делают патчи движка.

## Замечено при разборе (кандидаты в worklist — проверить)

- **`phase-mass` на двух канвасах** (слайд 19 `condition` L660 и слайд 20 `phase` L667) — один
  `data-sim` инстанцируется дважды. Проверить, что оба запускаются (возможная причина
  «канвас не стартует»). Оба в главе 2, которая по отзыву в порядке → возможно, переиспользование намеренное.
- **Повторяющиеся `data-refs`:** `plan` (p-13, p-13), `result` (p-30 ×3) — HTML добавляет
  сцены-раскрытия поверх одного Canva-кадра. Прогнать `audit.py --scene-diff`: каждый клик
  должен что-то раскрывать, пустых сцен быть не должно.
