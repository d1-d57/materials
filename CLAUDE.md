# CLAUDE.md — корень `materials/` (тонкий указатель, читается автоматически)

**Ты в `materials/` — монорепо всех проектов.** Здесь нет методологии; здесь маршрут.

## Кто ты сейчас — две роли, два входа

- **Аналитик / Cowork** (ведёшь работу, пишешь тексты и заходы, судишь отчёты) → **`README.md` §2 РОУТЕР** — таблица «задача → дом». Дальше `_studio/README.md` → Правило №0 → `_studio/docs/KARTA.md`.
- **Исполнитель / Claude Code** (тебе дали файл-заход) → **читай ТОЛЬКО свой заход** и то, что он называет поимённо. Проект НЕ изучай, этот файл дальше не разворачивай: заход самоценен. Канон — `_studio/docs/kak-delat/RUKOVODSTVO-zahodami.md`.

## Три вида папок

`_studio/` — **фабрика** (как делать: стандарты, конвейер, борд) · `_generator/` — **движки** (`build_doc.py` — документ, `build_deck.py` — слайды) · остальные — **проекты** (карта: `README.md` §3).

## Ты в папке проекта — четыре момента, когда ОБЯЗАН вернуться в фабрику

Работая в проекте, фабрику перестают открывать — а дисциплина живёт там. Поэтому не «иногда заглядывай», а список триггеров: делаешь слева — открываешь справа **тем же ходом**, не потом.

| Делаешь | Открой | Что случится иначе |
|---|---|---|
| **завёл новый `.md`** (любой, включая заход) | `_studio/docs/KARTA.md §6` — зарегистрировать | `KONSTITUCIYA §9`: документ-сирота = не существует. Ловится грепом, нарушается постоянно |
| **пишешь число, статус или охват**, которые можно вычислить из файлов | `KONSTITUCIYA §10` | Пишется не число, а команда, которая его считает. «Я посчитал и вписал» — брак, даже когда цифра сегодня верна; в этом репо так соврали пять раз |
| **заводишь новое правило** («давай всегда будем…») | `KONSTITUCIYA §11` | Правило заводится ВМЕСТЕ с тем, что покраснеет при нарушении. Нечему краснеть — это не правило, а надежда; так её и назови |
| **собираешь заход или арку** | `bootstrap_zahod.py` / `bootstrap_arka.py` | Руками теряются вшитые куски: контракт зоны, `## УРОКИ ФАБРИКЕ` с ЦЕНОЙ, скелет арки. Их отсутствие не видно, пока не понадобится |

## Шесть правил, которые нарушают чаще всего

1. **HTML — только готовым генератором** (`_generator/`). Новый не писать; чего не хватает — дорабатывать.
2. **После сборки документа — гейт:** `python3 _generator/tools/check_view.py <src>` (ловит «текст съеден при отрисовке»; в формулах писать `\lt`/`\gt`, не `<`/`>`).
3. **Иллюстрация — по словарю** `_studio/konvejer/09-illustracii/SLOVAR-primitivov.md`. Взял примитив, вышло плохо → **чинить словарь**, а не только свой рисунок.
4. **Предпосылку проверяй по живым файлам** — включая свою и включая написанную владельцем. Ложна → скажи с доказательством, не гоняйся за фантомом.
5. **Git — ТОЛЬКО через `_generator/tools/git_zona.py`**, никаких голых `git` руками. Обычный `git status` НЕ read-only: он переписывает индекс, берёт `.git/index.lock` и роняет чужой коммит — так гейт, следивший за потерями, сам сорвал три коммита за сессию. `doctor` — что с репо; `check --zone` — проверить зону; `plan` → `commit` — закоммитить; `worktree` — параллельный заход. **Весь канон git — `_studio/docs/kak-delat/GIT-disciplina.md` (единственный дом).** Исполнитель коммитит свою зону САМ и сдаёт хэш; приёмка гоняет `check --zone` первым ходом и грязную зону не принимает.
6. **Отметка «закрыто / не переоткрывать» без ДАТЫ ДАННЫХ доверия не заслуживает** (Р34). Такая отметка уже запрещала проверить устаревшее и дала шесть подхватов за сессию. Нашёл без даты — считай вопрос открытым и скажи. Ставишь сам — пиши дату данных, а не только вердикт.
