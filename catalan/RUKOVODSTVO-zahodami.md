# RUKOVODSTVO-zahodami.md — как Cowork ведёт Claude Code (проект «Каталан»)

> **КОГДА читать:** когда пишешь заход для Claude Code, шлёшь ему задачу или принимаешь отчёт. · **ЧТО дописывать сюда:** только методологию петли Cowork ↔ Code (правила, канал, стандартный текст, приёмка, модели). НЕ роли/среду (`COWORK.md`), не вход Code (`CLAUDE.md`), не арк-механику (`ARKA.md`). · **КУДА дальше:** скелет захода — §6.
>
> Методология для аналитика (Cowork): сам код не пишет — **пишет заходы, судит отчёты, держит петлю тугой.** Самодостаточно: при работе на скилл `agentic-coding-session-brief` не опираемся — здесь та же дисциплина, распечатанная под этот проект. (Скилл — общая стартовая база всех проектов; этот файл — его проекция на «Каталан».) Code стартует с ЧИСТЫМ контекстом каждый сеанс — прошлого не помнит, проект читает заново; значит всё, что должно сохраниться, лежит в файлах, не в его памяти.

## Принцип
Состояние живёт на диске (файлы проекта + файл-заход), не в памяти сессии. Отсюда: заход **самодостаточен** (вход, что прочитать, что сделать, как отчитаться — внутри текста), **один заход = одна задача** (чистый старт бьёт длинную мутную сессию), durable — сразу в файлы.

**Роль-сплит.** **Cowork** (сильная модель, Opus) держит стратегию и ВСЮ документацию/историю: читает тщательно, полный контекст задачи. **Code** (быстрая, Sonnet — дефолт) — одна чётко поставленная задача с максимально ПУСТЫМ контекстом: читает только заход и названные якоря, выполняет ультимативно, отдаёт отчёт, останавливается. Code ничего не консолидирует и проект не доразбирает.

**Среда «Каталана» (важно для точки отката).** Папка **не под git** → точка отката это **tar-снапшот в `snapshots/`** (его делает Code в начале захода). **zip не использовать** — на этом mount не финализируется, только `tar`. Удаление файлов **гейтится** (`Operation not permitted`) → не считать невозможным (запросить разрешение), а durable-смысл из файла поднять в дом-ядро ДО удаления.

## §1. Канал — один файл в папке арки
Обмен с Code идёт через ОДИН файл: `zhurnal/<арка>/kod_<тема>.md`. В нём весь обмен:
- сверху — **заход** (пишет Cowork): контекст, что прочитать поимённо, что сделать, границы, критерий;
- снизу — секции `## ПЛАН` / `## ВОПРОСЫ` / `## ОТЧЁТ`, которые **заполняет Code**.

Code читает ТОЛЬКО этот файл (правило — `CLAUDE.md`), остальной проект не изучает. Cowork потом берёт отчёт прямо с диска — ничего вручную не переносить.

**Почему.** Один файл = Code не лезет во всю документацию и не ломает лишнего; асимметрия удержана (Cowork читает тщательно, Code — минимально).

> Петля: путь файла — внутри сообщения? модель названа первой строкой? сказано «читай только это»? Нет — сообщение не готово.

## §2. Стандартный текст владельцу → Code (полный путь + МОДЕЛЬ ВНУТРИ текста)
Владелец не вставляет весь заход в Code — шлёт **короткий текст с ПОЛНЫМ абсолютным путём файла ВНУТРИ** (не отдельной строкой, не «вот папка, вот текст») и **моделью первой строкой**. Cowork, отдавая заход, СРАЗУ даёт готовый к пересылке текст с подставленным путём и моделью:

```
Модель: <Sonnet 5 | Opus 4.8> — <одна фраза почему> (в Claude Code — /model).
Claude Code, твой заход — файл `<ПОЛНЫЙ_АБСОЛЮТНЫЙ_ПУТЬ>/zhurnal/<арка>/kod_<тема>.md`. Прочитай ТОЛЬКО его и то, что он называет; остальной проект не изучай. Папка не под git — сначала сделай tar-снапшот в snapshots/. План, вопросы и финальный отчёт пиши в этот же файл, в секции внизу (## ПЛАН / ## ВОПРОСЫ / ## ОТЧЁТ). Ничего сверх задачи не трогай.
```

**Модель — ОБЯЗАТЕЛЬНА первой строкой в КАЖДОМ заходе** (какую и почему — §8).

## §3. Заход — дай Code всё, иначе соберёт не то
Самодостаточность + контекст ЗАРАНЕЕ + проверяемый критерий.
- Заход несёт ВСЁ: рабочая папка, что прочитать ПОИМЁННО (точные файлы), что сделать, границы, как отчитаться. Скажи явно: «читай только названное, проект не доразбирай».
- Дай существующие конвенции и имена **авансом** → Code переиспользует, не плодит своё (дома — из `NAVIGATION.md`).
- Есть ошибка/лог/вывод — вкладывай **RAW** и «почини», не пересказ (пересказ теряет деталь).
- **Критерий готовности — условие, которое может ПРОВАЛИТЬСЯ** (не «я закончу»): «6 файлов на местах, битых ссылок 0, `check_docs` зелёный», а не «сделал».
- **Точка отката — tar-снапшот** в `snapshots/` в начале захода (единственная точка отката; git нет).
- **ВСЕГДА требуй в отчёт: сколько шёл прогон и сколько токенов потрачено.** В КАЖДОМ заходе, не по запросу (источник — `/cost`, лог прогона).
- **Флаг «стоп до цели».** Если заход по замыслу останавливается ДО результата, которого ждёт владелец (собрал, но не запустил) — скажи это **громко и заранее** одной фразой: «получишь X, но НЕ Y; Y запускается отдельно так-то». Не мелким шрифтом в хвосте.
- **Преимущество Cowork: ты сам видишь файлы.** Трогает заход то, что ТОЛЬКО ЧТО закрыли, — сверься на ЖИВЫХ файлах ПЕРЕД написанием (между заходами мог пройти другой). Пометь «уже закрыто — проверить зелёным, не открывать заново».
- Лоссовый/двигающий заход (перенос, удаление, сжатие) → встрой **верификатор** (§5).

**Почему.** Code с чистым контекстом, не получивший канон, честно изобретёт уже принятое решение — это ловится по нескольку раз, пока контекст не дают заранее. Регулярная нужда «чистить после агента» = сигнал, что контекст не дали.

> Петля перед отправкой: Code с нуля поймёт? назван точный вход и что прочитать? критерий может ПРОВАЛИТЬСЯ? Нет хоть одного — заход не готов.

## §4. Приёмка отчёта — суди по отчёту, но проверь ГЕЙТЫ
Доверяй содержанию, но пройди КАЖДЫЙ гейт:
- **ГЕЙТЫ (все обязательны):** критерий выполнен · числа сходятся · границы соблюдены (запрещённое не тронуто) · решения обоснованы · вопросы Code разобраны · верификатор/`check_docs` зелёные · **время прогона + токены в отчёте** · **нет тихого недобора** (Code остановился до ожидаемого → это должно быть заявлено громко; тихий стоп до цели = провал гейта).
- **Дешёвая сверка по живым файлам:** ты видишь файлы — быстрый `tree`/`grep`/`check_docs`, что заявленное = реальность. Не построчно.
- **Дисциплинированное НЕ-действие** (Code отказался от рискованной правки при нулевой пользе, вынес в отчёт) — это ХОРОШО, не повод отклонять.
- **Вердикт:** принять ИЛИ вернуть на точечную дочистку (не переделывать всё). **Приёмку и ратифицированные решения — в дневник арки** (`zhurnal/<арка>/SESSIYA.md`; durable — в дома при консолидации). Вопрос Code без ответа → ответ идёт в начало СЛЕДУЮЩЕГО захода.

**Почему.** Свежий глаз проверяет, не автор. Приёмка на чистую веру = пропущенный гейт, который Code тихо не закрыл, всплывёт через три захода.

> Петля: можешь назвать КАЖДЫЙ гейт и сказать «пройден»? есть вопрос Code без ответа? Нет — приёмка не закрыта.

## §5. Верификатор внутри захода (для потерь и перемещений)
Заход двигает/удаляет/сжимает → встрой ОТДЕЛЬНЫЙ свежий субагент-верификатор как ГЕЙТ: «исходный смысл → новый дом» полно (список потерь ПУСТ); каждая ссылка резолвится (битых 0, программно). **Ключ — ДРУГОЙ субагент и ДРУГОЙ метод**: читает оригиналы из **tar-снапшота**, сверяет `sha256`/программно. У автора правок слепые пятна — свежий с иным методом их ловит.

**Повторяющуюся проверку — в ПОСТОЯННЫЙ чекер.** Нужна КАЖДЫЙ заход (сироты, битые ссылки, синхрон чисел) → `tools/check_docs.py` (stdlib, детерминизм, без исполнения кода) + в ворота. *(В «Каталане» чекер ещё не заведён — в очереди Code-заходов; до него сверка ручная по живым файлам.)*

## §6. Скелет захода (меняется только тело §3)
```
# Канал Claude Code — <короткое имя>
> Для Claude Code: твой единственный файл-заход. Читай ТОЛЬКО его и названные якоря; проект не изучай.
> План/вопросы/отчёт — в секции внизу этого файла. Метрика — КАЧЕСТВО. Часы — норма.

## ЗАДАЧА (один проход до конца)
КОНТЕКСТ. <проект в 1–2 фразы; прошлый этап: состояние; ЦЕЛЬ: что закрыть>. Приёмка — по отчёту, без построчной сверки. <Если стоп до цели: получишь X, но НЕ Y.>
### 0. ПЕРВЫЙ ХОД. Рабочая папка <путь>; СРАЗУ tar-снапшот в snapshots/ (git нет); прочитать ТОЛЬКО <названные файлы>; изложить ПЛАН в ## ПЛАН перед действиями.
### 1. ДИСЦИПЛИНА (Карпатов). Назвать предпосылки/развилки (ложную — оспорить, включая в этом заходе); минимум без спекуляций; хирургия (каждая строка → к заданию, чужой стиль хранить); критерий, который может провалиться. Якорные замены — abort при ≠1. Сохранять по умолчанию (вопросы — в ## ВОПРОСЫ/ОТЧЁТ). СУБАГЕНТЫ (§8, аккуратный режим): вложенные — осмысленно, не случайный рой; ≤5 параллельно (остальное в очередь); рейт-лимит = отступить + доложить, не слепой ретрай. Назвать ЯВНО: сколько субагентов и на что.
### 2. ГРАНИЦЫ. <что НЕ трогать: данные/тексты/соседние фазы; рабочее ради красоты не переписывать>.
### 3. ЗАДАЧА. <конкретно>. КРИТЕРИЙ ГОТОВНОСТИ: <проверяемое условие, которое может провалиться>.
### 4. ВЕРИФИКАТОР (если двигаем/теряем). Свежий субагент, ДРУГОЙ метод, сверка с tar-снапшотом, программно.
### 5. ОТЧЁТ → секция ## ОТЧЁТ внизу: что сделал + ЗАЧЕМ / как проверил / что НЕ трогал / вопросы / результат верификатора / **время прогона + токены**.

## ПЛАН — (заполняет Code)
## ВОПРОСЫ — (заполняет Code)
## ОТЧЁТ — (заполняет Code)
```

## §7. Тип захода и когда не усердствовать
- **Мутирующий** (двигает/правит файлы): коммиты/снапшот по блокам, сверка после каждого, верификатор для перемещений.
- **Аналитический** (только смотрит/измеряет): данные не трогать; артефакт + ПРЕДЛОЖЕНИЯ; решение — владельцу.
- **Организационный** (порядок папки/доков): содержание/архитектуру не менять.
- **Оспаривай предпосылку — включая от владельца и в самом заходе:** допущение проверь по живым файлам ПРЕЖДЕ, чем строить.
- **Один риск за раз.** Тяжёлое режь по риску: read-only АУДИТ → МУТАЦИЯ по плану → read-only СВЕРКА. Синтез содержания отделяй от ПЕРЕМЕЩЕНИЯ файлов (перемещение рвёт ссылки — отдельным заходом с верификатором).
- Тривиальный заход (одна строка, опечатка) — без церемоний §0–§5, не переспрашивать трактовку. Усердие там, где цена ошибки — переделка; быстро там, где откат дёшев.

## §8. Бюджет, лимиты (Max 20x) и какая модель в заход
Точных токен-цифр Anthropic не публикует; источник правды — `/cost` в Code и лог прогона, не память.
- **5-час окно — БОЛЬШОЕ** (эмпирически Max 20x ≳ 7 млн ток./окно): полный прогон влезает с запасом → не строй заход вокруг страха «сожжём окно». Окно скользящее.
- **Реальный дефицит — НЕДЕЛЬНЫЕ капы** (один на все модели + отдельный на Sonnet): их душит проект из МНОГИХ прогонов. Тиринг (haiku-масса / sonnet-суждение / opus-скупо) бережёт именно недельный бюджет.
- **Пул общий:** claude.ai + Claude Code + Cowork (и этот чат считается); параллельные инстансы жгут вдвое.
- **Модель оркестратора — главный рычаг:** координацию (спавн субагентов, файловый I/O) гони на **Sonnet**; Opus — только на узкое ядро (план/плетение). Паттерн «план на Opus, исполнение на Sonnet» — `/model opusplan`.

### §8.1. Аккуратный режим субагентов (не запрет)
Инцидент 2026-07-02: заход развёл лавину субагентов — легли на рейт-лимиты, холостые падения, лишняя переработка. Токенов мало — беда не в цене и не во вложенности, а в **бесполезном разбегании**. Вложенные субагенты РАЗРЕШЕНЫ, когда осмысленны; заход с делегированием несёт бюджет: **(1)** вложенность — по плану и с причиной, не случайный рой; **(2)** ориентир ≤5 параллельно, остальное в очередь; **(3)** рейт-лимит = отступить + доложить, не слепой ретрай; **(4)** рой падающих субагентов без результата = разбегание → стоп + доклад.

### §8.2. Какую модель ставить в заход (первой строкой, §2)
Факты (июль 2026, сверено по живым источникам — перенесено из `kurs leto 2026`; при сомнении пересверить):
- **Opus 4.8** — $5 / $25 за млн ток. (вход/выход); агентное кодирование ~69%. Тяжёлое рассуждение.
- **Sonnet 5** (вышел 30.06.2026) — $3 / $15 стандарт, **интро $2 / $10 до 31.08.2026**; агентное кодирование ~63%; контекст 1M; лучше держит prompt-injection, меньше галлюцинаций.
- **⚠️ Парадокс «Sonnet дешевле — но не всегда»:** новый токенайзер (~1.0–1.35× токенов на тот же текст) + многословнее (~+30%); в длинных агентных прогонах компаундится и total может догнать Opus. Метрика — **стоимость за успешный РЕЗУЛЬТАТ, а не за токен**: где Opus решает с первого раза, а Sonnet ретраит, Opus по факту дешевле.

| Тип захода | Модель | Почему |
|---|---|---|
| **Исполнительный, полностью расписанный** — якорные замены, вставки дословным текстом, renumber, рендер/сборка, гейт-линтер (весь reasoning в заходе) | **Sonnet 5** (дефолт) | механика; глубина Opus ничего не покупает; дешевле + бережёт недельный кап; abort+верификатор ловят сбой |
| **Исследовательский / неоднозначный** — сквозной рефактор, трудный дебаг, «разберись и почини» без готовых якорей | **Opus 4.8** | план рождается по ходу; выше успех с первого раза → меньше ретраев |
| **Смешанный** — план на Opus, механику на Sonnet | `/model opusplan` | опус планирует, sonnet исполняет |

**Дефолт — Sonnet.** Opus — только когда заход требует глубокого рассуждения В ХОДЕ ИСПОЛНЕНИЯ (не на этапе, который Cowork уже закрыл, написав заход). Чем детальнее заход (точные якоря, критерий, границы), тем увереннее Sonnet — хороший заход сам удешевляет модель.
