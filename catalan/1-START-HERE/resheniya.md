# РЕШЕНИЯ — durable: что решено и почему

## Принятые

### 1. Проект = два продукта в одной папке (2026-07-03)
**ЗНАНИЕ** (вечнозелёный справочник области) + **ПУБЛИКАЦИИ** поверх него (курс сейчас, позже другие лекции и большой сайт). Одна папка, чёткая граница слоёв, **односторонняя зависимость**: публикации ссылаются на знание, не наоборот. Математику правим только в `spravochnik/`, не в отрендеренном HTML.
*Почему:* собрать один раз полную базу области и переиспользовать под разные форматы (курс, монография, отдельные лекции), не теряя и не дублируя.

### 2. Портируем ОС памяти из `kurs leto 2026`, не изобретаем (2026-07-03)
`NAVIGATION` с двумя таблицами (делаешь→читай / появилось→допиши) + правило регистрации + `check_docs`; арки в `zhurnal/<дата>_<тема>/`; долгая память vs локальная память арки; консолидация в конце арки. Канон процесса — скилл `agentic-coding-session-brief`.
*Почему:* `kurs leto 2026` уже решил ровно «боль памяти»; две таблицы `NAVIGATION` = вход-по-сценарию (что читать) + куда-консолидировать (куда писать) — это и есть две заявленные боли.

### 3. Зерно знания — средние главы + карта-навигатор (2026-07-03)
Статьи среднего размера (по доказательству / модели / сюжету), адресация по `id`; сверху `KARTA-OBLASTI` индексирует их по роду и по сквозным нитям с обратными ссылками. Не атомы, не монолит. Любой порядок лекции = маршрут по карте.
*Почему:* курс не линеен — многие темы взаимозаменяемы и переставимы; нужен навигатор, чтобы найти мысль, не читая весь корпус.

### 4. Монолит пока не дроблю; распил — заход Code (2026-07-03)
93-КБ knowledge-base лёг как `spravochnik/_seed-kb.md`; `KARTA-OBLASTI` временно указывает на его 9 разделов. Распил на `stati/` + провязка карты — Code-заход с верификатором полноты.
*Почему:* приоритет сегодня — встал хребет и уход в арку «Программа курса»; распил механический, делегируется на чистый контекст.

### 5. Структура курса: два независимых мира + карта раньше концепции (2026-07-03)
Курс = 2 мини-курса, **независимые** (можно слушать один — требование), но **единые по духу** (красивые биекции; каждый открывается исследовательской задачей). Ведущая гипотеза деления: **МК1 — мир путей Дика** (баллотировка + возвращение, много доказательств формулы Каталана); **МК2 — мир формулы Кэли** (Прюфер/Жойяль/Питман/Поллак; парковки ↔ помеченные деревья ↔ помеченные пути Дика). Технический хребет-мост: **циклическая лемма** доказывает и Каталан (Dvoretzky–Motzkin), и Кэли (Pollak). Порядок работы: **сперва карта области + ресёрч, структуру лекций не лочим до карты** (`zhurnal/2026-07-03_programma-kursa/karta-chernovik.md`).
*Почему:* «4 комбинаторики + 4 вероятности» отвергнуто (не процесс-first). Два родственных мира дают сразу независимость и единство духа. Мир Кэли в `spravochnik` отсутствует → ресёрч-фронт арки; идеальную концепцию собираем после карты.

### 6. Карту знаний строим итеративно, волнами (2026-07-03)
Не один большой заход, а короткие волны: чуть поработали → нашли потенциальные дыры → волна ресёрча → скачали/прочитали/дописали в библиотеку и короткую базу → снова. Причина: в математике связь двух разделов нельзя предсказать заранее (может не существовать; может существовать, но быть не открытой) — на такое натыкаются поиском, а не планированием. Мы не открываем математику, только систематизируем известное; каждая волна на ~99% совпадает с известным, но добавляет важный штрих. Метафора владельца: намывание золота — заходить в воду много раз, не один. Практика: **одна задача за раз**; Claude Code не грузить огромным заходом; между этапами — `session-handoff`.

### 7. Стратегия арки: разведка → карта, граф утверждений — в конце (2026-07-03)
Порядок внутри арки: сперва **разведка** (круги веб-поиск → загрузка → чтение → синтез, решение №6), затем карта фактов; **граф утверждений собираем в конце арки**, не в начале. Задача этой арки — **задел-карта**: установить, какие факты/биекции вообще существуют в природе, особенно на стороне Кэли, где — в отличие от множества доказательств формулы — красивая объединяющая биекция толком не записана («симфония вокруг путей Дика» рассыпана по источникам). Конечный продукт (кросс-арочный, по образцу `popsci-research`): **связанная линейная последовательность утверждений** → короткий текст-бриф → HTML, который автор читает и подтверждает «этот курс я хочу прочитать» → анонс → слайды. Граф — средство систематизации (объекты · множества · утверждения · связи, обходимые маршрутом), не самоцель.
*Почему:* структуру нельзя фиксировать раньше, чем известна карта фактов; в части Кэли связи исследованы неравномерно, их находят поиском, не планированием. Граф-в-конце снимает риск лочить структуру на неполной карте.
*Процесс:* заходы к Claude Code пишутся через project-local Code-doc (проекция скилла `agentic-coding-session-brief`, сейчас переписывается) — до его появления тяжёлое чтение PDF через Code на паузе; поисковая нога разведки от него не зависит и идёт уже сейчас.

### 8. База знаний = компактная память агента; источники — переизложения (2026-07-03)
База (`spravochnik/stati/`) — **рабочая память агента, не учебник**: владелец её НЕ читает, обращается через Cowork. Храним **находку + связи + указатель на источник**, НЕ определения и не разбор конструкций (восстановимы по указателю или в интернете). Ориентация (иначе мёртвый груз): `KARTA-OBLASTI` резолвит каждый `id` + **нить = упорядоченный маршрут-сюжет**; узел без нити — привязать или удалить. Хранение: файл на нить `stati/<нить>.md` (узлы в порядке сюжета) + общий `stati/*-obiekty.md` (объекты-ручки). Стандарт — `spravochnik/STANDART-uzla.md`. **Источники — переизложения, не первоисточники** (Kreweras 1980 / Knuth и т.п. не читаем; берём обзоры/конспекты/слайды). Формат черновой, эволюционирует. Уточняет №3: гранулярность — компактный узел, не средняя статья.
*Почему:* база нужна агенту для recall, не человеку для чтения → плотность и связность важнее полноты; переизложения экономят усилия и ближе к школьной подаче. Отдельно от базы — человеко-читаемая карта-deliverable (№9).

### 9. Ближний deliverable арки — полная читаемая карта Мира 2 (2026-07-03)
Работаем **исключительно над второй частью курса — Мир 2 (Кэли/парковки, 4 лекции)**; цель — **полностью картографировать** и выдать **читаемый документ карты**, который владелец прочитает и поймёт, «сложится ли» эта часть. Первая часть (Мир 1, пути Дика) при готовой второй понятна сама (материал в `_seed-kb`). Миры независимы (№5) → две отдельные работы; сознательно ведём только Мир 2, чтобы снять неопределённость. Нить B готова (узлы); дальше — нить A, сшивка через `area`, добор, сборка карты.
*Почему:* боль владельца — не знает, сложится ли вторая часть; полная карта Мира 2 снимает её и разблокирует анонс/слайды.

### 10. Аудитория Мира 2: жёсткое исключение — линейная алгебра; графы — основы знают (2026-07-04, уточнено)
Школьники после 8 класса. **Жёстко:** линейной алгебры нет (это 10–11 кл.) → доказательство Кэли через Кирхгофа/матрицы (Aigner–Ziegler, 2-е док-во) **отброшено**. **Уточнение владельца:** графы и комбинаторика — ОСНОВЫ знакомы (кто-то слышал и про формулу Эйлера); деревья с нуля строить НЕ обязательно, базу можно опереть — «графы им новьё» было преувеличением. **Гейт отбора:** путь к результату — через школьную комбинаторику и азы графов, не через чужой аппарат (линал). Следствие: burning/сэндпайлы (владелец: «безумно сложно») — только при ЭЛЕМЕНТАРНОМ, сэндпайл-free изложении; иначе фон. **Слишком сложное/отброшенное НЕ выбрасываем — держим ВИДИМО помеченным** (слой карты «кунсткамера» + уровни узлов): владелец хочет обозреть глазами и, возможно, «потрогать руками». **Ресёрч — приоритет и не отступать:** одну вещь разные источники подают по-разному, ясность бывает ровно в одном тексте — искать самый понятный; карту строить итеративно, потом обновлять.
*Почему:* нельзя лочить содержание/уровень, не сверив с реальным бэкграундом аудитории; ясность — функция выбора источника («найти правильный текст» — часть работы); трудное лучше отложить на виду, чем скрыть — владелец сам решит, что взять.

### 11. Deliverable для владельца — строгий математический текст, не карта-нарратив (2026-07-04)
Карта-навигатор (`KARTA-MIRA-2.md`) хороша как ориентация — агенту и для обзора связей/мостов/сложности, — но владельцу ДЛЯ ЧТЕНИЯ материала как формат не годится: тема новая, «абстрактно» из нарратива он её не воспринимает. Нужен **строгий математический текст**: определения, формулировки-утверждения, полные доказательства. Затем — красивый HTML поверх, через `popsci-research` (только часть написания; ресёрч уже сделан). Терминология: многих терминов на русском НЕТ (область слабо описана по-русски) — это норм, даём латиницу/оригинал, русский канон не выдумываем. Уточняет №9: deliverable арки = не одна карта, а **маттекст-скелет → HTML**; карта остаётся внутренним/обзорным слоем.
*Почему:* владелец — математик; для новой темы ему нужны точные формулировки и доказательства, а не пересказ.

### 12. Правило нарратива: связь двух объектов — с двух сторон, характеристику дать изобрести (2026-07-05)
Чтобы показать, что два объекта/статистики связаны, НЕ определять обе и приравнивать. Вспомнить статистику там, где она естественна (часто — Мир 1: площадь на путях Дика), и спросить, чему она соответствует на другой стороне; нужную характеристику дать читателю изобрести. Технический факт под это: `area = промах` — тождество на уровне ФОРМЫ (обе не зависят от меток: $D(f)=\binom{n+1}2-\sum f(i)$, определяется числом машин по столбцам), поэтому это чистый мост уровня формы.
*Почему:* приравнивание в лоб убивает мотивацию (замечание владельца по §6 статьи — `zhurnal/2026-07-03_programma-kursa/zamechaniya-statya-mir2.md`, Зам. 2). Кандидат в общий принцип подачи.

Мир 1 ведём ОТДЕЛЬНОЙ аркой (реш. №5 — миры независимы): пути Дика, число Каталана, много доказательств формулы/возвращения; материал частью в `spravochnik/_seed-kb.md`. **Вход новой арки = «Семена Мира 1»** (`zamechaniya-statya-mir2.md`, блок): цикл-лемма + обобщение «путь с лишним шагом вверх», перестановки Кнута/231-избегающие, биекции путь↔дерево и их эквивалентность, area как статистика М1, круг Поллака как источник биекций. *Почему:* Мир 2 картографирован и оформлен; большой новый ресёрч Мира 1 чище начинать с пустого контекста и хорошего захода.

### 14. Рамка Мира 1 и объединение курса в общий HTML (2026-07-05)
Сверка рамки сессии 2 (перед сборкой карты). (1) **Вход/порядок — комбинаторика-сначала:** Л1 стартует НЕ с теорвера, а с комбинаторной задачи о триангуляциях n-угольника → графы/деревья (базовые утверждения индукцией) → полные бинарные деревья, трюк «вырезания» (раздутие `_seed-kb` §3; древесную версию — оформить и проверить `proof-self-review`) → двучленная рекуррента Cₙ↔соседняя → формула через факториалы. Вероятностная ветка (баллотировка → несбаланс. пути → блуждание) — со Л2. Альтернатива «вход от общего пути через биномы» рассмотрена и **отклонена владельцем** (проще и честнее показать балансир-only красоты в чистом виде до несбаланса; задача-вход не обязана быть вероятностной). (2) **Ассоциэдр↔парковка + q-Каталан → капстоун в КОНЦЕ Мира 2** (объект — парковки), не в ядро Мира 1. (3) **Deliverable — ОДИН общий HTML на обе половины** (две части / вкладки), а не изолированная статья Мира 1; при удобстве писать сразу в общий документ. (4) **Метод сборки:** нити-память (`spravochnik/stati/`) → линейный сюжет → HTML; «остановимся, где остановимся».
*Почему:* process-first не требует, чтобы стартовая задача была вероятностной — комбинаторный вход проще для сильных школьников и не ломается на несбалансе. Курс задуман единым миром двух половин: общий HTML честнее отражает мосты и капстоун. Уточняет №11 (deliverable) и №13 (рамка Мира 1).

### 15. Общий HTML — вкладки (не единый поток); рендер слоёв и иллюстрации (2026-07-05)
Сборка обеих половин в один HTML-файл через **вкладки**, а не единый скролл (владелец по существу: вкладка удобнее для навигации и станет контейнером под будущий по-лекционный распил — каждая лекция получит «законченный вид» и своё оглавление, при этом можно найти место внутри лекции, оставаясь отдельно от других). **Сейчас 3 вкладки:** I·Мир путей Дика · II·Мир парковок и деревьев · III·Капстоун (ассоциэдр↔парковка + q-Каталан, перенесённый из хвоста `mir2-statya`). Каркас — под будущее дробление вкладки-части на лекционные без переделки. Реализация: один файл, общий `<head>` с дизайн-системой `kurs/mir2-statya.html`, таб-бар, каждая вкладка = свой `<article>` + своё sticky-оглавление; **межмировые мосты — явные ссылки с переключением вкладки + якорь** (не теряются, а кликаются). **Рендер слоёв — как в Мире 2** (основная проза + карточки Опр/Теорема/Док-во + поля `.mn` ТОЛЬКО под контекст-комментарии «это место сложнее/проще», не под математику): более глубокий материал остаётся inline (asides/малые карточки), НЕ прячется; вне-школьное — строкой-упоминанием. Обязательного механизма «со звёздочкой = свёрнуто» НЕТ; сворачиваемость блоков — опциональная читательская добавка для обзора, не требование. **Иллюстрации** — число не лимитируем: картинка на каждый объект, о котором речь («не словами, а картинками»); это не финальная версия. **Объём Мира 1 — паритет** с Миром 2; границы разделов мягкие (короткие подводки в начале лекций — норма, к числу не привязываемся; финальный баланс даст будущий распил). Баллотировка — слабая версия (путь ≥0), строгий Бертран замечанием; area↔inv (231/312) не фиксируем. Уточняет №14 (вкладки vs поток; рендер; иллюстрации). Заход Code — `zhurnal/2026-07-05_mir1/kod_html-obshchiy.md`, deliverable — `kurs/kurs-obshchiy.html`.
*Почему:* владелец предпочёл вкладки по существу (навигация + путь к по-лекционному самодостаточному виду), а не по вкусу; поля исторически несли контекст, не математику — конвенцию не ломаем; картинка-на-объект — авторский стандарт подачи.

### 16. Курс разложен на 9 вкладок-лекций; хранение поэтапное (2026-07-05)
