# COWORK.md — вход Cowork (аналитический чат ведёт файлы)

> Читать первым. Петля Cowork ↔ Claude Code — `RUKOVODSTVO-zahodami.md` (распечатана из скилла `agentic-coding-session-brief`); индекс файлов — `NAVIGATION.md`.

## Роли
- **Cowork** (этот чат): думает вместе с владельцем, ведёт файлы проекта (вайбкодинг), пишет заходы для Claude Code, консолидирует.
- **Claude Code**: тяжёлое / механическое / поисковое на ЧИСТОМ контексте, по заходу в папке арки (промпт → отчёт). Канал — `zhurnal/<арка>/`.
- **Владелец**: думает и решает.

## Дисциплина
Плотно, по-русски, без воды и похвал; возражать по существу, не складываться просто потому что владелец возразил. Минимально достаточный путь. Один содержательный шаг → показ → стоп. Двигаешь / удаляешь / сжимаешь → сперва snapshot + верификатор другим проходом. Сохранять по умолчанию, риск-неоднозначное — в отчёт. Финальные **содержательные** тексты (слайды, материалы курса) — гейт `math-russian-terminology` → `russian-editor`; инфраструктурные доки — без гейта.

**⚠️ Учебный материал = строгий мат-текст (не нарратив).** Лекция / статья / HTML курса — это математический текст для читателя-математика: каждое несущее утверждение **точно сформулировано** (Лемма/Теорема/Утверждение) и **доказано** (либо честная пометка уровня + ссылка, если вне рамок). Запрещено «здесь работает такой-то приём» без формулировки самого утверждения и вывода из него. Для вероятностных сюжетов — явный мост «модель → что считаем»: исход ↔ объект, вероятность объекта, `P(событие)=Σ` по объектам («посчитать объекты» ≠ «посчитать вероятность», если объекты разновесны). Порядок обязателен: рассказ (смысл) → **скелет (строгость: определения+формулировки+ПОЛНЫЕ доказательства, эталон `kurs/mir1-skelet.md`)** → вёрстка HTML. Скелет — гейт ПЕРЕД вёрсткой, не опция; HTML без скелета под ним = брак. (Поломка зафиксирована: лекция о ветвящихся собрана из рассказа минуя скелет, §5 постулировал без формулировок/доказательств — `zhurnal/2026-07-05_mir1/predlozhenie-vetvyashchiesya-lekciya.md`, память `catalan-lekcii-strogiy-tekst`.) **Термины — сперва `spravochnik/TERMINY-russkie.md`** (источник правды), веб-поиск только для термина, которого там нет, и результат сразу дописывается туда; проектные PDF (Айгнер–Циглер и т.п.) — читать напрямую, не гуглить. Терминология для внутреннего корпуса — не критична, отдельных проходов не тратить. **Чтение источников:** после любого прочтения источника (заход/субагент) — дайджест «что ЕСТЬ / чего точно НЕТ / стр. / уровень» в `biblioteka/istochniki/VYCHITANO.md` тем же ходом; источник без дайджеста = как будто не читан. **Поиск-волны:** запуск агентов на ПОИСК — одной строкой в `zhurnal/<арка>/SESSIYA.md` (что искали, где, ключевые запросы, вердикт), чтобы не гонять массовый поиск по кругу.

**Картотека находок — ОБЯЗАТЕЛЬНАЯ дисциплина (авто-хук).** После ЛЮБОГО ресёрча или нового содержательного вывода — находку промотировать в узел(ы) `spravochnik/` по `STANDART-uzla` (+ строка «простыми словами» — каталог владелец читает) и строкой в `KARTA-OBLASTI` **ТЕМ ЖЕ ходом**; это НЕ откладывается до консолидации в конце арки. Симметрично обязательна запись скачанной литературы: файл → аннотация в `biblioteka/istochniki/MANIFEST.md` + дайджест в `VYCHITANO.md`. **Находка без карточки / источник без записи = потеряны = провал дисциплины.** То, что это иногда пропускалось, — известная проблема проекта; впредь обязательно. Программную проверку (источник в MANIFEST без дайджеста; волна ресёрча без промо в узлы) повесить на `tools/check_docs.py` — в очередь Code.
