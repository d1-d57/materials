## Шаг 1. Полный обзор биективных доказательств формулы Каталана

### 1.0. Контекст

Формула Каталана: Cₙ = C(2n,n)/(n+1) = (2n)! / ((n+1)! · n!).

Эквивалентные формы:
- Cₙ = C(2n,n) − C(2n,n+1)
- (n+1)·Cₙ = C(2n,n)
- (2n+1)·Cₙ = C(2n+1,n)
- (4n+2)·Cₙ = (n+2)·Cₙ₊₁

Каждое биективное доказательство устанавливает одно из этих тождеств, предъявляя биекцию между двумя конечными множествами с известными мощностями.

### 1.1. Принцип отражения (André, 1887)

- **Тождество:** Cₙ = C(2n,n) − C(2n,n+1)
- **Модель:** Монотонные решёточные пути на сетке n×n (шаги →, ↑).
- **Суть:** «Плохие» пути (пересекающие диагональ y = x, т.е. касающиеся прямой y = x+1) биективно соответствуют всем монотонным путям из (0,0) в (n−1, n+1). Биекция: найти первую точку касания прямой y = x+1, отразить оставшуюся часть пути относительно этой прямой. Обратная биекция — та же операция (она инволюция).
- **Что даёт:** Cₙ = (все пути) − (плохие пути) = C(2n,n) − C(2n,n+1) = C(2n,n)/(n+1).
- **Лучшие источники:** Mészáros, Cornell lecture notes (pi.math.cornell.edu/~karola/dimex/catalan.pdf), Proposition 1.5; Wikipedia «Catalan number», Second proof; Berkeley Math Circle handout (Sahoo).
- **Визуализируемость:** Высокая. Два поля: слева — плохой путь на сетке, справа — путь в (n−1, n+1). Пользователь строит плохой путь, видит точку касания и отражение в реальном времени.

### 1.2. Циклическая лемма (Dvoretzky–Motzkin, 1947)

- **Тождество:** (2n+1)·Cₙ = C(2n+1, n), что эквивалентно Cₙ = C(2n,n)/(n+1).
- **Модель:** Последовательности из (n+1) символов X и n символов Y.
- **Суть:** Циклическая лемма — любая последовательность из m символов X и k символов Y, m > k, имеет ровно (m−k) доминирующих циклических сдвигов (доминирующий = на каждом префиксе число X строго больше числа Y). Для m = n+1, k = n получаем ровно 1 доминирующий сдвиг. Удалив первый X из доминирующего сдвига, получаем путь Дика. Обратно: взяв путь Дика, приписываем X в начало — это единственный доминирующий сдвиг. Каждый из C(2n+1, n) слов порождает ровно один путь Дика, каждый путь Дика получается из (2n+1) слов. Итого Cₙ = C(2n+1, n) / (2n+1).
- **Атрибуция:** Dvoretzky & Motzkin (1947), обзор Dershowitz & Zaks (1990, Europ. J. Combin.).
- **Лучшие источники:** Dershowitz & Zaks (1990); Wikipedia «Catalan number», Fourth proof; Renault «Four Proofs of the Ballot Theorem».
- **Визуализируемость:** Высокая. Кольцевое представление: последовательность замыкается в кольцо, кольцо вращается до единственного доминирующего положения → путь Дика.

### 1.3. Exceedance-биекция (= Chung–Feller)

- **Тождество:** C(2n,n) = (n+1)·Cₙ — множество всех C(2n,n) монотонных путей из (0,0) в (n,n) разбивается на (n+1) равных классов.
- **Модель:** Монотонные решёточные пути (шаги →, ↑) из (0,0) в (n,n), без ограничений. Exceedance = число вертикальных рёбер, лежащих строго выше диагонали. Принимает значения 0, 1, …, n.
- **Суть:** Предъявляется биекция, уменьшающая exceedance на 1. Алгоритм: найти первое вертикальное ребро выше диагонали, проследить путь до возвращения на диагональ (точка X), поменять местами части пути до и после X. Обратная биекция — находим последнее горизонтальное ребро, заканчивающееся на диагонали, аналогичная перестановка.
- **Связь с Chung–Feller:** Теорема Chung–Feller утверждает то же самое, но на языке «grand Dyck paths» (шаги ↗, ↘): число путей из (0,0) в (2n,0) с ровно k «flaws» (нисходящих шагов ниже оси y=0) не зависит от k и равно Cₙ. Это тот же результат, переформулированный через поворот системы координат на 45°. Стандартная биективная версия: Chen (2008, Discrete Math. 308), Hodges (1955) — биекция между путями с k flaws и k+1 flaws через cut-and-paste.
- **ВАЖНО:** Exceedance-биекция и Chung–Feller-биекция по сути — одно и то же доказательство в двух координатных системах. Для проекта достаточно реализовать одну из двух версий. Версия с exceedance (на сетке n×n) более наглядна.
- **Лучшие источники:** Wikipedia «Catalan number», Third proof; Berkeley Math Circle handout (Sahoo), подробный разбор с примером для n=3; ISI Kolkata notes (isical.ac.in, Catalan-numbers.pdf); Mütze et al. (2016, arXiv:1603.02525) для усиленной версии.
- **Визуализируемость:** Высокая. Можно показать полную таблицу 20 путей для n=3, разбитых на 4 класса по 5, и анимировать переход между классами.

### 1.4. Раздутие/сдутие триангуляций

- **Тождество:** (4n+2)·Cₙ = (n+2)·Cₙ₊₁
- **Модель:** Триангуляции выпуклых многоугольников.
- **Суть:** Левое множество: триангуляция (n+2)-угольника с фиксированным основанием + ориентированное ребро (любое из 2n+1 рёбер, с выбором направления → 2(2n+1) = 4n+2 вариантов). Правое множество: триангуляция (n+3)-угольника с фиксированным основанием + выделенная не-базисная сторона многоугольника (n+2 штук). Биекция →: ориентированное ребро «раздувается» в треугольник — вершина, на которую указывает ориентация, расщепляется на две, новая сторона выделяется. Биекция ←: треугольник при выделенной стороне «сдувается», две его оставшиеся стороны сливаются, из направления сдувания восстанавливается ориентация ребра.
- **Что даёт:** Рекурренция (4n+2)·Cₙ = (n+2)·Cₙ₊₁ с начальным условием C₀ = 1 однозначно определяет Cₙ = C(2n,n)/(n+1).
- **Лучшие источники:** Wikipedia «Catalan number», First proof (among the bijective ones); Euler Circle lecture notes (simonrs.com/eulercircle/combinatorics/sanjay-catalan.pdf); прототип уже реализован в проекте.
- **Визуализируемость:** Высокая. Два поля: слева — меньший многоугольник с ориентированным ребром, справа — больший многоугольник с выделенной стороной. Раздутие/сдутие — наглядная геометрическая операция.

### 1.5. Формула крюков для таблиц Юнга формы 2×n

- **Тождество:** Cₙ = (2n)! / ((n+1)! · n!) — из формулы крюков для формы (n,n).
- **Модель:** Стандартные таблицы Юнга формы 2×n (= прямоугольник 2 строки, n столбцов, заполненный числами 1, …, 2n, возрастающими по строкам и столбцам).
- **Суть:** Таблицы Юнга формы (n,n) находятся в прямой биекции с путями Дика длины 2n: число i в первой строке → шаг ↗ на позиции i, число j во второй строке → шаг ↘ на позиции j. Формула крюков даёт (2n)! / ∏h = C(2n,n)/(n+1). Однако сама формула крюков — это не элементарная биекция; её биективные доказательства (Franzblau–Zeilberger 1982, Pak–Stoyanovskii 1992, Novelli–Pak–Stoyanovskii 1997) сложны.
- **Статус для проекта:** Это скорее дополнительная модель (таблицы Юнга 2×n как ещё один тип каталановского объекта), а не отдельное биективное доказательство формулы. Формула крюков — не элементарная биекция, для визуализации не годится. Однако биекция «таблица Юнга ↔ путь Дика» элементарна и может быть включена в Блок 2 (биекции между моделями).
- **НЕ рекомендуется для Блока 3 (доказательства формулы).**

### 1.6. Итог: классификация и рекомендации

Найдено **4 существенно различных биективных доказательства** формулы Каталана, пригодных для визуализации:

| # | Доказательство | Тождество | Модель | Тип биекции |
|---|----------------|-----------|--------|-------------|
| 1 | Принцип отражения | Cₙ = C(2n,n) − C(2n,n+1) | Решёточные пути | Биекция дополнения: плохие пути ↔ пути в другую точку |
| 2 | Циклическая лемма | (2n+1)·Cₙ = C(2n+1,n) | Циклические последовательности X,Y | (2n+1)-to-1: каждая последовательность → 1 путь Дика |
| 3 | Exceedance (≈ Chung–Feller) | C(2n,n) = (n+1)·Cₙ | Монотонные пути | Разбиение на (n+1) равных классов |
| 4 | Раздутие триангуляций | (4n+2)Cₙ = (n+2)Cₙ₊₁ | Триангуляции | Рекурренция через раздутие/сдутие |

**Что НЕ найдено:**
- Самостоятельного биективного доказательства формулы на языке деревьев (не через перевод в пути). Все известные proof ideas работают на путях или на триангуляциях.
- Биективного доказательства через non-crossing partitions, дающего формулу напрямую (non-crossing partitions — каталановские объекты, но замкнутая формула для них обычно выводится через биекцию с путями Дика + одно из доказательств выше).
- Принципиально нового 5-го доказательства, не сводимого к перечисленным.

**Замечание о Chung–Feller:** Chung–Feller — не отдельное от exceedance доказательство, а его переформулировка через поворот на 45°. Для проекта это одно доказательство (реализовывать в версии exceedance на сетке n×n, т.к. она нагляднее).

## Шаг 2. Детальный разбор: Принцип отражения (André, 1887)

### 2.1. Тождество

Cₙ = C(2n, n) − C(2n, n+1)

Левая часть: число монотонных решёточных путей из (0,0) в (n,n), не заходящих строго выше диагонали y = x. Это «хорошие» пути (= пути Дика в кодировке X = →, Y = ↑).

Правая часть: (все пути) − (плохие пути). Принцип отражения показывает, что число плохих путей = C(2n, n+1) = C(2n, n−1), через биекцию с путями из (0,0) в (n−1, n+1).

### 2.2. Определения

**Монотонный путь** на сетке n×n: последовательность из n шагов R = (1,0) и n шагов U = (0,1), ведущая из (0,0) в (n,n). Всего таких путей C(2n, n).

**Хороший путь (путь Дика):** монотонный путь, в котором на каждом префиксе число U-шагов ≤ числа R-шагов. Эквивалентно: путь не заходит строго выше прямой y = x.

**Плохой путь:** монотонный путь, в котором существует префикс с #U > #R. Эквивалентно: путь касается или пересекает прямую y = x + 1.

**Целевое множество (для биекции):** все монотонные пути из (0,0) в (n−1, n+1), т.е. последовательности из (n−1) шагов R и (n+1) шагов U. Мощность = C(2n, n−1) = C(2n, n+1).

### 2.3. Алгоритм биекции →  (плохой путь → путь в (n−1, n+1))

**Вход:** плохой путь P = s₁s₂…s₂ₙ из (0,0) в (n,n) (sᵢ ∈ {R, U}).

**Шаги:**
1. Пройти по пути слева направо, отслеживая текущие координаты (x, y).
2. Найти индекс k — позицию первого шага, после которого y > x (т.е. путь впервые оказался строго выше диагонали). Этот шаг обязательно является U-шагом, и после него точка (x, x+1) лежит на прямой y = x + 1.
3. Разрезать путь: prefix = s₁…sₖ, suffix = sₖ₊₁…s₂ₙ.
4. Отразить suffix: заменить каждый R на U и каждый U на R.
5. Результат: P' = prefix + reflected_suffix.

**Выход:** путь P' из (0,0) в (n−1, n+1).

**Корректность:** prefix ведёт из (0,0) в точку (a, a+1) для некоторого a. suffix ведёт из (a, a+1) в (n, n), содержит (n−a) шагов R и (n−a−1) шагов U. После отражения: (n−a−1) шагов R и (n−a) шагов U, ведёт из (a, a+1) в (a + n−a−1, a+1 + n−a) = (n−1, n+1). ✓

### 2.4. Алгоритм обратной биекции ← (путь в (n−1, n+1) → плохой путь)

**Вход:** монотонный путь Q = s₁s₂…s₂ₙ из (0,0) в (n−1, n+1).

**Шаги:**
1. Пройти по пути слева направо, отслеживая (x, y).
2. Найти индекс k — позицию первого шага, после которого y = x + 1 (путь впервые коснулся прямой y = x + 1). Такой шаг обязательно существует: путь стартует при y ≤ x (в (0,0): y = x = 0), а заканчивается при y > x + 1 (в (n−1, n+1): n+1 > n), поэтому должен пройти через y = x + 1.
3. Разрезать: prefix = s₁…sₖ, suffix = sₖ₊₁…s₂ₙ.
4. Отразить suffix: R ↔ U.
5. Результат: Q' = prefix + reflected_suffix.

**Выход:** плохой путь Q' из (0,0) в (n,n).

**Обе операции — одна и та же процедура:** найти первое касание y = x + 1, отразить хвост. Операция является инволюцией на множестве путей длины 2n с подходящими конечными точками (но меняет конечную точку!). Прямая и обратная биекции имеют идентичную структуру кода.

### 2.5. Алгоритм (псевдокод для JavaScript)

```
function reflectBadPath(path, n) {
  // path: массив символов 'R','U' длины 2n
  // Возвращает: массив символов длины 2n (путь в (n-1, n+1))
  
  let x = 0, y = 0;
  let k = -1;
  for (let i = 0; i < path.length; i++) {
    if (path[i] === 'R') x++; else y++;
    if (y > x) { k = i; break; }    // первое нарушение: y = x + 1
  }
  
  let result = path.slice(0, k + 1);                  // prefix: до k включительно
  for (let i = k + 1; i < path.length; i++) {
    result.push(path[i] === 'R' ? 'U' : 'R');         // отражение хвоста
  }
  return result;
}

function reflectInverse(path, n) {
  // path: массив 'R','U' длины 2n, путь в (n-1, n+1)
  // Возвращает: плохой путь в (n, n)
  
  let x = 0, y = 0;
  let k = -1;
  for (let i = 0; i < path.length; i++) {
    if (path[i] === 'R') x++; else y++;
    if (y === x + 1) { k = i; break; }   // первое касание y = x + 1
  }
  
  let result = path.slice(0, k + 1);
  for (let i = k + 1; i < path.length; i++) {
    result.push(path[i] === 'R' ? 'U' : 'R');
  }
  return result;
}
```

### 2.7. Визуализация для интерфейса

**Левое поле:** сетка n×n. Пользователь строит монотонный путь (кликами или drag). Диагональ y = x отображена пунктиром. Если путь — хороший, отображается сообщение «путь Дика». Если плохой — подсвечивается первый шаг, нарушающий условие, и прямая y = x + 1.

**Правое поле:** сетка (n−1) × (n+1). Отображается образ — путь в (n−1, n+1).

**Анимация биекции →:** 
1. Подсветить точку первого касания y = x + 1.
2. Разделить путь на prefix (зелёный) и suffix (красный).
3. Анимировать отражение suffix относительно прямой y = x + 1 (визуально: suffix «переворачивается» через прямую).
4. Результат появляется на правом поле.

**Обратная стрелка ←:** пользователь строит произвольный путь на правом поле (из (0,0) в (n−1, n+1)), тот же алгоритм восстанавливает плохой путь на левом поле.

**Дополнительная визуализация:** счётчик внизу: «C(2n,n) = {all} = {good} + {bad} = Cₙ + C(2n,n+1)».

### 2.8. Тонкие места для реализации

1. **Нумерация шагов vs вершин.** Алгоритм работает с шагами (рёбрами), а не с вершинами. После k-го шага (0-indexed) мы находимся в вершине (x, y). Нарушение фиксируется после шага, а не в вершине.

2. **Прямая и обратная биекции — почти идентичный код.** Единственное различие: в прямой биекции ищем первое y > x (строгое неравенство); в обратной ищем первое y = x + 1 (равенство). При реализации на целых координатах это одно и то же условие (y > x ⟺ y ≥ x + 1 для целых).

3. **Граничный случай n = 0.** C₀ = 1, пустой путь. Плохих путей нет. Множество путей в (−1, 1) пусто. Работает корректно.

4. **Отражение — не геометрическое отражение всего пути.** Отражается только хвост (часть после первого касания). В графическом интерфейсе важно визуально показать, что prefix сохраняется.

## Шаг 3. Детальный разбор: Раздутие/сдутие триангуляций

### 3.1. Тождество

(4n+2)·Cₙ = (n+2)·Cₙ₊₁

С начальным условием C₀ = 1 это однозначно даёт Cₙ = C(2n,n)/(n+1).

### 3.2. Определения

**Соглашение:** выпуклый многоугольник с m вершинами, пронумерованными 0, 1, …, m−1 по часовой стрелке. Основание (base) = ребро {0, m−1}.

**Триангуляция:** разбиение многоугольника на треугольники непересекающимися диагоналями. У (n+2)-угольника: n треугольников, n+2 стороны + n−1 диагоналей = 2n+1 рёбер.

**Ориентированное ребро:** упорядоченная пара (a → b), где {a, b} — ребро триангуляции (сторона или диагональ). Всего 2·(2n+1) = 4n+2 ориентированных рёбер.

**Левое множество L:** пара (T, (a → b)), где T — триангуляция (n+2)-угольника, (a → b) — ориентированное ребро T. Мощность: (4n+2)·Cₙ.

**Правое множество R:** пара (T', s), где T' — триангуляция (n+3)-угольника, s = {i, i+1} — не-базисная сторона многоугольника (i.e., s ≠ base). Таких сторон n+2. Мощность: (n+2)·Cₙ₊₁.

### 3.3. Алгоритм сдутия (deflation): R → L

**Вход:** триангуляция T' (n+3)-угольника (вершины 0, …, n+2, base = {0, n+2}), не-базисная сторона s = {i, i+1}.

**Шаги:**
1. Найти единственный треугольник Δ в T', содержащий сторону s. Пусть третья вершина — r. Итого Δ = {i, i+1, r}.
2. Удалить ребро s = {i, i+1}. Слить вершины i и i+1 в одну: все рёбра, инцидентные вершине i+1, перенести на вершину i.
3. Перенумеровать: каждая вершина j > i+1 становится j−1. Многоугольник уменьшается на одну вершину → (n+2)-угольник.
4. Результирующее ориентированное ребро: **(i → r')**, где r' = r при r ≤ i, и r' = r−1 при r > i+1. (Вершина i — объединённая вершина, r' — перенумерованная третья вершина.)

**Выход:** триангуляция T (n+2)-угольника + ориентированное ребро (i → r').

**Правило ориентации (ключевое):** ребро всегда ориентировано **от объединённой вершины к третьей вершине схлопнутого треугольника**. Это однозначно определяет ориентацию и гарантирует биективность.

### 3.4. Алгоритм раздутия (inflation): L → R

**Вход:** триангуляция T (n+2)-угольника (вершины 0, …, n+1, base = {0, n+1}), ориентированное ребро (a → b).

**Шаги:**
1. Вершина a — та, которую будем расщеплять. Пусть pred(a) = (a−1) mod (n+2) — предшественник a на границе многоугольника по часовой стрелке.
2. Вставить новую вершину a' между pred(a) и a на границе. Перенумерация: вершины ≥ a сдвигаются на +1. Новая вершина a' получает номер a, старая a становится a+1.
3. Определить смежные вершины a в T, упорядоченные по часовой стрелке от pred(a). Пусть это pred(a) = v₀, v₁, v₂, …, vₖ = succ(a), где succ(a) = (a+1) mod (n+2). Вершина b находится на позиции j в этом списке.
4. **Перераспределение рёбер:** рёбра от a к вершинам v₀, v₁, …, v_{j−1} (те, что по часовой стрелке до b) передаются вершине a'. Рёбра от a к вершинам v_{j+1}, …, vₖ (те, что после b) остаются у a.
5. Ребро {a, b} расщепляется: появляются {a', b_new} и {a_new, b_new} (где b_new, a_new — перенумерованные вершины).
6. Новое ребро многоугольника: {a', a_new} (= {a, a+1} в новой нумерации). Это и есть **выделенная сторона**.

**Выход:** триангуляция T' (n+3)-угольника + выделенная не-базисная сторона {a, a+1}.

### 3.5. Псевдокод (deflation)

```
function deflate(edges, m, side_i) {
  // edges: набор рёбер триангуляции m-угольника (пары [u,v], u < v)
  // side_i: индекс i, задающий сторону {i, i+1} (non-base)
  // Возвращает: { newEdges, orientedEdge: [merged, rNew] }
  
  let i = side_i, j = i + 1;
  
  // 1. Найти третью вершину треугольника при стороне {i, j}
  let adj_i = new Set(edges.filter(e => e.includes(i)).map(e => e[0]===i ? e[1] : e[0]));
  let adj_j = new Set(edges.filter(e => e.includes(j)).map(e => e[0]===j ? e[1] : e[0]));
  let r = [...adj_i].find(v => adj_j.has(v) && v !== i && v !== j);
  
  // 2. Удалить сторону {i,j}, слить j в i
  let newEdges = [];
  for (let [u, v] of edges) {
    if ((u===i && v===j) || (u===j && v===i)) continue;  // удалить
    let nu = (u === j) ? i : u;
    let nv = (v === j) ? i : v;
    if (nu === nv) continue;
    // 3. Перенумеровать: вершины > j сдвигаются на -1
    nu = nu > j ? nu - 1 : nu;
    nv = nv > j ? nv - 1 : nv;
    newEdges.push([Math.min(nu,nv), Math.max(nu,nv)]);
  }
  // убрать дубликаты
  newEdges = [...new Set(newEdges.map(e => e.join(',')))].map(s => s.split(',').map(Number));
  
  // 4. Ориентированное ребро
  let rNew = r > j ? r - 1 : r;
  return { newEdges, orientedEdge: [i, rNew] };  // от merged к третьей вершине
}
```

### 3.7. Визуализация

**Левое поле:** (n+2)-угольник с триангуляцией. Пользователь выбирает ребро и его ориентацию (кликом по ребру, стрелка показывает направление).

**Правое поле:** (n+3)-угольник с триангуляцией. Выделенная сторона подсвечена.

**Анимация раздутия (→):** вершина a «расщепляется» на две, между ними вырастает новая сторона и треугольник. Геометрически наглядная операция.

**Анимация сдутия (←):** треугольник при выделенной стороне «схлопывается», две вершины сливаются в одну, появляется стрелка ориентации.

### 3.8. Тонкие места для реализации

1. **Определение ориентации — единственное нетривиальное место.** Правило: при сдутии ориентация всегда от объединённой вершины к третьей вершине. При раздутии ориентация определяет, какие рёбра переходят к новой вершине.

2. **Перенумерация вершин.** При сдутии вершина i+1 удаляется, все вершины с бо́льшими номерами сдвигаются на −1. При раздутии вершина вставляется на позицию a, все вершины ≥ a сдвигаются на +1. Это источник off-by-one ошибок в реализации.

3. **Базисное ребро.** Основание {0, m−1} никогда не бывает выделенной стороной. При сдутии основание может содержать одну из вершин схлопнутого ребра — это корректно (основание сохраняется, просто одна из его вершин перенумеруется).

4. **Случай, когда ориентированное ребро — само основание.** Это легальный элемент левого множества. Раздутие работает корректно: основание расщепляется, новый треугольник примыкает к старому основанию.

5. **Упорядочение смежных вершин по часовой стрелке** — критично для правильного перераспределения рёбер при раздутии. В выпуклом многоугольнике смежные вершины v вершины a можно упорядочить по циклическому расстоянию (a − v) mod m.

## Шаг 4. Детальный разбор: Циклическая лемма (Dvoretzky–Motzkin, 1947)

### 4.1. Тождество

(2n+1)·Cₙ = C(2n+1, n)

Эквивалентно: Cₙ = C(2n+1, n) / (2n+1) = C(2n, n) / (n+1).

### 4.2. Циклическая лемма (формулировка)

**Лемма.** Пусть дана последовательность из m символов X и k символов Y, где m > k. Тогда среди (m+k) циклических сдвигов этой последовательности ровно (m−k) являются *доминирующими*.

**Доминирующая последовательность:** последовательность, в которой каждый (непустой) префикс содержит строго больше X, чем Y.

**Частный случай для Каталана:** m = n+1, k = n. Тогда m − k = 1: ровно один доминирующий сдвиг.

### 4.3. Доказательство леммы (XY-уничтожение)

Расположить m+k символов по кругу. Повторно удалять соседние пары XY (X непосредственно перед Y по часовой стрелке). Порядок удаления не важен — результат единственен. После удаления всех пар останется ровно m−k символов X, стоящих подряд на окружности. Каждый из них — начало доминирующего сдвига.

**Почему это работает:** каждое XY-уничтожение сохраняет множество доминирующих стартовых позиций. Каждый оставшийся X является началом такого сдвига. (Полное доказательство: Dershowitz & Zaks, 1990.)

### 4.4. Применение к формуле Каталана

**Множества:**
- Левое: все C(2n+1, n) последовательностей из (n+1) символов X и n символов Y. Длина 2n+1.
- Правое: Cₙ путей Дика длины 2n (= слов Дика из n X и n Y с условием неотрицательности всех префиксных сумм).

**Отображение (2n+1)-to-1:** каждая последовательность S из левого множества однозначно определяет путь Дика:
1. Найти единственный доминирующий циклический сдвиг S.
2. Удалить первый символ (он обязательно X).
3. Оставшиеся 2n символов — путь Дика.

**Обратное:** каждый путь Дика D получается из ровно (2n+1) различных последовательностей (всех циклических сдвигов слова XD).

### 4.5. Алгоритм → (последовательность → путь Дика)

**Вход:** последовательность S = s₁s₂…s_{2n+1} из (n+1) X и n Y.

**Метод 1 (brute force, O(n²)):**
Для каждого k = 0, 1, …, 2n: проверить, является ли сдвиг S[k:]+S[:k] доминирующим. Единственный подходящий k — ответ.

**Метод 2 (XY-уничтожение, O(n)):**
1. Записать S на окружности (массив длины 2n+1).
2. Повторно удалять соседние пары (X,Y) (учитывая wrap-around: последний и первый элемент тоже соседи).
3. Останется один X. Его позиция в исходной последовательности — сдвиг k.

**Метод 3 (минимум префиксных сумм, O(n)):**
1. Вычислить кумулятивные суммы: σᵢ = (число X среди s₁…sᵢ) − (число Y среди s₁…sᵢ). Считаем X = +1, Y = −1.
2. Найти позицию последнего минимума σ (если несколько минимумов с одинаковым значением — взять последний).
3. Доминирующий сдвиг начинается в позиции k = (позиция последнего минимума) + 1 (mod 2n+1).

**Выход:** путь Дика D = доминирующий сдвиг без первого символа.

### 4.6. Алгоритм ← (путь Дика → все порождающие последовательности)

**Вход:** путь Дика D длины 2n.

**Шаги:**
1. Построить полную последовательность: W = X + D (приписать X в начало). Длина W = 2n+1.
2. W — единственный доминирующий сдвиг.
3. Все (2n+1) циклических сдвигов W — это ровно все последовательности, порождающие данный путь Дика.
4. Каждый сдвиг W[k:]+W[:k] для k = 0, …, 2n — легальная последовательность из (n+1) X и n Y.

В интерфейсе: пользователь строит путь Дика → показывается кольцо XD → кольцо можно вращать в любую позицию.

### 4.7. Псевдокод

```
function seqToDyck(seq) {
  // seq: массив символов 'X','Y' длины 2n+1, содержит (n+1) X и n Y
  // Возвращает: { dyck: массив длины 2n, shiftIndex: число }
  
  // Метод 3: минимум префиксных сумм
  let n2p1 = seq.length;
  let sum = 0;
  let minSum = Infinity, minPos = -1;
  for (let i = 0; i < n2p1; i++) {
    sum += (seq[i] === 'X') ? 1 : -1;
    if (sum <= minSum) {         // <= гарантирует ПОСЛЕДНИЙ минимум
      minSum = sum;
      minPos = i;
    }
  }
  
  let k = (minPos + 1) % n2p1;   // начало доминирующего сдвига
  let dom = seq.slice(k).concat(seq.slice(0, k));
  let dyck = dom.slice(1);       // убрать первый X
  
  return { dyck, shiftIndex: k };
}

function dyckToSeq(dyck, shiftIndex) {
  // Обратная операция
  let dom = ['X'].concat(dyck);
  let n2p1 = dom.length;
  let unshift = (n2p1 - shiftIndex) % n2p1;
  return dom.slice(unshift).concat(dom.slice(0, unshift));
}
```

### 4.9. Визуализация

**Основной вид:** кольцо из (2n+1) ячеек, каждая содержит X или Y. Кольцо можно вращать (drag или кнопками). Под кольцом — линейная развёртка текущего сдвига с «горным» профилем (partial sums).

**→ (произвольная последовательность → путь Дика):**
1. Пользователь заполняет кольцо (n+1) символами X и n символами Y.
2. Система анимирует XY-уничтожение: пары XY мигают и исчезают, пока не останется один X.
3. Кольцо поворачивается так, чтобы уцелевший X оказался вверху.
4. «Разворачиваем» кольцо в линейную последовательность, начиная с уцелевшего X.
5. Первый X удаляется → путь Дика отображается на правом поле как горный профиль.

**← (путь Дика → последовательность):**
1. Пользователь строит путь Дика на правом поле.
2. X приписывается в начало → замыкается в кольцо.
3. Пользователь вращает кольцо в любую позицию → на левом поле отображается соответствующая последовательность.

### 4.10. Тонкие места для реализации

1. **Метод минимума префиксных сумм — самый простой для реализации.** O(n), один проход, не требует сложных структур данных. Важно: при нескольких минимумах брать **последний**.

2. **XY-уничтожение для анимации.** Для визуализации XY-уничтожение нагляднее (пользователь видит, как пары исчезают). Для вычислений — метод минимума быстрее и проще.

3. **Wrap-around в XY-уничтожении.** При удалении пар нужно учитывать соседство последнего и первого элемента на кольце. Реализация требует аккуратности (использовать связный список или повторять проход, пока есть удаления).

4. **Обратная операция тривиальна** по конструкции: это просто циклический сдвиг фиксированной строки.

5. **Связь с леммой о голосовании (ballot problem).** Если m > k·p для целого p, то число доминирующих сдвигов = m − k·p. Случай p = 1, m = n+1, k = n — это ровно формула Каталана.

## Шаг 5. Детальный разбор: Exceedance-биекция

### 5.1. Тождество

C(2n, n) = (n+1)·Cₙ

Множество всех C(2n, n) монотонных путей из (0,0) в (n,n) разбивается на (n+1) равных классов размера Cₙ.

### 5.2. Определения

**Монотонный путь:** последовательность из n шагов R = (1,0) и n шагов U = (0,1), из (0,0) в (n,n). Всего C(2n,n) путей.

**Exceedance (превышение):** число U-шагов, лежащих строго выше диагонали y = x. Формально: U-шаг из (x,y) в (x,y+1) считается «выше диагонали», если y ≥ x. Exceedance принимает значения 0, 1, …, n.

**Класс exc = 0:** пути, не заходящие выше диагонали = пути Дика. Их ровно Cₙ.

### 5.3. Алгоритм уменьшения exceedance на 1: exc(k) → exc(k−1)

**Вход:** путь P с exceedance = k > 0.

**Шаги:**
1. Пройти по пути от (0,0), отслеживая (x, y).
2. Найти позицию первого U-шага выше диагонали: первый индекс i такой, что P[i] = 'U' и y ≥ x (в точке (x,y) перед этим шагом).
3. Продолжить по пути до первого возвращения на диагональ: найти первый индекс j > i такой, что после выполнения шага P[j] мы находимся в точке (t, t) на диагонали.
4. **Разрезать и переставить:** новый путь = P[j+1:] + P[j] + P[0:j].

Иными словами: путь P = [Before][X][After], где X = P[j] (ребро возврата на диагональ), Before = P[0:j], After = P[j+1:]. Новый путь = After + X + Before.

**Выход:** путь P' с exceedance = k − 1.

### 5.4. Алгоритм увеличения exceedance на 1 (обратная биекция): exc(k) → exc(k+1)

**Вход:** путь P с exceedance = k < n.

**Шаги:**
1. Пройти по пути от (0,0), отслеживая (x, y).
2. Найти позицию **последнего** R-шага, начинающегося на диагонали: последний индекс i такой, что P[i] = 'R' и y = x (в точке (x,y) перед этим шагом).
3. **Разрезать и переставить:** новый путь = P[i+1:] + P[i] + P[0:i].

**Выход:** путь P' с exceedance = k + 1.

### 5.5. Почему это работает (идея)

При перестановке ровно одно вертикальное ребро меняет статус: то, которое раньше начиналось на диагонали (и было «не выше»), после перестановки оказывается выше диагонали (или наоборот для обратной операции). Все остальные вертикальные рёбра сохраняют свой статус относительно диагонали. Поэтому exceedance меняется ровно на ±1.

Обратимость: «последний R на диагонали» в P' — это ровно тот R-шаг, который был «первым возвратом на диагональ» при прямой операции. Перестановка — инволюция (с точностью до выбора точки разреза).

### 5.6. Псевдокод

```
function decreaseExceedance(path, n) {
  // path: массив 'R','U' длины 2n
  // Возвращает: массив длины 2n с exceedance на 1 меньше
  
  let x = 0, y = 0;
  
  // 1. Найти первый U-шаг выше диагонали
  let firstAbove = -1;
  for (let i = 0; i < path.length; i++) {
    if (path[i] === 'U' && y >= x) { firstAbove = i; break; }
    if (path[i] === 'R') x++; else y++;
  }
  if (firstAbove < 0) return null;  // exceedance = 0
  
  // 2. Продолжить до возврата на диагональ
  // Пересчитать (x,y) до позиции firstAbove, затем идти дальше
  x = 0; y = 0;
  for (let i = 0; i < firstAbove; i++) {
    if (path[i] === 'R') x++; else y++;
  }
  // Выполнить шаг firstAbove
  if (path[firstAbove] === 'R') x++; else y++;
  
  let splitPos = -1;
  for (let i = firstAbove + 1; i < path.length; i++) {
    if (path[i] === 'R') x++; else y++;
    if (y === x) { splitPos = i; break; }
  }
  
  // 3. Переставить
  return path.slice(splitPos + 1)
    .concat(path[splitPos])
    .concat(path.slice(0, splitPos));
}

function increaseExceedance(path, n) {
  // Обратная операция
  let x = 0, y = 0;
  let lastRonDiag = -1;
  
  for (let i = 0; i < path.length; i++) {
    if (path[i] === 'R' && y === x) lastRonDiag = i;
    if (path[i] === 'R') x++; else y++;
  }
  if (lastRonDiag < 0) return null;  // exceedance = n
  
  let i = lastRonDiag;
  return path.slice(i + 1)
    .concat(path[i])
    .concat(path.slice(0, i));
}
```

### 5.8. Визуализация

**Основной вид:** сетка n×n с диагональю. Все C(2n,n) путей отображаются в таблице, сгруппированной по exceedance (как выше).

**Интерактив 1:** Пользователь строит произвольный монотонный путь на сетке. Система вычисляет exceedance, подсвечивает вертикальные рёбра выше диагонали. Кнопка «−1» применяет алгоритм уменьшения с анимацией (подсветка точки разреза, перестановка частей). Кнопка «+1» — обратная операция.

**Интерактив 2:** Кнопка «→ Dyck» — многократное применение уменьшения до exc = 0 (с анимацией каждого шага).

**Ключевая визуальная идея:** exceedance-биекция — это «перестановка двух кусков пути в точке касания диагонали». Визуально: путь разрезается ножницами на диагонали, две части меняются местами.

### 5.9. Тонкие места для реализации

1. **Условие «выше диагонали» для U-шага:** проверяем y ≥ x **перед** выполнением шага. Ребро из (x,y) в (x,y+1) выше диагонали, если y ≥ x.

2. **Условие «R на диагонали» для обратной:** проверяем y = x **перед** выполнением шага. Ребро из (x,y) = (t,t) в (t+1,t).

3. **Точка разреза — это ребро, а не вершина.** Разрез происходит «при ребре» (at edge), перестановка включает само ребро в середину нового пути.

4. **Формат перестановки:** path = Before + [edge] + After → After + [edge] + Before. Это НЕ циклический сдвиг (edge остаётся на стыке).

5. **Связь с Chung–Feller.** В координатах Дика (шаги ↗ и ↘ вместо R и U) exceedance соответствует числу «flaws» (нисходящих шагов ниже оси). Биекция та же, но описывается в терминах первого нисходящего шага ниже оси и первого возвращения на ось. Для проекта рекомендуется использовать версию с R,U на сетке n×n (нагляднее).

## Шаг 6. Другие биективные доказательства — проверка полноты

### 6.1. Что проверялось

Целенаправленный поиск дополнительных биективных доказательств формулы Cₙ = C(2n,n)/(n+1) по следующим направлениям:

1. Доказательства на языке деревьев (бинарных, планарных, корневых).
2. Доказательства через non-crossing partitions.
3. Доказательства через таблицы Юнга формы 2×n.
4. Содержание книги Stanley «Catalan Numbers» (2015), раздел 1.6 «A Combinatorial Proof».
5. Обзор Simion «Noncrossing partitions» (Discrete Math., 2000).

### 6.2. Результаты

**Деревья.** Все известные доказательства формулы на деревьях работают через перевод в пути (Дика или решёточные). Прямого биективного доказательства формулы Cₙ = C(2n,n)/(n+1), оперирующего только деревьями без перехода к путям, в литературе не обнаружено. Деревья — каталановские объекты, для них существуют биекции с путями Дика (Шаг 8), но не самостоятельное доказательство формулы.

**Non-crossing partitions.** Являются каталановскими объектами (Kreweras, 1972). Подсчёт NC(n) = Cₙ проводится через биекцию с другими каталановскими объектами (обычно пути Дика или деревья) + одно из 4 доказательств формулы. Самостоятельного биективного пути от non-crossing partitions к формуле не существует.

**Таблицы Юнга 2×n.** Формула крюков даёт f^{(n,n)} = (2n)!/((n+1)!·n!) = Cₙ — это алгебраическое тождество. Биективные доказательства формулы крюков существуют (Franzblau–Zeilberger, 1982; Novelli–Pak–Stoyanovskii, 1997), но они сложны и не дают наглядной визуализации для проекта. Биекция «таблица Юнга 2×n ↔ путь Дика» элементарна (число i в первой строке → шаг ↗ на позиции i), но это биекция между моделями (Блок 2), а не доказательство формулы.

**Stanley (2015), раздел 1.6.** Содержит доказательство формулы через принцип отражения (в терминах Dyck words). Разделы 2–3 книги содержат 214 биективных упражнений, но все они — биекции между каталановскими объектами, а не доказательства замкнутой формулы.

**Chung–Feller.** Подтверждено (Шаг 1): эквивалентно exceedance-биекции через поворот координат на 45°.

### 6.3. Итог

**Новых биективных доказательств формулы не найдено.** Список из 4 доказательств (Шаг 1) является полным в следующем смысле: все известные элементарные биективные доказательства формулы Cₙ = C(2n,n)/(n+1) сводятся к одному из четырёх типов:

| # | Тип | Тождество | Механизм |
|---|-----|-----------|----------|
| 1 | Принцип отражения | Cₙ = C(2n,n) − C(2n,n+1) | Биекция дополнения |
| 2 | Циклическая лемма | (2n+1)·Cₙ = C(2n+1,n) | (2n+1)-to-1 через цикл. сдвиги |
| 3 | Exceedance / Chung–Feller | C(2n,n) = (n+1)·Cₙ | Разбиение на n+1 класс |
| 4 | Раздутие триангуляций | (4n+2)·Cₙ = (n+2)·Cₙ₊₁ | Рекурренция через inflation/deflation |

Доказательства 2 и 3 тесно связаны: оба разбивают бо́льшее множество на равные классы, но используют разные множества и разные механизмы (циклический сдвиг vs перестановка частей пути).

### 6.4. Рекомендации для проекта

Для Блока 3 (доказательства формулы) реализовать все 4 доказательства. Этого достаточно для полного покрытия: любое другое известное биективное доказательство — вариация одного из этих четырёх.

Дополнительные модели (non-crossing partitions, таблицы Юнга, stack-sortable перестановки) следует включить в Блок 2 (биекции между моделями через хаб), но не в Блок 3.

## Шаг 7. Модели и рекуррентные разложения

### 7.0. Общая рекурренция

Все модели удовлетворяют рекурренции Сегнера:

C₀ = 1, Cₙ = Σ_{k=0}^{n-1} Cₖ · C_{n-1-k}  (для n ≥ 1)

Рекурренция следует из каноническогo разложения объекта размера n на два объекта размеров k и n−1−k. Во всех моделях разложение определяется выбором «первого элемента» (first return, корень, ухо при основании).

### 7.1. Модель 1: Пути Дика (= скобочные последовательности)

**Определение.** Путь Дика длины 2n — последовательность из n символов '(' и n символов ')', в которой каждый префикс содержит не меньше '(' чем ')'. Эквивалентно: монотонный путь из (0,0) в (n,n) шагами R=(1,0), U=(0,1), не заходящий выше диагонали y = x. Кодировка: '(' ↔ R, ')' ↔ U.

**Рекуррентное разложение (first return):**

Непустой путь Дика w единственным образом записывается как w = **(** w₁ **)** w₂, где w₁ и w₂ — пути Дика (возможно пустые). Первая '(' и соответствующая ей ')' — это первый возврат на диагональ.

- |w₁| = 2k, |w₂| = 2(n−1−k), k ∈ {0, …, n−1}.
- Разложение: найти первый индекс i, где глубина вложенности возвращается к 0. Тогда w₁ = w[1:i], w₂ = w[i+1:].
- Обратная сборка: w = '(' + w₁ + ')' + w₂.

**Верификация (n=3):**
| Путь Дика | w₁ | w₂ | k |
|-----------|-----|-----|---|
| ((())) | (()) | ε | 2 |
| (()()) | ()() | ε | 2 |
| (())() | () | () | 1 |
| ()(()) | ε | (()) | 0 |
| ()()() | ε | ()() | 0 |

**Интерфейс:** пользователь строит путь кликами на сетке (или вводом скобок). First return подсвечивается → путь делится на два блока.

### 7.2. Модель 2: Полные бинарные деревья

**Определение.** Полное бинарное дерево (full binary tree) — корневое планарное дерево, в котором каждая внутренняя вершина имеет ровно 2 ребёнка (left, right), а листья не имеют детей. Дерево размера n имеет n внутренних вершин и n+1 лист.

**Рекуррентное разложение (по корню):**

Непустое дерево T единственным образом разбивается как T = (L, R), где L — левое поддерево (k внутренних вершин) и R — правое поддерево (n−1−k внутренних вершин). k ∈ {0, …, n−1}.

- Разложение: left = T.left, right = T.right.
- Обратная сборка: T = new Node(left, right).

**Верификация (n=3, 5 деревьев):**
| Дерево | left (k) | right (n−1−k) |
|--------|----------|---------------|
| (•,(•,(•,•))) | • (0) | (•,(•,•)) (2) |
| (•,((•,•),•)) | • (0) | ((•,•),•) (2) |
| ((•,•),(•,•)) | (•,•) (1) | (•,•) (1) |
| ((•,(•,•)),•) | (•,(•,•)) (2) | • (0) |
| (((•,•),•),•) | ((•,•),•) (2) | • (0) |

**Интерфейс:** пользователь строит дерево кликами (добавление пары детей к листу). Корневое разложение подсвечивается как два поддерева разными цветами.

### 7.3. Модель 3: Триангуляции (n+2)-угольника

**Определение.** Выпуклый (n+2)-угольник с вершинами 0, 1, …, n+1 по часовой стрелке. Основание = ребро {0, n+1}. Триангуляция — разбиение на n треугольников непересекающимися диагоналями.

**Рекуррентное разложение (по базисному треугольнику):**

Основание {0, n+1} принадлежит единственному треугольнику — базисному треугольнику {0, v, n+1}, где v ∈ {1, …, n}. Этот треугольник делит многоугольник на два:

- Левый подмногоугольник: вершины {0, 1, …, v}, основание {0, v}. Это (v+1)-угольник → C_{v−1} триангуляций. При v = 1 — отрезок (0 триангуляций = C₀ = 1 пустая).
- Правый подмногоугольник: вершины {v, v+1, …, n+1}, основание {v, n+1}. Это (n+2−v)-угольник → C_{n−v} триангуляций.

Индексы: k = v−1, m = n−v, k + m = n−1. ✓

- Разложение: найти третью вершину v базисного треугольника (смежную с обоими концами основания); извлечь рёбра левого и правого подмногоугольников.
- Обратная сборка: объединить триангуляции левого и правого подмногоугольников, добавить диагонали {0, v} и {v, n+1} (если они не стороны) и базисный треугольник.

**Верификация (n=3, пятиугольник, 5 триангуляций):**
| Диагонали | Апекс v | Левый (C_{v−1}) | Правый (C_{n−v}) |
|-----------|---------|-----------------|------------------|
| (0,2),(0,3) | v=3 | C₂ (4-угольник) | C₀ (отрезок) |
| (0,2),(2,4) | v=2 | C₁ (треугольник) | C₁ (треугольник) |
| (0,3),(1,3) | v=3 | C₂ (4-угольник) | C₀ (отрезок) |
| (1,3),(1,4) | v=1 | C₀ (отрезок) | C₂ (4-угольник) |
| (1,4),(2,4) | v=1 | C₀ (отрезок) | C₂ (4-угольник) |

Распределение: v=1 → 2 шт, v=2 → 1 шт, v=3 → 2 шт. Итого: C₀·C₂ + C₁·C₁ + C₂·C₀ = 2+1+2 = 5. ✓

**Интерфейс:** пользователь проводит диагонали в многоугольнике (кликом по парам вершин). Базисный треугольник подсвечивается → два подмногоугольника выделяются цветом.

### 7.4. Модель 4: Планарные деревья (plane trees / ordered rooted trees)

**Определение.** Планарное дерево (plane tree, ordered rooted tree) — корневое дерево, в котором дети каждой вершины линейно упорядочены (слева направо). Дерево размера n имеет n рёбер и n+1 вершину.

**Представление:** каждая вершина — список поддеревьев-детей [T₁, T₂, …, Tₖ]. Одинокая вершина = [].

**Рекуррентное разложение (first-child / rest):**

Непустое дерево (n ≥ 1) единственным образом разбивается по первому ребёнку корня:
- Поддерево первого ребёнка: T₁, содержит k рёбер.
- «Остаток»: дерево с корнем и оставшимися детьми [T₂, …, Tₖ], содержит n−1−k рёбер.
- Ребро от корня к первому ребёнку — «первый возврат» (аналог '(' в скобочных).

Разложение: first_child = root.children[0], remaining = tree с children = root.children[1:].
Сборка: tree.children = [first_child] + remaining.children.

Это в точности first-return decomposition пути Дика после перевода «DFS-обход → скобочная последовательность» (спуск по ребру = '(', подъём = ')').

**Верификация (n=3, 5 деревьев):**
| Дерево | Первый ребёнок (k рёбер) | Остаток (n−1−k рёбер) |
|--------|--------------------------|------------------------|
| r[•,•,•] | • (0) | r[•,•] (2 ребра) |
| r[•,r[•]] | • (0) | r[r[•]] (2 ребра) |
| r[r[•],•] | r[•] (1) | r[•] (1 ребро) |
| r[r[•,•]] | r[•,•] (2) | r[] = • (0 рёбер) |
| r[r[r[•]]] | r[r[•]] (2) | r[] = • (0 рёбер) |

**Интерфейс:** пользователь строит дерево добавлением детей к вершинам (клик по вершине → добавить ребёнка). Первый ребёнок корня и его поддерево подсвечиваются → два блока.

### 7.5. Согласованность разложений

Все 4 разложения дают одну и ту же рекурренцию Cₙ = Σ C_k · C_{n-1-k} и согласованы с каноническими биекциями между моделями (Шаг 8). Это означает: если объект модели A разложить на (A_left, A_right), перевести каждую часть в модель B через хаб, а потом собрать — получится то же самое, что перевести целый объект модели A в модель B. Проверка этой коммутативности — задача Шага 8.

### 7.6. Модели-кандидаты, не включённые в основной список

**Non-crossing partitions.** Каталановский объект с содержательным рекуррентным разложением (последний блок отсекает часть множества). Однако визуализация менее наглядна, чем для 4 основных моделей. Рекомендуется для расширенной версии сайта.

**Stack-sortable перестановки / 321-avoiding перестановки.** Важные каталановские объекты, но рекуррентное разложение менее естественно для интерактива. Биекция с путями Дика — через RSK или через стековую сортировку — сложнее для визуализации.

**Стандартные таблицы Юнга формы 2×n.** Элементарная биекция с путями Дика (число i в 1-й строке → шаг X на позиции i). Рекомендуется добавить как дополнительную модель в Блок 2, т.к. биекция тривиальна.

## Шаг 8. Биекции между моделями через хаб

### 8.1. Архитектура хаба

Хаб — скобочные последовательности (= пути Дика). Каждая из 3 других моделей имеет каноническую биекцию в хаб и обратно. Биекция любой пары моделей — композиция: Модель A → Хаб → Модель B.

Ключевое свойство: **все биекции согласованы с рекуррентным разложением**. Это значит:

    разложить объект → перевести части → собрать = перевести целый объект → (тот же результат)

Программно проверено для всех трёх моделей при n=3. ✓

### 8.2. Биекция: Полные бинарные деревья ↔ Хаб

**FBT → Dyck (рекурсивно):**
- Лист (None) → пустая строка «»
- Узел (L, R) → '(' + FBT→Dyck(L) + ')' + FBT→Dyck(R)

**Dyck → FBT (рекурсивно):**
- Пустая строка → Лист (None)
- Непустая w: разложить w = (w₁)w₂ → Node(Dyck→FBT(w₁), Dyck→FBT(w₂))

**Согласованность:** разложение FBT по корню (L, R) соответствует first-return разложению w = (w₁)w₂. Коммутативность: ✓.

**Псевдокод:**
```
function fbtToDyck(tree) {
  if (tree === null) return '';
  return '(' + fbtToDyck(tree.left) + ')' + fbtToDyck(tree.right);
}

function dyckToFbt(w) {
  if (w === '') return null;
  let [w1, w2] = dyckDecompose(w);  // w = (w1)w2
  return { left: dyckToFbt(w1), right: dyckToFbt(w2) };
}
```

### 8.3. Биекция: Планарные деревья ↔ Хаб

**Plane tree → Dyck (DFS-обход):**
- Для каждого ребёнка корня (слева направо): '(' + рекурсия(ребёнок) + ')'
- Одинокая вершина (без детей) → пустая строка

**Dyck → Plane tree:**
- Пустая строка → одинокая вершина []
- Непустая w: разбить на блоки нулевой глубины. Каждый блок (wᵢ) — один ребёнок.
  - Найти все подстроки w вида (cᵢ) на глубине 0. Для каждой cᵢ → рекурсия → ребёнок.

**Согласованность:** первый ребёнок корня соответствует первому блоку (w₁) в first-return разложении. Остальные дети — это w₂, интерпретированная как следующие блоки. Коммутативность: ✓.

**Псевдокод:**
```
function ptreeToDyck(tree) {
  return tree.children.map(c => '(' + ptreeToDyck(c) + ')').join('');
}

function dyckToPtree(w) {
  if (w === '') return { children: [] };
  let children = [];
  let depth = 0, start = 0;
  for (let i = 0; i < w.length; i++) {
    if (w[i] === '(') { if (depth === 0) start = i; depth++; }
    else { depth--; if (depth === 0) children.push(dyckToPtree(w.slice(start+1, i))); }
  }
  return { children };
}
```

### 8.4. Биекция: Триангуляции ↔ Хаб

**Triangulation → Dyck (рекурсивно по базисному треугольнику):**
1. Найти базисный треугольник {0, v, n+1} (третья вершина v основания {0, n+1}).
2. Левый подмногоугольник (вершины 0…v) → w₁ = Triang→Dyck(left).
3. Правый подмногоугольник (вершины v…n+1, перенумерованные с 0) → w₂ = Triang→Dyck(right).
4. Результат: '(' + w₁ + ')' + w₂.

**Dyck → Triangulation (рекурсивно):**
1. Разложить w = (w₁)w₂. Пусть k = |w₁|/2.
2. Апекс базисного треугольника: v = k + 1.
3. Создать базисный треугольник {0, v, n+1}. Добавить диагонали {0, v} (если v > 1) и {v, n+1} (если v < n).
4. Рекурсивно: w₁ → триангуляция вершин 0…v; w₂ → триангуляция вершин v…n+1 (со сдвигом нумерации).

**Согласованность:** разложение по базисному треугольнику соответствует first-return разложению. Коммутативность: ✓.

**Псевдокод:**
```
function triangToDyck(diags, n) {
  if (n === 0) return '';
  let v = findBaseTriangleApex(diags, n);  // 3-я вершина треугольника при основании
  let leftDiags = diags.filter(([a,b]) => a <= v && b <= v);
  let rightDiags = diags.filter(([a,b]) => a >= v && b >= v).map(([a,b]) => [a-v, b-v]);
  return '(' + triangToDyck(leftDiags, v-1) + ')' + triangToDyck(rightDiags, n-v);
}

function dyckToTriang(w, offset = 0) {
  let n = w.length / 2;
  if (n === 0) return [];
  let [w1, w2] = dyckDecompose(w);
  let k = w1.length / 2;
  let v = offset + k + 1;
  let diags = [];
  if (k + 1 > 1) diags.push([offset, v]);          // left diagonal
  if (k + 1 < n) diags.push([v, offset + n + 1]);   // right diagonal
  diags = diags.concat(dyckToTriang(w1, offset));
  diags = diags.concat(dyckToTriang(w2, v));
  return diags;
}
```

### 8.5. Полная таблица соответствий (n = 3)

| Dyck | FBT | Plane tree | Триангуляция (диагонали) |
|------|-----|------------|--------------------------|
| ((())) | (((•,•),•),•) | r[r[r[•]]] | {0,2}, {0,3} |
| (()()) | ((•,(•,•)),•) | r[r[•,•]] | {0,3}, {1,3} |
| (())() | ((•,•),(•,•)) | r[r[•],•] | {0,2}, {2,4} |
| ()(()) | (•,((•,•),•)) | r[•,r[•]] | {1,3}, {1,4} |
| ()()() | (•,(•,(•,•))) | r[•,•,•] | {1,4}, {2,4} |

Все 5 объектов в каждой модели попарно различны. Биекции обратимы: round-trip проверен. ✓

### 8.6. Интерпретация для интерфейса (Блок 2)

Пользователь выбирает две модели из списка. Строит объект в одной. Нажимает → → объект переводится в другую через хаб.

Внутренне: objectA → dyck → objectB. Хаб можно показывать как промежуточный шаг (необязательно, но полезно для обучения).

Анимация: рекурсивное разложение объекта A на части → перевод каждой части → рекурсивная сборка объекта B. Части подсвечиваются соответствующими цветами.

### 8.7. Тонкие места

1. **Нумерация вершин триангуляции.** При рекурсии правый подмногоугольник перенумеровывается (сдвиг на −v). При обратной операции — сдвиг на +offset. Основной источник ошибок.

2. **Диагональ vs сторона.** При построении триангуляции из Dyck слова диагонали {0, v} и {v, n+1} не добавляются, если они являются сторонами многоугольника (при v = 1 или v = n соответственно).

3. **Порядок детей в планарном дереве.** Порядок строго слева направо. При разборе Dyck слова каждая подстрока (cᵢ) на нулевой глубине порождает одного ребёнка, слева направо.

4. **Пустые объекты.** C₀ = 1: пустой путь Дика = «», лист в FBT = None, одинокая вершина в plane tree = [], «двуугольник» (отрезок) в триангуляции = нет диагоналей. Все биекции корректно обрабатывают этот случай.

### 9.4. Подводные камни при программировании

**Общие:**
- Off-by-one в индексации: n объектов Каталана = Cₙ, но (n+2)-угольник для триангуляций, n+1 лист для FBT. Соглашение о «размере» должно быть единым (n = число пар скобок = число внутренних вершин FBT = число рёбер plane tree = число треугольников в триангуляции).
- Пустой объект (n = 0): пустая строка, одинокий лист, одинокая вершина, отрезок (2-угольник). Все биекции и разложения должны корректно работать с этим случаем.

**Модель-специфичные:**
- **Триангуляции:** перенумерация вершин при рекурсии (сдвиг offset). Диагональ vs сторона — не добавлять «диагональ» {0, v}, если v = 1.
- **Раздутие/сдутие:** ориентация ребра (от merged к третьей вершине). Перераспределение рёбер по часовой стрелке при inflation. Обработка случая, когда ориентированное ребро — сторона основания.
- **Циклическая лемма:** при нескольких равных минимумах префиксных сумм брать последний. Wrap-around в XY-уничтожении.
- **Exceedance:** условие y ≥ x проверяется ДО выполнения шага (в начальной точке ребра). Перестановка включает edge-разделитель посередине (не чистый циклический сдвиг).
- **Отражение:** отражается только хвост пути (после первого касания y = x + 1), а не весь путь.

**Интерфейсные:**
- Для n ≥ 4 число объектов растёт быстро (C₄ = 14, C₅ = 42). Полные таблицы реалистичны до n = 4. Для n ≥ 5 показывать только конкретный объект + его образ.
- Все 4 модели должны использовать единую цветовую схему для частей рекуррентного разложения (например: w₁/left = синий, w₂/right = оранжевый, разделитель/корень/базисный треугольник = серый).
