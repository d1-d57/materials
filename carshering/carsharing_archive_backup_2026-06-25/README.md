## §1. Что это

Кейс по **ценообразованию каршеринга** (Москва). Три вопроса: **Q1** — базовые цены трёх тарифов (минутный / фиксированный А→Б / пакеты), **Q2** — как тестировать тарифы, **Q3** — сервисный сбор. Класс задачи — **управление доходностью** (revenue management).

**Жёсткое ограничение:** приватных данных оператора нет и не будет — всё из формулировок задачи (📋) и открытых данных Москвы (📊). Честный финал — не одно число, а диапазоны + анализ чувствительности (`PRINCIPLES.md`).

**Куда идём.** H1 — честная заземлённая Excel-модель + сведённая документация (этот этап). H2 — пересборка в **один самодостаточный HTML-инструмент** с рычагами, который считает оптимум и который можно задеплоить и «потыкать» (бриф — `cowork/briefs/0002_html_tool.md`). H2 стартует после H1.

## §5. КАК ВНОСИТЬ ИЗМЕНЕНИЯ (коротко; полно — `cowork/GUIDE.md`)

- **Документацию и стратегию** ведёт **Cowork** (аналитик). **Код модели** (`build_model.py`, генерация xlsx, будущий HTML) правит **Cladkod** (Claude Code).
- **Заход** для Cladkod кладётся в `cowork/briefs/NNNN_<имя>.md`; **отчёт** Cladkod возвращает в `cowork/reports/<дата>_<имя>.md` — оттуда его читает Cowork (вручную переносить не нужно).
- **Каждая фаза правит в одной связке:** `data_sources.md` (числа) → `model/build_model.py` (пересборка) → затронутые доки → новая запись в `provenance/journal.md`.
- Граница Cowork↔Cladkod — чистое сохранённое состояние (если под git — коммит). Одновременно в рабочее дерево не пишут.

## §6. Сборка модели

`model/build_model.py` генерирует `model/carsharing_pricing.xlsx` (4 листа: Параметры / Юнит-экономика / Тарифы / Сервисный_сбор). openpyxl формулы не считает → скрипт рядом печатает те же величины питоном (**оракул**) для самопроверки. Меняешь вход в `build_model.py` → перегенерируешь xlsx, докладываешь «было → стало».
