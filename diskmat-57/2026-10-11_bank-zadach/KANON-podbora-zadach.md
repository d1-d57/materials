## 1. Цель
Каждому ребёнку дать задачи, которые он решает на **50–80 %** за занятие: не слишком просто, не слишком трудно, «разумный челлендж» (владелец 21:10). Инструмент — **аватары**: группы детей, для которых занятие собирается одной версией. Сейчас их 4; дальше 6, 10 и больше, по мере данных (владелец 21:24).

## 2. Аватары [M]
- **Четыре группы:**
  - **СН — самый низ:** глубокие трудности, около 4 детей;
  - **Ни — низ:** временные трудности («не услышал, не понял»), около 8;
  - **Ц — центр:** около 6;
  - **В — верх:** около 8.
- **Работа групп на паре:**

- **Как считается аватар.** Сила по теме — перцентиль-ранг ребёнка в каждой классной работе, среднее с затуханием (полураспад 14 дней), плюс △-сигналы. Пороги — `sistema-7i/sistema/dvizhok.py` (`CUT`, `klaster_syroj`, шаг не больше одного уровня за пересчёт).
- **Одна реализация — в боте [F].** С 11.10 аватар считает одна функция `bot-7i/bot7i/avatary.py` по выгрузке бота: правила перенесены из `dvizhok.py`, регрессия: на ВХОДНЫХ данных старой системы новый модуль дал те же уровни — 28 детей из 28 на трёх точках (84 из 84), то есть правила перенесены точно. Результат лежит в выгрузке, таблица `avatary`; детям и в экран преподавателя не идёт. Старая система помечена «🗄 ЗАМЕНЕНО». - **Уровень динамичный [F]** (владелец 23:05 «аватары строятся перед каждым занятием»). ## 5. Правила листка (с 13.10) [M]
1. **Задача сразу в банк.** Условие, ответ (число, где возможно), решение по `bank-7i/resheniya/STIL.md`, уровень ○ / △ / доп.
2. **Операции из словаря** `razmetka/SLOVAR-operacij-v0.md` (для арифметики — свой словарь той же формы). **Каждая операция — минимум двумя пунктами** разного сюжета и близкой трудности.
3. **Прогноз решаемости по аватарам** — у каждого пункта до занятия.
4. **Цель по трекам:**
   - ○ — для СН и Ни (семинар): ожидаемая решаемость трека 50–80 %;
   - △ — для Ц и В: ожидаемая решаемость трека тоже 50–80 % (цель 50–80 % — для каждого аватара на его треке, владелец 21:10);
   - дополнительные — сверх трека, для В; могут быть ниже 50 %, в цель трека не входят.
5. **Якоря — 2–3 пункта с известной решаемостью** (из прошлых работ или их близнецы). Через них новая тема привязывается к шкале.
6. **Отметка на листке — галочка за каждую попытку** (владелец 21:36). Отметку «пробовал, не сдал» вести невозможно: в момент сдачи неизвестно, сдаст ли ребёнок позже. Число галочек у пункта — это попытки. «+» — сдал. Пусто — не брался. Пункт с галочками и без «+» — «пробовал, не сдал»: это выводится, руками не ставится. **ОТКРЫТО (владелец 22:33):** как галочки попадают в данные — идея: каждому преподавателю распечатка «его школьники × задачи», в клетках галочки и «+», хорошо распознаваемая; размер и формат не решены; альтернатива — через бот (спросить преподавателей). Бот уже разбирает клетку «✓✓+» (README bot-7i, «Attempts»), но ни один источник галочек пока не несёт.
7. **После занятия — сверка** прогноза с фактом по аватарам и запись факта в банк. Это главный цикл двух недель до каникул.

## 6. Процедура занятия — «предсказание → факт» (владелец 21:36) [M]
- **Папка.** У каждого занятия своя папка итерации; все файлы собираются генераторами, ничего руками.
- **До урока.** В папке лежит **ПРЕДСКАЗАНИЕ** — машиночитаемый файл: пункт × аватар → ожидаемая решаемость (и ожидаемое число попыток, когда начнём их считать).
- **После урока.** Результаты загружаются в ту же папку из выгрузки бота. Сверка «предсказание против факта» по аватарам строится **автоматически**: где ошиблись, на сколько, какие пункты вне 50–80 %.
- **Гейт.** Табло краснеет, пока нет предсказания до урока или сверки после.
- **Оформление.** Процедура оформляется как скилл или процедура работы с каждым занятием, поверх существующего табло (Ф9 и Ф14 становятся генерируемыми, а не необязательными файлами).
- **Как сейчас (команды, `diskmat-57/mashina-listka/MASHINA.md`, раздел «Занятие: предсказание → факт») [F]:**
  1. папка итерации с `ITERACIYA.json`, поле `"nachalo": "<дата>T14:00"` (пара 14:00–17:00, владелец 23:05; `novaya.py` ставит по умолчанию);
  2. `python3 diskmat-57/mashina-listka/predskazanie.py zagotovka <папка> <rabota_id> …` → аналитик ставит доли по аватарам (опора — `reshaemost.csv`, якоря) → `predskazanie.py proverit <папка>`;
  3. `PREDSKAZANIE.csv` в git **раньше `nachalo`** (коммит заходом) — это доказательство «до урока»; иначе табло красное;
  4. после урока: СНАЧАЛА обновить выгрузку бота (`bot-7i/vygruzka.py`, иначе новой точки нет), потом `python3 diskmat-57/mashina-listka/sverka.py <папка>` → `SVERKA.md`, факт дописывается в шкалу;
  5. `tablo.py` зелёный; статус «не нужно» для Ф9/Ф14 запрещён.
- **Гипотеза владельца [H].** Ошибки прогноза шли от того, что аватаров сначала не было (потом два); чем их больше, тем меньше статистических промахов. Проверяется той же сверкой с 13.10.
