Схема — договорённость о ПОЛЯХ и о том, КТО их заполняет; формат файла можно менять, смысл полей — только решением владельца.

> Пометки: **[сейчас]** — заполняется с первого дня; **[позже]** — поле заведено, пустует до бота NLOGN или до нужды; **[выводится]** — не пишется руками, считается.

## 0. Четыре сущности

| сущность | что это | где живёт |
|---|---|---|
| **Задача** | идея: сюжет, решения, ответ по смыслу; контейнер для вариантов | карточка `diskmat-57/bank-7i/zadachi/<id>.md` |
| **Вариант** | то, что реально выдали: формулировка А или Б, с числами и подачей | внутри карточки |
| **Решение** | способ решить задачу; у задачи их может быть несколько | внутри карточки |
| **Попытка** | ребёнок × вариант × пункт × работа | данные бота и разметки сдач, НЕ в карточке |

Правило раскладки: **навык и метод — у решения; сложность — у варианта; ошибка и помощь — у попытки.** Если вариант меняет то, что делает ребёнок (например, порядок перебора дан в одном варианте и не дан в другом), это не вариант, а другая задача.

## 1. Карточка задачи — файл на задачу

`diskmat-57/bank-7i/zadachi/<id>.md`: YAML-шапка с полями, ниже текст разделами.

```yaml
id: poezd-vagony                 # стабильный слаг, не номер в листке
nazvanie: Поезд                  # для преподавателя
tema: kombinatorika              # тема программы
navyki: [plus-minus-1]           # [выводится] объединение навыков всех решений
metod: [podschet-s-dvuh-storon]  # [выводится] объединение методов решений
uroven: ○                        # ○ / △ / ◇ / ★ — уровень владельца (Р313); ◇/★ детям не показываются
istochnik: Шень, Листок 1, №6    # откуда задача, если чужая
varianty:
  - var: А
    usloviye_iz: diskmat-57/…/kontrolnaya_06-10_dannye.py   # условие НЕ перепечатывается, берётся из источника листка
    dano: ""                     # что подсказано в формулировке: «порядок перебора дан», «запишите разностью» …
    punkty:
      - p: а
        otvet: "18"              # число (Р328, владелец 16:35); нечисловой ответ — текстом
        chislo: 18               # пусто для нечисловых
  - var: Б
    …
vydavalas:                       # где и когда давалась — каждая выдача
  - rabota: KR-2026-10-06        # id работы из bot-7i/katalog.yaml
    nomer: "○1"
oshibki:                         # словарь типичных ошибок задачи
  - kod: minus-1-zabyl
    tekst: сложили без вычитания общего вагона
```

Текст карточки — разделы `## Условие` (только если задача не из листка), `## Решение 1`, `## Решение 2`, … В заголовке решения — его поля одной строкой:

```
## Решение 1 · навыки: plus-minus-1 · метод: podschet-s-dvuh-storon · основное
```

| поле решения | что | кто |
|---|---|---|
| навыки | 1–3 навыка из словаря, один помечен основным | аналитик, владелец утверждает |
| метод | метод из словаря методов | аналитик |
| основное | какое решение эталонное / самое короткое | аналитик |
| текст | идея одной строкой + решение в пару абзацев + «где ошибаются» | по странице калибровки |

## 2. Словари

Стартует с 6 навыков из `sistema-7i/sistema/dannye/navyki.csv`. Навык делится, когда на одной его задаче класс неожиданно проваливается (пример — «рост ВИ 14→95 %» был ростом разности).

**Методы** — `diskmat-57/bank-7i/metody.md`: короткий словарь «схем» решения (перебор с выбранным порядком, разрез по группам, подсчёт дополнения, двойной подсчёт, …); где совпадает — именами рубрикатора problems.ru «Методы».

## 5. Как банк используют листок и бот

- **Листок** собирается из карточек: `id` задачи + вариант → условие и ответ; шпаргалка принимающих (номер · вариант · ответ) — из тех же карточек. Исключения из «только из банка» допустимы (Р311, Р323).
- **Ответы в боте** — сейчас из `diskmat-57/bank-7i/otvety.csv` (заход `kod_otvety-v-bote.md`); когда карточки появятся, таблица **порождается** из них, источник один.
- **«Разбор»** — под работой в боте: у пункта «Твой ответ · Ответ · отметка», ниже решение из карточки (основное, при наличии — другое).
- **«Теория»** — отдельный блок занятия, не из карточек; теорию постфактум не пишем (Р315).
- **Кабинет навыков** — позже: ступени лестницы ребёнка по навыкам, считаются из попыток через навыки основных решений.

## 6. Чего схема НЕ делает

Не строит аватары и адаптивность (NLOGN, Р323); не требует от ассистентов полей сверх клетки «+ / галочка»; не хранит данные детей в карточках.
