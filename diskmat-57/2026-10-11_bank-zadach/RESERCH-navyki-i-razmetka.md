# Навык живёт в решении, а сложность в варианте

*Предложение для обсуждения, это не готовая схема. Схему банка пишем после «да» владельца по разделам 5–7.*

Пометки: **[измерено]** — эмпирический результат с источником; **[мнение/практика]** — дизайн-правило, заявление вендора, традиция; **[вывод]** — наш вывод из источников, на 28 детях не проверен. Отдельно помечены источники, которые в заметках процитированы по памяти, не перечитаны или являются препринтами.

## 1. Коротко

Главная мысль: разметка должна различать четыре сущности. **Задача** — это идея. **Вариант** — то, что реально выдали: формулировка вместе с подачей. **Решение** — метод с навыками. **Попытка** — ребёнок × вариант × момент. Навыки и метод живут на решении. Сложность живёт на варианте. Ошибка и помощь живут на попытке. Если свалить всё это на «задачу», получится ровно та каша, которую мировая практика ловит постфактум: скрытые навыки, неизоморфные «близнецы», завышенные плюсы.

Решение «давать или нет» мировая практика принимает одинаково при любой модели: **экспертный граф «нужно до» и проверка, что задача лежит на «фронтире» ребёнка, плюс статус навыка по лестнице с порогами**. Литература прямо говорит, что вкладываться надо в **богатство входных данных** (помощь, первая попытка, тип ошибки, контекст «в блоке / в смеси / отложенно»), а не в умную модель. Это согласуется с нашим AUC ≈ 0,5 у BKT на 28 детях. Сложность без больших данных устроена так: учитель задаёт априорную оценку (лучше сравнительным суждением «труднее / легче»), данные её поправляют. Доля решивших на 28 детях известна только с точностью ±0,18. Машинная эпоха меняет одно: с первого дня храним **тройку «фото — транскрипция — человеческий вердикт»**, эталонные решения по методам и словарь ошибок. Без этого будущий машинный проверяющий систематически ставит лишние плюсы.

Не берём: диагностические модели (DINA/G-DINA), BKT с подгоняемыми параметрами, восстановление графа по данным, LLM как оракул сложности, автоприём без человека.

## 2. Философия: что такое задача для разметки

Мысленный эксперимент владельца (один ученик, полная запись решений, «наш ЕГЭ» из рабочих задач) требует принять решение «давать / не давать» по параметрам. Литература показывает, что у «задачи» эти параметры не одного рода и физически сидят в разных местах.

**Задача (идея).** Здесь хранится то, что не меняется при переформулировке: сюжет, ответ, множество известных решений, словарь типичных ошибок, семейство, флаг «гроб» (◇/★ по Р313). Задача — это контейнер, а не единица учёта.

**Вариант (выдаваемая формулировка).** Варианты из одного шаблона систематически различаются по сложности. Пелáнек приводит дроби: сравнить 1/2 и 2/10 гораздо легче, чем 4/6 и 5/8 **[измерено, неформально]** ([Pelánek, domain modeling](https://www.fi.muni.cz/~xpelanek/publications/domain-modeling.pdf)). Сильнее другое: «одинаковые» задачи различаются скрытым навыком. Площадь круга «вперёд» и «назад» оказались разными компонентами знания на 11 датасетах DataShop **[измерено]** ([Liu, Koedinger, McLaughlin, EDM 2014](https://educationaldatamining.org/EDM2014/uploads/procs2014/long%20papers/107_EDM-2014-Full.pdf)). Сложение площадей с готовой разбивкой и с разбивкой, которую ребёнок придумывает сам, тоже оказались разными навыками («Decompose») **[измерено]** ([DataShop case study](https://pslcdatashop.web.cmu.edu/about/case-studies/koedinger-geometry-script-for-web.htm)). Проект QUASAR добавляет, что когнитивный запрос задачи деградирует при реализации: учитель подсказывает, и задача уровня «делать математику» становится процедурой **[измерено]** ([JCMP, Henningsen & Stein](https://jcmp.calstate.edu/jcmp/article/download/54/28)). Отсюда **[вывод]**: сложность и запрос — свойства варианта вместе с подачей («дан ли порядок перебора», «дана ли разбивка на случаи»), а не задачи. Если вариант меняет то, *что делает ребёнок*, это уже не вариант, а другая задача с лишним навыком. Это прямое продолжение Р312 (А/Б — вариации одной задачи).

**Решение.** Литература по диагностическим моделям при нескольких стратегиях даёт каждой стратегии свою строку требуемых навыков (MS-DINA). В примере с вычитанием дробей стратегия 1 требует {a,b,c,d}, стратегия 2 — {a,b,f} **[модель]** ([Zhang et al. 2021](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2021.568348/pdf)). Сложность тоже зависит от стратегии. На задачах с неизвестным началом «раскрутка с конца» давала 69 % успеха, символьные преобразования — 51 % **[измерено]** ([Koedinger & Nathan 2004](https://www.stat.cmu.edu/~brian/PIER-methods/For%202013-03-04/Data/Koedinger-Nathan-LS04.pdf)). Лейкин делает разные решения одной задачи объектом учёта: «пространство решений», кластеры по представлению и инструменту **[мнение/практика, исследовательская традиция]** ([RANGE, Haifa](https://range.haifa.ac.il/en/creativity-in-mathematics-and-task-types)). Детали её балльной схемы в заметках приведены **по памяти, не проверены**. Вывод **[вывод]**: тег «метод» и набор навыков принадлежат решению. У задачи остаётся объединение тегов её решений и пометка «эталонный / самый дешёвый путь». Это ровно интуиция владельца «теги понимаются через решение» и Р314 (разные решения показываются).

**Попытка (наблюдение).** Это единственное место, где есть данные о ребёнке. Здесь хранятся исход, помощь, метод, которым ребёнок *реально* решал, и тип ошибки. Обзоры по моделированию ученика описывают стандартный ход так: навыки размечаются на эталонном решении, а фактическую стратегию и ошибку пишут отдельно на уровне попытки **[мнение/практика]** ([Pelánek, domain modeling](https://www.fi.muni.cz/~xpelanek/publications/domain-modeling.pdf)).

Итоговая раскладка: **навык** сидит на решении, а на задаче — объединение. **Метод** сидит на решении (эталон) и на попытке (факт). **Ошибка** заведена в словаре на задаче, а ставится на попытке. **Сложность**: априорная оценка на варианте, эмпирическая считается по попыткам этого варианта, разность сложности между методами — на решении.

## 3. По направлениям

### 3.1. Навыки-теги: 1–3 на задачу, операциональные определения, расщепление по провалам

Компонент знания в KLI определяется через поведение: это единица, *выводимая* из успехов и провалов на группе родственных задач. Зернистость выбирают «на уровне, где новичок ошибается», всё более мелкое считается атомарным **[мнение/практика, теория]** ([KLI, Koedinger–Corbett–Perfetti](https://home.cs.colorado.edu/~mozer/Teaching/syllabi/TopicsInCognitiveScienceFall2011/KLI-paper-v5.00.pdf)). Р292 («навык = действие ребёнка») с этим совпадает. Из KLI добавляется рабочий тест: навык настоящий, если на нём проваливаются *вместе* и если он растёт от практики.

Про число навыков на задачу самое прямое свидетельство дают модели ASSISTments. Тонкая ручная разметка (78 навыков) предсказывала итоговый госэкзамен лучше грубой (1, 5, 39): ошибка 14,7 % против 19,4 % у одного навыка в 2006 году **[измерено]**. Строили её так: один эксперт за ~7 часов разметил ~300 заданий с ограничением **«не больше 3 навыков на задание»**. Без ограничения получалось до 9 навыков, и авторы признали это неработоспособным. В среднем вышло **1,44 навыка на задание** ([Feng et al.](https://web.cs.wpi.edu/~mfeng/pub/IEEE_feng.pdf)). Там же есть цифра, которая отрезвляет: согласие двух учителей с экспертом на тонкой разметке — **полное в 22 % случаев**, на уровне отдельных навыков расхождений больше, чем совпадений **[измерено]**. Значит, без операционального определения каждого навыка (что считается, что не считается, 1–2 якорные задачи) разметка между учителем и ассистентами разъедется **[вывод]**.

Встречный результат. На 62 тыс. экспертно размеченных упражнений из вузовских учебников кривые обучения по навыкам в большинстве *не* убывали, а сложность конкретной задачи объясняла успех лучше, чем владение навыком **[измерено]** ([van de Sande, EDM 2016](https://www.educationaldatamining.org/EDM2016/proceedings/paper_127.pdf)). Грубые навыки при малом числе попыток на навык почти ничего не предсказывают. Это аргумент держать сложность варианта отдельным полем, а не выводить её из навыков.

Как улучшают экспертную разметку. Типичная поправка — **расщепление** слишком общего навыка, внутри которого спрятан неучтённый: «разбей сам», «иди назад». Диагностика — «провал» на кривой у части задач навыка **[измерено]** ([LFA, Cen–Koedinger–Junker](https://www.ml.cmu.edu/research/dap-papers/cen_kddpaper2.pdf)). На наших масштабах формальный LFA не подогнать: в демонстрации было 24 ученика, но ~4 000 наблюдений по шагам. Качественная процедура переносится полностью **[вывод]**: ищем в навыке задачу, где класс неожиданно провалился, спрашиваем, что она требует сверх остальных, и расщепляем. Внутренний живой пример — «рост ВИ 14→95 %» из большого обзора 08.10. На деле это был рост разности, потому что ○3б решается вычитанием. Здесь подменённый навык, ровно случай Р322(5). Он ловится только если навык записан на *решении*, а метод ребёнка — на *попытке*.

Ещё одно свидетельство слепоты эксперта к трудности: большинство учителей и исследователей предсказали, что символьные уравнения легче текстовых задач, а дети решали их хуже (42 % против 70 %) **[измерено]** ([Koedinger & Nathan 2004](https://www.stat.cmu.edu/~brian/PIER-methods/For%202013-03-04/Data/Koedinger-Nathan-LS04.pdf)).

Math Academy (вендор, не рецензировано) разводит два отношения между навыками. Первое — «нужно до» (пререквизит). Второе — «тренирует попутно» (encompassing), с весом из [0,1], который эксперт ставит вручную только на ключевых рёбрах. Пройденная продвинутая задача засчитывает неявное повторение простых **[мнение/практика, вендор]** ([Skycak, FIRe](https://gwern.net/doc/www/www.justinmath.com/9af2ce40376e836660c237a0e971d1896a163eee.html)). Для спирального курса, где незакрытый навык переходит в следующую тему (Р292), второе отношение — именно то, что нужно для учёта повторений **[вывод]**. Цифры Math Academy про «4× быстрее» — заявление вендора без независимой проверки ([Hecker 2025](https://frankhecker.com/2025/02/10/math-academy-part-3/)).

Оценка оттуда же **[вывод]**: в среднем до 80 % успеха нужно ~7 возможностей на навык (PNAS 2023, **цифры по вторичному пересказу**, их чувствительность оспорена препринтом 2026 года) ([Scott Young о Koedinger et al. 2023](https://www.scotthyoung.com/blog/2024/02/06/learning-rate-paper/)). Тогда на каждый навык минимума нужно порядка 7+ задач *нужного уровня* в банке, иначе цикла практики не получится.

### 3.2. Методы и таксономии: готового словаря «нашего» перебора нет

Р312 сформулировал вопрос так: «навык → метод — research, не изобретать велосипед». Ответ из обзора: **велосипеда нужной зернистости нет, но его форму можно взять готовой**.

Существуют два рода словарей. Процессные эвристики: Пойа, Мейсон–Бёртон–Стейси (специализировать, обобщать, ввести обозначение, гипотеза, обоснование, фазы Entry/Attack/Review), контрольный слой Шёнфельда **[мнение/практика]** ([оглавление MBS](https://www.obalkyknih.cz/file/toc/493593/pdf); [Шёнфельд, сводка TECFA](https://tecfa.unige.ch/themes/sa2/act-app-dos2-fic-mathemat2.htm)). Олимпиадные «принципы»: Дирихле, крайний, инвариант, раскраска, оценка+пример. Рубрикатор problems.ru держит ветку **«Методы» (4 283 задачи, 12 рубрик)** параллельно предметным темам, то есть задача несёт и тему, и метод. При этом **рубрики «Перебор» в «Методах» нет** **[измерено: проверено 11.10]** ([problems.ru «Методы»](https://problems.ru/view_by_subject_new.php?parent=214)). Энгель, Цейтц, Генкин–Итенберг–Фомин, Шень в заметках **по памяти, оглавления не проверены**. Самая полезная из них идея — трёхуровневая иерархия Цейтца strategy → tactic → tool, которая явно разводит уровни абстракции тегов **[мнение/практика, по памяти]**.

Ближайший аналог «умного перебора» как размечаемой структуры — схемы Маршалл. Из 3 027 арифметических текстовых задач 2 695 укладываются в 5 схем по структуре решения, и сортировке по схемам учили за 0,5–2,5 часа **[измерено]** ([MAA Research Sampler о Marshall 1995](https://sites.oxy.edu/lengyel/tracksplus/actuarial_changes/rs_2.html)). Вывод **[вывод]**: для 7И нужен свой короткий словарь «схем перебора» (канонический порядок, дерево, разбиение на случаи, кодирование объекта строкой, дополнение) как тегов *решения*. Вдобавок у каждого решения стоит хранить одно поле «**что гарантирует полноту и отсутствие повторов**» — концептуальное ядро процедуры. Это и отличает «процедуру со связями» (уровень 3 у Stein–Smith) от механики. Обзор Rittle-Johnson–Schneider–Star поддерживает двусторонность: отработка процедуры ведёт к пониманию не хуже обратного порядка **[измерено, обзор]** ([Springer 2015](https://link.springer.com/article/10.1007/s10648-015-9302-x)). Значит, «рабочие задачи» — законная цель, а не натаскивание.

Оси PISA (Formulate / Employ / Interpret, контекст «Occupational», вычислительное мышление) хорошо *описывают* цель курса ([PISA 2022](https://pisa2022-maths.oecd.org/)). На решение «давать / не давать» они не влияют, поэтому в схему сейчас не идут. Внешней проверки, что банки «по методам» учат лучше банков «по темам», найдено не было.

### 3.3. Сложность без больших данных: априорная оценка учителя плюс поправка данными, интервалы вместо точек

Арифметика (посчитано из биномиальной модели, 28 детей) **[вывод]**: стандартная ошибка доли решивших при p = 0,5 составляет ≈0,09, 95 %-интервал ±0,18. Разница меньше ~0,2 между двумя задачами одного листка — шум. Зато крайние метрики владельца информативны. «Не решил никто» почти наверняка значит p ≲ 0,1, ведь при p = 0,1 вероятность такого исхода всего ≈0,05. «Решили все» симметрично означает p ≳ 0,9. Дискриминативность (корреляция задачи с остальными) на 28 детях имеет SE ≈ 0,19, и значение 0,3 на одном листке от нуля не отличимо. Для калибровки Раша ~30 человек дают точность ±1 логит, ~100 человек — ±0,5 **[мнение/практика, правило Linacre, не перечитано]** ([rasch.org](https://www.rasch.org/rmt/rmt74m.htm)). Elo-подход (Пелáнек) работает при холодном старте, но для хороших оценок сложности задачи ему нужны «хотя бы 100 учеников» **[измерено, симуляция]** ([Pelánek 2016](https://www.fi.muni.cz/~xpelanek/publications/CAE-elo.pdf)). Отсюда: эмпирическая сложность накапливается за годы и по семействам вариантов, а в первый год работает априорная оценка учителя.

Насколько хороша оценка учителя. Абсолютные оценки сложности задач плохи. Признаковые предсказания исторически не объясняют больше 25 % дисперсии **[измерено, систематический обзор]** ([Oxford, El Masri](https://www.education.ox.ac.uk/project/judging-demands-and-predicting-task-difficulty-a-systematic-review-of-the-literature/)). Учителя слабых классов недооценивают детей на лёгких задачах, учителя сильных переоценивают на трудных, а якорем служит образ класса, а не задача **[измерено]** ([Güzel & Başokçu 2023](https://link.springer.com/article/10.1007/s11409-023-09333-2)). Эти две ошибки — ровно два провала метрики листка («никто не решил» и «все решили»). Сравнительное суждение работает лучше: судьи неплохо упорядочивали задачи SAT наборами по 7 **[измерено, коэффициенты в заметках не извлечены]** ([ETS RR-14-39](https://www.ets.org/research/policy_research_reports/publications/report/2014/jtmq.html)). По метаанализу 101 сессии надёжность сравнительного суждения определяется числом сравнений на объект, а не числом судей: ~10 сравнений на задачу дают надёжность ≥0,8 **[измерено]** ([Kinnear, Jones, Davies 2025](https://link.springer.com/article/10.3758/s13428-025-02744-w)). Ранжировать 100 задач стоит ~500 парных суждений, и учитель с 4 ассистентами это потянет **[вывод]**.

Признаки, которые литература связывает со сложностью: число шагов или вложенных случаев, нужна ли «идея», какой метод и проходили ли его, размер пространства перебора, наличие ловушки-ошибки, длина формулировки **[вывод из обзоров, на олимпиадных задачах не проверено]** ([AlKhuzaey et al., IJAIED](https://link.springer.com/article/10.1007/s40593-023-00362-1)). LLM как прямой оценщик сложности слаб. На BEA 2024 лучшая система едва обошла «предсказание среднего» (RMSE 0,299 против 0,311) **[измерено]** ([ACL 2024.bea-1.42](https://aclanthology.org/2024.bea-1.42.pdf)). На SAT Math ρ ≈ 0,41, и GPT-5 оказался хуже GPT-4.1 («проклятие знания») **[измерено, препринт]** ([2512.18880](https://alphaxiv.org/overview/2512.18880v1)). Симуляция «класса» слабыми моделями с последующей подгонкой IRT даёт r ≈ 0,75–0,82 на NAEP **[измерено, препринт, на уровне аннотации]** ([2601.09953](https://arxiv.org/abs/2601.09953)). Признаки, извлечённые LLM, дают r ≈ 0,78, но на 250 тыс. ответов **[измерено, препринт]** ([2602.00034](https://arxiv.org/abs/2602.00034)). Все результаты получены на стандартизированных заданиях, для олимпиадной дискретки чисел нет.

Ещё одна деталь, которую стоит собирать с первого дня: **«не брался» ≠ «не решил»**. При их смешении поздние задачи листка выглядят труднее, чем они есть **[вывод]**. При выборочной выдаче (○/△) сырая доля решивших смещена, а модельная оценка нет **[измерено, симуляция]** ([Pelánek 2016](https://www.fi.muni.cz/~xpelanek/publications/CAE-elo.pdf)). Р293 «кластер как усреднённый человек» здесь ложится естественно: средняя по уровню ○/△ служит общим средним в иерархической модели, к которому стягиваются оценки задач **[вывод]**.

### 3.4. Выбор следующей задачи и «освоил»: простые правила на богатом входе

Фронтир (outer fringe) из теории пространств знаний формализует «давать или нет»: даём задачу, если всё, что «нужно до», уже в состоянии ребёнка, а её самой там нет. ALEKS держит курсы по 300–600 тем и для диагностики выбирает вопрос, исход которого ближе всего к 50/50 **[измерено/практика]** ([ALEKS practical perspective, препринт 2021](https://www.mheducation.com/content/dam/mhe/research/prek-12/essa-tier-4/aleks-practical-perspective-knowledge-space-theory.pdf)). Из этого переносится понятие фронтира и правило «проверочную задачу берём там, где меньше всего уверены», а вероятностная калибровка не переносится **[вывод]**. Граф строят эксперты, а по данным его не восстановить. Даже на чистой синтетике (400 профилей × 300 шагов) F1 восстановления рёбер 0,2–0,46, и на данных адаптивной системы он падает до 0,17 **[измерено, симуляция]** ([arXiv 2402.01672](https://arxiv.org/pdf/2402.01672)). Данные служат проверкой ребра: решил B, не решив пререквизит A, — пересмотреть ребро.

Правила освоения. Пелáнек в обзоре: BKT против логистических моделей «не решено», простые скользящие средние часто дают разумные предсказания, **вход важнее модели** **[мнение/практика, обзор]** ([Pelánek UMUAI 2017](https://www.fi.muni.cz/~xpelanek/publications/umuai-overview.pdf)). В симуляциях BKT с порогом 0,95 объявлял освоение почти всем преждевременно, а подогнанный slip менялся с 0,31 до 0,07 в зависимости от объёма данных **[измерено, симуляция]** ([Pelánek, mastery criteria](https://www.fi.muni.cz/~xpelanek/publications/mastery-modeling.pdf)). В ASSISTments правило «N подряд» на задаче переноса было точнее KT: ≈73 % у 5 подряд, ≈57 % у 3 подряд, ≈54 % у KT. **Выборки малые (n=37 на перенос), цифры пересчитаны промежуточной моделью, сверить с оригиналом** ([Kelly et al., EDM 2015](https://www.educationaldatamining.org/EDM2015/proceedings/poster630-631.pdf)). Самое сильное свидетельство о порогах — рандомизированный эксперимент ALEKS на ~33 млн точек. Порог 5 против 3 даёт **~+2 п. п. удержания при базовом ~0,6**, этот выигрыш тает за недели, а время растёт на ~30 %. Но если первое действие ученика — ошибка или просмотр объяснения, выигрыш больше 4 п. п. **[измерено]** ([Matayoshi et al., JEDM](https://jedm.educationaldatamining.org/index.php/JEDM/article/download/900/254)). В режиме обучения ALEKS просмотр объяснения рвёт серию, а «не знаю» весит иначе, чем ошибка **[мнение/практика]**.

Смешивание задач. Кластерный рандомизированный эксперимент на 54 классах 7-го года: перемешанная практика против блочной дала **d = 0,83** на тесте через месяц, эффект положителен у всех 15 учителей **[измерено]** ([Rohrer et al. 2019](https://Www.Gwern.net/doc/psychology/spaced-repetition/2019-rohrer.pdf)). Механизм — выбор стратегии по виду задачи, то есть ровно навык «узнать, какой метод нужен», который составляет предмет «лабораторного» экзамена. Правило «N подряд в одной теме» по сути блочное **[вывод]**.

Живые репетиторы. Обычные в 92 % проверок понимания спрашивают «понятно?», а ответ «да» почти не связан с успеваемостью **[измерено]** ([Graesser et al. 1995](https://talkbank.org/class/access/0docs/graesser1995.pdf)). Эксперты (INSPIRE у Леппера) начинают с диагностических задач и сначала чинят непонимание, вызов добавляют потом **[мнение/практика, качественно]** ([INSPIRE](https://www.eoas.ubc.ca/research/cwsei/resources/INSPIRE-Guidelines.pdf)). Ориентир «85 %» — теорема про стохастический градиентный спуск, а не результат о людях ([Wilson et al. 2019](https://doaj.org/article/d1aeacdf1f304a25962f05454cebb437)). В адаптивной практике рабочая цель ~65 %, а выбор сложности учеником не помог: слабые просили задачи труднее **[измерено, факты географии]** ([Papoušek & Pelánek 2017](https://www.fi.muni.cz/~xpelanek/publications/difficulty-adjustment.pdf)). Сложность решает учитель. Ребёнку можно дать выбор *внутри* фронтира **[вывод]**.

### 3.5. Машинная эпоха: решает не модель, а то, что мы сохранили

Машинная разметка навыков: GPT-4 совпадал с экспертным тегом в 35–56 % случаев (top-1), хотя эксперты в 2/3 случаев *предпочитали* формулировки LLM. Это не математика, а химия и e-learning **[измерено]** ([Moore et al., L@S 2024](https://arxiv.org/abs/2405.20526v1)). Подход, который литература делает решаемым: «подходит ли определение навыка k к задаче q» с подбором примеров **[мнение/практика, препринт]** ([2406.13885](https://arxiv.org/html/2406.13885v1)). Значит, словарь навыков с текстовыми определениями и 2–3 якорными задачами нужен и людям (против 22 % согласия), и будущей машине **[вывод]**.

Проверка рукописных решений по фото. На вузовских вычислительных задачах с рубрикой совпадение с преподавателем по пунктам рубрики ~89–99 %. **87 % расхождений лучшей модели дала транскрипция фото**, а не математическое суждение. На размытых фото модель «додумывала» текст, похожий на эталон **[измерено, препринт]** ([Levine et al., 2605.19043](https://arxiv.org/pdf/2605.19043)). На ~3 900 квизах по анализу 10,7 % машинных оценок признаны неверными, плюс автоисправление ошибок ученика и галлюцинации в пустых клетках **[измерено, препринт]** ([Yu et al., 2603.00895](https://arxiv.org/pdf/2603.00895)). Без эталона и рубрики проверяющий завышает оценки. На олимпиадных доказательствах лучшая конфигурация (эталон + схема оценивания) ошибается в среднем почти на 1 балл из 7, а слабые доказательства без контекста завышает на ~1,7 балла **[измерено]** ([ProofBench, 2510.13888](https://arxiv.org/html/2510.13888v1)). Верный ответ не гарантирует верного решения: ~52 % решений олимпиадного уровня с верным ответом содержат ошибку по ходу **[измерено]** ([ProcessBench](https://arxiv.org/pdf/2412.06559)). Рассуждения 7-классников о дискретке по типу ближе к доказательствам, чем к вычислениям. Реалистичная роль машины — предварительная проверка и флаг, вердикт за человеком **[вывод]**.

Ошибки. Схему задают соревнования Eedi: фиксированный словарь заблуждений с текстовыми описаниями (2 587 штук), к которому привязывают ответы. Открытая проблема — заблуждения, не встречавшиеся в обучении **[измерено]** ([Eedi](https://www.eedi.com/news/from-wrong-answers-to-real-insights-how-we-used-a-kaggle-challenge-to-map-student-misconceptions)). MAP@3 > 0,94 в 2025 году получен всего на **15 вопросах**, так что эта цифра переоценивает реальность ([Learning Agency](https://the-learning-agency.com/the-cutting-ed/article/case-study-math-misconceptions-competition)). Самая дешёвая пошаговая метка с публичным бенчмарком — «номер первой ошибочной строки» ([ProcessBench](https://arxiv.org/pdf/2412.06559)).

ИИ-тьюторство. Лучше всего подтверждены сценарии «ИИ помогает человеку» (Tutor CoPilot: +4 п. п. освоения, +9 у слабых тьюторов; размеры выборки в пересказах расходятся) ([NSSA](https://nssa.stanford.edu/studies/tutor-copilot-human-ai-approach-scaling-real-time-expertise)) и «ИИ после своей попытки». Свободный доступ к GPT-4 дал −0,19 SD на последующем экзамене без помощи **[измерено, по пересказу в препринте]** ([2607.08849](https://arxiv.org/pdf/2607.08849)). Рандомизированных экспериментов, где именно LLM выбирает следующую задачу, не найдено, поэтому стартаповские заявления об «адаптивности» стоит читать как рекламу.

## 4. Классификация «освоил / не освоил» из большого обзора 08.10: что с ней делает внешняя очевидность

В большом обзоре 08.10 лежали четыре элемента. Ни один не утверждён целиком, но Р316 требует учёта «освоил / не освоил» через метод фиксации, а не сумму плюсов.

**Лестница статуса «нет данных / не умеет / с помощью / сам / уверенно» (4.7) — внешняя очевидность подтверждает, лестница уточняется.** Тот же скелет у Khan Academy (Not started → Attempted → Familiar → Proficient → Mastered, уровни растут и падают, пороги не опубликованы) ([Khan support](https://support.khanacademy.org/hc/en-us/articles/115002552631)) и у счётчика ALEKS, где подсказка рвёт серию. Наш AUC 0,49/0,56/0,55 у BKT и взвешенного счёта совпадает с выводом Пелáнека, что модель ничего не добавляет. Ставим лестницу и в модель не вкладываемся. Уточнения **[вывод]**:

- (а) Пороги. «Сам» — это ~2–3 подряд без помощи (порог 3 у ASSISTments и ALEKS). Ребёнку, который *начал с ошибки или с подсказки*, порог поднимаем: только у таких детей ALEKS увидел заметный выигрыш.
- (б) «Уверенно» определяется не числом повторов, а **переносом**: верно решил задачу в смеси с другими темами через ≥1–2 недели. Основания — Rohrer (смешивание) и Kelly (порог различает лучше всего на переносе).
- (в) Статус может падать, как у Khan. Провал в смешанной проверке опускает «уверенно» до «сам».
- (г) В лестницу нужно отличие «нет данных» от «не брался» на уровне попытки.

**«Умеет — только по самостоятельной; листки и ДЗ — наблюдения» (4.6) — меняется формулировка.** Внешние данные дают другой разрез: не «тип документа», а **была ли помощь и где стоит задача (в блоке / в смеси / отложенно)**. Данные о помощи (подсказки, число попыток) предсказывают итоговый экзамен *лучше*, чем одна правильность ([Feng, Heffernan, Koedinger 2006](https://www.sri.com/publication/education-learning-pubs/digital-learning-pubs/predicting-state-test-scores-better-with-intelligent-tutoring-systems-developing-metrics-to-measure-assistance-required/); величина эффекта в заметках не извлечена). Значит, листки с журналом приёма — не второсортные наблюдения, а основной поток данных. Риск у листков реальный, но другой: формат «лабораторной» допускает друзей и интернет, а самоотчёт «понял» ничего не стоит (Graesser). Предложение **[вывод]**: у попытки есть поле **условия** (самостоятельная / в классе при приёме / дома). «Сам» ставится по попытке без помощи *при приёме* или по самостоятельной. «Уверенно» — только по самостоятельной или отложенной смешанной проверке. КР при этом естественный носитель «уверенно», а не единственный источник «умеет».

**Близнецы в начале и конце темы, КР = прошлая неделя + близнец двухнедельной давности (3.4/3.6) — подтверждается, с жёсткой оговоркой.** Отложенная смешанная проверка — ровно то, что дало d = 0,83 у Rohrer. Близнецы — единственный реалистичный при 28 детях способ получать контрасты (дешёвый аналог Difficulty Factors Assessment из KLI). Но литература про изоморфы и скрытые навыки, а заодно наш собственный случай ○3б показывают: **близнец считается близнецом только тогда, когда совпадают действия ребёнка**. Если вариант решается другим методом (вычитание вместо перебора), он измеряет другой навык. Поэтому у варианта поле «что дано / подача» и проверка близнеца по эталонному решению обязательны. Слабое согласие двух КР (ρ = 0,28) и то, что ○ КР 6.10 почти не различают класс, согласуются с тем, что на 28 детях доля решивших варианта известна с точностью ±0,18. Одна КР — это шумная точка, а не вердикт.

**Журнал приёма: попытки, подсказки, тип ошибки (3.9) — подтверждается сильнее всего, и это главный параметр.** Свидетельства с трёх сторон: данные о помощи (Feng 2006), «вход важнее модели» (Пелáнек), первое действие как модератор (ALEKS RCT). Плюс внутренний факт: принимающие поставили «+» шести неверным ответам. Отсюда два требования **[вывод]**: (1) у варианта хранится **ответ или ключевой критерий**, по которому приём сверяется; (2) у попытки хранится **кто принимал** (а позже — фото), чтобы ненадёжность приёма можно было измерить, а не только подозревать. Ограничение Р316 «не нагружать ассистентов бюрократией» значит, что код ошибки выбирается из короткого списка у *этой* задачи, а не пишется текстом.

**Кластер ≠ статус (Р293) — согласуется.** Кластер — грубая общая способность, которой пользуются Elo/Раш, статус — критериальная лестница по навыку. Литература держит их раздельно: оценка способности ребёнка набирается быстрее сложности задачи, потому что ребёнок решает много задач.

| **исход**: не брался / не решил / решил с помощью / решил сам | лестница; «не брался» ≠ провал | А | сейчас |
| помощь: была ли и какая (подсказка из списка / «наводящий вопрос») | рвёт серию; поднимает порог | А | сейчас (да/нет), тип — бот |
| принимающий | измерить надёжность приёма | Б | сейчас |

|---|---|---|---|

Правило выбора, которое получается из этих полей **[вывод, на 28 детях не проверено]**: задача доступна, если её основной навык ещё не «уверенно», а все навыки, которые «нужно до», уже не ниже «сам». Среди доступных берём вариант, чья априорная сложность ближе всего к точке «50/50 для этого ребёнка». Каждая n-я задача — смешанная проверка из уже «самостоятельных» навыков.

## 6. Что не берём и почему

**Диагностические модели (DINA / DINO / G-DINA, MS-DINA).** При N = 30 не все комбинации навыков вообще наблюдаются, и даже при N = 300 элементы Q-матрицы восстанавливаются с точностью 0,79–0,86 **[измерено, симуляция]** ([Wang et al. 2020](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2020.02120/pdf)). Берём только *структуру данных*: навыки по каждому решению, конъюнктивная семантика «нужны все».

**BKT, PFA и вообще подгонку параметров модели знаний на 28 детях.** Своя проверка (AUC ≈ 0,5) и литература (нестабильный slip, преждевременное «освоил») сходятся. Возвращаться имеет смысл только при объединении данных за несколько лет и классов. Elo по сложности варианта — кандидат «позже», не сейчас.

**Формальный LFA/AFM.** Берём качественную процедуру расщепления навыков, без подгонки.

**Восстановление графа по данным.** На порядки не хватает данных даже относительно синтетики, где F1 ≤ 0,46.

**Полную структуру пространства знаний ALEKS и алгоритм FIRe.** Берём понятия фронтира и «тренирует попутно». Вероятностная структура и проприетарный алгоритм требуют масштабов, которых у нас нет.

**LLM как оракул сложности.** ρ ≈ 0,4 даже на SAT. Допустимо позже как ещё один судья в сравнительном суждении или извлекатель признаков.

**Автоприём машиной.** Ложные зачёты, галлюцинации по размытому фото, ~1/7 балла ошибки на доказательствах. Машина только подсвечивает.

**Ориентир «85 %» и выбор сложности ребёнком.** Первое — не результат о людях. Второе в эксперименте не помогло.

**Правило Пелáнека «один навык на задачу» и «40 задач на навык».** Оно для систем с короткими задачами на беглость. У нас задачи длинные, поэтому 1–3 навыка с одним основным и ~7+ задач нужного уровня на навык минимума.

**Оси PISA / Bloom / вычислительного мышления, оценку оригинальности по Лейкин, дискриминативность задач.** Ни одна из них не меняет решение «давать или нет» на 28 детях. Первые две полезны для описания курса, оригинальность — позже для разборов, дискриминативность — шум (SE ≈ 0,19).

**Самооценку ребёнка «трудно / норм / легко».** Дешёвая, но самоотчёт плохо связан с умением (Graesser). Не сейчас.

## 7. Открытые вопросы владельцу

1. **Где живут навыки.** (а) На решении, а у задачи объединение — предлагаемое. (б) Только на задаче, по эталонному решению: проще, но ○3б-подобные подмены будут невидимы.
2. **Как засчитывать попытку, решённую не эталонным методом.** (а) Засчитывать навыки фактического метода — предлагаемое, требует поля «метод ребёнка». (б) Засчитывать навыки эталона. (в) Засчитывать только основной навык задачи независимо от метода.
3. **Может ли «сам» ставиться по листку.** (а) Да, если при приёме не было помощи, а «уверенно» — только по самостоятельной или отложенной смеси — предлагаемое. (б) Нет, оставить 4.6 как есть: «умеет» только по самостоятельной.
4. **Пороги лестницы.** (а) «Сам» = 2 подряд без помощи, а для начавших с ошибки 3. (б) Всегда 3. (в) Без счёта: решение учителя по журналу.
5. **Рёбра графа.** (а) Между навыками — предлагаемое, мало рёбер. (б) Между задачами — точнее, но сотни рёбер руками.
6. **Код ошибки — кто и когда.** (а) Принимающий выбирает из 3–5 кодов задачи при приёме. (б) Учитель по фото раз в неделю на выборке. (в) Пока не собирать, только «верно / неверно / не брался».
7. **Сравнительное ранжирование сложности.** (а) Сессия с ассистентами: наборы по 7 задач, ~10 сравнений на задачу. (б) Только ○/△ плюс эмпирика. (в) Ранжировать лишь задачи минимума.
8. **Словарь методов перебора.** (а) Свой короткий список (канонический порядок, дерево, случаи, кодирование, дополнение) по форме Цейтца и Маршалл. (б) Взять рубрики problems.ru и добавить «перебор».
