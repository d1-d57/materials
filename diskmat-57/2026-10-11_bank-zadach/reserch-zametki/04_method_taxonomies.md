# Классификация задач по методу решения / эвристике / типу задачи, и банки, устроенные вокруг решений

Пометки об источниках: [V] = проверено в этом поиске (ссылка открыта, содержание подтверждено); [M] = по памяти / общеизвестное, в этом поиске НЕ проверено, при цитировании проверить. Свидетельства (эмпирические исследования) отделены от традиции / мнения авторов.

## 1. Таксономии эвристик и методов (Пойа, Шёнфельд, Мейсон–Бёртон–Стейси, Энгель, Цейтц; русская традиция: Генкин–Итенберг–Фомин, рубрикатор problems.ru, Шень)

### Takeaway
Существует два разных рода «словарей методов»: (а) **процессные** эвристики, не зависящие от темы (Пойа, Мейсон–Бёртон–Стейси, контрольный слой Шёнфельда: специализировать, обобщать, ввести обозначение, идти с конца, проверить), и (б) **олимпиадные «принципы»**, привязанные к классу задач (инвариант, Дирихле, крайний, раскраска, чётность, оценка+пример). Рубрикатор problems.ru — живой пример банка, где «Методы» — самостоятельная ветка рядом с предметными темами, т.е. задача несёт одновременно тег-тему и тег-метод. Для «рабочих нестандартных задач» (перебор с универсальным порядком) ни один из словарей не даёт готового тега нужной зернистости: «перебор» там либо отсутствует как метод, либо слишком грубый.

В 1987 он сильнее подчёркивает метакогницию и культурное измерение. [V] — [TECFA summary of Schoenfeld](https://tecfa.unige.ch/themes/sa2/act-app-dos2-fic-mathemat2.htm); книга: [Elsevier](https://shop.elsevier.com/books/mathematical-problem-solving/schoenfeld/978-0-12-628870-4)

- **Энгель, *Problem-Solving Strategies* (Springer, 1998)** [M]: главы-методы — Invariance principle, Coloring proofs, Extremal principle, Box principle (Дирихле), Enumerative combinatorics, Number theory, Inequalities, Induction principle, Sequences, Polynomials, Functional equations, Geometry, Games, Further strategies. Смешение «метод» и «тема» в одном оглавлении.
- **Цейтц, *The Art and Craft of Problem Solving*** (1-е изд. 1999, 2-е 2007, 3-е 2017) [M]: трёхуровневая иерархия **strategy** (общий психологический подход: «get your hands dirty», wishful thinking, penultimate step) → **tactic** (математический приём широкого назначения: симметрия, крайний принцип, Дирихле, инварианты) → **tool** (узкий приём/трюк). Это самая полезная для банка идея: уровни абстракции тегов явно разведены.
- **Генкин, Итенберг, Фомин, «Ленинградские математические кружки» (1994; англ. *Mathematical Circles (Russian Experience)*, AMS 1996)** [M]: главы — Чётность, Комбинаторика-1, Делимость и остатки, Принцип Дирихле, Графы-1, Неравенство треугольника, Игры, Задачи для первого года, Индукция, Делимость-2, Комбинаторика-2, Инварианты, Графы-2, Геометрия, Системы счисления, Неравенства, Задачи для второго года. Организация — «одна идея = одна глава», внутри — лестница от простого. Оглавление не проверено в этом поиске.
- **Шень** (МЦНМО, «Индукция», «Игры и стратегии с точки зрения математики», «Вероятность: примеры и задачи», «Программирование: теоремы и задачи») [M]: книги организованы как последовательности задач вокруг одной идеи, с решениями после каждой задачи — формат «задача+решение как атом», но без внешней системы тегов. Не проверено.

### Inferences
- Для банка разумно держать **несколько независимых осей**, а не одно дерево: (1) предметная тема, (2) «тактика» (Дирихле/крайний/инвариант/раскраска/оценка+пример/от противного/индукция/конструкция), (3) процессное действие (специализация, обобщение, ввести обозначение/кодирование, идти с конца, проверить/экстенд), (4) уровень Цейтца (strategy/tactic/tool). problems.ru де-факто делает (1)+(2).
- «Систематический перебор с выбором универсального порядка» (разбиения 6, «все слова», дерево вариантов) отсутствует как метод во всех проверенных/вспомненных таксономиях — это аргумент в пользу собственного тега (например, «перебор: канонический порядок», «перебор: дерево», «перебор: разбиение на случаи», «кодирование объекта»).
- Mason–Burton–Stacey Review/EXTEND — естественное место для «рабочих» задач: процедура известна, а ценность — в проверке полноты и переносе.

- Не удалось проверить оглавления Энгеля, Цейтца, Генкина–Итенберга–Фомина и книг Шеня онлайн (поиск дал вторичные учебные программы). Есть только память.
- Подтемы 3-го уровня problems.ru (например, внутри «Классической комбинаторики» и где именно живёт «Чётность и нечётность») не открыты: сайт виден через fetch, но лимит запросов. Стоит открыть `view_by_subject_new.php?parent=<id>` для «Классической комбинаторики».
- Как problems.ru назначает несколько тем одной задаче (сколько тем в среднем у задачи, есть ли тег у отдельного *решения*) — не проверено. По памяти [M] темы прикрепляются к задаче, а не к решению; у задачи может быть несколько решений и несколько тем.

## 2. Классификация задач по когнитивному запросу (Stein & Smith, Bloom/Anderson–Krathwohl, PISA, TIMSS)

### Takeaway
Самая «рабочая» для учителя шкала — четыре уровня когнитивного запроса (Stein, Smith и соавт.): memorization / procedures without connections / procedures with connections / doing mathematics. Ключевая эмпирическая находка проекта QUASAR: высокоуровневые задачи систематически **деградируют в процессе урока** (учитель даёт слишком много подсказок, снимает открытость) — т.е. уровень — свойство не задачи, а задачи-в-реализации. «Рабочие нестандартные задачи» по описанию учителя попадают ровно в «procedures with connections».

### Cited Findings
- Четыре уровня (в источнике атрибутированы Henningsen & Stein, 1997) [V]: 1) **Memorization** — воспроизведение факта/формулы/определения; 2) **Procedures without connections** — выполнение процедуры без понимания её концептуальной основы, обычно без требования объяснить; 3) **Procedures with connections** — процедура используется для построения понимания, часто через связь представлений; 4) **Doing mathematics** — обоснование подходов к открытым задачам, включая изобретение новых подходов. — [JCMP (Cal State)](https://jcmp.calstate.edu/jcmp/article/download/54/28)
- **Деградация уровня при реализации** (эмпирика, QUASAR): высокоуровневые задачи часто превращаются в рутинные; учитель снижает запрос, давая слишком много подсказок или убирая открытость. Факторы сохранения уровня: достаточно времени, постоянное давление на объяснение и смысл, опора на предыдущее знание (Henningsen & Stein, 1997; Stein, Grover & Henningsen, 1996). [V] — [JCMP](https://jcmp.calstate.edu/jcmp/article/download/54/28)
- Инструмент для учителей: Smith, Stein, Arbaugh, Brown, Mossgrove (2004), «Characterizing the cognitive demands of mathematical tasks: A task-sorting activity», в *Professional Development Guidebook for Perspectives on the Teaching of Mathematics*, NCTM, с. 45–72. [V] — [Knowles Teachers](https://knowlesteachers.org/?p=24417)
- Классификация уровня автоматическими средствами: есть свежие работы, оценивающие ИИ-инструменты в классификации когнитивного запроса по этой шкале. [V, только заголовки] — [arXiv 2603.03512](https://arxiv.org/pdf/2603.03512); [arXiv 2604.12743](https://arxiv.org/pdf/2604.12743) (модификация задач низкого уровня в высокий)
- **PISA 2022** [V]: математическая грамотность = способность рассуждать математически и **formulate, employ, interpret** математику. Три процесса цикла моделирования: *Formulate* (увидеть, где применима математика, перевести в структуру, переменные, представления, выявить допущения), *Employ* (применить понятия, процедуры, рассуждения), *Interpret and evaluate* (вернуть результат в контекст, оценить разумность, критиковать ограничения модели). Добавлено **computational thinking** как часть математической грамотности. Контентные категории: Change and relationships, Space and shape, Quantity, Uncertainty and data; контексты: Personal, **Occupational**, Societal, Scientific. Оговорка самого фреймворка: «21st century skills» (critical thinking, creativity, systems thinking) перечислены, но задания PISA 2022 специально под них не строились. — [PISA 2022 Mathematics Framework](https://pisa2022-maths.oecd.org/)
- **TIMSS** [M]: когнитивные домены Knowing / Applying / Reasoning (с 2007; примерно 35/40/25% заданий в 8 классе). Не проверено в этом поиске.
- **Bloom revised (Anderson & Krathwohl, 2001)** [M]: 2-мерная таблица — knowledge dimension (factual, conceptual, procedural, metacognitive) × cognitive process (remember, understand, apply, analyze, evaluate, create). В математике критикуется за то, что «apply» и «analyze» плохо разделимы на нестандартных задачах. Не проверено.

### Inferences
- Шкала Stein–Smith — это **ось для тега «запрос»**, а не для метода; для банка нужна как отдельное поле. Главная её польза — напоминание, что запрос зависит от формулировки и от того, сколько подсказки дали: одна и та же задача про разбиения 6 — «doing mathematics» без подсказки и «procedures without connections», если выдан порядок перебора. Значит, в банке стоит хранить **уровень для конкретной формулировки/подачи**, а не для «задачи вообще».
- PISA-ось Formulate/Employ/Interpret прямо соответствует цели курса (инженеры, биологи): «рабочая» задача про перебор — это в основном Employ, а выбор кодирования объекта («как записать разбиение, чтобы перебирать») — это Formulate. Можно тегировать **какой из шагов цикла задача тренирует**.

### Gaps
- Первичный текст Stein, Smith, Henningsen, Silver (2000) *Implementing Standards-Based Mathematics Instruction* и Task Analysis Guide (полный список признаков каждого уровня) не открыт.
- TIMSS 2023 framework и формулировки Bloom-в-математике не проверены.

## 3. Задачи с несколькими решениями (Leikin), схемы задач (Marshall), разборы-примеры и типы задач

### Takeaway
Leikin (Хайфа) — единственная найденная традиция, где **разные решения одной задачи** являются объектом учёта: Multiple Solution Tasks (MST), «пространства решений», оценка беглости/гибкости/оригинальности. Marshall (1995) — пример эмпирически построенной таксономии **типов задач по схеме** (5 схем покрывают ~89% арифметических текстовых задач), т.е. классификация по структуре решения, а не по сюжету. Обе опоры поддерживают идею «тег понимается через решение».

### Cited Findings
- **MST — определение**: задачи, явно требующие решить одну задачу несколькими способами (напр., алгебраически vs геометрически vs графически), для развития гибкости и понимания связей между представлениями (Leikin & Lev, 2013). Метрики креативности: **fluency** (число решений), **flexibility** (переключение между подходами/представлениями), **originality** (редкость решения). Ключевые работы: Leikin (2009) «Exploring mathematical creativity using multiple solution tasks»; Levav-Waynberg & Leikin (2012); Leikin (2014). [V] — [RANGE, Univ. of Haifa](https://range.haifa.ac.il/en/creativity-in-mathematics-and-task-types); [Leikin 2009 record](https://cris.haifa.ac.il/en/publications/exploring-mathematical-creativity-using-multiple-solution-tasks-2/)
- Levav-Waynberg & Leikin (2012), *Canadian Journal of Science, Mathematics and Technology Education* 12, 311–333: знание оценивается по **корректности и связности** решений, креативность — комбинацией fluency, flexibility, originality. [V, по аннотации] — [Springer](https://link.springer.com/article/10.1080/14926156.2012.732191)
- Детали схемы Leikin (2009) [M — проверить по первоисточнику]: различаются **expert solution space** (все известные решения), **individual solution space** (решения одного ученика, делятся на available/potential) и **collective solution space** (объединение решений группы); решения группируются в «кластеры», если они отличаются (а) представлением, (б) используемыми свойствами/понятиями, (в) инструментами из разных разделов математики. Баллы: flexibility — 10 за первое решение / за решение из нового кластера, 1 — за решение из уже встреченного кластера, 0.1 — за почти повтор; originality — 10, если решение встречается у <15% (или <40%?) группы, ниже — меньше баллов; креативность = сумма произведений flexibility×originality по решениям. Эти числа взяты из памяти, в открытых страницах их не было.
- **Marshall, *Schemas in Problem Solving* (Cambridge UP, 1995)**: из 3027 арифметических текстовых задач (учебники + калифорнийские стандартизированные тесты) 2695 укладываются в 5 ситуационных схем — **Change, Group, Compare, Restate, Vary**; по одной или в комбинации они описывают почти все типичные задачи. В четырёх исследованиях испытуемые учились распознавать и сортировать задачи по схемам, некоторые — за 0.5–2.5 часа обучения. Схема описывается как «абстракция её существенных реляционных признаков». [V] — [MAA Research Sampler (Selden & Selden, 1997)](https://sites.oxy.edu/lengyel/tracksplus/actuarial_changes/rs_2.html); [Cambridge](https://www.cambridge.org/core/books/schemas-in-problem-solving/2174356A82052145A6C94010D82266CA)
- Четыре компонента знания схемы у Marshall [M]: identification (распознать), elaboration (общая структура), planning (как использовать), execution (выполнение). На проверенной странице не было.
- Worked examples / expertise reversal (Sweller, Kalyuga) [M]: разобранные примеры эффективнее самостоятельного решения у новичков, эффект пропадает/обращается у более опытных; сравнение разных решений одной задачи (Rittle-Johnson & Star, 2007, «Does comparing solution methods facilitate conceptual and procedural knowledge?», J. Educ. Psych.) улучшало процедурную гибкость. Не проверено в этом поиске.

### Inferences
- Для банка из Leikin следует **структура данных**: задача → множество решений → каждое решение помечено «кластером» (метод/представление/инструмент); разные решения одной задачи — разные кластеры. Тег «метод» тогда принадлежит **решению**, а у задачи — объединение тегов её решений. Это прямо совпадает с интуицией учителя («теги понимаются через решение»).
- Метрика «редкость решения» (originality) даёт естественный способ отмечать в банке «стандартное» и «неожиданное» решение одной задачи — полезно для разбора на уроке.
- Marshall показывает, что классификация **по структуре решения** (схеме) обучаема и даёт компактный словарь; аналог для дискретки 7 класса — небольшое число «схем перебора» (упорядоченный/неупорядоченный выбор, разбиение на случаи, дерево, правило произведения, дополнение).

### Gaps
- Точные формулы баллов Leikin и пороги originality — нужен PDF Leikin (2009) в *Creativity in Mathematics and the Education of Gifted Students* (Sense).
- Работ, где MST применяются к **комбинаторике/перебору**, а не к геометрии/алгебре, не найдено.

## 4. Процедурное vs концептуальное знание (Rittle-Johnson и др.) и «процедуры, отскакивающие от зубов»

### Takeaway
Обзор Rittle-Johnson, Schneider & Star (2015): связь **двусторонняя** — процедурное знание поддерживает концептуальное так же, как наоборот; данных в пользу «сначала понятие, потом процедура» мало, порядок почти не сравнивался напрямую. Это поддерживает идею «рабочих задач» как полноправного средства, а не «натаскивания».

### Cited Findings
- «procedural knowledge supports conceptual knowledge, as well as vice versa»; разные порядки обучения (понятие→процедура vs процедура→понятие) напрямую сравнивались редко, поэтому мало свидетельств в пользу какого-то одного; авторы обсуждают, почему педагоги по умолчанию считают «сначала понятие» лучшим. Rittle-Johnson, B., Schneider, M., & Star, J. R. (2015). Not a one-way street: Bidirectional relations between procedural and conceptual knowledge of mathematics. *Educational Psychology Review, 27*(4), 587–597. [V] — [Springer](https://link.springer.com/article/10.1007/s10648-015-9302-x)
- Schneider, Rittle-Johnson & Star (2011, *Developmental Psychology*) — эмпирическая проверка итеративной модели на продольных данных [M; файл найден поиском, не открыт] — [Uni Trier PDF](https://www.uni-trier.de/fileadmin/fb1/prof/PSY/PAE/Forschung/SchneiderEtAl2011.pdf)
- «Procedural fluency» как одна из пяти нитей математической компетентности (conceptual understanding, procedural fluency, strategic competence, adaptive reasoning, productive disposition) — NRC *Adding It Up* (2001) [M]. Важно: «strategic competence» = умение сформулировать, представить и решить задачу — ближе всего к «выбору порядка перебора».
- Процедурная **гибкость** (Star, 2005; Star & Rittle-Johnson): знание нескольких процедур и умение выбрать подходящую — отдельная от беглости характеристика [M].

### Inferences
- «Процедуры, отскакивающие от зубов» у учителя — это скорее procedural fluency + strategic competence на уровне Stein–Smith «procedures with connections»: процедура (перебор в каноническом порядке) известна, но её выбор и проведение без потерь/повторов требуют понимания (почему порядок гарантирует полноту и отсутствие дублей). Литература поддерживает двунаправленность: отработка процедуры может вести к пониманию.
- Отсюда тег-кандидат: для каждого решения хранить **«что гарантирует полноту/отсутствие повторов»** (концептуальное ядро процедуры).

### Gaps
- Как в этой литературе измеряется концептуальное знание (задачи «объясни», «оцени чужое решение») — не прочитано.
- Исследований процедурной беглости именно для комбинаторного перебора у школьников в этом поиске не найдено (известна линия Lockwood по «sets of outcomes» в комбинаторике у студентов [M] — не проверено).

## 5. Рамки прикладной / «рабочей» математической компетентности (цикл моделирования, computational thinking)

### Takeaway
Ближайшая к цели курса официальная рамка — PISA 2022: цикл формулировать → применять → интерпретировать, плюс computational thinking и контекст «occupational». Она даёт оси для тегов (какой шаг цикла, какой контекст), но не словарь методов дискретки.

### Cited Findings
- PISA 2022: процессы Formulate / Employ / Interpret & evaluate; reasoning как ядро; computational thinking введено как часть грамотности и как инструмент для предсказаний, аргументов и **сравнения решений**; контекст «Occupational» — рабочие задачи, доступные 15-летним. [V] — [PISA 2022 Framework](https://pisa2022-maths.oecd.org/)
- Цикл моделирования Blum & Leiß (2007, 7 шагов: понять ситуацию → упростить/структурировать → математизировать → работать математически → интерпретировать → валидировать → изложить) [M].
- Computational thinking (Wing, 2006): decomposition, pattern recognition, abstraction, algorithm design [M]. Связь с перебором прямая: «универсальный порядок перебора» = алгоритм генерации комбинаторных объектов.

### Inferences
- Для курса «будущие инженеры/биологи» уместно тегировать каждое решение по CT-оси: декомпозиция (разбиение на случаи), абстракция/кодирование (запись объекта строкой), алгоритм (порядок перебора), проверка (полнота). Это переводит олимпиадную «тактику» в язык, понятный профессиональному применению.

### Gaps
- Прямых исследований, что дискретно-математические «рабочие задачи» в 7 классе переносятся на профессиональную деятельность, не искалось/не найдено.

## 6. Практические банки, тегирующие по методу и хранящие несколько решений

### Takeaway
problems.ru — подтверждённый пример банка с отдельной веткой «Методы» (12 рубрик) параллельно предметным темам. Eedi — пример банка с иерархией тем, где **дистракторы** несут информацию об ошибочных представлениях (misconceptions), но в открытом датасете NeurIPS 2020 явной разметки дистрактор→misconception не было. Про AoPS, Brilliant, KöMaL проверенных данных в этом поиске нет.

### Cited Findings
- problems.ru: см. раздел 1 (ветка «Методы»: 4283 задачи в 12 рубриках). [V] — [problems.ru](https://problems.ru/view_by_subject_new.php?parent=214)
- **Eedi** (NeurIPS 2020 Education Challenge): у каждого вопроса список SubjectId разной зернистости; темы образуют **дерево** (верх: «Algebra», «Data and Statistics», «Geometry and Measure»; пример вложенности: «Factorising» → «Factorising into a Single Bracket»). Задания 1–2: 27 613 вопросов; задания 3–4: 948 вопросов. Каждый вопрос — 4 варианта, ровно один верный; дистракторы «embody misconceptions», но явной метки misconception на дистракторе в метаданных нет — предлагается выводить их кластеризацией ответов. [V] — [arXiv 2104.04034](https://arxiv.org/pdf/2104.04034); датасет >20 млн ответов — [arXiv 2007.12061](https://arxiv.org/abs/2007.12061v2)
- Позднее Eedi провёл Kaggle-соревнование по сопоставлению дистракторов с misconceptions (т.е. разметка misconception появилась) [V, только заголовок] — [Eedi blog](https://eedi.com/blog/from-wrong-answers-to-real-insights-how-we-used-a-kaggle-challenge-to-map-student-misconceptions)
- AoPS (Art of Problem Solving) [M]: AoPS Wiki хранит задачи соревнований (AMC/AIME/USAMO) со страницами «Solution 1, Solution 2, …» — множественные решения одной задачи как норма формата; книжная серия AoPS (Intro to Counting & Probability) организована по методам. Не проверено.
- KöMaL (Венгрия, с 1894) [M]: архив задач журнала с опубликованными решениями; классификация по номерам серий (C, B, A, …) по сложности, а не по методу. Не проверено.

### Inferences
- Ни один из найденных банков не тегирует **решение** отдельно от задачи (проверенно — только на уровне задачи). Модель «задача ↔ много решений ↔ теги у решений» из Leikin реализована, по-видимому, только в исследовательских инструментах, а в открытых банках — как неструктурированный текст «Решение 1 / Решение 2» (AoPS Wiki [M], problems.ru [M]).
- Eedi показывает полезную альтернативу «тегам метода»: **теги ошибки** — для рабочих задач на перебор естественны «ошибочные» теги (пропуск случая, двойной счёт, порядок учтён лишний раз).

### Gaps
- Не проверены: структура тегов Brilliant, AoPS Wiki (категории), KöMaL archive, польские архивы (OM/Delta), Math Stack Exchange-подобные базы.
- Не найдено исследований эффективности банков, организованных по методу, vs по теме.
