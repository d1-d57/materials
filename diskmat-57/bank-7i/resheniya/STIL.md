# Стиль решений банка 7И

Свод правил владельца из калибровки 11.10. Голосовые 17:29–18:55 лежат в `2026-10-11_bank-zadach/GOLOSOVOE-vladelca-2026-10-11-bank-5…8.txt`, образец — `src/KR-2026-10-06.py`. Правила здесь сжаты, первоисточник — голосовые.

## Зачем решение
Ребёнок открывает решение, когда у него «−»: ему нужно понять, в чём ошибка. Принимающий открывает его, когда ребёнок рассказывает решение с другим ответом. Решение — это рецепт в духе лабораторной работы: видна идея, и её можно повторить на похожей задаче. Кроме того, по решению размечают задачи: какая идея нужна и какой навык.

## Форма
- **Первой строкой идёт ответ** (`z.otv`): по пунктам, варианты А и Б. Условие не перепечатывается, его бот показывает сам.
- **Шаги.** В каждом шаге (`z.ol`) одна идея. Писать кратко, но «широко»: не пропускать мысль, которую слабый ребёнок сам не достроит.
- **Подводка.** Содержательный приём — способ перечислять или группы для таблицы — вводится через подводку `z.plan(…)`: что сделаем и зачем. Потом идёт чёткое описание: первый объект, правило, как получается следующий. После него примеры, а таблица уже в конце.
- **Маленький пример ставится в начало**, если он помогает. Пример берётся естественный, не вырожденный: никакого «поезда из одного вагона». Проверки на маленьком в конце не нужны.
- **Картинка вместо слов «представим картину»**: нарисовать (`z.pic`). Где нужна таблица — `z.tab`. Формула пишется отдельной строкой (`z.f`).
- **Вариант Б** — одна-две строки `z.vb(…)` тем же рассуждением на других числах. Если ход решения в Б другой, его пишут полностью.
- **Другое решение** (`z.drugoe`) пишется только тогда, когда идея действительно другая: длинная сумма против короткой разности; рукопожатия перебором против «каждый с каждым, пополам». Если такое решение есть, его пишут обязательно.
- **Раздела «где ошибаются» нет.**

## Язык
- Стиль безличный и математический: «посчитаем», «заметим», а не «ты» и не «мы с тобой». Русский живой, без канцелярита.
- Без формальных отсылок: не писать «по индукции», «для любого n», формулы с буквами вроде n − 1. Исключение — задача, которая сама просит общую формулу.
- Ссылаться только на проверяемые схемы, которые разбирали на уроке. Таких схем две: **правило суммы** (части без общих элементов складываются) и **правило разности** (всё минус лишнее). Не ссылаться на «±1» и «ошибку на единицу» как на правило. Вместо этого показать, какой элемент посчитан дважды или потерян.
- Для совокупностей писать «группа» или «часть», не «кусок».
- Пока не используем: правило произведения как правило, C из n по 2, рекурренты. Умножение как сокращённое сложение одинаковых строк таблицы допустимо: «8 строк по 5».

## Три идеи (черновик владельца; номер идеи ставится в `idei=[…]`)
1. **Заменить задачу более простой.** Посчитать большую совокупность, которая раскладывается на части: одна часть — искомая, остальные считаются легко. Сюда относятся правила суммы и разности и поправка «общая часть посчитана дважды».
2. **Дать каждому объекту одно имя.** Это нумерация числами 1…N (чётные — делением на 2) или естественная запись: слагаемые по убыванию, буквы флага. Тогда считать объекты — то же, что считать имена.
3. **Перебирать по правилу.** Ясно, какой объект первый и какой идёт за каким. Тогда ничего не пропущено и нет повторов.

## Рисунки
Рисунок делается функцией из `risunki.py`: `poezd`, `numeraciya`, `krugi`, `spichki`, `flagi`, `reshetka`, `ryad` — или собственным SVG через `svg(w, h, body, label)`.
- Цвет задаётся только классами из `reshenie.css` (`s-*`, `f-*`, `cw` и `cv` в тексте). Атрибутов `fill="#…"` нет.
- Внутри рисунка только метки: числа и короткие подписи. Объяснение пишется в подписи под рисунком (`cap`).
- У каждого рисунка есть `label`: что на нём, одной фразой для чтения с экрана.

## Проверка
- Каждый числовой ответ записывается в `z.chisla(А={…}, Б={…})`; для ДЗ без вариантов — `z.chisla(_={…})`. Сборщик сверяет эти числа с `otvety.csv`.
- Каждое число в решении проверено полным перебором в Python до записи.
