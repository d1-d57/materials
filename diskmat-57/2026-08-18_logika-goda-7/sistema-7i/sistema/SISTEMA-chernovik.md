## 1. Статус навыка: три модели

### 1.1. Градации и правила (рекомендуемая — лестница) [M]

| знак | статус | правило (по событиям, где навык — основной в пункте) |
|---|---|---|
| **—** | нет данных | ни одного наблюдения на листке/приёме/КР (ДЗ не считается) |
| **0** | не умеет | наблюдения есть, но навык не сдан нигде — ни сам, ни с помощью |
| **П** | с помощью | сдавал с помощью (листок, приём), но последняя КР по навыку не сдана или КР ещё не было |
| **С** | сам | последняя КР, где был навык, сдана |
| **У** | уверенно | две последние КР с навыком сданы, и они в разные дни |

«Сдал навык на событии» — верно ≥ 2/3 обязательных пунктов с этим навыком (1 из 1, 2 из 2, 2 из 3). Пусто на КР — не сдал. Необязательные △ (по выбору) идут только в плюс: верный △ — сдал, неверный — не улика. ДЗ (дом) в статус не входит — стоит рядом справочно (меряет помощь, `01-klass.md`). Ручная правка Вани (`ruchnye.csv`) главнее модели.

**Переходы:** КР сдана → С (если и предыдущая КР сдана в другой день → У). КР не сдана → П (если когда-то сдавал с помощью), иначе 0 — то есть «уверенно» падает до П одним провалом КР (это и есть проверка «устойчиво»). Листок/приём поднимает только 0 → П, на С/У не влияет. Незакрытый навык минимума (не У к концу темы) переносится в следующую тему как «долг»: статус сохраняется, навык ставится в КР новой темы.

**Что даст бот (поэтапно) [M]:** «плюсик» = событие режима «помощь» (0 → П). Когда появятся «попытка» и «подсказка»: приём с 1-й попытки без подсказки — тоже самостоятельное событие (может дать С, но не У: У — только две КР). Сайт ДЗ с автоприёмом — режим «дом», в статус не входит, но даёт флаг «дома решает / не решает» и выбор навыка для ДЗ.

### 1.2. Две другие модели

- **Взвешенный счёт с затуханием:** p = (Σ w·верно + 2·0,5)/(Σ w + 2), w = вес режима (КР 1, приём 0,35, ДЗ 0,1) · 0,5^(возраст/21 дн). Оценка: — если Σ w < 0,3; 0 если p < 0,5; П если вес КР < 0,67; У если p ≥ 0,8 и КР в ≥ 2 дня; С если p ≥ 0,67; иначе П.
- **BKT (Bayesian Knowledge Tracing):** P(знает) старт 0,3, после события «выучил» с вероятностью 0,15; угадать/ошибиться: КР 0,15/0,1, приём 0,6/0,05, ДЗ 0,75/0,05. Оценка: 0 если P < 0,4; П < 0,7; С < 0,95; У ≥ 0,95 (0,95 — стандартный порог «освоено» в адаптивных системах). Elo-подобная модель (рейтинг ребёнка против трудности пункта) — та же логика с той же нуждой в калибровке, отдельно не считалась.

## 2. Кластер по теме

### 2.1. Правило [M]

**Сила по теме** s — «насколько хорошо решает» (определение владельца): в каждом классном событии темы (листок, КР) перцентиль-ранг ребёнка по баллу ○ + △ + доп (на КР △ ×2; Р155: решил ≥ 3 △ без ошибок в ○ — ○ засчитаны); два листка одного дня усредняются; дни усредняются с затуханием (полураспад 14 дней), так что последняя пара весит больше. ДЗ в силу не входит. **△-сигнал** — событие, где ребёнок решил ≥ 2 △ (мини-листок ≥ 4 из 6).

| уровень | правило | сейчас |
|---|---|---|
| верх | s ≥ 0,55 и ≥ 2 △-сигналов («знает базу, нужно продвинутое») | 9 |
| середина | остальные | 6 |
| низ | s < 0,4 | 8 |
| самый низ | s < 0,25 и самостоятельно («сам»/«уверенно») не больше одного навыка минимума | 3 |
| мало данных | работы меньше чем в 3 днях темы | 2 |

**Гистерезис [M]:** пороги над текущим уровнем ребёнка сдвинуты вверх на 0,05, под ним — вниз на 0,05 (чтобы выехать вверх, надо перескочить с запасом; чтобы провалиться — упасть с запасом); удержаться в верхе — достаточно 1 △-сигнала; за пересчёт — не больше одного уровня. Пересчёт — после каждой пары, когда внесены КР/приём. Ручная правка Вани (`ruchnye.csv`, «klaster») главнее. Новая тема стартует с уровнем прошлой темы до своей первой КР [M].

*[H] «Ворота» в верх* — кандидат владельца «написать идеально»: вход в верх только через КР, где все ○ минимума верны. В прототип не встроено: на 6.10 ○ «всё верно» — у единиц, ворота пока закрыли бы верх почти целиком; решить после следующей КР.

## 3. Хранение

**Рекомендация: плоские CSV в git (UTF-8, запятая), одна таблица — одна сущность; наблюдения — только дописываются.** Всё производное (статусы, кластеры, группы) не хранится, а пересчитывается. Эта папка — рабочий пример: `dannye/*.csv` собраны адаптером, движок читает только их.

| таблица | ключ | поля | кто пишет |
|---|---|---|---|
| `deti.csv` | id (r01…) | fio, aktiven | Ваня, раз в год |
| `navyki.csv` | kod | tema, deystvie, minimum (0/1), s_daty | Ваня, в начале темы |
| `sobytiya.csv` | id (KR-2026-10-06) | data, poryadok (в дне), tip KR/LS/ML/DZ/SAIT, rezhim sam/pomosch/dom, tema, istochnik | при подготовке пары |
| `punkty.csv` | (sobytie, punkt) | uroven ○/△/доп, obyazat 0/1, navyk_osn, navyki_vspom, obhod, uslovie [+ kluch, variant] | при подготовке листка/КР — разметка навыков ДО урока |
| `nablyudeniya.csv` | (sobytie, punkt, rebyonok, popytka) | verdikt + − 0 ?, podskazka (пусто/0/nav/ar), kto, istochnik, ts | бот, сайт, разметка фото КР — только дописывают |
| `ruchnye.csv` | строка | data, rebyonok, chto status/klaster, klyuch, znachenie, kto, prichina | только Ваня |
| `prepody.csv` | imya | rol seminar/priem, max_detej, k_klasteru | Ваня, перед парой |

**Как вносится каждый источник:**

- **Фото КР** → разметка (как сейчас, JSONL) → нормализатор пишет строки `nablyudeniya` с rezhim=sam (из события), popytka=1, verdikt по ключу из `punkty`. Пусто на ○ → «0».
- **Листок, устный приём (сейчас — CSV-таблица)** → строка на (ребёнок, пункт); «в» → «+». Попытки и подсказки пока пусто.
- **Telegram-бот ассистентов, этап 1 «плюсик»** → строка (sobytie, punkt, rebyonok, verdikt=+, kto=ассистент, ts). Этап 2 «попытки» → та же строка с popytka=n и verdikt − для неудачных. Этап 3 «обратная связь» → поле podskazka (0 / nav / ar) и, отдельно, `zametki.csv` (свободный текст, в статусы не идёт).
- **Сайт ДЗ с автоприёмом** → строки rezhim=dom (событие типа SAIT), popytka = номер отправки, verdikt по ключу. Бот-собеседник — то же + podskazka.
- **Ручная правка** — только `ruchnye.csv`; модель её не перезаписывает.

**CSV в git против SQLite [M]:**

| | CSV в git | SQLite |
|---|---|---|
| правка руками / глазами | да, в любом редакторе и в таблице | нужен клиент |
| история и откат | git: кто, когда, что | нет без отдельного журнала |
| одновременная запись бота и сайта | конфликт при параллельной записи — нужен один писатель или файл на источник | транзакции из коробки |
| объём (28 детей × ~30 пунктов × 30 недель ≈ 25 тыс. строк в год) | хватает с запасом | избыточно |
| дисциплина репозитория (`git_zona.py`, гейты) | встраивается | бинарник в git — плохо |

Решение: CSV — источник правды. Бот и сайт пишут каждый в свой файл (`nablyudeniya-bot.csv`, `nablyudeniya-sait.csv`) — нет параллельной записи в один файл; движок читает все `nablyudeniya*.csv`. SQLite — только если бот станет сервером с онлайн-запросами («что у Пети сейчас»), и то как кэш, пересобираемый из CSV.

## 5. Риски

- **Мало самостоятельных пунктов на навык [F]:** на КР 1–3 пункта на навык, «сдал» решается одним пунктом. Лечится не моделью, а КР: каждую неделю 6–8 ○-пунктов, на каждый навык минимума ≥ 2.
- **Разметка «пункт → навык» — суждение [M]:** пункты смешивают навыки (КР 6.10 ○6 — сумма + ±1 + «найди ошибку»). Ошибка разметки — ошибка статуса. Разметку делать до урока, спорные пункты не считать.
- **Листки с помощью завышают, а ДЗ не меряет [F]:** поэтому листки дают только П, ДЗ — ничего. Цена: «сам» видно только раз в неделю.
- **Принимающие ставят «+» неверным [F, мини-листок 6.10]:** бот без ключа размножит ошибку. Ключ — в `punkty.csv`, бот показывает его принимающему.
- **Дети, писавшие только △ [F]:** ○ не измерены — статус «нет данных/с помощью» при высокой силе. Правило: один ○-пункт минимума обязателен для всех.
- **Ассистенты не будут заполнять [M, владелец]:** система работает и на одном «плюсике» (этап 1); всё сверх — бонус.
- **Пороги кластера и выбор минимума — договорённость [M]:** резких разрывов в силе нет (`KLASTERY` §3); «самый низ» = 3 человека по условию, которое владелец должен подтвердить.
- **Ярлык [H]:** кластер виден детям через рассадку; гистерезис уменьшает дёрганье, но «самый низ» как название — только для команды.
