# `_generator` — illustration-aware сборщик слайд-колод

> ⚙️ **БРАТЬ ЭТОТ ГЕНЕРАТОР, НЕ ПИСАТЬ СВОЙ.** Любой HTML-артефакт (документ-вид, слайды, лекция, лонгрид) собирается только отсюда; писать новый парсер `md→HTML` запрещено (дорого и уже было — переделка `catalan/…/obyasnenie-html/`).
> - **Документ-вид** (поток текста для авторской вычитки, формулы KaTeX) → `python3 _generator/build_doc.py <src>` → `<src>/view.html`. Демо — `_generator/doc-demo/` (`matematika.md` ‖ `naupop.md`).
> - **Слайд-колода** (канон html-slides-studio) → `python3 _generator/build_deck.py <lecture>/src` → `src/dist/index.html`.
> - Правишь только источник (`content/*.md`, `illustrations/*.svg`, `tokens.css`); HTML — выход, руками не трогаешь. Только stdlib, без pip/сети.

Собирает **папку-источник** (`<lecture>/src/`) в один самодостаточный `index.html`
канона `html-slides-studio`. Обобщение `kurs leto 2026/istochnik/_generator/build.py`
на формат слайд-колод: каждая иллюстрация — отдельный файл, палитра и шрифты — в одном
месте, текст слайдов — markdown. HTML — чистая функция источника; правь источник, не HTML.

Полный контракт и решения — в `DESIGN.md`. Ниже — как пользоваться.

## Установка (один раз) — движок зовётся ИМЕНЕМ, а не путём

**Одна команда, из корня репозитория:**

```bash
python3 -m pip install --user -e _generator/ --no-build-isolation
```

Ставится пакет **`dvizhki`** — диспетчер (`_generator/dvizhki.py`), который знает, где лежат
движки, и потому избавляет от этого знания всех остальных. После установки движок зовётся
из ЛЮБОЙ рабочей папки — репозитория, worktree, папки курса:

```bash
python3 -m dvizhki doc <src-dir>     # build_doc.py        — документ-вид → <src>/view.html
python3 -m dvizhki dek <src-dir>     # build_deck.py       — слайд-колода → <src>/dist/index.html
python3 -m dvizhki vid <src-dir>     # tools/check_view.py — гейт выхода (правило №2 корня)
python3 -m dvizhki --spisok          # какие движки есть
```

Аргументы, поведение и коды возврата у движков ТЕ ЖЕ, что при запуске путём: диспетчер
исполняет тот же файл через `runpy`, не подменяя ни `__file__`, ни `sys.argv[0]`. Запуск
путём (`python3 _generator/build_deck.py …`) продолжает работать — он никуда не делся.

**Зачем это вообще.** Движок адресовался МЕСТОМ: скрипты курсов вычисляли путь к нему,
поднимаясь вверх от себя (`ROOT = Path(__file__).parents[N]`). Пока так, `_generator` нельзя
вынести в отдельный репозиторий — сломаются все разом и сломаются у курсов. Теперь место
знает один файл внутри самого движка, и вынос — это `git mv` плюс повтор команды установки.
Живая цена старой схемы уже оплачена: `obzory/…/zahod/render.py` считал уровни НЕВЕРНО
(`obzory/_generator/build_doc.py` не существует) и молча не работал.

⚠ **Три вещи, о которых надо знать заранее.**

1. **`--no-build-isolation` в команде — не украшение.** В боевой среде (системный `python3`
   3.9.6 из Command Line Tools, `pip 21.2.4`, `setuptools 58.0.4`) без него pip зовёт
   `setup.py develop --user --prefix=`, setuptools от этой пары гасит user-site и падает с
   `Permission denied` в системный `site-packages`. С флагом — `rc=0`.
2. **Консольная команда `dvizhki` тоже ставится, но по умолчанию НЕ в `PATH`:** `pip --user`
   кладёт её в `~/Library/Python/3.9/bin`. Нужна короткая форма без `python3 -m` — добавь
   в `~/.zshrc`: `export PATH="$HOME/Library/Python/3.9/bin:$PATH"`. Штатная форма, на
   которую переведены скрипты курсов, — `python3 -m dvizhki`: она работает без правки `PATH`
   и вдобавок сохраняет ТОТ ЖЕ интерпретатор, которым запущен зовущий скрипт.
3. **Установка привязана к папке.** `-e` запоминает, где `_generator/` лежал в момент
   установки. Переехал (`git mv`, новый клон, другой worktree) — повтори ту же одну команду.

## Команды
```bash
python3 _generator/build_deck.py dandelin/src            # линтер-гейт + сборка → dandelin/src/dist/index.html
python3 _generator/build_deck.py dandelin/src --lint     # только линтер

```
Только stdlib — ни pip, ни сети. Выход несёт HTML-коммент-баннер «СГЕНЕРИРОВАНО …
РУКАМИ НЕ ПРАВИТЬ» (не влияет на рендер).

## Рабочий цикл (ради чего всё)
- **Правка текста слайда** → редактируешь `src/content/sNN.md` (markdown) → пересборка.
  Диалект: пустая строка = абзац; `**слово**` = акцент `.acc`; `*слово*` = курсив;
  строки `- ` = список. Меняется только этот слайд.
- **Правка иллюстрации** → редактируешь один файл `src/illustrations/NAME.svg` (или
  `chapters/NAME.html` для 3D-главы) → пересборка. Ничто другое в 2360-строчном файле
  не сдвигается (проверено).
- **Палитра/шрифты** (единый стиль всех иллюстраций) → `src/tokens.css` (`:root{…}`).
  Линтер ловит `var(--x)`, не определённую в токенах (иначе SVG зальётся чёрным).

## Диалект документ-вида (`build_doc.py`) — что понимает движок

Всё ниже — **источник**, HTML руками не пишем. Расширено 2026-07-24 по разбору вида с владельцем.

| Пишешь в `*.md` | Получаешь |
|---|---|
| `## Заголовок` | раздел; **номер ставит движок** — руками номер НЕ писать (иначе «1. 1.»). Открыт |
| `### Подзаголовок` | подраздел + второй уровень оглавления. **Свёрнут** |
| `#### Пункт` | свёрнутый пункт (сюжет в списке, боковая находка). В оглавление не идёт |
| `{свёрнуто}` / `{развёрнуто}` в заголовке | перебить умолчание поштучно |
| `## Заголовок {скрыть}` | раздел остаётся в markdown, **в HTML не попадает** (служебное: источники, черновые заметки); гейт `check_view.py` про это знает и не краснеет |
| `**Утверждение 7 (Феллер).**`<br>`тело со следующей строки` | врезка; **метка отдельной строкой**, тело — абзацами. Врезки все одной геометрии, различаются цветом метки: `Теорема`/`Лемма`/`Предложение`/`Утверждение` — тёплый, `Определение` — синий, `Пример`/`Задача` — зелёный, `Замечание` — приглушённый синий. Серых безымянных плашек нет |
| строка внутри врезки целиком `$$…$$` | отдельный **центрированный** абзац-формула |
| строка внутри врезки с `**Зачин.**` | новый абзац (шаг доказательства) |
| `*Доказательство — подпись.* тело` **сразу за** утверждением | свёрнутый кат **внутри той же врезки**, без зазора |
| `*Доказательство.*` отдельно | свёрнутый кат сам по себе |
| `*Статус.* …` | уезжает **на правое поле** (это оговорка, не поток чтения) |
| `⚑ Флаг: …` | тоже на правое поле, красным |
| `> поле:mn …` | заметка на правом поле (370px, кегль как у основного текста) |
| `> поле:insight Тег \| текст` | прозрение — **тоже на поле**, голубым (это мост и комментарий, не главная линия) |
| `> поле:foot …` | **в HTML не идёт** (закрывающий статус черновика — для автора) |
| `**Пример 2.**`, `**Замечание 1.**`, `*Техфакт.*`, `*Рассказ.*` | свои врезки |

Чего движок **не умеет** (пишем сырым HTML — он пропускает блоки, начинающиеся с `<figure`, `<svg`,
`<div`, `<table`, `<details`): markdown-таблицы. Иллюстрация — инлайновый `<svg>` внутри `<figure>` с
`<figcaption>`, классы только `.s-*` (словарь примитивов).

**Иллюстрация на правое поле:** `<figure class="mn">`. **Критерий жёсткий и считается из `viewBox`:
высота/ширина ≥ 0,6 → на поле, иначе во всю строку потока.** Широкая полоса в жёлобе сжимается до
нечитаемости, высокая в потоке оставляет по бокам пустоту.

**Решай, КУДА рисунок пойдёт, ДО того как его рисуешь — и рисуй под это место.**

| Место | Каким рисовать |
|---|---|
| в потоке (во всю строку) | **горизонтальным**: длинная траектория, лента шагов, ряд панелей бок о бок. Тянуть в ширину, не в высоту |
| на поле | **узким, вытянутым вверх**: столбик, квадрат, компактная фигура. Ширина в жёлобе фиксирована (370px), лишняя ширина = мелкий шрифт |

Обратный ход — тот же: рисунок «почти проходит» → **чинить РИСУНОК, а не правило**. Обрезать поля,
убрать подписи, дублирующие `figcaption`, урезать хвост (для диагоналей Паскаля нужна вся диагональ,
а не вся строка), сжать шаг сетки. Живые прецеденты — `_illustracii/DISCIPLINA.md`.

Ставить фигуру **сразу за тем абзацем или утверждением, который она иллюстрирует**: на поле она
встаёт на его уровень.

**Внутри рисунка — только метки.** Слова-заголовки («суммы», «здесь видно, что…») из графики
убираются: пояснение живёт в `figcaption`. Служебные подписи прижимаются к краю, а сам предмет
рисунка центрируется — иначе он выглядит съехавшим (живой прецедент: подписи `n = 0…5` слева
сдвинули треугольник Паскаля вправо).

**Как устроено поле.** `.mn` — не `float`, а абсолют в жёлобе. `float` заставлял основной текст
обтекать заметку, то есть резал колонку: заметка выглядела вставкой в текст. Абсолют с `top:auto`
встаёт на статическую высоту и ширину колонки не трогает. Скрипт (`§4г`) разводит наложения и
**удерживает заметку внутри её раздела**: если она не помещается снизу, поднимается так, чтобы
кончалась на границе раздела (иначе комментарий про Серпинского уезжает читаться к Вандермонду).
Пересчёт — после набора формул, при сворачивании секций, при изменении ширины окна. Вертикальной
линейки у заметки нет: поле отделено пробелом и кеглем, разделитель выглядит байкой.

**Метка «текст ↔ поле».** Каждая заметка получает пару звёздочек: в тексте — надстрочная в конце
того блока, к которому она относится, в самой заметке — обратная. Видно, в какой момент заметку
читать, и откуда она пришла. Ставится движком, от автора ничего не требуется.

**Перекрёстные ссылки.** Упоминание «по утверждению 4», «из определения 2» **со строчной буквы**
автоматически становится ссылкой на соответствующую врезку. С прописной («Утверждение 4.») — это
метка самой врезки, она не линкуется. Работает для утверждений, теорем, лемм, предложений,
определений, примеров и замечаний.

**Навигация вида:** у каждого раздела и подраздела свой треугольник; в оглавлении группы
сворачиваются (по умолчанию закрыты — меню это компактный скелет), клик по разделу раскрывает его
подразделы как аккордеон, раскрывает секцию в тексте и прокручивает к ней; при скролле меню само
разворачивает группу того раздела, который читается. Плюс кнопки «развернуть всё / свернуть всё».

Служебного в виде НЕТ: ни `status`/`регистр`/счётчика долгов, ни надписи про KaTeX-рантайм, ни
имени папки в шапке — заголовок берётся из `#` первого потока.

### Нумерация врезок и рисунки — три факта, каждый стоил красного гейта

**Номер из метки движок ВЫРЕЗАЕТ и по умолчанию не показывает.** `**Определение 7 (индикатор).**` рендерится как «Определение (индикатор)»; номер уезжает в `id`-якорь. Показать номера — опт-ин во фронтматтере: `nomera: da`.

**Нумерация врезок — ОДНА сквозная последовательность на файл**, общая для определений, утверждений, примеров и задач. Три независимых ряда (Определение 1–12, Утверждение 1–13, Задача 1–20) выглядят естественно и валят `check_termin.py`: он читает объявленные номера как позиции, и «Пример 4», использующий «Определение 5», для него — термин, работающий раньше определения.

**Нумерация ПОФАЙЛОВАЯ, поэтому кросс-вкладочные ссылки по номерам мертвы.** «По утверждению 7» из пятой вкладки не найдёт утверждение из третьей. Между вкладками ссылаться ТОЛЬКО по имени: «по линейности математического ожидания (лекция 3)».

**🔴 Каждую иллюстрацию РЕНДЕРИТЬ и смотреть глазами.** Для дек-движка это правило записано (`../buffon/README.md §Цикл одной правки`), для документ-движка не было. Гейты его не заменяют: `check_view.py` проверяет, что текст не съеден, а не что рисунок понятен. В песочнице без браузера годится `pip install cairosvg --break-system-packages`, вырезать `<svg>` из источника, подставить в него `<style>` с определениями `.s-*` и отрендерить в PNG. *Цена 2026-08-02: из пяти SVG, прошедших все гейты, два были непригодны — в схеме-дереве узлы-тупики попали внутрь заливки соседней области и слились с узлами другого типа; на числовой прямой две встречные дуги легли друг на друга одной жирной линией. Обе поломки видны только на картинке.*

## Проверка (гейт «может провалиться»)
Пересборка **рендер-идентична** оригиналу. Доказано без браузера: после снятия
HTML-комментариев и схлопывания пробелов пересобранный `dist/index.html` совпадает
с `dandelin/index.html` **символ-в-символ** (обе нормали = 3 004 501 симв.); все 21
шаблон иллюстраций, 10 3D-глав, 5 шрифтов, 15 растров на месте, список потерь ПУСТ.
Это сильнее скриншот-сверки: на вход рендереру подаётся идентичный DOM.

Глазная попиксельная сверка — на своей машине (в песочнице браузера нет):
```bash
python3 _generator/render.py --compare dandelin/index.html dandelin/src/dist/index.html _render
```
(нужен Chrome + `pip install playwright pillow && playwright install chrome`.)
