# DVIZHKI — семейство движков markdown→HTML (`_generator/`)

> **Когда читать:** проектируешь/правишь сборку markdown→HTML (дек ИЛИ документ Фазы I); понимаешь роль `_generator` в фабрике. · **Что это:** `_generator/` — общий ДОМ ДВИЖКОВ (решение владельца 2026-07-11, вар. 1): движки не сливаются в один код (разные модели данных), но живут в одной папке под ОДНИМ контрактом; `_studio` — мозг фабрики, который ими пользуется. · **Куда дальше:** контракт хранения дека — `../_studio/konvejer/FORMAT-ISTOCHNIKA.md`; техника-первоисточник — `../_studio/zhurnal/2026-07-10_sborka-konvejera/distillat-tehnika-md-html.md`.

## Общий принцип семейства (контракт, которому обязаны ВСЕ движки)
1. **markdown — источник истины** (быстро/дёшево править содержание), **HTML — только вид**.
2. **Пересборка md→HTML — чистый Python, БЕЗ токенов** (stdlib: `re/pathlib/argparse/html/base64`; без сети/pip). Правка текста стоит копейки, пересборка — секунды.
3. **Линтер-гейт до сборки** (структурная ошибка → сборка прервана, exit 1).
4. **Выход смотрибелен** (самодостаточен настолько, насколько нужно стадии).
5. Правка = дешёвое изменение markdown, **не** HTML.

Родоначальник — `build.py` (в проекте `kurs leto 2026`, `istochnik/_generator/`). Наш дек-движок `build_deck.py` в коде задокументирован как его потомок. То есть это не «две разные истории», а **одно семейство**.

## Движок 1 — ДЕК (`build_deck.py`) · ГОТОВ
Вход: `<лекция>/src/` (`content/*.md` + `slides/*.html` + `illustrations/*` + `tokens.css` + `shablon.html` + `engine.js`). Выход: ОДИН самодостаточный `dist/index.html` канона — **фиксированный слайд-канвас 1440×810 + сцены**. Контракт — `FORMAT-ISTOCHNIKA.md`. Гейт правки — render-identity (byte-exact на эталонах доказан). Модель данных: слайды с жёсткой геометрией.

## Движок 2 — ДОКУМЕНТ (`build_doc.py`) · ГОТОВ
**Назначение:** растущие markdown-документы Фазы I (интервью → концепт лекции → гибрид-источник → раскадровка) → HTML-вид для авторской вычитки. Модель данных: **ПОТОК текста** (не слайд-канвас), с полями и математикой.

**Возможности (из `build.py` + отлаженной техники владельца, см. дистиллят):**
- **Растущий источник со `status:`** (`skelet → chernovik → … → polno`), гейтится линтером/`check_docs` — ОДИН документ наполняется по стадиям (это ответ на A1: интервью не пятистрочная анкета, а старт живого документа).
- **Авторские пометки и «мат-долг» — по ЖИВОМУ формату владельца (A3), grounded в `catalan`/`kurs leto`** (`../_studio/zhurnal/2026-07-10_sborka-konvejera/distillat-format-teksta.md`). В HTML-виде три примитива: `.insight` (крупные прозрения/развороты), `.mn` (мелкие оговорки в правом поле), `.foot` (статус черновика). **Мат-долг = конвенция `⚑ Флаг` → `Флаг закрыт`** (грепается, нельзя молча пропустить; закрывается полным выводом). `<details>` в его практике было для ОГЛАВЛЕНИЯ, не для доказательств — **пересмотрено 2026-07-24 владельцем: доказательства сворачиваются по умолчанию, на уровне генератора** (Р36).
- **⚠ Развилка-линчпин (владельцу, не наследовать молча):** гибрид-источник как ОДИН файл со свёрнутыми `<details>` (блюпринт Р5) vs ДВА параллельных документа — `rasskaz` (нарратив) + `skelet` (полные доказательства) — сшитых цитатой-сноской (реальная практика владельца). Сверить.
- **Гейт-против-воды:** приём-заглушка («аккуратно разложим промах») ОБЯЗАН нести рядом предложение-механизм (конкретный шаг). Без него — вода, гейт валит. (Реальный провал у владельца: `mir2-rasskaz §6` называет приём без единого шага; `statya.html` потом чинит конкретикой.)
- **Шаблон `skelet` для арки 3:** Определение / Утверждение / Доказательство / Источник / Уровень (школьно · приручение · вне-школы).
- **Математика** — KaTeX в HTML-виде для вычитки (на этой стадии допустим рантайм — это ВИД для автора, не финальный дек; в деке потом статический кэш, Р7).
- **Иллюстрации-плейсхолдеры 🖼** (описание + число сцен) — для стыка с аркой 9.
- **Регистр деки** (A4): поле в шапке источника — `устный` (текст рассказа НЕ ограничен по словам, лектор дораскажет; ограничение только на то, что попадёт на слайд) vs `читаемый` (слайд несёт весь довод). Едет в `brief.md` к арке 6.

**Статус:** РЕАЛИЗОВАН — `build_doc.py`. Всё перечисленное выше есть в коде: `> поле:` со словарём `FIELD_MAP`, `.mn`/`.insight`/`.foot`, лестница `status:` с линтером-гейтом, KaTeX-вид, мат-долг `⚑`, плейсхолдеры `🖼`, `registr:`.

**⚠ Пересборка вида 2026-07-24 (Р36–Р37, разбор с владельцем на живой лекции).** Описанное выше — состав; ниже то, что изменилось в ПОВЕДЕНИИ, и старые формулировки этого абзаца ему уступают:
- **Сворачивание — на уровне движка.** Каждый `##`/`###`/`####` — свой `<details>`; правило «раздел открыт, всё внутри свёрнуто». Доказательство (`*Доказательство.*` следом за утверждением) втягивается свёрнутым катом ВНУТРЬ врезки.
- **Оглавление — аккордеон** двух уровней с кнопками «развернуть / свернуть всё»; клик раскрывает секцию в тексте и прокручивает к ней.
- **Поле `.mn` — абсолют, не float** (float режет колонку); кегль как у основного текста; туда автоматически уезжают `*Статус.*` и `> поле:insight`; узкие рисунки — `<figure class="mn">` по критерию h/w ≥ 0,6. Наложения разводит скрипт, он же держит заметку внутри её раздела.
- **Мат-долг `⚑` в HTML НЕ рендерится** (учёт автора; линтер считает по markdown). `> поле:foot` — тоже.
- **Служебная секция** `## Заголовок {скрыть}`; поштучные `{свёрнуто}` / `{развёрнуто}`.
- **Автоссылки** «по утверждению 4» (со строчной) на врезку; пара звёздочек «текст ↔ поле».
- **Markdown-таблицы — умеет с 2026-08-04** (`md_table`, ветка 6a в `render_stream`): пайпы плюс обязательная разделительная строка `|---|---|`; выравнивание двоеточиями не поддержано. Сырой `<table>` по-прежнему проходит как доверенный HTML. Гейт `check_view` пропускает строки на `|` по той же причине, что и на `<`: это САМА разметка.
- 🔴 **Ловушка: правила `.d-proof` живут в ДВУХ местах** — в `DRILL_CSS` (для drill-рендера) и в главном шаблоне (~строка 1400). Работает второе. 2026-08-04 я поправил первое и отчитался о правке, которой на экране не было; поймал владелец. Правя CSS — грепни имя класса и убедись, что правило одно; если два, правь оба или проверь по СОБРАННОМУ файлу, а не по исходнику.
- **Метка «текст ↔ поле» (`.mn-ref`) — абсолютная, на полоске между колонкой текста и полями.** `attach_marker` вставляет её перед закрывающим тегом врезки, то есть ПОСЛЕ блочного ката с доказательством — оттого она вставала отдельной строкой на пустом месте. Лечится не нулевой шириной (дело не в переносе), а выводом из потока: блоки-носители получили `position:relative`, метка — `position:absolute;left:100%`. На экране уже 900 px возвращается в поток.
- **Что НЕ выводится в вид (решения владельца 2026-08-04).** `Статус: …` внутри метки врезки (`**Теорема 3 (имя). Статус: полное доказательство.**`) — параметр автора, движок его срезает (`_typed_block`); `check_view` снимает его теми же скобками, иначе гейт краснел бы на честном поведении. Голое `> поле:` больше не даёт `<aside>` в потоке: таких блоков в тексте не бывает, это объяснительная приписка — уходит на поля (`FIELD_MAP[""] = ("p","mn")`). Единственное место, где заводятся типы врезок, — `_STMT_CLS` + `_typed_block`; новых типов руками в markdown не изобретать.
- **Метка «текст ↔ поле» (`.mn-ref`) — нулевой ширины.** Раньше звёздочка переносилась на отдельную строку в конце врезки; теперь `display:inline-block;width:0;overflow:visible` — она рисуется правее последнего символа и перенос вызвать не может.
- **Кат «доказательство» — пилюля**, а не строка курсивом: `inline-flex`, скруглённая, в цвете акцента; по высоте занимает одну строку.
- **Оглавление — выдвижная шторка, с 2026-08-04** (Р-владелец: «левая полоса совершенно не нужна»). `.toc` стал `position:fixed` и уехал за левый край; на виду только язычок `☰` (псевдоэлемент `::after`, поэтому наведение на него = наведение на саму шторку). Наведение выдвигает поверх текста, уход мыши убирает — без единой строки JS. Поток занял всю ширину (`.layout` в одну колонку), кегль 21→23 px, `.stream` 790→950 px. На экране уже 900 px шторки нет — оглавление снова в потоке. ⚠ Заливки врезок (`.example`, `div.note`, `.tech`, `.mn`, `code`, `.cue`) были захардкожены светлыми и в тёмной теме светились; переведены в переменные `--box`, `--box-soft`, `--task-soft`, `--rem-soft`, `--code-bg`, `--cue-bg`, `--chip`.
- **Тёмная тема — с 2026-08-04.** Умолчание берётся из `prefers-color-scheme`; тумблер «тема» внизу слева перебивает системную настройку и запоминает выбор в `localStorage` (на `file://` работает не везде — потому через `try`). Палитра нейтрально-тёмная, не чёрная: фон `#1b1e22`, текст `#dcd8d0`. Все цвета вида — переменные `:root`; добавлены `--faint` (хром: стрелки, номера) и `--quiet` (курсивные метки), раньше они были захардкожены и в тёмной теме светились.
Полный диалект автора — `README.md §Диалект документ-вида`; визуальный контракт — `../_studio/docs/kak-delat/STANDART-oformlenia.md §3–4`.

Источник правды по разметке и виду — `../_studio/docs/kak-delat/STANDART-oformlenia.md`, по содержанию текста — `STANDART-teksta.md`. Этот файл описывает только принципы семейства движков.

## «Видеть, как выглядит, пока правишь» (важное требование владельца)
Смысл разделения md/HTML — дешёвая правка; НО автор и Claude-редактор должны ВИДЕТЬ результат (влезает ли, как сидит текст/поля/формулы), иначе «правлю вслепую».
- **Дек-движок:** `render.py` (скриншоты всех слайдов) + `audit.py` (overflow `.zone`, палитра) — Claude смотрит PNG/отчёт.
- **Doc-движок:** HTML-вид открывается напрямую (поток без фикс-канваса — переполнения слайда нет, но видно, как сидит текст, поля, формулы). Цикл: **правлю md → Python пересобирает (0 токенов) → смотрю HTML**. Claude после правки обязан пересобрать и глянуть вывод, а не править вслепую.
- **Раскадровка (арка 5, A5/A6)** = самый дешёвый doc-движковый вид слайд-текстов: посмотреть, как сидит, поправить markdown, пересобрать. ОДИН источник истины (markdown) на всех стадиях: раскадровка → тексты → финал; HTML — вид на каждой.
