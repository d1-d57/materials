# DESIGN — illustration-aware генератор колод (`build_deck.py`)

Спроектировано на Opus; реализация — Sonnet. Наследует философию
`kurs leto 2026/istochnik/_generator/build.py`, но для формата слайд-колод
`html-slides-studio` (канон 4-х блоков), с иллюстрациями как отдельными файлами.

## 1. Зачем
`build.py` (Markdown→страница) и `spetsmat_db` (база→HTML) не умеют иллюстрации
как отдельные файлы. Колоды `materials/*` — самодостаточные монолиты 2.5–3 МБ:
текст, палитра, шрифты, десятки иллюстраций (SVG / base64 / 3D-iframe / canvas-sim)
вшиты в один файл. Нужен генератор, который собирает **папку-источник**
(`content/*.md` + `illustrations/*` + `tokens` + `shablon.html`) обратно в один
самодостаточный `index.html` — так, чтобы:
- правка **текста** слайда была быстрой правкой markdown (не HTML);
- правка **одной иллюстрации** не требовала чтения других файлов;
- **палитра и шрифты** жили в одном месте (единый стиль всех иллюстраций);
- **вёрстка** была отдельным слоем;
- выход оставался **самодостаточным** и пересобирался быстро и дёшево.

## 2. Философия (из `build.py`)
- HTML — чистая функция источника. Правь источник, не HTML.
- **Линтер-гейт** перед сборкой: структурная ошибка → сборка прервана (exit 1).
- Чистая **stdlib** (`re, html, base64, pathlib, argparse`). Без сети/pip/React/сборщиков.
- Выход самодостаточен: всё вшито, открывается офлайн, ноль внешних asset-URL.
- Шапка выхода: HTML-коммент + видимый баннер **«СГЕНЕРИРОВАНО ИЗ src/ — РУКАМИ НЕ ПРАВИТЬ»**.

## 3. Что генератор делает и НЕ делает
**Делает:** собирает 4-блочную колоду канона из папки-источника; текст слайдов
рендерит из markdown; **всё остальное вшивает ДОСЛОВНО** из отдельных файлов
(иллюстрации, симуляции, 3D-главы, движок, шрифты, токены).

**НЕ делает:** не парсит и не преобразует внутренности иллюстраций/симуляций/three.js;
не переписывает движок; не трогает `istochnik`/`spetsmat`; не тянет KaTeX-рантайм
(математика печётся заранее в статический HTML — §7).

> Ключевая простота: единственный «умный» преобразователь — `markdown-текст → HTML зоны`.
> Всё прочее — конкатенация, а значит по построению без потерь.

## 4. Контракт папки-источника
```
<lecture>/src/
  brief.md            — фронтматтер: id, title, canvas (1440×810), ПОРЯДОК слайдов,
                        provenance (из какого index.html распилено), заметки/плейсхолдеры
  shablon.html        — 4-блочный каркас с плейсхолдерами (§5)
  tokens.css          — :root{...}: ПОЛНАЯ палитра + типо-токены — ЕДИНЫЙ источник стиля
  base.css            — структурный CSS канона (#stage/.slide/.zone/.fit/сцены) — дословно из deck-skeleton
  grids.css           — пер-слайдовые грид-раскладки (слой «вёрстка — отдельная забота»)
  overlay.css         — canon-overlay (акцент, размеры, blur_css, ритм) — опц., дословно
  engine.js           — блок [4] движок — ДОСЛОВНО, не править
  fonts/              — вшиваемые woff2 (base64) + @font-face манифест (fonts.css)
  content/  sNN.md    — ТЕКСТ слайда (markdown; поверхность быстрых правок)
  slides/   sNN.html  — layout-фрагмент: <section class="slide" id=..> с зонами,
                        {{слотами}} текста и пустыми data-ill боксами
  illustrations/ NAME.svg   — по файлу на иллюстрацию (SVG); raster — NAME.img.txt (base64) или NAME.png
  chapters/ NAME.html — 3D-главы (полные документы для iframe) — дословно
  lib/      three.min.js — вендорные библиотеки — дословно
  sims/     lab.js, ext/*.js — фреймворк симуляций (buffon) — дословно
  math/     *.tex | formulas.json — исходники формул (KaTeX-печать), опц.
```
Всё, что «дословно», распиливается из монолита байт-в-байт и реинлайнится без изменений.

## 5. Плейсхолдеры `shablon.html`
`{{TITLE}} {{GEN_BANNER}} {{FONTS}} {{TOKENS}} {{BASE_CSS}} {{GRID_CSS}} {{OVERLAY}}`
`{{SLIDES}} {{ASSETS}} {{SIMS}} {{ENGINE}}`
Каркас повторяет порядок блоков канона (head → `<style>` → `#stage>#deck` слайды →
chrome → `<template>` реестр → sim-скрипты → движок). **0 нерезрешённых плейсхолдеров = гейт.**

## 6. Сборка — маппинг блоков
- **[1] `<style>`** = `{{FONTS}}`(@font-face base64) + `{{TOKENS}}` + `{{BASE_CSS}}` + `{{GRID_CSS}}` + `{{OVERLAY}}`.
- **[2] слайды** = `content-order` из brief: конкатенация `slides/sNN.html`, где каждый
  слот `{{copy}}`/`{{copy:zone}}` заменён на `render_md(content/sNN[.zone].md)`.
- **[3] реестр ассетов** = для каждого `data-ill="NAME"`, встреченного в собранных слайдах →
  `<template id="ill-NAME">{илл. файл дословно}</template>`. Эмитить **только используемые**
  (`refs = {data-ill}`); неиспользуемый файл → warn. 3D: `chapters/NAME.html` →
  `<script type="text/html" id="tpl-NAME">{файл}</script>`; `lib/three*.js` → `<script>{файл}</script>`.
- **[3b] sims** = `sims/lab.js` + `sims/ext/*.js` → `<script>{файл}</script>` **перед** движком.
- **[4] движок** = `engine.js` дословно (+ опц. именованные патчи `sim_reset`, `overview` —
  как точечные `str.replace`, из `buffon-canon-build.py`).

## 7. Текст — markdown-диалект (единственный «умный» рендер)
Минимальный диалект, воспроизводящий существующую вёрстку канона (ср. `build.py:render_inline`):
- пустая строка → границы `<p>…</p>` в `.copy`;
- `**жирный**` → `<b class="acc">…</b>` (**канон: `.acc`, не `<strong>`**);
- `*курсив*` → `<em>`; `$…$` → KaTeX inline; `$$…$$` → блок;
- `- ` список → `<ul class="tlist"><li>…</li></ul>`;
- намеренный `<br>` — по явному маркеру (`  \n` или `<br>` в источнике), артефактные не плодить.
- **Escape-люк:** если зона слишком нетривиальна для round-trip, `slides/sNN.html` держит её
  inner HTML **дословно** (без `{{слота}}`). Markdown — только там, где безопасно.
  Это и есть гарантия пиксель-гейта: сомнительное — дословно.

## 8. KaTeX
Математика печётся заранее в статический `<span class="katex">…</span>` **до** движка;
`katex-inline.css` + woff2 KaTeX вшиваются. Источник — `math/*.tex`/`formulas.json`,
предвычисление → карта `name→HTML`. Dandelin: математики нет. Buffon: есть — 2-й проход.

## 9. Линтер-гейт (структурный, exit 1 при любой ошибке)
1. **0** нерезрешённых `{{...}}` в выходе.
2. Каждый `data-ill="NAME"` имеет файл (`illustrations/NAME.*` или `chapters/` tpl) — иначе **битая ссылка**.
3. Каждый `var(--x)` в `illustrations/*.svg`/`grids.css`/`overlay.css` **определён** в `tokens.css`
   (неопределённая переменная в SVG → чёрная заливка — известный инвариант канона).
4. **0** внешних asset-URL (`src`/`href` на шрифты/js/картинки/css). Ссылки `<a href>` в контенте — разрешены.
5. Порядок слайдов из `brief.md` покрывает все `content/`+`slides/`; нет сирот/дублей id.
6. (мягко) неиспользуемые `illustrations/*` → warn.

Печатать самопроверку-статистику: слайдов, шаблонов, `class="katex"`, `blur-reveal`, вес КБ.

## 10. CLI (зеркалит `build.py`)
```
python3 build_deck.py <src-dir>            # линтер-гейт + сборка → <src>/dist/index.html
python3 build_deck.py <src-dir> --lint     # только линтер
python3 build_deck.py <src-dir> -o <path>  # выбрать выход
```

## 11. Стратегия распила (критерий «может провалиться»)
- **Milestone 1 — ДОСЛОВНЫЙ распил.** Режем монолит по 4 швам; каждый `<template>`/
  `chapter`/`sim`/иллюстрацию — в свой файл; движок/шрифты/токены/грид — в свои. Текст слайдов
  пока **дословный HTML** в `slides/sNN.html` (без markdown). Генератор реинлайнит дословно.
  **Verify:** пересобранный `index.html` рендер-идентичен оригиналу (скриншоты) и почти байт-в-байт
  (допустима нормализация пробелов). Риск текста = 0.
- **Milestone 2 — markdown-изация текста.** По слайду выносим прозу зон в `content/sNN.md`,
  ставим `{{copy}}`. После каждого слайда — render-check зоны. Не сошлось → откат зоны в дословный HTML.
- **Milestone 3 — buffon** (KaTeX + lab.js sims), опционально, тем же контрактом.

## 12. Границы
Не переписывать `istochnik`/`spetsmat`; не тянуть React/сборщики/сеть; движок не трогать;
рабочие файлы не менять ради красоты; **оригинал `index.html` не удалять до зелёного верификатора**.

## 13. На будущее (НЕ сейчас)
Отдельный редактор «слева рендер — справа текст». Генератор уже даёт для него основу:
`content/*.md` — готовая правочная поверхность, `dist/index.html` — предпросмотр.
