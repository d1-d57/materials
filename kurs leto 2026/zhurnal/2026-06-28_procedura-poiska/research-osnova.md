## 1. Оркестрация Claude Code — что реально можно

- **Субагенты:** Task-tool / Agent SDK. Параллель — sweet spot **3–5 на слой**; для десятков — **Workflow tool** (оркестрация вне контекста разговора). Вложенность — макс **5** (на глубине 5 спавнить нельзя). «Проверить» точные капы.
- **Модель на субагента:** да — `CLAUDE_CODE_SUBAGENT_MODEL=haiku` по умолчанию + промоут синтез-воркеров до Sonnet/Opus; в SDK `AgentDefinition.model`. **Тиринг реален и настраиваем.**
- **Длинный автономный прогон:** авто-компакт ~80%+ контекста, **может катастрофически упасть → потеря контекста**; **нет авто-resume между сессиями** → durable-состояние на диск инженерим сами; компактить рано (~60%).
- **Узкое место — не параллелизм, а rate-limits (ITPM/OTPM, на аккаунт).** Реалистично за 2 ч: **~50–100 субагентов всего** (3–5 одновременно), ~0.5–1M токенов агрегатно. «100 агентов разом» — миф; ширина набирается **последовательными батчами** дёшево.
- **Headless:** `claude -p ... --output-format json` — реально для «запустить и спать»; но **нет интерактивных подтверждений** → права пред-авторизовать; **сначала дайрон** (= наш пилот).

## 2. Мульти-агентная курация — паттерны и ловушки

- **Оркестратор-воркер (hub-and-spoke), не плоский рой.** Субагент = фильтр-компрессор: жжёт широкий контекст, возвращает **сжатую выжимку** (= заполненный scorecard + ссылки), не сырьё.
- **Переспецифицировать каждую задачу субагента** (расплывчатость = провал №1): цель + формат вывода + источники + границы.
- **Ширина → потом узко** (broad query → оценить ландшафт → бурить).
- **Отдельный проход цитат/факт-чека** после синтеза (Anthropic держит CitationAgent отдельно; галлюцинации цитат 11–57%). **Источник на каждый факт** + проверка «сказал ли источник это» (NLI-чек) + право сказать «не нашёл».
- **Один LLM-судья по ОДНОЙ фиксированной рубрике** (0–1 + pass/fail) — стабильнее «комитета». ← **прямо валидирует: `sistema-ocenki` = единственная фикс-рубрика.** Пинить + версионировать.
- **Тиринг:** ~90% работы на дешёвую/нано-модель + ~10% на сильную → ~86% экономии при «пренебрежимой» потере на дешёвой части; границу класть на **синтез/суждение**; дешёвый вывод гнать через **ту же** рубрику.
- **Ловушки:** разрастание контекста на мёрже; «больше агентов» перестаёт помогать (бывает −35%); **смещения судьи** (позиция ~10–15 пт, многословие 15–30 пт, само-предпочтение 10–25%); **дрейф рубрики**; фабрикация цитат; каскад ошибок; синхронные стопоры.
- **Защиты:** рандомизировать порядок кандидатов; в рубрике явно «длина ≠ качество»; судья ≠ семейство-генератор (у нас всё Claude → хотя бы иной **тир** + изолированный контекст судьи); пер-факт-энтейлмент; внешняя память/файлы; чекпойнты; трейс решений.

## 3. Портфельный / beam-поиск по набору с LLM-судьёй

- **Каркас:** island-seeded **beam/эволюция**: LLM **предлагает** целые наборы из 6 → рубрика/судья **оценивает** → top-b выживают, остальное в отвал → повтор. LLM = оператор мутации+кроссовера в одном вызове («вот 2 сильных курса со счётом — собери лучший, замени слабейший слот»).
  - **«Заморозить идеал»** = элитизм (чемпион копируется нетронутым). **«Углублять»** = beam. **«Выкидывать»** = прунинг. **«Вариации»** = MAP-Elites архив (лучший в нише) / Парето-фронт.
- **Island model (FunSearch) против схлопывания:** под-популяции эволюционируют врозь, периодически **мигрируют элиты**. ← **острова = позвоночники-кандидаты** (чемпион «компьютеры» + челленджеры «случайность», «язык/информация», …). Так подвижный позвоночник встроен механикой, а не на глаз.
- **Покрытие+разнообразие (выбор 6):** субмодулярность (убывающая отдача → редундантность штрафуется сама) + **жадный алгоритм** (гарантия ≈63% оптимума) + **MMR**: `argmax λ·Rel − (1−λ)·max Sim(уже выбранным)`, старт λ≈0.7. **Слабая-но-дополняющая лекция бьёт сильную-но-избыточную** = ровно «параллели переписывают 6». Это формальный движок нашего Н4/баланса §6.
- **Два уровня — constraint-then-rank (ε-ограничение), НЕ взвешенная сумма** (та достаёт лишь выпуклую часть фронта — «гениально-странный, но цельный» курс ей недоступен). ← **`sistema-ocenki` уже это: ворота = жёсткий пол (ε-ограничение), баллы = ранг.** Независимое подтверждение, что форма судьи правильная для эволюц-поиска.
- **Стоп:** выигрыш фронтгружен, плато к ~3-й итерации; кап **3–5 поколений**; стоп если чемпион не сменился 2 раунда / маржинальный выигрыш < ε.
- **РЕВАРД-ХАК (критично):** в петле автор↔судья счёт судьи растёт, а реальное качество встаёт/падает — **спонтанно**; причина — **общий контекст судьи и автора**. **Фикс: судить каждого кандидата в СВЕЖЕМ изолированном контексте**, без памяти оптимизации; держать **вынесенный якорь** (эталон Монте-Карло + 1–2 ручные сверки); **стоп, когда счёт судьи растёт, а якорь — нет.**
- **Один чемпион + вариации:** MAP-Elites (ниши = дуга сложности / подобласть слота-3 / тип входа; лучший в нише = готовая вариация) + пер-слот раннеры в пределах δ (сменные слоты).
- Источник: FunSearch https://storage.googleapis.com/deepmind-media/DeepMind.com/Blog/funsearch-making-new-discoveries-in-mathematical-sciences-using-large-language-models/Mathematical-discoveries-from-program-search-with-large-language-models.pdf · MMR https://aayushmnit.com/posts/2025-12-25-DiversityMMRPart1/DiversityMMRPart1.html · субмодуляр https://homes.cs.washington.edu/~marcotcr/blog/greedy-submodular/ · MAP-Elites https://parasdahal.com/notes/MAP-Elites/ · ревард-хак https://arxiv.org/pdf/2407.04549 · Self-Refine https://arxiv.org/pdf/2303.17651

## 4. Как это пересобирает дизайн (скелет v2)

**Подтверждения (приятное):** (1) `sistema-ocenki` = провабли правильная функция качества для эволюц-поиска (constraint-then-rank + единая фикс-рубрика). (2) Подвижный позвоночник = island model (механика, не «на глаз»). (3) Н4/баланс = субмодуляр/MMR (формальный движок). (4) «Один курс + вариации» = MAP-Elites архив + пер-слот раннеры.

**Поправки к картинке владельца:** (1) не «100 разом», а **~50–100 субагентов последовательными батчами по 3–5**, дёшево; узкое место — rate-limits, не параллелизм. (2) **Судью изолировать** от генератора (свежий контекст на кандидата) + вынесенный якорь — иначе прогон «полирует судью», а не курс. (3) **Durable на диск каждую волну** обязателен (компакт может убить контекст; авто-resume нет).

**Процедура (5 волн, оркестратор headless + Workflow, durable-артефакт после каждой):**
1. **GATHER** (Haiku, батчи 3–5, сетка «область×мотив»): кандидаты + сырьё + черновой scorecard + источник-на-факт; вернуть сжато на диск.
2. **TRIAGE** (дёшево): мёрж, дедуп (хэш), ворота-провалы в отвал (ε-ограничение), ранг к эталону; выжившие ~10–15.
3. **DEEPEN** (Sonnet, изолированный контекст/тему): discovery-fiction-крафт, факт-чек (пер-факт), полный scorecard, крючки/параллели; заморозить/копать/выкинуть.
4. **ASSEMBLE** (сильная, island-beam): острова=позвоночники; LLM предлагает наборы-6 (мутация+кроссовер); счёт = ворота набора + MMR-покрытие + изолированный судья-когерентности; элитизм→чемпион; миграция; MAP-Elites→вариации; пер-слот раннеры→сменные слоты; кап 3–5 поколений; **анти-хак-tripwire**.
5. **DOSSIER:** чемпион-курс + 3–4 вариации + сменные слоты + **научпоп вау-питч** + карта параллелей + scorecard'ы лекций + открытые развилки владельцу.

**Сквозное:** типизированный scorecard-контракт (жёсткая схема) · изолированный судья + вынесенный якорь · источник-на-факт + верификация · тиринг моделей · пред-авторизация прав · **пилот-дайрон** перед ночным прогоном.
