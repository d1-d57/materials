# Процедура-бэклог — правки в КАНОН машины (для переиспользуемой системы)

> Накопитель улучшений контракта машины `procedura/`, вскрытых живыми прогонами. **НЕ для текущего прогона** — для консолидации в переиспользуемую версию на закрытии арки. Цель владельца: идеальная переиспользуемая система (машина + методичка), а не разовый прогон → каждый баг прогона лечим как правку в канон.

## Сделано (в этом прогоне)
- **scope ворот НАБОРА.** TRIAGE рубил тему по `n1` (≤2 дорогих) — это ворот НАБОРА, не темы (потеряли флагман «нейросети»). Поправлено в `wave2.md`/`wave3.md`/`wave4.md`: отсев темы — только Г1–Г8 (+Н3 «контекст»); Н1/Н2/Н4 считаются на ШЕСТЁРКЕ в ASSEMBLE. Согласовано с каноном `sistema-ocenki` §6.
- **субстрат.** Headless `claude -p` / `orchestrate.sh` в этом окружении не авторизован (401) → ШЕЛЬФ. Рабочий субстрат — оркестрация субагентами Code в авторизованной сессии (как пилот). Переиспользуемую версию писать под этот субстрат, не под headless.
- **анти-холостой-успех.** Волна не «готова» при пустом/0-байтном/невалидном durable — проверять КОНТЕНТ, не код возврата. (Вшито в заход; перенести в контракт волн.)

## К правке (вскрыто прогоном — чинить на консолидации, НЕ сейчас)
- **w3-склейка: validate+repair, как в w2.** DEEPEN (Sonnet) тоже иногда ломает плоскую схему (в прогоне 3/15 частей невалидны). Контракт `wave3.md` должен на СКЛЕЙКЕ явно требовать: валидировать каждую часть и **чинить (стиль w2), а не молча ронять** — DEEPEN-контент дорогой, схемный слип механический.
- **Удачные паттерны оркестрации — забекать в контракт.** w1 «субагент-на-область» (не на ячейку) и w3 «часть-на-тему в `_w3parts/` → склейка» хороши для контекста/resume. Сейчас это импровизация оркестратора — сделать частью контракта/RUNBOOK.
- **Тиринг оркестратора.** Дефолт оркестратора — **Sonnet**, не Opus (координация дешёвая, ум — в субагентах; Opus только в ядре w4). См. `RUKOVODSTVO-zahodami` §8.
- **Время+токены по волне** в `run_log.txt` — стандарт (есть; закрепить в контракте волн).
- **Бюджет.** Лимиты Max 20x: 5-час окно большое (≳7M ток.), дефицит — недельные капы. Планировать тиринг под недельный бюджет, не под страх окна. См. RUKOVODSTVO §8.
