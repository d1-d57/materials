## Шаг 0 — ВАЛИДАТОР / РЕМОНТ (жёстко, перед всем; требование B2)
Дешёвый GATHER слипает ключи (A-ключи в B-объекте; `verdikt` прозой вместо enum; пропущенные поля). Для КАЖДОЙ строки w1:
1. Проверь конформность `scorecard.schema.json`.
2. **Невалид → ЧИНИ**, если чинится однозначно: верни `verdikt`-прозу к ближайшему enum (`ядро/продажник/тело/связка/доработать/выбыла`); разложи перепутанные `a*`/`b*` по местам; добери дефолты осознанно (не угадывая баллы — если балл невосстановим, ставь по рубрике заново).
3. **Не чинится однозначно → ВЫБРОСЬ** с записью в лог.
4. Веди `repair_log`: `{tema, problem, action: "починен"|"выброшен", detail}`. Лог идёт в отчёт прогона.

## Шаг 1 — мёрж + ДЕДУП
Много ячеек переоткроют Монте-Карло / крипто / Тьюринга. Слей дубликаты (хэш + семантика): одна тема — один лучший scorecard (объедини источники, возьми сильнейшие формулировки).

## Шаг 2 — ВОРОТА-ОТВАЛ (ε-ограничение, constraint-then-rank)
Отсев — **ТОЛЬКО по воротам ЛЕКЦИИ Г1–Г8** (+ Н3 «контекст»: тема не вписывается в «математику компьютеров»). Провал любого из них → `выбыла` или `доработать` (НЕ ранжируй проваленное выше прошедшего). Ворота — пол, не балл.

**НЕ отсевай тему по `n1`/`n2`/`n4`.** Это ворота НАБОРА (Н1 ≤2 дорогих · Н2 единство · Н4 покрытие) — свойства ШЕСТЁРКИ, не одиночной темы; они считаются в ASSEMBLE (w4) на конкретном наборе. Дорогая тема (`n1=false`) сама по себе НЕ выбывает — «дорогая» это сигнал, а лимит «≤2 дорогих» применяется к набору позже. _(Иначе теряем флагман вроде «нейросети» — согласованный дорогой core курса.)_ В пер-темовом scorecard `n1/n2/n4` — мягкая подсказка, не приговор.

## Шаг 3 — ПЕРЕ-ОЦЕНКА НАНОВО (требование B4)
**НЕ наследуй баллы GATHER.** Ты — сильная модель; поставь scorecard заново по `rubric.md`: де-инфлируй завышения Haiku (его «всё ядро / всё = эталону» — артефакт дешёвого тира), воспроизведи человеческие роли из якоря (дни рождения → разогрев/продажник, не самостоятельная лекция). Ранг к Монте-Карло по Pugh (лучше/=/хуже) по осям A и B.

## Жёсткие правила вывода
- Выход строго по `scorecard.schema.json`: массив выживших scorecard-объектов (полные, валидные).
- enum — кириллицей дословно. Ключи — латиницей.
- **ПЛОСКАЯ форма (критично):** `g1..g8`, `n1..n4`, `a1..a5`, `b1..b4` — поля ВЕРХНЕГО уровня объекта. НЕ вкладывай их в под-объекты `gates{}`/`axes{}`/`nabor{}`. `dvizhki` — объект из 4 ключей со значениями-строками `⊕/–/сильный` (НЕ один общий флаг, НЕ bool). (Пилот: без этого модель схлопывает форму.)
