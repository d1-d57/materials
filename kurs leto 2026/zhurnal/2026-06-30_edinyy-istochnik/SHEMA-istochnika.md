# СХЕМА единого источника правды — спека v2 (шаг 1 арки)

> **Что это.** Как в Markdown лежит ПОЛНАЯ карта курса, чтобы (а) править через агента по протоколу легко, (б) генерить из неё HTML программно, (в) ничего не терять, не дублировать и **не давать ссылкам/счётчикам расходиться**. Это **спека**, не сам источник: формат файлов + адресация + слой целостности + протокол правок + контракт генератора. Заполнение контентом и сборка генератора — следующие шаги (Code-заходы).
>
> **Опора:** формат лекции — канон `1-START-HERE/sistema-ocenki.md §2.5` (2.5.0–2.5.8); анатомия с примером — `../2026-06-28_nauchpop-chernovik/L4-pilot-v4.md`; решение о структуре — `resheniya.md` п.15; ресёрч решений (docs-as-code, бэклинки, целостность, COPE, агент-по-протоколу) — `biblioteka/ISTOCHNIKI.md` §«Единый источник MD→HTML».
>
> **v2 переписывает черновик v1** (аудит арки 2026-06-30): карта дроблена по типу, добавлены адресация стабильным id, слой целостности, привязка HTML↔текст и протокол правок. Обоснование развилок — в дневнике сессии 2.

## 1. Четыре принципа (из них всё остальное)

1. **Полнота — жёсткая.** В источнике лежит ВСЁ: научпоп + математика + все связи графа + детали глубокого банка + связующие тексты. HTML отражает источник целиком. На входе влития **существующий HTML — равноправный источник** (в нём есть дописанное вручную), не только цель на выходе.
2. **Один дом на факт (без пересечений).** Каждый кусок правды лежит ровно в ОДНОМ месте. Лекция-внутреннее — в файле лекции; всё кросс-лекционное (рёбра/нити, лица, теории, курсовые артефакты) — в карте. Лекция **ссылается**, не переписывает.
3. **Источник правлю — HTML смотрю.** Источник — Markdown (+YAML-шапка). Одна команда генератора → свежий самодостаточный HTML в дизайне v3/v4. Расхождений нет по построению: HTML — чистая функция источника.
4. **Адресация стабильным id (НОВОЕ — корень лечения расползания).** Лекции, лица, теории, нити ссылаются по **устойчивому id по смыслу**, не по номеру-позиции. Номер лекции — отдельное поле только для показа. Пересорт лекций не трогает ни одной ссылки. *Почему:* нумерация уже разъезжалась (v1 Л3=Криптография ↔ v2 Л4=Криптография) — позиционные ссылки рвутся при каждом пересорте; id переживает его.

## 3. Адресация и реестр id (НОВОЕ)

- **Лекция:** `id: kriptografiya` в шапке + `poryadok: 4` (только показ). Ссылка — `→[kriptografiya]` или короткий `→[L:kriptografiya]`.
- **Лицо:** `{turing}`; ссылка в прозе — `→[turing]`.
- **Теория:** `{teoriya-chisel}`; ссылка — `→[T:teoriya-chisel]`.
- **Нить/ребро:** `{predel}`; в прозе нить помечается `→[N:predel]`.
- **Реестр id НЕ ведём руками.** Линтер строит индекс из мест объявления (шапки лекций, карточки `{…}` в карте). Так же и счётчики — **ничего не хранится, всё деривируется из живых файлов → расходиться нечему.** Дубль id и ссылка на необъявленный id — ошибки сборки (§7).

## 4. Формат файла-лекции (v4 §2.5, машиночитаемый)

### 4.1. Шапка (YAML)
```yaml

poryadok: 4                       # только показ; пересорт меняет это, не ссылки

role: ядро                        # ядро | тело | связка

budget: { math_blokov: 20, vsego_blokov: 38 }
status: skelet                    # skelet | chernovik | polno — ПЕРЕКЛЮЧАТЕЛЬ строгости линтера
---
```

### 4.2. Раздел — единица лекции
Заголовок: `## §N · ТИП · Название {флаги}`
- **ТИП** (§2.5.1/2.5.5): `КРЮЧОК` · `МАТЕМАТИКА` · `РАССКАЗ` · `ТЕХБЛОК` · `ЧЁРНЫЙ-ЯЩИК`.
- **{флаги}** (опц.): `{теорема-заголовок}` · `{отложимо}` · `{в-парах}` · `{в-кармане}`.
- Порядок разделов = порядок живой лекции, **линейно** (§2.5.3); отложимое — флагом/полем, не выносом в конец.

**Матблок** (`МАТЕМАТИКА`/`ТЕХБЛОК`/`ЧЁРНЫЙ-ЯЩИК`) — ровно 4 поля канона §2.5.2, тегом-абзацем:
```
**[утверждение]** $a^{p-1}\equiv 1\pmod p$ для простого $p$. Пример: $2^6=64\equiv1\pmod7$.
**[логика]** Быстрый односторонний тест простоты; ломается на числах Кармайкла (561).
**[подробность]** 2–3 примера руками + контрпример 561 = 3·11·17.
**[чёрный-ящик]** Доказательство самой теоремы Ферма (отложимо).
```
**Рассказ-блок** (`РАССКАЗ`) — полная проза научпопа (объём НЕ урезаем, §2.5; голос — `popsci-narrative` + Ильяхов/Нора Галь). **Формулы:** инлайн `$…$`, выносные `$$…$$` → компонент `.eq`. Раздел `{теорема-заголовок}` → его `[утверждение]` → `.claimbox`.

### 4.3. Поля-сноски (§2.5.7) — typed-блоки
```
> поле:нить →[N:sluchaynost-instrument] →[sluchaynost] случайность как доказательство
> поле:в-кармане HTTPS, замок в адресной строке
> поле:отложимо доказательство Эйлера — в записи
> поле:честно факторизация НЕ NP-полна (NP∩co-NP); если P=NP — RSA падает →[granicy]
> поле:боковой рассекречено 1997
> поле:cue-визуал роторы Энигмы (фото)
> поле:cue-интерактив раунд ZKP в парах
```
Типы: `нить` · `в-кармане` · `отложимо` · `честно` · `боковой` · `cue-визуал` · `cue-интерактив`. Генератор → `aside.note` / чип `.ln` / `.cue`.

### 4.4. Кросс-ссылки в прозе
- `→[informaciya]` — лекция (чип `.ln`; подпись = `title` лекции, не номер).
- `→[turing]` — лицо (генератор вставляет портрет `figure.port` у первого упоминания + чип; данные лица — в `lica.md`, НЕ здесь).
- `→[T:teoriya-chisel]` — сквозная теория. `→[N:predel]` — нить.
Лекция упоминает лицо/теорию **одной фразой роли-здесь**; био/маршрут/суть — в карте. Дубля нет.

### 4.5. Домашка (§2.5.6)
```
## §N · ДОМАШКА
1. Проверить малую теорему Ферма для p=11, a=2,3,7.
2. Обманет ли тест Ферма 341 по осн. 2? по 3? (341=11·31.)
7. * Почему ключ короче сообщения не даёт абсолютной стойкости (1 бит).
```
`*` после номера = со звёздочкой / черновик чёрного ящика. 5–10 задач.

## 6. Правило «полно и без пересечений» (контракт полноты)

| Род правды | Дом | Лекция-файл делает |
|---|---|---|
| Матблок (4 поля) данной лекции | файл лекции §4.2 | держит целиком |
| Научпоп-проза, байка данной лекции | файл лекции (РАССКАЗ) | держит целиком |
| Поле-сноска (нить/в-кармане/честно…) | файл лекции §4.3 | держит; `нить` ссылается `→[id]` |
| **Ребро / сквозная нить** | `karta/graf.md` | только `→[id]` в прозе |
| **Действующее лицо** (био, маршрут, фото) | `karta/lica.md` | только `→[id]` + фраза роли-здесь |
| **Сквозная теория** | `karta/teorii.md` | только `→[T:id]` |
| **Курсовой артефакт** (таймлайн/карта/манифест…) | `karta/svyazujushchee.md` | ничего (курсовой уровень) |

**Дословный повтор** (если блок обязан читаться идентично в двух местах) — не копия, а явная **трансклюзия** `{{вкл:id}}` с одним домом; генератор инлайнит при сборке.

**Полнота проверяема:** у любого куска банка ровно один слот. Верификатор влития (§9) строит чек-лист из ВСЕХ входов и проверяет, что каждый узел/ребро/лицо/теория/артефакт приземлился.

## 7. Слой целостности — «правлю кусок, вижу задетое» (НОВОЕ)

Два инструмента поверх контента; гоняются на каждой правке.

**Бэклинк-индекс.** Скрипт инвертирует все `→[id]` → `задето[id] = [(файл, §, цитата)]`. Перед правкой сущности агент спрашивает индекс: «кого задену, если трону `{turing}`» — и проходит все места. Это и есть «правлю тут — вижу там».

**Линтер-падающий-тест — два яруса** (строгость по `status`):

- **Структурные (жёсткий гейт, всегда — это баги):** `→[id]` резолвится в объявленный id · нет дубля id · матблок несёт все 4 поля · заголовок раздела валиден · нет битой `{{вкл:id}}`.
- **Редакционные (мягко; жёстко только при `status: polno`):** ≥~20 матблоков · квоты графа (`≥3 сквозных через ≥5` · `≥6 через ≥4` · `≥10 парных` · лицо в `2–5` лекциях · `≥4` типа нитей · `0 сирот`) · домашка 5–10. Лекция в `chernovik` честно недобирает — линтер пишет «L4: 14/20 матблоков», но сборку НЕ валит.

Счётчики/квоты линтер пересчитывает из живых файлов — **хранить и рассинхронить нечего.**

## 8. `PROTOKOL.md` — «где что править» (НОВОЕ)

Протокол в традиции NAVIGATION: для каждого типа правки — дом, задетое, что проверит линтер. Скелет:

| Появилось / правишь | Дом (куда) | Задето (проверь) | Линтер |
|---|---|---|---|
| Новое лицо | `karta/lica.md` (+`{id}`, фото) | лекции, где упомянуть `→[id]` | появления 2–5 |
| Лекция упоминает лицо | `→[id]` + фраза роли-здесь | `lica.md` поле `появления` | резолв id; счёт появлений |
| Новое/правка ребра или нити | `karta/graf.md` | обе лекции в `где:` | квоты графа |
| Сменил порядок лекций | поле `poryadok` в шапках | — (ссылки не трогаются) | `poryadok` уникальны 1–7 |
| Новая/правка теории | `karta/teorii.md` (+`{id}`) | лекции в `лекции:` | резолв `→[T:id]` |
| Матблок/проза лекции | раздел файла лекции | поля-сноски-нити на этот кусок | 4 поля; счётчик матблоков |
| **Правка РАМКИ** (цель лекции, манифест) | `cel` / `svyazujushchee.md` | манифест · таймлайн · карта-идей | **НЕ ловится → ФЛАГ на ревью** |

**Правило семантического рипла.** Механический рипл (переименовал id → починить ссылки; сменил появление → счётчик) ловят индекс и линтер. **Семантический** (сменил рамку → надо пересмотреть манифест/таймлайн/соседние переходы) алгоритм не ловит — агент ОБЯЗАН флагнуть «задето по смыслу: {манифест, таймлайн} — на ревью» и вынести владельцу. **Ревью-гейт:** смысловые ripple-правки идут через владельца, не закрываются молча.

## 9. Контракт генератора (для будущего Code-захода — не строим сейчас)

- **Вход:** папка `istochnik/`. **Выход:** один самодостаточный HTML (офлайн, фото base64, SVG-инфографика) в дизайне v3/v4 (`.claimbox/.eq/.cue/aside.note/figure.port/.ln/.h3tag/.techblock`). Одна команда.
- **Технология (направление, решается на Code-заходе):** свой тонкий Python (`markdown-it-py` + `mdit-py-plugins` container + Jinja2-шаблон, снятый с v3/v4) — наш случай требует Python-логики (SVG-карта из `graf.md`, резолв `→[id]`, base64-портреты). **Pandoc** `--standalone --embed-resources` + Lua — нулевой-код baseline для сверки.
- **Парсит:** YAML-шапки; разделы `## §N · ТИП · …{флаги}`; 4 поля матблока по тегам; поля-сноски `> поле:<тип>`; домашку; `karta/*.md` по `|`-строкам.
- **Резолвит (двупроходно — сперва собрать все id):** `→[L:id]`→чип `.ln` (подпись=title); `→[id-лица]`→портрет `figure.port`+чип; `→[T:id]`→стиль нити; `graf.md`→дуги/«метро»; `svyazujushchee.md`→4 SVG; `{{вкл:id}}`→инлайн канонического блока.
- **Привязка HTML↔текст:** на каждый блок — атрибут `data-source="L4-kriptografiya.md §6"`; коммент в рендере однозначно ведёт к MD-блоку. Комменты возвращаются маркерами в MD (паттерн md-redline): агент читает → правит → гасит.
- **Дисциплина:** `karpathy-guidelines` (минимум кода, детерминизм); проверяемый критерий («правлю поле в MD → одной командой HTML меняется ровно там»); верификатор «MD↔HTML без потерь».
