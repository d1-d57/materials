## 1. Зачем это (корень, а не симптом)
Симптом: мощные, продуктивные исследования и решения оседают НЕ там, где их найдёшь при работе, — и не доходят до сборки лекций. Живой пример прямо сейчас: свежий мастер-концепт лежит в папке ЗАКРЫТОЙ арки, а индекс `NAVIGATION.md` зовёт «текущим» устаревшую версию v2.

**Корень: не настроены (или не соблюдаются) правила против расползания — «что и в какой момент править».** Пока это не починено, дальше в лекции идти нельзя — работа будет теряться. Это блокер.

**Цель этой арки — система «одного окна».** Для каждого типа работы — ОДНО место, куда смотреть и куда писать, с явным текстом «как обновлять» и «в каком сценарии/арке сюда приходить». Плюс механизм, который не даёт расползаться снова. Итог: любое исследование/решение гарантированно «приземляется» в нужное место и идёт в работу.

> NB: у владельца есть эталонная настроенная система в другом проекте (на её архитектуре строили этот). В начале арки спросить/посмотреть её паттерны и адаптировать — не изобретать заново.

## 5. Целевая система «ОДНО ОКНО» (спроектировать, утвердить, вписать в NAVIGATION)
Единственная карта «тип работы → одно место читать → куда писать». Черновик для доводки:

| Работаю над… | Одно окно (читать) | Куда писать / обновлять |
|---|---|---|
| **концепцией** (нити, манифест, герои, приложения, области) | `ideal-koncept-kursa.md` (+ `dramaturgiya`) в постоянном доме | туда же; правило обновления — в шапке файла |
| **ТЗ** (ворота, баллы, формат лекции) | `1-START-HERE/sistema-ocenki.md` | туда, по правилу версионности §7 |
| **конкретной лекцией** | `istochnik/L…` (+ её арка, если активна) | туда |
| **дизайном / HTML** | `5-html/` (+ дизайн-канон, если появится) | туда |
| **промо / лендингом / питчем** | `6-lending/` (питч `pitch-kurs.md`) | туда |
| **решением / «почему»** | `1-START-HERE/resheniya.md` | «Принятые» |
| **будущим / отложенным** | `1-START-HERE/beklog.md` | туда |
| **статусом / следующим шагом** | `1-START-HERE/dnevnik-i-plan.md` | «Текущее состояние»/«Ближайший шаг» |
| **источниками** | `biblioteka/ISTOCHNIKI.md` | туда |

В шапке каждого «окна» — короткий блок: «что сюда кладём · как обновлять · из каких арок/сценариев сюда приходить». `NAVIGATION.md` — единственная карта, ведущая в эти окна.

## 6. Действия консолидации
1. **Концепт → постоянный дом.** Перенести `ideal-koncept` + `dramaturgiya` (+ `predlozhenie`/`kanon`/`obzor` как провенанс) из арк-папки в `1-START-HERE` рядом с ТЗ (рекомендация — «одно место» концепт+ТЗ) ИЛИ в отдельную `0-koncept/`. Двумя файлами, НЕ сливать в один (ТЗ огромный → мега-файл хрупок).
2. **`NAVIGATION.md` переписать** под реальность: мастер = `ideal-koncept`+`dramaturgiya`; питч зарегистрировать; новый порядок; v1/v2/`2-idei` пометить историей/провенансом.
3. **`istochnik/` renumber** под новый канонический порядок — но БЕЗ лекции по оптимизации (см. §7).
4. **Анти-дрейф:** сделать регистрацию enforced — каждый новый док получает строку в `NAVIGATION.md`; рассмотреть лёгкий чекер (по образцу линтера `istochnik/`): «сирот 0, битых ссылок 0, индекс покрывает все .md».

## 7. Лекция по оптимизации — НЕ трогать сейчас
Она в активной работе (HTML, своя арка). **Перенести/перенумеровать всё, КРОМЕ неё и её арки.** Про неё — строка в `dnevnik-i-plan.md` (и `beklog.md`): «relocation + renumber лекции по оптимизации под новый порядок → следующим заходом Code, который будет работать с этой лекцией». Так живую работу не рвём.

## 8. Кто двигает / ограничения
- Cowork из песочницы НЕ двигает/не переименовывает/не удаляет — только создаёт/правит (`COWORK §3`). Перемещения → заход Code (zip-бэкап + свежий субагент-верификатор ссылок) или владелец на Mac.
- Порядок «один риск за раз»: read-only аудит (сделан) → утвердить целевую карту §5 → NAVIGATION/дома/шапки (Cowork) → заход Code на перенос (всё кроме опт-лекции) → сверка верификатором.
- Субагенты Code — аккуратный режим: вложенность осмысленно, без роя; рейт-лимит = стоп, не ретрай (инцидент 02.07, см. `CLAUDE.md`).
- Фолд концепта в ТЗ (`sistema-ocenki.md` §1+§3.4) — отдельный заход владельца по §7; НЕ часть этой арки.
