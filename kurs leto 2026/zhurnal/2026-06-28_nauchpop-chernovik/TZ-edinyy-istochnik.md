# ТЗ-кикофф — Единый источник правды курса (MD → HTML)

> Новый сквозной кусок: свести ВСЮ правду о курсе в **один источник** (Markdown / папка), править там, смотреть в HTML, который генерится автоматически. **Полнота — жёсткое требование.** Статус: спека, не сборка.

## Цель
Один **полный** источник правды в Markdown, из которого **программно генерится HTML**. Владелец смотрит в HTML, говорит, что поправить — правки идут в Markdown. Без расхождений MD↔HTML; ничего из «большой карты» не теряется.

## Аудитория
Сейчас — владелец как автор/куратор (источник = инструмент авторинга). Потом — слушатели курса через сгенерённый HTML.

## Deliverable
1. **Схема источника** — как в MD лежит полная карта курса (лекции в формате v4 §2.5 · граф связей · действующие лица · теории · доказательства · **связующие тексты**), не пересекаясь.
2. **Генератор MD→HTML** — собирает HTML в дизайне v3/v4 из источника; одна команда → свежий HTML.
3. **Консолидированный источник** — вся правда влита (из `opisanie-v2` + глубокого банка), полно и без дублей.

## Контекст — правда сейчас РАССЫПАНА
- `opisanie-kursa-v2/` — кураторское описание 10/10 (~14k слов): `koncepcii-lekcij-v2` (ядро 7 лекций) · лица · теории · доказательство · связующее · манифест · scorecard.
- Глубокий банк `procedura-poiska/` (~44k слов): `klubok/graf-pautina` (граф связей) · `dosye.md` · `harvest-parallelej.md` · `almazy-katalog` · `bazovyy-pul`.
- `2-idei/` — котёл, сюжеты, кандидаты.
- HTML: `chernovik-kursa-v3.html` (полный макет 7 лекций) и `L4-v4.html` (пилот) — **рендеры ПОДМНОЖЕСТВА** (глубокий банк намеренно не вычерпан → «отражено не всё»).
- ТЗ: `sistema-ocenki.md` (v2, по ситуациям) — отдельный канон требований.

## Ограничения
- Источник — Markdown (править легко); смотреть — только HTML; одна команда регенерит.
- Дизайн HTML — канон v3/v4 (Forum/Glacial, две плоскости, компоненты `.claimbox/.eq/aside/.ln`…), офлайн-самодостаточный (base64).
- HTML = **полное** отражение накопленного + связующие тексты (их мы ценим).

## НЕ входит
- Собственно сборка генератора/консолидация прямо сейчас — это спека.
- Машинерия процедуры (скрипты `procedura/`, `jsonl`-логи) — не контент курса.
- Пересборка содержания лекций по разбору — отдельный трек (после/параллельно).

## Критерии готовности
- Вся правда о курсе — в одном источнике, без дублей; глубокий банк влит, ничего не потеряно (верификатор).
- Правлю MD → одной командой получаю **полный** HTML; смотрю только HTML.
- В HTML видны ВСЕ связи (граф) и детали, не подмножество.

## Открытые вопросы (решаем сейчас)
1. **Структура источника:** один большой MD / папка «файл на лекцию + карта-мета» / структурированные данные (YAML+MD-тела) → генератор.
2. **Входит ли ТЗ** (`sistema-ocenki`) в «один источник», или остаётся отдельным каноном.
3. **Планка полноты на старте:** сначала ПОЛНЫЙ источник для Л4 (образец) + генератор → проверить петлю, потом раскатка — или сразу все 7 + банк.
4. Технология генератора (Python-скрипт + шаблоны) — деталь сборки.

## Предлагаемая последовательность
1. Решить вопросы 1–3 (сейчас).
2. Спроектировать схему источника (блоки v4 §2.5 + граф + лица/теории/связующее).
3. Генератор MD→HTML — Code-заход (дисциплина `karpathy-guidelines`), дизайн v3/v4.
4. Влить «большую карту» в источник — **lossless, по лекции, старт с Л4**, верификатор «ничего не потеряно».
5. Смотреть в HTML → править MD → регенерить; `visual-design-review`.
