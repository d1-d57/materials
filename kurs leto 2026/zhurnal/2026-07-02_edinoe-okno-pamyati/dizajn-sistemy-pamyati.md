# Дизайн v1: система «одного окна» для контент-памяти курса
*На утверждение владельцу. Мутаций структуры до слова — нет.*

## 1. Проблема и корень
Симптом: мощный концепт осел в ЗАКРЫТОЙ арк-папке, `NAVIGATION` зовёт «текущей» устаревшую v2, питч не зарегистрирован. Корень — **у одной сущности нет единственного дома, а регистрация не enforced**. Пока не починено, сборка лекций будет терять работу.

Что уже есть (не изобретаем): процесс-память (`COWORK`/`ARKA`/`NAVIGATION`/дома `1-START-HERE` + `SVODKI`) и контент-линтер `istochnik/` — это упрощённый клон эталона `spetsmat`. **Дыра — КОНТЕНТ-память курса (концепт · тезисы · кросс-линки) без одного окна, и нет проектного чекера.**

## 2. Что берём из эталона spetsmat (адаптируем)
- **Одно окно = единый индекс** с таблицами «что читать» / «куда писать» / **«источник правды»** (§2 у эталона). У нас это `NAVIGATION` — достраиваем таблицей источников.
- **«Документ-сирота = не существует»** (КОНСТИТУЦИЯ §13): каждый новый `.md` регистрируется в индексе тем же ходом; ловит скрипт.
- **`check_docs.py` — stdlib-гейт** (сироты · битые ссылки · NFC-коллизии · абс-пути · архитектура↔ФС). Переносим как есть.
- **Единый источник на сущность** (числа жили только в одном месте — иначе рассинхрон 781→794). У нас: порядок — только `resheniya` п.18 + `poryadok`; концепт — только `0-koncept/`.
- **Тезис выводится из длинной формы**, кросс-линк по стабильному ключу; `detect_overlap` — советник дублей на консолидации.

## 3. Целевая система «одного окна» (контент)

### A. Дом концепта — новая папка `0-koncept/`
Переносит Code из закрытой арки (`0-` = сортируется первой, видимая путеводная звезда):
- `KONCEPT.md` (= `ideal-koncept-kursa.md`) — **единственное окно «что за курс»**: манифест (2 столпа), 7 лекций-карточек, ансамбль 6 героев, 2 зонтика, правило отбора.
- `dramaturgiya.md` (= `dramaturgiya-kursa.md`) — сквозное раскрытие героев, throughline. Активный оверлей.
- `svyazi-istochniki.md` (= `predlozhenie.md`) — связи/источники/теги. Активный оверлей (по SVODKI).
- `_provenance/` — `kanon` · `obzor` · `koncepciya-L7` (СТАРЫЙ порядок, история; читать как провенанс, не как текущее).

В шапке каждого активного файла — блок: **что кладём · как обновлять · откуда приходим (какая арка/сценарий) · единственный источник для чего**.

### B. Кросс-линк концепт↔лекции — по стабильному `id`, НЕ по номеру
`istochnik/L*.md` уже ключуются `id:` (`slozhnost`, `optimizaciya`…); `poryadok` — производный дисплей-атрибут. KONCEPT ссылается на лекции по `id`. Тогда рассинхрон номеров (концепт на новом порядке, `istochnik` на старом) **не ломает связей** — чекер линкует по `id`. Это и разблокирует отсрочку renumber (см. §5).

### C. Разделение домов — это и есть анти-дрейф
Чтобы одна инфа не жила в двух местах:
- **Лекция** (`istochnik/L*.md`) владеет СОДЕРЖАНИЕМ (математика, нарратив, герои-в-контексте) + своим `tezis`.
- **Концепт** (`0-koncept/KONCEPT.md`) владеет МЕЖЛЕКЦИОННОЙ структурой (манифест, сквозные нити, ансамбль по всем 7, зонтики, правило отбора) и **ссылается** на лекции по `id`, а не пересказывает их.
Разные гранулярности → минимальное перекрытие → нет дрейфа.

### D. Тезисы курса и лекций
- **Тезис курса** — в шапке `KONCEPT.md` (1 абзац).
- **Тезис лекции** — сейчас живёт в карточке лекции внутри `KONCEPT.md` (позиционирование: роль, связи, ключевая математика). Это «курс с высоты».
- Когда лекция собрана — в её шапку добавляется `tezis:` (контентный, выведен из полного текста), чекер сверяет карточку KONCEPT ↔ `tezis` лекции. **Пока лекции — скелеты (`status: skelet`), единый источник тезиса = карточка KONCEPT.** (Развилка iii.)

### E. Таблица «источник правды» (в `NAVIGATION`)
| Сущность | Единственный источник |
|---|---|
| Что за курс / нити / герои / зонтики | `0-koncept/KONCEPT.md` |
| Драматургия (раскрытие героев) | `0-koncept/dramaturgiya.md` |
| Связи / теги / источники сборки | `0-koncept/svyazi-istochniki.md` |
| Полный текст лекции | `istochnik/L*.md` (по `id`) |
| Порядок лекций | `resheniya` п.18 + `poryadok` в шапках |

## 4. Анти-дрейф машинерия
1. **`tools/check_docs.py`** (stdlib, из эталона; 6 проверок): (a) 0 сирот — каждый `.md` есть в `NAVIGATION`; (b) 0 битых ссылок; (c) NFC-коллизии имён (критично — у нас translit-правило против бага «й/ё»); (d) нет абс-путей песочницы в текстах; (e) папки в карте `NAVIGATION` ↔ ФС; (f) **id-целостность концепт↔лекции** (каждый `id` в KONCEPT ↔ файл `istochnik`; тезис присутствует; порядок ↔ п.18).
2. **`tools/detect_overlap.py`** (stdlib, советник) — кандидаты дублей прозы, гоняем на консолидации.
3. **Правило регистрации** «сирота = не существует» — в `NAVIGATION` + `COWORK`; enforced скриптом.
4. **`istochnik/` линтер** остаётся для контент-уровня.

## 5. Разбивка риска (один риск за раз)
1. ✅ Арк-скелет + дизайн (сделано, мутаций структуры нет).
2. **Утвердить эту карту** (владелец).
3. **Cowork:** переписать `NAVIGATION` (мастер · питч · новый порядок · таблица источников · v1/v2/`2-idei`→история) + шапки-«окна» в домах + правило регистрации. *(Только создание/правка — разрешено из песочницы.)*
4. **Заход Code:** перенос концепта → `0-koncept/` (+ `_provenance`) · написать `check_docs.py` + `detect_overlap.py` · прогнать зелёными · zip-бэкап · свежий субагент-верификатор ссылок. **БЕЗ** renumber и опт-лекции. Аккуратный режим субагентов.
5. **Cowork:** обновить пути в `NAVIGATION`, прогнать `check_docs`, финальная сверка.
6. **Закрыть арку** (durable по домам + SVODKI), зарегистрировать отложенное.

## 6. Развилки на решение владельца
- **(i) Renumber `istochnik/`** — **рекомендую отложить**. Частичный (6 из 7) ломает линтер `poryadok` уникальны 1–7 (опт-лекцию на `2` не трогаем). Кросс-линк по `id` делает номер косметикой. Renumber — одним чистым проходом в следующем заходе Code с опт-лекцией. *(Альтернатива: тронуть опт-лекцию сейчас — против §7 брифа.)*
- **(ii) Разбивка ТЗ курс/лекция** — **рекомендую отдельным заходом** после этой арки (бриф §8: «один риск за раз», `sistema-ocenki.md` ~77 КБ — хрупкий мега-файл). В карте фиксируем ЦЕЛЬ (лекц-ТЗ рядом с концептом), но хирургию не делаем сейчас.
- **(iii) Тезисы** — **рекомендую**: пока лекции-скелеты, тезис в карточке `KONCEPT`; при сборке лекции — `tezis:` в её шапку + чекер сверяет. *(Альтернатива: сразу отдельный `0-koncept/tezisy.md` — лишний дом, дублирует карточки.)*

## 7. Что НЕ входит в арку
Опт-лекция и её арка · renumber `istochnik/` · разбивка/фолд ТЗ · переоткрытие содержания (порядок/герои/манифест — решено) · сборка самих лекций.

## 8. Уточнения владельца v1.1 (2026-07-02, после слова) — ядро задачи
Владелец согласовал §1–§7 и уточнил два пункта:

**(A) Блок-синхрон концепт↔лекции↔питч.** Нужен не просто «концепт ссылается на лекции», а единый концепт, СИНХРОНИЗИРОВАННЫЙ с текстом каждой лекции на уровне блоков (правишь блок — второе не разъезжается), и большой концепт ↔ короткий питч тоже (одна инфа в двух формах). Механизм (markdown-native, честно): единый источник на блок + стабильные якоря + ссылки-трансклюзии + сборка `build.py` + чекер-рипл. Полная спека — **`sync-koncept-lekcii.md`**. Пилот — Л4 (собрана) + `KONCEPT` + питч; 5 скелетов получают якоря по мере сборки. → усиливает §3B/§3D.

**(B) Два бальных ТЗ + «комплект доводки лекции».** Курс-ТЗ (бальный, ворота, прогнать ВЕСЬ курс; переиспользуем для будущих курсов; отдельный дом) и лекц-ТЗ (бальный, ворота, довести лекцию). При доводке лекции в арку уходит **комплект = лекц-ТЗ + снимок концепта (описание всего курса сейчас) + файл лекции** — чтобы ворота «мосты» читались против конкретных идей/математики/героев концепта. Отсюда лекц-ТЗ держим рядом с концептом (или явный указатель). Хирургия разбивки `sistema-ocenki.md` — отдельным заходом (подтверждено). → уточняет §6(ii).
