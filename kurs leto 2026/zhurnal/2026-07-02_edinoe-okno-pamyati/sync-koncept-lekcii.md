# Спека: блок-синхрон концепт ↔ лекции ↔ питч
*Как «правишь одно — второе не разъезжается». Markdown-native, честно. Часть арки «Единое окно памяти».*

## Задача (владелец, 2026-07-02)
Единый концепт курса синхронизирован с текстом КАЖДОЙ лекции на уровне **блоков**; большой концепт синхронизирован с коротким **питчем** (одна инфа в двух формах). Меняешь блок в источнике — зависимые виды пересобираются, а расхождение ловит чекер.

## Честная граница
Markdown без БД не даёт «поменял тут — мгновенно появилось там». Даёт то же по результату: **один источник на блок + генерируемые виды + чекер, который не даёт разъехаться молча.** Правишь источник → пересобрал → всё сходится; чекер валит/флажит расхождение. Это ровно паттерн эталона `spetsmat` («короткая форма выводится из длинной», а не две рукописные копии).

## Механизм (4 части)
1. **Единый источник на блок.** Для каждого синхронизируемого блока — ровно один дом:
   - лекц-специфика (тезис · мосты этой лекции · герои-здесь · матядро) → файл лекции `istochnik/L*.md`;
   - курс-уровень (манифест · ансамбль по всем 7 · зонтики · правило отбора · сквозные нити) → `0-koncept/KONCEPT.md`.
2. **Стабильные якоря (конвенция проекта, не изобретаем).** Карточка лекции в `KONCEPT` объявляет id: `**ЛN. Название** {L:<id>}`. Блок-источник в лекции адресуется по `id` (frontmatter) + `§N`. Трансклюзия — маркером **`{{вкл:<id>}}`** — этот синтаксис УЖЕ валидируется линтером `build.py` (~строки 509–513), рендер добавляется заходом 3. `istochnik` уже несёт `→[id]`, `→[T:id]`, «поля-сноски-нити на кусок».
3. **Ссылка, не копия.** Карточка лекции в `KONCEPT` НЕ дублирует тезис/мосты — ссылается на блок лекции маркером `{{вкл:<id>}}`. Питч генерируется из карточек `KONCEPT` тем же принципом (короткая форма выводится из длинной).
4. **Сборка + чекер.** Генератор (`istochnik/_generator/build.py` уже есть) собирает читаемый концепт и питч, подставляя блоки по ссылкам. Чекер: каждая ссылка-якорь резолвится · блок-источник существует · при смене блока-источника зависимые пометки — **на ревью** (правило семантического рипла `istochnik/PROTOKOL.md`: механическое ловит линтер, смысловое — ФЛАГ владельцу, не закрывается молча).

## Направление синхрона (кто чей источник)
| Блок | Источник (правим тут) | Кто тянет/сверяет |
|---|---|---|
| тезис · мосты · герои-здесь · матядро лекции | файл лекции `istochnik/L*.md` | карточка лекции в `KONCEPT` |
| манифест · ансамбль · зонтики · сквозные нити · правило отбора | `0-koncept/KONCEPT.md` | лекции ссылаются «моя роль в нити X» |
| питч (короткая форма) | генерируется из `KONCEPT` | сверяется чекером против `KONCEPT` |

## Стадии
1. **Спека** (этот файл) — сейчас.
2. **Заход 2 (низкий риск):** якоря `{L:id}` в 7 карточках `KONCEPT` + чекер id-целостности концепт↔лекции (`check_docs.py`: набор id `KONCEPT` == набор лекций `istochnik`; `poryadok` уникальны 1–7) + генератор питча из `KONCEPT` (питч сейчас заготовка → нулевой риск). **`build.py` НЕ трогаем.**
3. **Заход 3:** рендер трансклюзии `{{вкл:id}}` в `build.py` (сборка читаемого вида концепта/питча с подстановкой блоков) + рипл-флаг при смене блока-источника. Пилот — Л4.
4. **Каждая новая лекция при сборке** получает якоря/тезис (5 скелетов — по мере готовности; опт-лекция — когда освободится).

## Что НЕ делаем
