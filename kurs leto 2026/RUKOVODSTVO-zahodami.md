# RUKOVODSTVO-zahodami.md — как Cowork ведёт Claude Code (этот проект)

> **КОГДА читать:** когда пишешь заход для Claude Code, шлёшь ему задачу или принимаешь отчёт. · **ЧТО дописывать сюда:** только методологию петли Cowork ↔ Code (правила, канал, стандартный текст, приёмка). НЕ среды/роли (`COWORK.md`), не вход Code (`CLAUDE.md`), не арк-механику (`ARKA.md`). · **КУДА дальше:** скелет захода — §6.
>
> Методология для аналитика (Cowork): он сам код не пишет — пишет заходы, судит отчёты. **Самодостаточно: на скилл `agentic-coding-session-brief` не опираемся** — здесь та же дисциплина, переписанная под этот проект и его конкретику. Code стартует с чистым контекстом каждый сеанс; всё, что должно сохраниться, лежит в файлах, не в его памяти.

## Принцип
Состояние живёт на диске (файлы проекта + файл-заход), не в памяти сессии. Отсюда: заход **самодостаточен** (вход, что прочитать, что сделать, как отчитаться — внутри текста), **один заход = одна задача**, durable — сразу в файлы. Папка **не под git** → точка отката это **zip-бэкап** (его делает Code в начале захода).

## §1. Канал — один файл в папке арки
Общение с Code идёт через ОДИН файл: `zhurnal/<арка>/kod_<тема>.md`. В нём весь обмен:
- сверху — **заход** (пишет Cowork): контекст, что прочитать, что сделать, границы, критерий;
- снизу — секции `## ПЛАН` / `## ВОПРОСЫ` / `## ОТЧЁТ`, которые **заполняет Code**.

Code читает ТОЛЬКО этот файл (правило — `CLAUDE.md`), остальной проект не изучает. Cowork потом берёт отчёт прямо с диска — ничего вручную не переносить.

## §2. Стандартный текст владельцу → Code (полный адрес + МОДЕЛЬ ВНУТРИ текста)
Владелец не вставляет весь заход в Code — он шлёт **короткий текст с ПОЛНЫМ абсолютным путём файла ВНУТРИ** (не отдельной строкой, не «вот папка, вот текст»). Стандартная форма:

```
Модель: <Sonnet 5 | Opus 4.8> — <одна фраза почему> (в Claude Code переключается `/model`).
Claude Code, твой заход — файл `<ПОЛНЫЙ_АБСОЛЮТНЫЙ_ПУТЬ>/kod_<тема>.md`. Прочитай ТОЛЬКО его и то, что он называет; остальной проект не изучай. Папка не под git — сначала zip-бэкап. План, вопросы и финальный отчёт пиши в этот же файл, в секции внизу (## ПЛАН / ## ВОПРОСЫ / ## ОТЧЁТ). Ничего сверх задачи не трогай.
```

**Модель — ОБЯЗАТЕЛЬНА первой строкой в КАЖДОМ заходе** (какую и почему — §8.1). Cowork, отдавая заход владельцу, СРАЗУ даёт этот текст с уже подставленным путём и моделью — готовый к пересылке.

## §3. Заход — дай Code всё, иначе соберёт не то
Самодостаточность + контекст заранее + проверяемый критерий.
- Заход несёт ВСЁ: рабочая папка, что прочитать ПОИМЁННО (точные файлы), что сделать, границы, как отчитаться. Скажи явно: «читай только названное, проект не доразбирай».
- Дай существующие конвенции и имена авансом → Code переиспользует, не плодит своё.
- Есть ошибка/лог — вкладывай RAW, не пересказ.
- **Критерий готовности — условие, которое может ПРОВАЛИТЬСЯ** (не «я закончу»): «6 файлов на местах, битых ссылок 0, grep чист».
- **ВСЕГДА требуй в отчёт: сколько времени шёл прогон и сколько токенов потрачено.** Code/прогон это видит — пусть впишет в `## ОТЧЁТ`; для скриптовых прогонов логируй время и `usage` из `claude -p --output-format json`. Это в КАЖДОМ заходе, не по запросу.
- **Преимущество Cowork:** ты сам видишь файлы. Трогает заход то, что недавно меняли — сверься на живых файлах ПЕРЕД написанием. Асимметрия: Cowork читает тщательно (релевантное), Code — минимально (названные якоря).
- Лоссовый/двигающий заход (перенос, удаление, сжатие) → встрой **верификатор** (§5).

## §4. Приёмка отчёта — суди по отчёту, но проверь гейты
Доверяй содержанию, но пройди КАЖДЫЙ гейт:
- критерий выполнен · границы соблюдены (запрещённое не тронуто) · решения обоснованы · вопросы Code разобраны · верификатор зелёный.
- **Дешёвая сверка:** ты видишь файлы — быстрый санити-чек (`tree`/`grep`), что заявленное = реальность. Не построчно.
- Дисциплинированное НЕ-действие (Code отказался от рискованного при нулевой пользе, вынес в отчёт) — это хорошо, не повод отклонять.
- Вердикт: **принять** ИЛИ **вернуть на точечную дочистку** (не переделывать всё). **Приёмку — в дневник арки** (`SESSIYA.md`): что принято, какие решения ратифицированы. Вопрос Code без ответа → ответ идёт в начало следующего захода.

## §5. Верификатор внутри захода (для потерь и перемещений)
Заход двигает/удаляет/сжимает → встрой ОТДЕЛЬНЫЙ свежий субагент-верификатор как ГЕЙТ: «исходное → новое» полно (список потерь пуст); каждая ссылка резолвится (битых 0, программно). Ключ: **другой субагент, другой метод** (сверка с zip-бэкапом, sha256) — у автора правок слепые пятна.

## §6. Скелет захода (меняется только тело §3)
```
# Канал Claude Code — <короткое имя>
> Для Claude Code: твой единственный файл-заход. Читай только его. План/вопросы/отчёт — в секции внизу.

## ЗАДАЧА (один проход до конца)
КОНТЕКСТ. <проект в 1–2 фразы; прошлый этап; цель>. Приёмка — по отчёту.
### 0. ПЕРВЫЙ ХОД. Рабочая папка <путь>; СРАЗУ zip-бэкап (git нет); прочитать ТОЛЬКО <названные файлы>; изложить ПЛАН в ## ПЛАН перед действиями.
### 1. ДИСЦИПЛИНА. Минимальная правка + проверка; якорные замены (abort при ≠1); сохранять по умолчанию; оспаривать ложную предпосылку. **СУБАГЕНТЫ (§8, аккуратный режим): вложенные — можно осмысленно, не случайный рой; ориентир ≤5 параллельно (остальное в очередь); рейт-лимит=отступить+доложить, не слепой ретрай. Назвать ЯВНО: сколько субагентов и на что.**
### 2. ГРАНИЦЫ. <что НЕ трогать>.
### 3. ЗАДАЧА. <конкретно>. КРИТЕРИЙ: <проверяемое условие>.
### 4. ВЕРИФИКАТОР (если двигаем/теряем). Свежий субагент, сверка с бэкапом, программно.
### 5. ОТЧЁТ → секция ## ОТЧЁТ внизу. Что сделал + зачем / как проверил / что не трогал / результат верификатора / **время прогона + потраченные токены**.

## ПЛАН — (заполняет Code)
## ВОПРОСЫ — (заполняет Code)
## ОТЧЁТ — (заполняет Code)
```

## §7. Тип захода и когда не усердствовать
- **Мутирующий** (двигает/правит файлы): дисциплина выше, верификатор для перемещений.
- **Аналитический** (только смотрит): данные не трогать, артефакт + предложения, решение владельцу.
- **Оспаривай предпосылку — включая от владельца:** допущение проверь по живым файлам прежде, чем строить заход.
- Тривиальный заход (одна строка) — без церемоний §0–§5. Усердие там, где цена ошибки — переделка; быстро там, где откат дёшев.

## §8. Бюджет и лимиты (Max 20x) — планировать по факту, не по страху

> **⚠️ АККУРАТНЫЙ РЕЖИМ СУБАГЕНТОВ (не запрет).** Инцидент 2026-07-02: заход развёл лавину субагентов — легли на рейт-лимиты, ретраились и ушли в никуда, холостые падения. Токенов мало (дешёвые, крошечный % лимита) — беда не в цене и не во вложенности, а в бесполезном разбегании. Вложенные субагенты РАЗРЕШЕНЫ, когда осмысленны; заход с делегированием несёт аккуратный бюджет: **(1) вложенность — по плану и с причиной, не случайный рой; (2) ориентир ≤5 параллельно, остальное в очередь; (3) рейт-лимит = отступить + доложить, не слепой ретрай; (4) рой падающих субагентов без результата = разбегание → стоп + доклад.** Цель — максимум эффективности без лишних падений. Продублировано в `CLAUDE.md`.

Точных токен-цифр Anthropic НЕ публикует (только «Max 20x = 20× Pro»); источник правды — `/cost` в Code и `run_log.txt` прогона.
- **5-час окно — БОЛЬШОЕ.** Эмпирически Max 20x ≳ **7 млн токенов** за окно (живой замер 2026-06-28: GATHER ~360k = <5%). Полный прогон процедуры (≈1.5–3 млн ток.) влезает с запасом → **НЕ строй заход вокруг страха «сожжём 5-час окно».** Окно скользящее, сбрасывается при упоре.
- **Реальный дефицит — НЕДЕЛЬНЫЕ капы:** их два — один на ВСЕ модели + отдельный на **Sonnet**. Их душит проект из МНОГИХ прогонов, не один. Тиринг (haiku-масса / sonnet-суждение / opus-скупо) бережёт именно недельный бюджет.
- **Пул общий:** claude.ai + Claude Code + Cowork (и этот чат считается); параллельные инстансы жгут вдвое.
- **Модель оркестратора — главный рычаг.** Opus в разы дороже Sonnet за ход; гонять КООРДИНАЦИЮ (спавн субагентов, файловый I/O) на Opus — лишний жор. Дефолт оркестратора Code — **Sonnet**; Opus только на узкое ядро (план/плетение). Паттерн «план на Opus, исполнение на Sonnet» (`/model opusplan`).
- **Контекст-окно 200k** (отдельно от usage; пересылается каждый ход) → durable+resume, субагенты изолируют контекст, `/clear` между задачами.

### §8.1. Какую модель ставить в заход-прогон (указывать В КАЖДОМ заходе, §2)

Факты (июль 2026, сверено по живым источникам — Anthropic/Platform Docs, TechCrunch, MindStudio):
- **Opus 4.8** — $5 / $25 за млн ток. (вход/выход); агентное кодирование ~69%. Тяжёлое рассуждение.
- **Sonnet 5** (вышел 30.06.2026) — $3 / $15 стандарт, **интро $2 / $10 до 31.08.2026**; агентное кодирование ~63%; контекст 1M; лучше держит prompt-injection, меньше галлюцинаций/угодливости. По цене-за-токен дешевле Opus на ~40% (интро ~60%).
- **⚠️ Парадокс «Sonnet дешевле — но не всегда».** У Sonnet 5 новый токенайзер (тот же текст = ~1.0–1.35× токенов) и он по сути многословнее (~+30% токенов на задачу); в длинных агентных прогонах с extended-thinking это компаундится (выход каждого шага раздувает вход следующего) и total может ДОГНАТЬ/ПЕРЕГНАТЬ Opus. Правильная метрика — **стоимость за успешный результат, а не за токен**: где Opus решает с первого раза, а Sonnet ретраит, Opus по факту дешевле.

**Матрица (модель — первой строкой forwarding-текста §2):**

| Тип захода | Модель | Почему |
|---|---|---|
| **Исполнительный, полностью расписанный** — якорные замены, вставки дословным текстом, renumber, рендер/сборка, линтер-гейт (весь reasoning уже в заходе) | **Sonnet 5** (дефолт) | механика; глубина Opus ничего не покупает; дешевле + бережёт общий недельный кап; abort+верификатор ловят сбой |
| **Исследовательский / неоднозначный** — крупный сквозной рефактор, трудный дебаг, архитектурное решение, «разберись и почини» без готовых якорей | **Opus 4.8** | план рождается по ходу; выше успех с первого раза → меньше ретраев; цена ошибки = переделка |
| **Смешанный** — план на Opus, механику на Sonnet в одном прогоне | `/model opusplan` | опус пишет план, sonnet исполняет |

**Дефолт — Sonnet.** Opus — только когда заход требует глубокого рассуждения В ХОДЕ ИСПОЛНЕНИЯ (не на этапе, который Cowork уже закрыл, написав заход). Max-угол: Opus тянет ОБЩИЙ недельный кап (у Sonnet свой отдельный) → Opus скупо, на узкое ядро. Плюс из §8: чем детальнее заход (точные якоря, критерий, границы), тем увереннее Sonnet — хороший заход сам по себе удешевляет модель.
