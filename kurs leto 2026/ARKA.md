# ARKA.md — как работать в арке (канон)

> **КОГДА читать:** на входе в арку (Ф0 — решаем, заводить ли) и как справочник по ходу. После Ф0 сюда не возвращаешься — живёшь в папке арки. · **ЧТО дописывать сюда:** только работу ВНУТРИ арки (рождение, ритуалы, шаблоны, Code-канал). НЕ глобальное поведение Cowork (→ `COWORK.md`), не решения/числа (→ `1-START-HERE/`), не контент курса. · **КУДА дальше:** §8 указатели.
>
> Это скрипт, не описание. На входе иди по шагам §2, ни одного не пропуская. Каждый — с петлёй проверки.

## §1. Что такое арка (и зачем)

**Арка — единица работы:** многосоставная задача на несколько сессий (спроектировать лекцию, собрать лендинг, навести порядок в проекте). У неё своя папка `zhurnal/<ГГГГ-ММ-ДД_тема>/`, которая работает как **локальная память** — маленькая копия памяти проекта внутри арки.

**Две памяти.**
- **Долгая = проект** (`1-START-HERE/` решения и слои · `biblioteka/` источники · `NAVIGATION.md` индекс). Источник правды. Меняется редко, читается точечно.
- **Локальная = арка** (`zhurnal/<арка>/`). Оперативная память одной задачи: концепция, план, дневник, каналы к Code. Сюда пишем всё текущее. Ephemeral — в конце durable уходит в долгую.

**Зачем так.** Большой контекст вредит не только кошельку, но и точности — модель плывёт задолго до предела окна. Поэтому долгую память читаем ОДИН раз, на входе в арку; дальше работаем на дистиллированных арк-доках. Меньше контекста → надёжнее.

**Три режима:** ВХОД (Ф0 — единственный раз читаем долгую широко) → РАБОТА (живём в арк-папке, из долгой подгружаем точечно по указателю) → ЗАКРЫТИЕ (durable из арки → по домам долгой).

## §2. Ф0 — как ЗАВЕСТИ арку (скрипт; по шагам, не перескакивать)

**Как запускается.** Владелец открывает проект (инструкции проекта велят первым делом прочитать `COWORK.md`) и пишет первым сообщением намерение. Стандартная форма:
```
Новая арка: <одной фразой — что хочу и зачем>. Действуй по ARKA.md: сначала интервью (по 1–2 вопроса), потом ресёрч, и только если решим, что это арка, — заводи папку. Файлы до решения не пиши.
```
Cowork по роутеру `COWORK §4` попадает сюда и идёт по шагам. **До решения go (Шаг 3) файлы не создаются — сначала разговор.**

### Шаг 1 — интервью + ворота «нужна ли арка»
Вытащить у владельца намерение и границы, решить — арка или разовая задача. **Интервью, не допрос:** 1–2 вопроса за раз, к каждому свой best-guess (поправить легче, чем родить с нуля); что уже сказано или лежит в файлах — подтверждай, не переспрашивай; логистику ставь дефолтом.
Вытащить (широкое → узкое): что за задача и **зачем сейчас** → какую функцию строим (что увидим/проверим в конце) → границы, **что НЕ входит** (anti-scope, самый недооценённый вопрос) → что уже есть по теме → как поймём, что закрыли.
Скиллы входа: `the-interviewer` / `project-kickoff` / `brainstorming`.

**Ворота — арка НЕ по умолчанию.** НЕ заводить, если хоть одно: разовая/однопроходная · влезает в один чат · не трогает много мест и структуру · уже есть открытая арка про это. Заводить, если: многосоставная · на несколько сессий · трогает структуру/много мест · или мета (как мы работаем). Решение go/no-go аргументированное и **оспариваемое**.

> Петля: назвал ПОЧЕМУ это арка, а не разовая задача? владелец подтвердил намерение и anti-scope? Нет — арку не заводить, дальше не идёшь.

### Шаг 2 — ресёрч (до решения)
- **Внутри проекта:** как устроено то, что собираемся менять; что уже решено по теме (`NAVIGATION` → `resheniya` · `zhurnal/SVODKI` · прошлые арки). Проект бывает плохо пронавигирован — сверяй по живым файлам, не верь индексу слепо.
- **Снаружи:** как это делается в мире (если уместно) — субагентами, вернуть дистиллят со ссылками; ссылки — в `biblioteka/ISTOCHNIKI.md`.
- **Запись находок:** всегда выжимка + указатель `файл → раздел → когда вернуться` (большое не копируем). Показать владельцу — он вспомнит упущенное.

> Петля: каждое место, которое арка тронет, имеет точный указатель? находки сверены с живыми файлами? владелец видел выжимки? Нет — ресёрч не закрыт.

### Шаг 3 — go / no-go
Свести интервью + ресёрч в вывод, опираясь на найденное, не на догадку. **No-go** → зафиксировать строкой в `zhurnal/SVODKI.md` / вопросом в `1-START-HERE/dnevnik-i-plan.md`, арку не плодить, стоп. **Go** → шаг 4.

### Шаг 4 — создать доки арки (только на go)
1. Папка `zhurnal/<ГГГГ-ММ-ДД_тема>/`.
2. `NAVIGATOR.md` по шаблону (§9) — адрес проекта · концепция · границы · указатели в долгую (из шага 2) · внешние источники · скиллы · впечатанный блок «Процедуры — куда идти» (вход/план/хэндофф/закрытие → ARKA). **Навигатор = хаб:** создаётся вместе с папкой, дальше из него видно, КУДА идти за любой процедурой — без чтения больших текстов.
3. `SESSIYA.md` (ДНЕВНИК) — вести с этого хода (§4).
4. `PLAN.md` — короткий план: шаги + «СЕЙЧАС» (скилл планирования — `project-kickoff` или `agentic-coding-session-brief`).
5. Закрыть стартовую сессию хэндоффом (§6).

> Петля (Ф0 готов): папка есть? навигатор несёт концепцию + границы + указатели + ритуал? дневник начат? план есть? хэндофф выдан? Нет хоть одного — Ф0 не закрыт.

## §3. Вход в чат внутри арки (НЕ полный Правило №0)
Каждая новая сессия арки начинается так — и долгую память широко НЕ читает:
1. `NAVIGATOR.md` — что за арка, указатели, процедуры.
2. `PLAN.md` — раздел «СЕЙЧАС».
3. хвост `SESSIYA.md` — последняя запись.
4. **Staleness-чек** (red-flags, любой → стоп, разберись / при нужде полный вход): решения в `resheniya`/`sloi` сдвинулись · файл из указателей пропал или переехал · предпосылка хвоста противоречит реальности.

**Триггер-аварийка** (задача трогает структуру проекта / скоуп / меняет «решённое») → полный вход (Правило №0: `NAVIGATION` → `1-START-HERE/dnevnik-i-plan` → `resheniya`/`sloi`).

> «Разговор первым»: на старте сессии сориентируйся по 1–3, скажи владельцу, что понял и что предлагаешь, дождись слова — потом пиши файлы.

## §4. Память арки — 3 дока (+ каналы)
Зеркало долгой памяти, локально:
- **`NAVIGATOR.md`** = ОРИЕНТАЦИЯ. Концепция + границы + указатели в долгую + процедуры. Стабилен, правится редко. Читается ПЕРВЫМ.
- **`PLAN.md`** = ГДЕ-МЫ. Шаги ✓ + «СЕЙЧАС» (первый конкретный шаг следующего хода). Обновляется каждый чат.
- **`SESSIYA.md`** (ДНЕВНИК) = ДЕТАЛЬ + РЕШЕНИЯ + ИСТОРИЯ. Дистиллят, не свалка; **один док**, не два; у каждого решения — «почему». Ведётся с первого хода (переживает обрыв окна).
- **`kod_<тема>.md`** = канал к Claude Code (§5).

Шаблоны — в §9.

## §5. Claude Code — канал внутри арки
Code общается с проектом ТОЛЬКО через один файл в папке арки. Так он не лезет во всю документацию и не ломает лишнего.
- **Промпт** кладёшь в `zhurnal/<арка>/kod_<тема>.md` (заход по `RUKOVODSTVO-zahodami.md`: цель · что прочитать · что сделать · границы · проверяемый критерий · гейт-верификатор, если двигаем/теряем; папка не под git → точка отката это zip-бэкап).
- Владельцу — короткое сообщение: «запусти Code на этом файле».
- **Code читает ТОЛЬКО этот файл** (правило — в `CLAUDE.md`), выполняет, кладёт в тот же файл `## ВОПРОСЫ` (если есть) и `## ОТЧЁТ`.
- Владелец читает вопросы и отчёт, пересылает Cowork. Cowork **судит по отчёту** (проходит гейты), не перепроверяя построчно.

## §6. Хэндофф чат → чат (шаблон)
В конце каждого чата (это НЕ конец арки): обнови `PLAN` (галочки + «СЕЙЧАС») и при нужде `NAVIGATOR`; строку в `SESSIYA`; выдай владельцу:
```
Продолжаем арку «<имя>». Папка: zhurnal/<арка>/.
Не читай весь проект. Войди по арк-ритуалу:
  1) NAVIGATOR.md  2) PLAN.md («СЕЙЧАС»)  3) последнюю запись SESSIYA.md.
Дальше — по «СЕЙЧАС».
```
Консолидацию в дома на стыке чатов НЕ делаем — durable живёт в арке до закрытия.

## §7. Закрытие арки (консолидация)
Когда арка сделана:
1. Прочитать `SESSIYA.md` ЦЕЛИКОМ, выловить каждое осевшее (решение / понимание / отложенное).
2. Разнести по домам долгой: решение → `1-START-HERE/resheniya.md`; открытое или шаг → `dnevnik-i-plan.md`; идея на будущее → `beklog.md`; ингредиент → `2-idei/kotel.md`; источник → `biblioteka/ISTOCHNIKI.md`. Что осталось только в дневнике — **не существует**.
3. Запись в `zhurnal/SVODKI.md` (сверху): что делали, к чему пришли, что открыто.
4. Пометить арку закрытой (строкой в SVODKI). Арк-папка → история.

> Петля: каждое осевшее имеет дом ИЛИ сознательное «не нужно»? SVODKI обновлён? Нет — арка не закрыта.

## §8. Что НЕ дублируем (указатели)
Глобальное поведение Cowork (роли · среда · окно · ритуал) → `COWORK.md`. Решения и слои → `1-START-HERE/`. Источники → `biblioteka/`. Полный индекс → `NAVIGATION.md`. Вход Code → `CLAUDE.md`. Методология захода Code → `RUKOVODSTVO-zahodami.md`.

## §9. Шаблоны

**`NAVIGATOR.md`** (стабилен, читается первым):
```
# НАВИГАТОР арки «<имя>»
## Адрес проекта — <абсолютный путь к папке проекта> (нужен, в частности, для заходов Code; обновить при переносе)
## Концепция — что строим, какую функцию (1 абзац)
## Границы — что НЕ входит (anti-scope)
## Указатели в долгую — места проекта, которые трогаем (выжимка; большое → файл→раздел→когда обращаться)
## Внешние источники — ссылки (дублируются в biblioteka/ISTOCHNIKI.md)
## Скиллы арки — какие поднимать
## Процедуры — куда идти (где прочитать, не «как»):
##   вход в сессию → ARKA §3 · план (PLAN) → ARKA §4 · хэндофф → ARKA §6 · закрытие → ARKA §7 · заход Code → RUKOVODSTVO-zahodami.md
```

**`PLAN.md`** (обновляется каждый чат):
```
# ПЛАН арки «<имя>»
## ⭐ СЕЙЧАС — первый конкретный шаг следующего хода
## Шаги
- [x] сделано  ·  - [ ] осталось
```

**`kod_<тема>.md`** (канал к Code):
```
## ПРОМПТ — <заход для Code по `RUKOVODSTVO-zahodami.md`>
## ВОПРОСЫ — (заполняет Code)
## ОТЧЁТ — (заполняет Code)
```
