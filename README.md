# materials — ТЫ ЗДЕСЬ. Читай первым, до всего остального

> **Это корневой роутер.** Он не содержит методологии — он говорит, **куда идти** за ней. Задача одна: ты входишь в `materials/` и за минуту понимаешь (1) в каком проекте работаешь, (2) где фабрика, (3) какой документ открыть под свою задачу. · **ЧТО дописывать сюда:** только новый проект (§3) или новый маршрут (§2). Методология сюда НЕ пишется — у неё есть дома.

## §0. Что такое `materials/` — три вида папок

| Вид | Папка | Что это |
|---|---|---|
| 🧠 **ФАБРИКА** | `_studio/` | **Как делать.** Методология, стандарты, конвейер, дисциплина, борд задач. Мозг всей работы. |
| 🔧 **ДВИЖКИ** | `_generator/` | **Чем собирать.** `build_doc.py` (документ), `build_deck.py` (слайды), гейты. Руки. |
| 📚 **ПРОЕКТЫ** | все остальные | **Что делаем.** Конкретные курсы, лекции, исследовательские нити (§3). |

**Первый ход всегда один:** пойми, в каком ПРОЕКТЕ задача (§3) → возьми метод в ФАБРИКЕ (§2) → собирай ДВИЖКОМ, не руками.

## §1. Порядок входа (железно)

1. **Этот файл** — понять, где ты и куда идти.

Только потом — частная задача.

## §4. Что НЕ делать (самые дорогие ошибки, все — живые)

- **Не писать новый генератор.** Есть `build_doc.py` и `build_deck.py`; чего не хватает — дорабатывать. *(Инцидент: ad-hoc md→HTML в обход канона.)*
- **Не изобретать вид.** Палитра, макет, типы блоков решены раз навсегда: `STANDART-oformlenia.md`.
- **Не изобретать примитивы рисунка.** Есть словарь. *(Иначе получается 92 разных рисунка вместо одного языка.)*
- **Не расширять границы захода** и не изучать проект целиком, если ты исполнитель: заход самоценен.
- **Не проверять предпосылку по памяти.** Даже свою, даже владельца — сверяй по живым файлам. *(Прецедент: «генератор не умеет картинки» оказалось ложью, проба заняла минуту.)*
- **Не отдавать артефакт, не посмотрев на него.** Машинные гейты зелёные ≠ визуально готово (#15).
