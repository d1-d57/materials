### 🔴 ТРИ ДЕФЕКТА, ИЗ-ЗА КОТОРЫХ РАБОТА С ПРЕПОДАВАТЕЛЯМИ НЕВОЗМОЖНА

Это не «недоделано», это сломано. Каждый проверяется командой.

**Д1. `/api/prepodavateli` отвечает 403 ВСЕГДА.**
`server.py:456` требует `vhod.rol(...) == "organizator"`. Но пароль выключен
(`SVOBODNAYA_PRAVKA` по умолчанию включена, `server.py:75`), куки никто не ставит,
значит `rol()` возвращает `None`, значит 403 на любой запрос. **Единственный эндпойнт
правки преподавателей закрыт замком, ключ от которого сам же выключен.**
Проверка: `curl -s -X POST localhost:PORT/api/prepodavateli -d '{"deystvie":"vernut","teacher_id":3}'`

**Д2. Интерфейса к нему нет.** Фронт вызывает ровно три адреса: `/api/kabinety`,
`/api/enrollment`, `/api/view`. Слова `prepodavateli` в шаблоне нет. Даже сняв 403,
нажать было бы негде.

**Д3. Снятого преподавателя не вернуть.** `_all_teachers` (`server.py:158`) отдаёт
`where aktiven is null or aktiven = 1` — только активных. Действие `vernut` в API есть,
но человека, которого возвращают, ни в одном списке не видно. **Ветка кода мёртвая
по построению.**

## §1. ЧТО ТАКОЕ АДМИНКА И ЧЕМ ОНА ОТЛИЧАЕТСЯ ОТ ВНЕШНЕЙ ЧАСТИ

| | внешняя часть | админка |
|---|---|---|
| адрес | GitHub Pages, красивый | машина владельца, туннель |
| кто открывает | школьники, преподаватели, родители | организаторы, ссылка только у них |
| что делает | **показывает** | **меняет** |
| пароль | не нужен | нет и сегодня не нужен |
| красота | планка высокая | **плотность важнее красоты** |

🔴 **Админка — рабочий инструмент, а не витрина.** Крупные заголовки, воздух и
пояснительные подписи здесь вредны: они отодвигают следующее поле. Плотно, мелко,
всё на экране.

🔴 **Один экран — одна сущность.** Не сваливать преподавателей и школьников в одну
таблицу: у них разные действия и разная частота правок.

### 🔴 Смена группы — новое требование владельца 04.09

Дословно: *«Должна быть возможность переводить преподавателей из группы в группу.
У них есть кнопка „Преподаватель“, и там можно нажать, если в редакторской
админ-панели поменять что-то»*.

⚠ **Это уточняет более раннюю формулировку** («преподаватели не переводились, прецедентов
не было»). Прежняя запись понижала приоритет — она **отменена**: возможность обязательна.
Редкость операции влияет на то, сколько места ей дать, а не на то, быть ей или нет.

**Что происходит при смене группы — назвать явно, это не мелочь:**
- у преподавателя меняется `gruppa`;
- его кабинет меняется сам, потому что вычисляется из группы;
- 🔴 **его школьники остаются на нём и уезжают вместе с ним в новую группу** —
  иначе нарушится правило «школьник закреплён за преподавателем СВОЕЙ группы»
  (`07_TZ-SAJT §5`). Показать это перед сохранением: *«вместе с ним переедут 4 школьника»*.

### Добавление — задать группу СРАЗУ

Сейчас `dobavit` заводит человека без `gruppa`, и он немедленно становится записью
с пустой группой. **Группа обязательна при заведении**, форма без неё не отправляется.

### Никогда не удалять

`ubrat` = снять из активных. За человеком висит история прошлого года.
**В админке не должно быть кнопки «удалить» вовсе** — не «есть, но с подтверждением».

## §4. ЭКРАН «ШКОЛЬНИКИ»

Основная работа. Уже наполовину сделан (`POST /api/enrollment` живёт с 18:53).

**Строка:** `фамилия имя · класс · ГРУППА · [принимающий ▾]`
Группа идёт **раньше** принимающего — владелец: *«обычно в первую очередь
отображается группа»*.

**Выпадающий список принимающих:** сначала преподаватели текущей группы школьника,
потом остальные, разделителем. Выбрал чужого → группа и кабинет школьника меняются сами.

**Ждущие назначения — наверху и красным.** Число считать командой, не вписывать:

```
python3 -c "import sqlite3;c=sqlite3.connect('data/spetsmat.db');print(c.execute('select count(*) from students s where s.id not in (select student_id from enrollment e join teachers t on t.id=e.teacher_id where t.aktiven=1)').fetchone()[0])"
```

**Аракелова Дарья** — классный руководитель, не ученица. В списке школьников её нет;
из базы не удалять.

## §5. ЭКРАН «КАБИНЕТЫ»

Три строки, и это весь экран:

```
дата: [2026-09-05]
В → [303]     Д → [302]     Н → [203]
```

Пишет в `kabinet_na_den (data, gruppa, kabinet)` — таблица есть, четыре строки в ней уже
лежат. Правка отражается на всех страницах сразу, потому что кабинет **вычисляется**
из группы, а не хранится у человека.

Нет строки на дату — законный случай, кабинет не показывается. **Не подставлять
вчерашний молча.**

## §7. КРИТЕРИЙ ГОТОВНОСТИ — проверяется командами, не глазами

| # | клауза | чем проверяется |
|---|---|---|
| 1 | `/admin` отдаёт 200 | `curl -o /dev/null -w '%{http_code}' localhost:PORT/admin` |
| 2 | правка преподавателя проходит БЕЗ куки | `curl -X POST .../api/prepodavateli` → не 403 (закрывает Д1) |
| 3 | в списке видны неактивные | ответ `/api/teachers?vse=1` содержит `Ян Маршалл` (закрывает Д3) |
| 4 | смена группы работает | POST смены → `select gruppa from teachers where id=?` вернуло новое |
| 5 | школьники переезжают вместе | после смены группы у всех его детей группа новая |
| 6 | `teachers.kabinet` больше не пишется | `grep -c "set kabinet" veb/server.py` → 0 (закрывает Р2) |
| 7 | новый преподаватель без группы не заводится | POST без `gruppa` → 400 |

**Скриншот каждого из трёх экранов — в отчёт.** Описание словами скриншот не заменяет.
