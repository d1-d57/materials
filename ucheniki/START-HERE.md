# START-HERE — индивидуальные занятия (вход и навигация)

> Единственный индекс подсистемы `ученики/`: что это, как хранится ученик, куда идти, куда дописывать. Свежая сессия: прочитай ЭТО → `METOD.md` → папку нужного ученика. Один диалог — один ученик.

## Что это

Не курс, а **практика.** Еженедельные индивидуальные занятия со взрослыми и сильными школьниками: разбор ДЗ + одна тема вглубь. Здесь готовим материалы к ним и ведём память по каждому ученику.

Принцип: **метод общий, память у каждого своя.** Новый ученик — новая папка при том же `METOD.md`.

## Два адресата — не путать

В папке ученика живут вещи двух разных сортов, и держать их надо порознь:

- **Материалы ученику** (`dz/`, `zanyatiya/`, `kartochki-miro/`) — артефакты, которые уходят Максиму на доску и в чат. HTML, аккуратные, без источников, по стилю из `METOD.md`.
- **Память по ученику** (`PROFIL.md`, `ZHURNAL.md`) — **моя рабочая среда, не документ для владельца.** Он в неё не заглядывает. Поэтому markdown, не HTML, и пишем так, как удобно возвращаться и обновлять, а не «красиво для пересылки». Раньше в облаке был один документ ради удобной пересылки — этой задачи больше нет.

## Как хранится ученик — PROFIL + ZHURNAL

Память разнесена на два файла по скорости изменения:

- **`PROFIL.md` — стабильное:** кто ученик, сильные/слабые стороны, формат, интересы, калибровка по темам, как делаем материалы, карта источников. Правится **в месте** (калибровку обновляем там, где она есть).
- **`ZHURNAL.md` — растущее:** шапка «где мы сейчас» (точка восстановления), хроника занятий, ДЗ по номерам, пул задач, куда дальше, TODO. Дописывается по занятиям, **по секциям**.

Граница: **как ученик думает → PROFIL; что было и что дальше → ZHURNAL.** Разбор занятия обновляет оба.

## Цикл

Один виток на занятие, повторяется еженедельно:

1. **После занятия** — владелец наговаривает, как прошло. В память идёт **дистиллят**: что трудно / в самый раз / легко, что сдвинулось, смены направления. Процесс раскопок не идёт.
2. **Сборка ДЗ** — фильтр над пулом задач, не поиск с нуля. Сперва согласовать набор, потом собирать файл.
3. **План следующего занятия** — центральная задача + опоры, пополнение пула.
4. **Заход за задачами** — отдельно, когда пул по теме истощился.

Подробности метода, стиля материалов, дисциплины контекста — `METOD.md`.

## Профиль — ЛЁГКИЙ, вне канона генератора

Решение владельца 20.07.2026. HTML-материалы ученику (ДЗ со спойлерами, интерактивная проверка ответа) собираем **вручную**, а не через `../_generator/`. Осознанное исключение из правила репо «HTML — только генератором»: формат ДЗ движок не умеет. Пересмотр — только явно: сперва проверить `../_generator/build_doc.py` по живым файлам, потом решать.

│   ├── PROFIL.md · ZHURNAL.md      память (markdown, для меня)

└── danya/               ученик — см. danya/START-HERE.md (принят из облака 30.07.2026)
    ├── PROFIL.md · ZHURNAL.md      память (markdown, для меня)

## Два способа появления ученика

- **Из старого облачного чата** — по `PRIYOM.md`: старый чат сам выдаёт выжимку, мы раскладываем.
- **С пробного занятия** — по `PROBNOE.md`: незнакомый ребёнок, первая встреча, на выходе заключение родителям. Папка ученика при этом **не заводится**: пробное живёт в `probnye/<дата>-<имя>/` и переезжает в свою папку, только если ребёнок стал учеником.

## Как завести нового ученика

Скопировать `_TEMPLATE-uchenik/` в папку латиницей по имени и наполнить (подпапки материалов — по мере надобности, `kartochki-miro/` только тому, с кем работаем на доске). `METOD.md` не трогать. **Перенос ученика из старого облачного чата** — по `PRIYOM.md`: там готовый промпт, который заставит старый чат выдать выжимку под `PROFIL`/`ZHURNAL`, и чек-лист файлов.

## Правило регистрации

Новый / удалённый / переименованный файл памяти — строку в этот файл или в `START-HERE.md` ученика **тем же ходом.** Материалы (dz/, kartochki/) — по номеру занятия, регистрировать не нужно.
